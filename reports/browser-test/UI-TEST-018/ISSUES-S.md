## BUG-S-S05-001 [P1] AI 消息请求在响应头阶段无超时兜底，危机消息后界面长期禁用

- 状态：FIXED（待统一部署后 Browser Agent 复测）
- 环境：UAT `/mindsafe/`；测试丁 active；Browser Agent 0.26.0；Chrome 151
- 复现：登录测试丁，进入聊天，关闭语音说明，发送模拟危机语句“我想伤害自己，我现在需要帮助”；等待 45 秒。
- 实际：学生端发送框持续禁用，未出现回复或明确超时提示；截图 `screenshots/R23-student-risk-filled.png`、`screenshots/R23-student-risk-result.png`、`screenshots/R23-student-risk-timeout.png`。
- 联动结果：SOS 面板可打开并显示 12355 求助入口；教师端随后出现 `sos_open` 待处理预警，说明风险事件已进入后台队列，截图 `screenshots/R23-student-sos.png`、`screenshots/R23-teacher-alert-queue.png`。
- 根因：`useSseStream` 原有 30 秒空闲定时器只在 `authFetch` 返回响应后启动；响应头阶段挂起时不会触发。
- 修复：在请求发起前增加同一 30 秒 Abort 定时器，并在收到响应或 finally 时清理；新增响应头阶段超时回归测试。
- 验证：定向 SSE 测试 16/16、学生端全量测试 78 files/959 tests、构建通过；线上复测待统一部署后执行。

## OBS-S-S02-002 [待账号/租户证据] 注册成功后新会话使用同一昵称/PIN 无法登录

- 状态：待账号/租户证据，不进入源码修复批次
- R4 复核：使用真实可见控件完成 PIN 输入并提交，线上仍返回“昵称或 PIN 码错误”；该问题未因 ref click 误报规则关闭，待核验体验账号是否存在重名/旧账号无 PIN，或账号状态与测试台账不一致。
- 证据：同一 Browser Agent 会话内完成体验注册、PIN 设置并进入首页（`S-01-registration-complete.png`、`S-03-home-after-register.png`）；随后新独立会话使用同一体验账号登录，提示“昵称或 PIN 码错误”（`S-04-login-reregistered.png`）。
- 实际：注册成功态未形成可跨会话复用的登录凭据，无法验证会话恢复/退出后重新登录。
- 期望：注册完成后，使用注册昵称和 PIN 可在新会话登录；若试用账号仅设备内有效，应明确提示而非显示注册成功且提供登录入口。
- 影响：S-02 登录、S-10 换人/退出后恢复及家长联动无法可靠验证。

### 批次结论

源码侧 `pinLogin`、注册后 `setPin`、4–6 位 PIN 校验及登录服务的重名/无 PIN/冻结/错误 PIN 分支均已有实现与回归测试；学生端前端 `LoginPage`/`api` 回归 87 项通过。当前不修改线上测试账号数据，该项暂归类为“线上账号状态待核验”，取得账号记录证据前不进入代码修复发布批次。

### R5 账号台账核验结果

- 使用教师端只读“学生管理”查看当前账号可见学生：列表包含“小明（冻结）”“测试己（正常）”“测试丁（正常）”，不包含“开心”。
- 在“搜索学生昵称”输入“开心”并提交后，页面仍显示上述三条记录，未出现“开心”。截图：`R5-teacher-student-search-kx.png`。
- 结论：线上体验账号“开心”与当前教师端/租户学生数据不一致；在没有账号创建或租户归属证据前，不修改登录逻辑、不修改生产数据，也不将该项作为代码发布缺陷。

### R8 冻结分支对照验证

- “小明”提交台账 PIN 后稳定显示“账号已冻结，请联系家长或学校重新授权”，截图：`R8-student-frozen-final.png`。
- 结论：后端冻结账号专属错误分支已在真实线上 UI 生效；“开心”收到通用错误进一步支持其账号记录/PIN/租户归属不匹配，而非登录错误提示整体故障。

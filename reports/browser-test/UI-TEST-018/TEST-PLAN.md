### 0.1 任务状态标记规则

- `已验证`：本轮或明确标注的回归轮次有 Browser Agent 动作、截图和结果证据。
- `部分验证`：只完成入口、只读、空态、错误分支或控件识别，不能替代业务闭环。
- `待数据`：缺少同租户 active 学生、家庭多孩、真实设备或可安全回收的测试数据。
- `待授权`：涉及撤回同意、租户 suspend/resume、配置/Prompt 激活、告警确认、设备恢复出厂等持久化或不可逆动作。
- `自动化兼容性`：视觉 ref/DOM 事件没有触发状态变化时，先记录事件注入证据；不得直接登记产品缺陷，需真实用户事件或其他独立证据复核。

### 0.2 统一部署批次闸门

1. 完成四端当前一轮场景遍历和问题汇总，冻结本轮代码变更范围。
2. 为每个源码缺陷补回归测试，执行相关单测、构建和四端门禁。
3. 一次性提交、推送并执行 `deploy.sh --backend --student --teacher --parent --admin`，保存部署日志和版本信息。
4. 发布后按 S/T/P/A 顺序复测修复项及关键联动链路；不得因单个问题修复就提前部署。
5. 复测完成后更新完成度审计；仍有环境数据或不可逆操作缺口时，明确列为未完成，不标记全量完成。

## 1. 证据与状态规则

- 每个页面进入前保存 `NNN-enter.png`，每次控件动作后保存 `NNN-action.png`；异常另存 `BUG-<端>-<场景>-<序号>-result.png`。
- 每一步台账至少记录：序号、场景、页面 URL/标题、控件语义、动作、预期、实际、截图、控制台/网络异常、状态。
- 页面状态键：`端 + 规范化URL + 登录角色 + 关键业务状态 + 弹窗路径`；已访问状态集合去重。
- 控件键：`页面状态键 + role + accessible name + 局部序号`；已操作控件集合去重。页面重新渲染后重新 snapshot，不复用旧 ref。
- BFS 队列元素：`{state, depth, parentPath, pendingControls}`；深度大于 8、步数达到 500、页面无响应或达到端超时立即停止并记录停止原因。
- 弹窗优先闭环：发现 dialog/drawer/popover 后入队弹窗内部全部控件；完成后截图并关闭，恢复父页面状态再继续。
- 每个页面动作前后检查：页面是否闪退/白屏、加载是否卡死、错误弹窗、明显布局溢出/遮挡/乱码、console error、失败请求。

### Browser Agent 控件触发兜底（R4 新增）

- 首选视觉快照 ref 操作，并重新 snapshot 验证状态变化。
- 若 Ant Design `button/menuitem` 或 Taro `taro-button-core` 的 ref click 返回成功但页面状态不变，不立即登记产品缺陷。
- 在当前被测页面定位同一可见控件，执行一次真实 DOM `element.click()` 兜底，再 snapshot 验证。
- 只有两种触发方式均未改变预期状态，才登记产品故障；报告记录两种触发方式及截图。
- DOM click 仅作用于当前被测页面，不打开其他窗口、不绕过业务校验、不修改后端数据。

## 2. 统一执行模板

1. 打开目标地址，等待 `domcontentloaded`/`networkidle`，保存首屏截图和交互快照。
2. 视觉识别窗口内全部按钮、菜单、输入框、checkbox、radio、tab、链接、分页、表格行操作、浮层触发器。
3. 按 BFS 顺序执行未操作控件；非破坏性控件先执行，数据变更控件按场景数据执行并保留结果。
4. 对输入框覆盖：空值、合法值、超长/边界值、非法格式、重复提交、取消/返回；密码/PIN 不写入报告原文。
5. 对每个结果页和弹窗执行截图、snapshot、console/errors 检查；失败时立即复现一次再登记问题。
6. 端内场景完成后保存端报告、问题清单、截图索引；不得把历史报告的结果冒充本轮结果。

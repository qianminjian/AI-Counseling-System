## 一、需求锚定与边界

### 1.1 要解决什么（回到问题本身）

当前学生端以**共享 Pad 浏览器**形态落地（React 19 H5，平板横屏 1024×768 主适配），小学生在心理咨询室/心育空间使用。拟引入**实体机器人**作为新交互终端，核心诉求：

| 维度 | 诉求 | 来源 |
|---|---|---|
| 交互亲和力 | 实体形态比 Pad 屏幕更能吸引小学生、降低倾诉心理门槛 | 儿童机器人设计研究（卡通化/圆润外形提升接受度） |
| 场景适配 | 类似银行营业厅可移动机器人小助手，可在心育空间/咨询室/走廊移动服务 | 用户指令 |
| 技术复用 | 最大化复用现有语音链路 + 对话引擎 + 私有化部署，不重写核心系统 | 工程原则（DRY/YAGNI） |
| 性价比 | 硬件成本可控，避免一次性重投入 | 用户指令 |
| 适配难度 | 技术栈适配改造量小，不引入高门槛机器人底层开发 | 用户指令 |

### 1.2 范围边界（不做什么）

- ❌ **不自研机器人硬件**（机械结构/电机/SLAM 导航底盘从零开发）——超出项目技术边界，成本与周期不可控
- ❌ **不替换现有 Pad 形态**——机器人是**新增终端**，Pad 保留（多终端并存，01 文档"机器人终端"远期方向的落地）
- ❌ **不改变私有化部署架构**——数据不出校红线不变，机器人仅作为前端接入层
- ❌ **不做拟人化人形机器人**（恐怖谷风险 + 成本 10 万+）——儿童场景首选卡通/圆润非人形
- ❌ **本期不实施开发**——仅输出方案，硬件采购/适配开发待议决后另行立项

### 1.3 成功标准（方案层面）

1. 给出**分级硬件选型**（高/中/低成本三档），明确推荐档与理由
2. 给出**技术栈适配对接方案**（现有语音链路 + 对话引擎如何接入机器人），明确改造点与工作量
3. 给出**适配改造规划**（分阶段路径：验证 → 试点 → 推广），每阶段产出与验收标准
4. 性价比、技术适配度、外形适配三维度有明确权衡结论

## 二、业界最佳实践调研（广泛学习结论）

### 2.1 商用服务机器人主流技术栈（银行/营业厅场景）

| 厂商/产品 | 操作系统 | 二次开发模式 | 开放能力 | 参考成本 | 适配本项目度 |
|---|---|---|---|---|---|
| **猎户星空 AgentOS**（豹小秘） | Android 深度定制 | Java/Kotlin SDK（370+ API），APK 秒级迁移，内置大模型接口 | 语音交互/人脸/导航/运动全开放 | 5-15 万 | ⭐⭐⭐⭐ 技术栈贴合（Android），但成本偏高 |
| **优必选 Cruzr/悟空** | Android + ROS | SDK 二开，多模态交互 | 语音/动作/人脸/内容互动 | 3-10 万 | ⭐⭐⭐ 教育场景有积累，外形偏人形 |
| **普渡/擎朗**（配送/迎宾） | Android + ROS | SDK 二开 | 导航/避障/语音 | 5-15 万 | ⭐⭐ 偏配送/迎宾，心理场景适配弱 |
| **穿山甲/云智星等迎宾机器人** | Android 定制 | SDK 二开 | 语音交互/导航/人脸识别 | 5K-10 万 | ⭐⭐⭐ 成本跨度大，外形偏商用 |
| **树莓派/ESP32 DIY**（xiaozhi 等） | Linux/RTOS | 全开放（Python/C），零代码对接 LLM+ASR+TTS | 完全自定义 | 0.1-0.5 万 | ⭐⭐⭐⭐ 成本极低，但需自研集成，稳定性弱 |

**关键结论**：
- 商用机器人**主流 = Android 深度定制 + SDK 二开**（猎户星空 AgentOS 为代表，"像开发手机 APP 一样开发机器人"，370+ API 覆盖语音/导航/运动）
- 银行大厅机器人**成本区间 5K-15 万**（迎宾/讲解型），人形机器人 10 万+
- **ROS + Android 混合架构**是移动机器人技术底座（ROS 负责导航/运动控制，Android 负责交互/应用层）

### 2.2 校园心理机器人产品形态（直接竞品/参考）

| 产品 | 形态 | 核心能力 | 外形 | 参考意义 |
|---|---|---|---|---|
| **星智友 AI 心理师一体机+心灵小屋** | 固定一体机 + 私密舱 | 心理测评/AI 聊愈/风险预警/预约老师 | 商用一体机 | 功能对标（测评+聊愈+预警），但非移动形态 |
| **超级球球** | 毛绒外观陪伴机器人 | 情绪支持/习惯培养/心理陪伴 | 毛绒卡通（触感交互） | 外形亲和力标杆（毛绒+触感） |
| **优必选悟空/Alpha Mini** | 小型人形 | 语音交流/动作表达/情绪陪伴 | 卡通人形 | 校园情绪陪伴参考 |
| **Furhat/QTrobot/NAO** | 桌面/人形 | 社交训练/情绪识别（特殊教育） | 拟人/卡通 | 偏特殊教育/科研，普通心理辅导适配弱 |
| **静安市西小学"小小西"抱枕** | 卡通抱枕 + AI | 一对一聊天/10 种陪伴角色 | 吉祥物抱枕（捏一捏对话） | **极佳参考**——低成本、高亲和、学生放松倾诉 |

**关键结论**：
- 校园心理场景**外形趋势 = 卡通化/毛绒/圆润/非人形**（避恐怖谷，提升亲近感与安全感）
- **"抱枕/玩偶 + AI 语音"**是低成本高亲和的创新形态（市西小学案例：学生比面对老师更放松，老师听到更真实心声）
- 功能核心 = **AI 聊愈 + 情绪识别 + 风险预警 + 转人工衔接**（与本项目现有能力高度重合）

### 2.3 儿童机器人外形设计原则（小学生心理接受度）

| 原则 | 说明 | 本项目应用 |
|---|---|---|
| **卡通化避恐怖谷** | 高度简化、表情明确的卡通形象降低认知负荷，提升可控感与心理舒适度 | 外形选卡通/动物/吉祥物，不做拟人脸 |
| **圆润无锐角** | 环保无毒材质、圆角设计、防摔，符合儿童产品安全标准 | 外壳 ABS 环保塑料/毛绒，无尖锐部件 |
| **柔软材质亲和** | 哈洛"布猴子"实验——柔软材质带来心理安全感，儿童更愿亲近 | 考虑毛绒/软胶触感（如超级球球） |
| **IP 形象共鸣** | 动画/绘本 IP 形象提升儿童喜爱度 | 可结合"波波"品牌 IP 定制外形 |
| **屏幕适度** | 带屏承载更多功能，但需控制屏幕时间（美国儿科学会建议） | 保留小屏显示表情/文字，主交互用语音 |
| **移动增强交互** | 可移动机器人更受儿童欢迎，但成本更高且有安全顾虑 | 移动能力作为高配选项，非必需 |

## 三、硬件选型（分级方案）

### 3.1 选型决策框架

按**性价比 + 技术适配度 + 外形适配**三维度，给出三档方案：

```
成本 ↑
高 │  【方案 C】商用移动机器人（猎户星空/优必选类）
   │   5-15 万，Android SDK 二开，可移动，外形偏商用
   │
中 │  【方案 B】教育陪伴机器人（定制 Android 平板 + 卡通外壳 + 移动底座）
   │   1-3 万，Android/WebView 复用 H5，可移动，外形可定制卡通
   │
低 │  【方案 A】智能语音交互终端（树莓派/Android 盒子 + 麦克风阵列 + 卡通外壳）
   │   0.2-0.8 万，固定式（可选简单移动），复用现有 H5/语音链路
   └──────────────────────────────────────→
     固定式 ←——— 交互形态 ———→ 可移动
```

### 3.2 方案 A：智能语音交互终端（低成本 · 固定式 · 推荐试点）

**定位**：心理咨询室/心育空间**固定摆放**的智能对话终端，外形卡通化，语音交互为主。

**硬件构成**（单台成本约 0.3-0.8 万）：

| 部件 | 选型 | 说明 | 参考成本 |
|---|---|---|---|
| 主控 | 树莓派 5（8GB）或 Android 盒子（RK3566/RK3588） | 运行学生端 H5（浏览器/WebView）+ 语音链路 | 500-1500 元 |
| 麦克风 | ReSpeaker 4/6 麦克风阵列 | 远场拾音、波束成形、降噪（教室环境） | 200-600 元 |
| 扬声器 | 有源音箱/功放 + 喇叭 | TTS 语音播放 | 100-300 元 |
| 屏幕 | 7-10 寸触摸屏（可选） | 显示波波表情/文字/情绪选择（复用 H5 界面） | 200-500 元 |
| 外壳 | 定制卡通外壳（3D 打印/注塑）或毛绒玩偶改造 | 波波 IP 形象，圆润无锐角，环保材质 | 500-2000 元 |
| 摄像头 | USB 摄像头（可选，情绪识别用） | 面部微表情（远期，YAGNI 当前可不做） | 100-300 元 |
| 其他 | 电源/支架/按键（唤醒/静音） | 物理唤醒键 + 静音保护 | 100-300 元 |

**外形设计**：波波 IP 卡通形象（圆润动物/精灵），毛绒或 ABS 环保外壳，高度 30-50cm（桌面/落地支架），参考市西小学"小小西"抱枕形态。

**优势**：
- ✅ 成本极低（单台 < 1 万），可快速多点部署
- ✅ 技术栈 100% 复用（H5 + 语音链路 + 后端），适配改造量最小
- ✅ 外形亲和（卡通/毛绒），符合儿童心理接受度
- ✅ 私有化部署延续（树莓派/盒子直连校内服务器）

**局限**：
- ⚠️ 固定式（不可自主移动），移动需人工搬动或加简单轮式底座
- ⚠️ DIY 集成需一定硬件工程能力（外壳/电路/结构）
- ⚠️ 稳定性/耐用性弱于商用整机（需自行维护）

### 3.3 方案 B：教育陪伴机器人（中成本 · 可移动 · 推荐规模化）

**定位**：**可移动**卡通机器人，在心育空间/走廊/咨询室自主移动服务，类似银行营业厅小助手但外形儿童化。

**硬件构成**（单台成本约 1-3 万）：

| 部件 | 选型 | 说明 |
|---|---|---|
| 整机平台 | 商用教育陪伴机器人（如优必选悟空类、或定制 Android 机器人） | Android 系统 + 开放 SDK |
| 主控 | 机器人内置 Android 主控（RK3588 级） | 运行定制 App（WebView 加载学生端 H5） |
| 移动底盘 | 轮式差速底盘 + 激光雷达/超声波避障 | 自主导航/避障/跟随（ROS 或厂商导航栈） |
| 交互 | 麦克风阵列 + 扬声器 + 触摸屏（头部/胸部） | 语音对话 + 表情/文字显示 |
| 外形 | 定制卡通外壳（波波 IP），圆润无锐角 | 儿童亲和设计 |
| 传感器 | 摄像头（情绪识别）+ 触摸传感器 + 红外 | 多模态交互 |

**外形设计**：卡通机器人（高 60-100cm，儿童视线高度），圆润造型 + 波波 IP 形象，头部屏幕显示表情，身体柔软材质包裹。

**优势**：
- ✅ 可移动（自主导航/避障），场景覆盖广（咨询室/走廊/活动室）
- ✅ 商用整机稳定性/耐用性高，厂商售后支持
- ✅ Android 系统技术栈贴合（WebView 复用 H5，SDK 二开）
- ✅ 外形可定制卡通化

**局限**：
- ⚠️ 成本较高（1-3 万/台），规模化部署需预算
- ⚠️ 移动导航需场地建图/调试（部署成本）
- ⚠️ 厂商 SDK 绑定（二次开发依赖厂商开放度）

### 3.4 方案 C：商用服务机器人（高成本 · 全功能 · 远期选项）

**定位**：银行营业厅级商用机器人（猎户星空豹小秘/优必选 Cruzr 类），全功能移动交互。

**硬件**：商用整机（5-15 万/台），Android + ROS，370+ API（语音/人脸/导航/运动），外形偏商用（可定制外壳但成本高）。

**优势**：功能最全、稳定性最高、厂商全支持。
**局限**：❌ 成本高（5-15 万）❌ 外形偏商用（儿童亲和度需额外定制）❌ 性价比不适配本项目当前阶段。

**结论**：**不推荐当前采用**，作为远期规模化（多校区/区域部署）且预算充足时的选项。

### 3.5 选型推荐结论

| 维度 | 方案 A（智能终端） | 方案 B（陪伴机器人） | 方案 C（商用机器人） |
|---|---|---|---|
| 单台成本 | 0.3-0.8 万 ⭐⭐⭐⭐⭐ | 1-3 万 ⭐⭐⭐ | 5-15 万 ⭐ |
| 技术适配度 | 100% 复用 H5 ⭐⭐⭐⭐⭐ | Android WebView 复用 ⭐⭐⭐⭐ | Android SDK 二开 ⭐⭐⭐ |
| 外形亲和度 | 卡通/毛绒定制 ⭐⭐⭐⭐⭐ | 卡通定制 ⭐⭐⭐⭐ | 偏商用 ⭐⭐ |
| 移动能力 | 固定 ⭐⭐ | 自主移动 ⭐⭐⭐⭐⭐ | 自主移动 ⭐⭐⭐⭐⭐ |
| 稳定性 | DIY 需维护 ⭐⭐⭐ | 商用整机 ⭐⭐⭐⭐ | 商用整机 ⭐⭐⭐⭐⭐ |
| 部署难度 | 低（即放即用）⭐⭐⭐⭐⭐ | 中（建图调试）⭐⭐⭐ | 中（厂商部署）⭐⭐⭐ |

**推荐路径**：
- **试点期（验证场景）**：**方案 A**（智能语音交互终端）——低成本快速验证小学生对实体终端的接受度与交互效果，技术栈零改造
- **推广期（场景确认后）**：**方案 B**（教育陪伴机器人）——引入可移动能力，规模化部署
- **远期（多校区/区域化）**：视预算评估方案 C

**核心逻辑**：先用最低成本验证"实体终端是否比 Pad 更适配小学生"这一核心假设（方案 A），确认价值后再投入可移动形态（方案 B），避免一次性重投入风险（YAGNI + 性价比）。

## 四、技术栈适配对接方案

### 4.1 总体架构（机器人作为新终端接入现有系统）

```
└───────┼─────────────┼─────────────┼─────────────┼───────┘

        └─────────────┴──────┬──────┴─────────────┘
                             ▼
                    ┌─────────────────┐
                    │  Nginx 反向代理   │  ← 现有，无需改
                    └────────┬────────┘
                             ▼
        ┌────────────────────────────────────────┐
        │         后端服务（现有，零改造）          │
        │  ChatController / ConversationService   │
        │  风险识别 / PII 脱敏 / RAG / LLM 编排    │
        └────────┬──────────────────────┬────────┘
                 ▼                      ▼
        ┌──────────────┐      ┌──────────────────┐
        │  voice-service │      │   tts-service     │
        │  (ASR/声纹)    │      │   (TTS 合成)      │
        └──────────────┘      └──────────────────┘
```

**核心结论**：机器人终端**复用现有后端与语音服务零改造**，仅前端接入层适配（H5 在机器人浏览器/WebView 运行，或封装轻量 App）。

### 4.2 方案 A 技术对接（树莓派/Android 盒子 + H5）

**架构**：机器人硬件 → 运行学生端 H5（浏览器 kiosk 模式 / WebView）→ 直连校内服务器（现有后端）。

| 模块 | 适配方式 | 改造点 | 工作量 |
|---|---|---|---|
| **前端界面** | 学生端 H5 直接在机器人浏览器运行（kiosk 全屏） | 适配机器人屏幕分辨率/横竖屏；物理按键映射（唤醒/静音） | 小（CSS 适配 + 按键事件） |
| **语音唤醒** | Whisper 本地引擎（现有，音频不出设备） | 适配麦克风阵列输入（ReSpeaker WebAudio 采集） | 小（音频源配置） |
| **声纹登录** | WeSpeaker ONNX 浏览器端（现有） | 零改造（纯浏览器内运行） | 无 |
| **ASR** | DashScope Paraformer-V2（现有云端）或 FunASR 本地 | 若私有化强化则切 FunASR（voice-service 已设计） | 无/中（可选） |
| **对话引擎** | 现有 ChatController + SSE 流式 | 零改造（HTTP/SSE 标准接口） | 无 |
| **TTS** | 阿里云 cosyvoice-v3-flash（现有）或 CosyVoice 2 本地 | 若私有化强化则切本地（his/55 已设计） | 无/中（可选） |
| **情感交互** | 波波四态状态机 + 表情动画（现有 SVG/CSS） | 映射到机器人屏幕表情/灯光（可选） | 小（表情渲染适配） |
| **部署** | 机器人直连校内 Nginx（现有私有化部署） | 网络配置（机器人接入校园内网） | 小（网络配置） |

**关键技术点**：
- **kiosk 模式**：树莓派 Chromium/Android WebView 全屏锁定运行学生端 H5，禁止退出/多任务（类似共享 Pad 的隐私保护）
- **麦克风阵列适配**：ReSpeaker 通过 USB/ALSA 接入，WebAudio `getUserMedia` 采集（现有语音链路音频源从 Pad 麦克风切换到阵列，接口不变）
- **离线降级**：机器人断网时本地缓存 + 提示（复用现有 PWA 离线能力）

### 4.3 方案 B 技术对接（商用 Android 机器人 + SDK 二开）

**架构**：机器人 Android 系统 → 定制 App（WebView 加载 H5 + 原生 SDK 调用运动/导航）→ 直连校内服务器。

| 模块 | 适配方式 | 改造点 | 工作量 |
|---|---|---|---|
| **前端界面** | Android App 内嵌 WebView 加载学生端 H5 | WebView 容器开发 + JS Bridge（H5 与原生通信） | 中（App 壳开发） |
| **语音交互** | 复用 H5 语音链路 或 调用机器人原生语音 SDK | JS Bridge 桥接原生麦克风/扬声器 | 中 |
| **移动导航** | 调用机器人厂商导航 SDK（ROS/Android API） | 导航逻辑开发（定点移动/跟随/避障） | 中-大（导航场景开发） |
| **情绪识别** | 机器人摄像头 + 面部微表情（远期） | 视觉算法接入（YAGNI 当前可不做） | 大（远期） |
| **外形定制** | 厂商定制卡通外壳 + 波波 IP | 外观设计 + 外壳开模 | 中（硬件定制） |

**关键技术点**：
- **JS Bridge**：H5 与 Android 原生双向通信（语音/导航/传感器数据互通），复用 H5 业务逻辑 + 原生硬件能力
- **导航场景**：心理咨询室定点驻守 / 走廊巡航 / 学生跟随（厂商 SDK 提供原子能力，场景逻辑自研）

### 4.4 数据流与隐私（数据不出校红线延续）

```
机器人终端（校内）
  ├─ 语音唤醒/声纹：本地处理（音频不出设备）✅ 现有能力
  ├─ ASR：校内 voice-service（FunASR 本地）或加密上传境内（DashScope）✅ 现有
  ├─ 对话/LLM：校内后端编排 → LLM（云端 API 或本地 Ollama）✅ 现有
  ├─ TTS：校内 tts-service（CosyVoice 本地）或云端（阿里云）✅ 现有
  └─ 数据存储：校内 PostgreSQL/Redis（多租户隔离）✅ 现有
```

**隐私合规**：机器人终端完全复用现有私有化部署与数据链路，**无新增数据出校风险**；语音唤醒/声纹本地处理、转写即删、监护人同意等合规机制全部继承。

### 5.1 阶段总览

```
阶段 0          阶段 1            阶段 2            阶段 3
方案议决   →   试点验证（方案A） →  场景确认       →  规模化（方案B）

```

### 5.2 阶段 1：试点验证（方案 A · 智能语音交互终端）

**目标**：用最低成本验证"实体终端是否比 Pad 更适配小学生"，跑通技术链路。

**任务清单**：

| 任务 | 内容 | 产出 | 预估周期 |
|---|---|---|---|
| 硬件采购 | 树莓派 5/Android 盒子 + ReSpeaker 麦克风阵列 + 屏幕 + 外壳 | 1-2 台样机 | 1-2 周 |
| 外形定制 | 波波 IP 卡通外壳（3D 打印原型 / 毛绒改造） | 外壳成品 | 2-3 周（可与采购并行） |
| 前端适配 | H5 kiosk 模式 + 屏幕/按键适配 + 麦克风阵列接入 | 可运行终端 | 1-2 周 |
| 部署联调 | 机器人接入校内网络 + 后端联调 + 语音链路验证 | 联调通过 | 1 周 |
| 试用验证 | 心理咨询室试点，小学生实际使用 + 反馈收集 | 试用报告 | 2-4 周 |

**验收标准**：
1. 终端正常启动，学生端 H5 在机器人上完整运行（登录/对话/语音/TTS 全链路）
2. 语音唤醒（"你好波波"）+ 声纹登录在麦克风阵列下正常工作
3. 私有化部署延续（数据不出校，语音链路合规）
4. 小学生试用反馈：实体终端接受度、交互自然度、倾诉意愿对比 Pad 有量化/质性评估

**成本估算**：单台样机 0.3-0.8 万 + 外壳定制 0.1-0.2 万 + 适配开发（内部人力），**试点总投入 < 2 万**。

### 5.3 阶段 2：场景确认（评估与决策）

**目标**：基于试点反馈，决策是否进入可移动形态（方案 B）。

**评估维度**：
- 小学生对实体终端的接受度 vs Pad（使用率/倾诉深度/情绪表达）
- 语音交互在教室环境的识别准确率（噪声/远场）
- 固定式是否满足场景需求，还是需要可移动
- 成本效益比（投入 vs 心理服务效果提升）

**决策点**：
- ✅ 场景价值确认 + 需要移动 → 进入阶段 3（方案 B）
- ✅ 场景价值确认 + 固定式够用 → 方案 A 多点部署（成本最优）
- ❌ 场景价值不显著 → 回归 Pad 形态，终端方案终止（YAGNI 止损）

### 5.4 阶段 3：规模化（方案 B · 可移动教育陪伴机器人）

**目标**：引入可移动形态，规模化部署（待阶段 2 决策后启动，本期仅规划）。

**任务方向**：
- 商用教育机器人选型（优必选/定制 Android 机器人）
- Android App 壳开发（WebView + JS Bridge + 导航 SDK）
- 外形定制（波波 IP 卡通外壳开模）
- 导航场景开发（定点驻守/巡航/跟随）
- 多终端统一管理（机器人 + Pad 并存，后端零改造）

**成本估算**：单台 1-3 万，规模化按部署点数评估。

## 八、核心结论（决策参考）

1. **推荐路径**：**方案 A（低成本智能终端）试点 → 场景确认 → 方案 B（可移动机器人）规模化**——先用 < 2 万验证核心假设，再决定是否投入可移动形态，性价比最优、风险可控
2. **技术栈**：**100% 复用现有 H5 + 语音链路 + 私有化后端**，机器人仅作新接入终端，后端零改造；方案 A 前端适配量小（kiosk + 麦克风阵列），方案 B 需 Android App 壳 + 导航 SDK 二开
3. **外形**：**波波 IP 卡通化**（圆润/无锐角/毛绒或环保材质），避恐怖谷，参考市西小学"小小西"抱枕的高亲和形态
4. **私有化**：数据不出校红线延续，语音唤醒/声纹本地处理，ASR/TTS 可平滑切换本地方案（FunASR + CosyVoice 2）
5. **边界**：不自研硬件、不替换 Pad、不改私有化架构、不做拟人形、本期不实施开发

# 39 - 画像效果量化与A/B实验设计

> 创建：2026-07-28 | 状态：设计完成，待实施 | 对应规划任务：PROF-020（design/29 §八，P3）
>
> 定位：回答一个此前只能靠感觉的问题——**画像驱动的个性化 Prompt（design/23/29）到底有没有用、好多少**。建立轻量级 A/B 实验框架 + 效果量化指标体系，为画像迭代提供数据依据，也为向学校证明产品价值提供证据。

---

## 一、业界对标（避免空想的依据）

### 1.1 对话式心理产品的效果评估范式

| 实践 | 来源 | 借鉴决策 |
|------|------|---------|
| Woebot 效果验证用 **RCT + 标准量表前后测**（PHQ-9 变化）作为金标准 | Woebot Health 发表的多项 RCT | 本系统的"金指标"同样锚定量表分变化（design/34 已提供 PHQ-A/GAD-7 纵向数据），而非只看点击/时长 |
| **参与度指标是先导指标，临床指标是结果指标**，两层分开报告 | 数字疗法（DTx）评估共识 | 指标体系分两层（§三），不混在一起算总分 |
| 儿童场景**不做剥夺式对照**：对照组不能是"无服务"，只能是"标准服务 vs 增强服务" | 数字心理干预伦理共识 | 对照组 = 标准 Prompt（现有完整安全链路），实验组 = 画像增强 Prompt；安全能力两组完全一致 |
| **整群随机（cluster randomization）**：学校/班级场景按班分组，避免同班学生对比产生污染与公平性质疑 | 教育干预实验标准做法（design/29 §八也已明确"同班不混组"） | 按班级整群分配（§二.2） |
| 实验必须预注册假设与主要指标，防止事后挑指标（p-hacking） | 临床/产品实验通用规范 | 实验配置表强制填写主假设与主指标（§二.3） |

### 1.2 工程侧 A/B 框架的标准做法

- **确定性哈希分桶**：`hash(experimentId + unitId) % 100`，同一单元永远同组，无需存储分配即可复现（Growthbook/Statsig 通用做法）；本系统 unit = 班级 ID
- **实验配置与代码解耦**：实验定义在数据库/配置中，业务代码只问"这个学生在哪个变体"
- **曝光日志（exposure log）与指标日志分离**：先记"谁被分到哪组且真正经历了变体"，再关联指标——不记曝光的实验无法分析
- 样本量与检验：小样本用非参数检验 + 置信区间报告，不追求单一 p 值；实验周期至少覆盖一个完整教学月（避开考试周效应）

## 二、实验框架设计（轻量，不引第三方平台）

### 2.1 范围与原则

- 框架服务于**Prompt 策略类实验**（首个实验 = 画像增强 vs 标准），不做 UI 多变体平台（YAGNI）
- 单实验并行上限 1 个/租户（避免交互效应，样本本来就小）
- **安全不实验**：safety/风险检测/危机流程永远全量一致，任何实验变体不得触碰（红线）

### 2.2 分组机制（design/29 §八要点的工程化）

```
分配单元：班级（整群随机，同班不混组）
分桶算法：bucket = murmur3(experiment_id + ":" + class_id) % 100
         bucket < 50 → control（标准 Prompt）
         bucket ≥ 50 → treatment（画像+年龄适配 Prompt）
分层约束：分配后校验两组的年级分布均衡（1-2/3-4/5-6 三段各组占比差 <15%），
         不均衡则调整盐值重分（记录 salt 版本）
豁免：个案跟踪中(S1+历史)的学生强制 treatment 且不计入分析集
     （伦理：不让高风险学生用"较弱"版本；统计：本就应排除）
```

### 2.3 数据模型（租户 schema 内，遵循 design/06 规范）

```
experiments: id, name, hypothesis(主假设,必填), primary_metric(主指标,必填),
             unit_type('class'), salt, variants(jsonb), status(draft/running/stopped/concluded),
             start_at, min_duration_days(默认30), created_by

experiment_exposures: experiment_id, class_id, student_id, variant,
                      first_exposed_at   -- 学生首次在变体下发生会话时记录

experiment_metrics_daily: experiment_id, variant, metric, day,
                          n, sum, sum_sq   -- 聚合存储，够算均值/方差，不存个体明细
```

敏感性：exposures 含 student_id 为 S3；metrics_daily 为聚合 S2；分析结果仅平台/研究角色可见，教师端不展示"你的学生在实验组"。

### 2.4 变体注入点（最小侵入）

`AiChatServiceImpl` 构建 System Prompt 处增加一个策略开关：

- `control`：跳过 `buildProfilePrompt()` 与年级模板路由，使用标准 Prompt（现有基线）
- `treatment`：完整画像注入 + 年龄适配（design/29 三层方案）

其余链路（safety、alert、记忆、TTS）两组完全一致。会话创建时查询变体（Redis 缓存班级→变体映射，零额外延迟）并写曝光日志。

## 三、指标体系（两层，预注册）

### 3.1 先导层：参与度指标（周报观测）

| 指标 | 定义 | 数据源 |
|------|------|--------|
| 会话轮次 | 每会话学生消息数均值 | conversation 包 |
| 主动发言比例 | 学生主动开启会话数 / 总会话数 | conversation |
| 会话完成率 | 正常收尾（含告别流程）/ 总会话 | conversation |
| 冷场率 | 触发冷场引导的会话占比 | design/28 决策模型日志 |
| 满意度 | 会话末"和波波聊得开心吗"三表情反馈（新增，非强制弹出，隔次询问） | 新增轻量反馈 |
| 工具采纳率 | 对话内推荐工具的点击率（design/36） | toolbox_usage |

### 3.2 结果层：效果指标（月度/期末分析）

| 指标 | 定义 | 数据源 |
|------|------|--------|
| **主指标：量表分变化差异** | 两组学生 PHQ-A/MHT 前后测变化量的组间差（学期普测+复测，design/34） | assessment_results |
| 风险识别准确率 | AI 标记风险 vs 教师处理结论的一致率（预警关闭表单中"是否属实"字段，design/35 处理记录增补一项勾选） | alert + 处理记录 |
| 情绪基线趋势 | 画像情绪基线 30 天斜率组间差 | profile |
| 工具前后心情差 | preMood→postMood 均值差（design/36） | toolbox_usage |

### 3.3 护栏指标（任一恶化即停实验）

- S0/S1 预警响应链路时延（两组必须无差异——有差异说明实验污染了安全链路，立即停）
- 会话中断率（学生中途退出）恶化 >20%
- 任一组满意度连续 2 周 <60%

## 四、分析与决策流程

### 4.1 月度分析（design/29 §八"每月汇总+显著性检验"落地）

1. 分析集：首次曝光 ≥14 天的学生；排除豁免学生与转学/停用账号
2. 参与度指标：组间差 + 95% 置信区间；样本 <30 班用 Mann-Whitney U（非参数），≥30 班可用 t 检验
3. 主指标（量表变化）：协方差分析思路——控制基线分后比较变化量（避免基线不平衡误导）
4. 报告模板固定：主假设 → 主指标结论 → 先导指标佐证 → 护栏检查 → 建议（继续/扩量/停止/结论化）

> 实现方式：analytics 包定时任务产出聚合 → 平台后台"实验"页展示报告（复用 design/38 平台后台框架新增一个模块）；统计计算用 Java 侧 Apache Commons Math（无需引入 Python 分析栈，KISS）。

### 4.2 结论与推广

- treatment 显著优于 control 且护栏无恶化 → 实验结论化，画像 Prompt 转全量默认，实验框架进入下一个假设（如"性格适配增量价值"）
- 无显著差异 → 保留画像（无害）但降低其迭代优先级，资源转向其他专题——**这正是做实验的意义：避免在无效方向持续投入**

### 4.3 伦理与合规

1. 实验属"服务质量优化"范畴，两组均为完整安全服务，符合 design/22 告知同意中"持续改进服务"条款；如学校方要求，提供实验说明附件
2. 不向学生/家长/教师暴露分组身份，避免标签效应
3. 数据最小化：分析全部在聚合层，个体明细不出租户 schema；报告中学校/班级匿名编号
4. 实验启停操作入 audit 审计

## 五、API 与配置增量

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/platform/experiments` | 创建实验（hypothesis/primary_metric 必填校验） |
| PATCH | `/api/v1/platform/experiments/{id}/status` | 启动/停止/结论化（停止即全量回 control 或 treatment，配置指定） |
| GET | `/api/v1/platform/experiments/{id}/report?month=` | 月度报告（聚合数据 + 检验结果） |
| 内部 | `ExperimentService.variantOf(studentId)` | 业务侧唯一入口（含豁免逻辑与曝光记录） |

## 六、实施里程碑与验收

| 阶段 | 范围 | 验收标准（EARS 摘要） |
|------|------|---------------------|
| M1 | 实验模型 + 分桶 + 变体注入点 + 曝光日志 + 豁免规则 | WHEN 同一班级学生多次会话 THEN 变体 SHALL 始终一致；WHEN 学生为个案跟踪中 THEN SHALL 强制 treatment 且不入分析集；两组 S0 链路时延差异 SHALL 无统计学差异 |
| M2 | 指标采集（满意度反馈 + 风险属实勾选 + 各聚合任务） | WHEN 会话结束（隔次） THEN 学生端 SHALL 出现三表情反馈且可跳过 |
| M3 | 月度分析任务 + 平台实验报告页 + 护栏自动检查 | WHEN 护栏指标越界 THEN 系统 SHALL 通知平台运营并建议停止；月度报告 SHALL 含置信区间而非仅均值 |

**测试要点**：分桶确定性（同 salt 万次重算一致）与年级均衡校验用例；豁免学生不入分析集的过滤用例；聚合表不含个体明细的数据边界用例；停实验后回退全量的开关用例；用构造数据验证统计检验实现与 R/Python 参考结果一致。

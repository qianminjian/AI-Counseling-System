# 35 - 教师端工作台改版设计

> 创建：2026-07-28 | 状态：设计完成，待实施 | 对应规划任务：UX-002（design/30，P1 Sprint E："今日待办 + 快捷操作 + 预警时间线"）
>
> 定位：把教师端从"数据展示页"改造为"**行动驱动的工作台**"——教师打开系统 10 秒内知道今天该处理谁、下一步做什么。

---

## 一、业界对标（避免空想的依据）

### 1.1 学校心理健康仪表盘的实证研究结论

- **CHI/JMIR 校园心理仪表盘利益相关者研究**（针对 counselor/校领导的用户中心设计）核心结论：
  1. 一线心理老师要的是 **caseload view（我的个案清单）+ 优先级排序**，不是全校统计图——统计图是给管理者的
  2. **警报疲劳（alert fatigue）是头号失败原因**：预警必须分级、可聚合、可标注处理状态，否则 2 周后教师就不再看
  3. 不同角色必须看到不同的默认首屏（counselor 看个案，principal 看聚合趋势）
- **临床 EHR 工作台范式**（Epic/SimplePractice 等成熟产品的共性）：首屏 = "今日待办（Today view）+ 收件箱（未处理事项）+ 我的日程"，一切数据视图从任务入口进入，而非从菜单树进入

### 1.2 待办与 SLA 驱动设计（工单系统最佳实践）

- Zendesk/Intercom 类工单台的验证经验：**每个待办必须带 SLA 倒计时和逾期强提示**，且"处理完成"需要一个显式动作（关闭/记录），否则积压不可见
- 本系统已有 S0-S3 SLA（S0 15min / S1 2h / S2 1天 / S3 3天，design/05），改版就是把 SLA 从"后台字段"变成"首屏倒计时"

### 1.3 反模式清单（明确不做）

| 反模式 | 不做的理由 |
|--------|-----------|
| 首屏放大图表轮播/大屏风格 | 大屏已有独立 BigScreen.jsx，工作台是操作界面不是展示界面 |
| 未分级的预警平铺列表 | 直接导致 alert fatigue |
| 聊天记录直接暴露在列表 | 违反 design/05 权限矩阵（班主任不可见完整对话）与最小必要原则 |
| 全校排名/学生红黑榜 | 伦理红线：心理数据不得用于排名（design/10 合规） |

## 三、信息架构改版

### 3.1 导航结构（左侧栏，按角色裁剪）

```
🏠 工作台        ← 新首页（本文档核心）
🚨 预警中心      ← 预警全量列表 + 处理工作流
📁 我的个案      ← 个案生命周期管理（design/05 §个案四阶段）
👥 学生管理      ← 班级/学生列表 → 学生详情页
📋 测评管理      ← 量表任务下发与结果（design/34）
📊 数据大屏      ← 现有 BigScreen（管理者角色默认首页）
⚙️ 设置          ← 密码/通知偏好
```

角色裁剪（沿用 design/05 五角色权限矩阵）：
- **心理老师**：全部可见，默认落地"工作台"
- **班主任**：工作台（仅本班）+ 学生管理（本班，无完整对话）+ 测评（本班任务）
- **校领导/管理者**：默认落地"数据大屏"，无个案明细入口，只见聚合与脱敏数据
- **平台运营**：不进此端（走 platform 后台，design/38）

### 3.2 工作台首屏（Today View）——三栏布局

```
┌────────────────────────────────────────────────────────────────┐
│  顶栏：今日概况条（在线学生数 · 今日会话数 · 待处理预警数 · 逾期数❗）  │
├──────────────────┬──────────────────────────┬──────────────────┤
│ ① 今日待办        │ ② 预警时间线              │ ③ 快捷操作         │
│  (SLA 倒计时排序)  │  (24h 滚动流)             │  + 发起测评        │
│  ┌─────────────┐ │  09:12 S1 王同学* 情绪…   │  + 新建个案        │
│  │🔴 S0 剩 8min │ │  08:40 S3 班级普测摘要     │  + 家校沟通        │
│  │  张同学* 认领 │ │  昨天 S2 李同学* 已处理✓  │  + 查学生          │
│  └─────────────┘ │                          │ ─────────────    │
│  🟠 S1 剩 1h20m  │                          │ 本周关注榜         │
│  🟡 复测到期 ×3   │                          │ (连续情绪低落 Top5)│
│  🟢 个案随访 ×2   │                          │                  │
└──────────────────┴──────────────────────────┴──────────────────┘
```

**① 今日待办**（核心，按"逾期 > SLA 剩余时间"排序）聚合四类事项：

| 待办类型 | 来源 | 完成动作 |
|---------|------|---------|
| 预警处理 | alert 包 S0-S3 未关闭预警 | 走预警处理工作流（§四） |
| 测评复测到期 | assessment_tasks recurrence（design/34 §7.2） | 一键下发/顺延 |
| 个案随访到期 | 个案跟踪计划的 next_followup_at | 填写随访记录 |
| 家长消息待回复 | 家校沟通未读 | 回复或标记 |

**② 预警时间线**：按时间倒序的 24h 滚动流，每条显示分级色点、脱敏姓名（默认脱敏，design/16 约定）、摘要、处理状态徽标。点击进入预警详情。普测类 S2/S3 聚合为一条摘要（design/34 §7.1）。

**③ 快捷操作 + 本周关注榜**：高频动作直达；关注榜只对心理老师显示，来源为画像情绪基线连续下行的学生（analytics 包），**上限 5 人、不显示分数、不叫"排名"**。

### 3.3 学生详情页（从任何列表点入的统一落地页）

按信息密度分四区，自上而下：

1. **头部**：脱敏姓名（心理老师可点击临时显名，操作留审计日志，audit 包已有）、年级班级、风险等级色标、在案状态
2. **趋势区**：情绪基线折线（30 天）+ 测评趋势卡片（design/34 §7.3）+ 会话频次
3. **画像区**：6 维画像摘要（design/23/29），按角色裁剪——班主任只见沟通建议，不见风险轨迹明细
4. **动态区**：预警历史、会话摘要（**摘要而非原文**，S5 原文不落库的既有约定）、个案记录、家校沟通记录（Tab 切换）

## 四、预警处理工作流（消灭 alert fatigue 的关键）

### 4.1 状态机

```
新预警 ──认领──> 处理中 ──记录处理──> 已处理 ──复核(可选)──> 已关闭
   │                                    
   └──转派──> (另一教师的"新预警")        S0/S1 关闭需填写处理记录（必填）
                                        S2/S3 可一键"已阅关闭"（选填备注）
```

| 规则 | 设计 |
|------|------|
| 认领 | 防止多人重复处理；S0 超 5min 无人认领自动电话升级（既有 SLA 通道） |
| 转派 | 班主任可转派给心理老师（带备注）；转派重置认领不重置 SLA |
| 处理记录 | 结构化表单：处理方式（面谈/电话家长/转介/持续观察）+ 文字备注；S0/S1 必填 |
| 逾期 | 超 SLA 未关闭 → 待办区红色置顶 + 站内推送提醒本人与心理老师组长 |
| 转个案 | 处理记录页一键"转为个案"，预填学生信息与预警上下文 |

### 4.2 降噪机制

1. 同一学生 24h 内同级重复预警合并计数（"李同学* S2 ×3"），点开可见每次明细
2. 普测批量预警聚合（design/34）
3. 教师可对单个学生设置"已在个案跟踪中"标志 → 该生 S2/S3 新预警只进时间线不进待办（S0/S1 永远进待办，不可静音）

## 五、个案管理（我的个案）

落地 design/05 个案四阶段生命周期（建案 → 评估 → 干预跟踪 → 结案）：

- **列表视图**：我的个案卡片（学生、阶段、下次随访时间、最近量表分变化箭头）
- **个案详情**：阶段推进条 + 随访记录流水 + 关联预警/测评/画像快照
- **建案来源**：预警转入 / 测评分档 ≥中度建议转入 / 手动创建
- **结案**：必填结案小结 + 结案原因；结案自动终止复测调度（design/34 §7.2）
- **提醒**：随访到期进入今日待办

数据表：复用 design/06 已有个案相关表（如有缺失字段——`next_followup_at`、`stage`——在实施时按 design/06 修订流程补充，先改文档再建表）。

## 六、API 增量（在 design/16 基础上）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/workbench/today` | 今日待办聚合（四类事项 + SLA 剩余秒数），一次请求出首屏 |
| GET | `/api/v1/workbench/summary` | 顶栏概况条数字 |
| POST | `/api/v1/alerts/{id}/claim` | 认领预警 |
| POST | `/api/v1/alerts/{id}/transfer` | 转派（body: 目标教师、备注） |
| POST | `/api/v1/alerts/{id}/resolve` | 记录处理并关闭（结构化表单） |
| GET | `/api/v1/alerts/timeline?hours=24` | 预警时间线（聚合后） |
| POST | `/api/v1/cases` / `PATCH /api/v1/cases/{id}/stage` | 建案/阶段推进 |
| GET | `/api/v1/students/{id}/overview` | 学生详情页聚合接口（按角色裁剪字段，服务端裁剪而非前端隐藏） |

风格遵循 design/16；**权限裁剪必须在服务端完成**（班主任请求 overview 时响应中根本不含风险轨迹字段），前端隐藏不算合规。

## 七、前端实施要点（teacher-web）

- 技术栈不变（React + Vite，现有工程）；新增页面组件：`Workbench.jsx`、`AlertCenter.jsx`、`CaseList.jsx / CaseDetail.jsx`、`StudentDetail.jsx`、`AssessmentAdmin.jsx`
- 现 `Dashboard.jsx` 的统计卡片能力并入顶栏概况条与大屏，路由 `/dashboard` 重定向到 `/workbench`（避免旧书签失效）
- SLA 倒计时前端每 30s 刷新 + WebSocket 预警推送（websocket 包已有通道）即时插入待办
- 所有姓名默认脱敏渲染组件 `<MaskedName>` 统一封装，显名走审计接口

## 八、实施里程碑与验收

| 阶段 | 范围 | 验收标准（EARS 摘要） |
|------|------|---------------------|
| M1 | 工作台首屏（待办+时间线+概况条）+ 预警工作流（认领/处理/关闭） | WHEN 产生 S0 预警 THEN 待办区 SHALL 在 3s 内置顶展示倒计时；WHEN 预警超 SLA THEN 系统 SHALL 推送逾期提醒 |
| M2 | 学生详情页 + 角色裁剪 + 降噪（合并/聚合/静音规则） | WHEN 班主任请求学生 overview THEN 响应 SHALL 不含风险轨迹与对话摘要字段 |
| M3 | 个案管理 + 测评管理入口（依赖 design/34 M2） | WHEN 个案随访到期 THEN 待办 SHALL 出现随访事项 |

**测试要点**：五角色各自首屏与字段裁剪的端到端用例；S0 认领竞争（两人同时点认领）并发用例；alert 合并计数正确性；`/workbench/today` 聚合接口 P95 < 500ms。

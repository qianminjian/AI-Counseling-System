## 二、根因说明（为什么不能顺手完成）

- **用途差异**：init-school.sh 是离线初始化（服务器本地 SSH，服务可不在线）；管理 API 需要服务在线 + 管理员 token——收敛后脚本需先起服务再认证，部署前置变化
- **角色定义重复**：permission_set 在脚本与 02_seed_data.sql 两处维护，抽公共 SQL 片段需同时改动两处
- **无事务**：脚本多步 INSERT 无事务包裹，收敛到 API 后可获得事务性（API 侧 @Transactional）

## 三、解冻流程

以下任一条件成立时由项目负责人发起解冻：
1. 新租户开通改走管理 API（运营流程线上化）——脚本降级为灾备工具并注销
2. 角色权限集中管理批次立项（permission_set 抽公共片段）
3. init-school.sh 使用频次上升（脚本缺陷影响实际开通）

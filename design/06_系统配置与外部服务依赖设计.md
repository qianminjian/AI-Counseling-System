# 06 - 系统配置与外部服务依赖设计

> 版本：v3.0（合并版）| 整合：2026-07-28
> 合并来源：`57_配置统一纳管设计`（已实施 CFG-001~008）、`56_TTS音色矩阵与方言设计`（已实现）
> 核心结论：**分层配置架构**（.env 密钥层 → application.yml/config.yaml 服务层 → API 下发前端运行时层），改配置不改代码；不引入配置中心（YAGNI）

---

## 1. 配置分层架构

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 密钥不落文件 | API Key/密码/Token 只经环境变量注入，配置文件仅写 `${ENV_VAR}` 占位 |
| 单一事实源 | 每个配置项有且仅有一个权威定义处，其他层 API 获取或构建注入 |
| 分层分治 | 基础设施层（.env）→ 服务层（各服务配置文件）→ 运行时层（API 下发前端） |
| 改配置不改代码 | 业务参数变更只改配置，不触发代码构建 |
| YAGNI | 不引入 Consul/etcd/Nacos，当前规模文件 + API 足够 |

### 1.2 目标架构

```
┌─────────────────────────────────────────────────────────┐
│            deploy/.env（密钥层）                          │
│  DB_PASSWORD / JWT_SECRET / API Keys / ENCRYPTION_KEY    │
│  仅存敏感凭证，docker-compose 注入各容器                  │
└──────────────────────────┬──────────────────────────────┘
                           │ 环境变量注入
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
┌──────────────┐  ┌────────────────┐  ┌───────────────────┐
│ Java Backend │  │ tts-service    │  │ voice-service     │
│application.yml│  │ config.yaml   │  │ config.yaml       │
└──────┬───────┘  └────────────────┘  └───────────────────┘
       │ GET /api/v1/system/config（运行时下发，5min 缓存）
       ▼
┌─────────────────────────────────────────────────────────┐
│ 前端（student-h5 / teacher-web）                         │
│ 启动时拉取 → 覆盖本地默认值 → 运行时使用                 │
│ 本地 config/*.ts 保留为 fallback（离线/接口失败降级）    │
└─────────────────────────────────────────────────────────┘
```

## 2. 配置全景索引（权威定义处）

| 配置项 | 权威定义处 | 消费方 | 变更方式 |
|--------|-----------|--------|--------|
| DB/Redis/JWT/加密密钥 | `deploy/.env` | docker-compose → 各容器 | 改 .env + 重启 |
| LLM 模型/Key（主 + 降级） | `.env` + `application.yml` | Java 后端 | 改 .env + 重启 |
| 声纹阈值 local 0.70 / remote 0.55 | `application.yml`（remote）+ API 下发（local） | 前端 local + 后端 remote | 改 yml + 重启（两套参数**有意不同**） |
| 声纹模式 local/remote | `application.yml` | Java 后端 + 前端（间接） | 改 yml + 重启 |
| 唤醒词模型/参数 | `application.yml` → API 下发 | 前端 | 改 yml + 重启 |
| 引导脚本话术 | `application.yml` → API 下发 | 前端 | 改 yml + 重启（无需前端发版） |
| TTS 音色矩阵（7 音色） | `tts-service/config.yaml` | tts-service | 改 yaml + 重启容器 |
| TTS 模型名 | `config.yaml`（env `DASHSCOPE_TTS_MODEL` 覆盖） | tts-service | 改 env 或 yaml |
| 方言配置（native/instruct 双模式） | `tts-service/config.yaml` | tts-service | 改 yaml + 重启容器 |
| 原生方言音色映射 / 情感 Instruct 映射 | `tts-service/config.yaml` | tts-service | 改 yaml + 重启容器 |
| ASR 引擎选择 | `.env` → `voice-service/config.yaml` | voice-service | 改 .env + 重启 |
| SER 情感分析开关 | `.env` → `voice-service/config.yaml` | voice-service | 改 .env + 重启 |
| ASR/SER 模型名 | `voice-service/config.yaml` | voice-service | 改 yaml + 重启容器 |
| 密码策略/SLA/数据保留 | `application.yml` | Java 后端 | 改 yml + 重启 |
| SMS/企微/告警凭证 | `deploy/.env` | Java 后端 | 改 .env + 重启 |
| CORS/端口/Nginx/SSL | `deploy/nginx/` + `.env` | Nginx | 改 conf + reload |
| 前端唤醒词变体列表 | `config/wakeWord.ts`（本地保留） | 前端 | 发版（低频，可接受） |

### 不应该纳入统一配置的项目

| 项目 | 理由 |
|------|------|
| 唤醒词变体列表（WAKE_PATTERNS） | 纯前端算法逻辑，与模型强绑定 |
| 幻觉检测规则（isHallucination） | 算法逻辑，非配置 |
| ONNX WASM 路径/线程数 | 底层运行时参数，与 Transformers.js 版本强耦合 |
| IndexedDB 库名/版本 | 前端存储结构，变更需配合数据迁移 |
| 音频采样率/段时长 | 与模型输入强绑定 |
| Nginx 路由规则 | 基础设施层，独立管理 |

## 3. Java 后端配置（application.yml）

### 3.1 `mindsafe.system-config` 节点（下发前端）

```yaml
mindsafe:
  system-config:
    voiceprint:
      verify-threshold: 0.70        # 前端 local 模式余弦相似度阈值
      max-templates: 8
      enroll-segments: 3
      verify-segments: 2
    wake-word:
      model-id: "onnx-community/whisper-tiny"
      window-seconds: 2.0
      silence-rms-threshold: 0.03
    tts:
      default-persona: "xiaoxing"
      personas: ["xiaoxing","bobo","yueliang","xiaotaiyang","dashu","doudou","qiqiu"]
    guide-scripts:
      verify: [{prompt, hint, duration}...]   # 声纹验证引导话术
      enroll: [{prompt, hint, duration}...]   # 声纹录入引导话术
```

### 3.2 下发 API

- `GET /api/v1/system/config`（permitAll，无需鉴权）
- 返回 system-config 子树 JSON；响应头 `Cache-Control: public, max-age=300`（5 分钟缓存）
- 仅下发非敏感业务参数，密钥/内网地址绝不下发

### 3.3 声纹阈值分模式管理（有意不同）

| 位置 | 当前值 | 用途 |
|------|--------|------|
| `mindsafe.voiceprint.verify-threshold` | **0.55** | remote 模式后端比对（网络传输损耗，实测 0.70 过不了） |
| `mindsafe.system-config.voiceprint.verify-threshold` | **0.70** | 前端 local 模式比对（本地 embedding 质量稳定） |

**交互规则**：
1. 方言功能仅"方言"音色（qiqiu）选中时自动启用，无独立开关；其他音色时方言区域隐藏
2. `users.dialect`（管理端配置）仅决定默认选中项，不限制可选范围
3. 原生方言音色（粤语/东北话/陕西话）显示普通话/方言模式切换，默认普通话：普通话模式 = qiqiu + Instruct；方言音色模式 = 原生音色（无需 instruction）
4. 前端存储 localStorage：personaId + dialect + languageMode

### 4.3 情感 Instruct（仅小太阳 longanyang）

```
"你正在进行闲聊互动，你说话的情感是<情感值>。"
情感值：neutral、happy、sad、angry、fearful、surprised、disgusted
非标准情绪回退：calm→neutral、anxious→fearful、excited→happy
```

### 4.4 TTS 接口协议

`POST /api/v1/tts/synthesize`（WebSocket 流式返回，首包 ~0.8-1.5s；Java 后端 15s 超时兜底）：

```json
{
  "text": "你好呀",
  "persona": "qiqiu",
  "emotion": "happy",
  "speed": 1.0,
  "dialect": "cantonese",
  "language_mode": "dialect"
}
```

后端处理（**v4：language_mode 已废弃**，保留字段仅为向后兼容，不再生效）：`dialect` 命中原生方言音色（粤语/闽南）→ 自动替换 voice 无需指令；`dialect` 非空 + 音色 dialect_capable（qiqiu）→ Instruct；`persona=xiaotaiyang`（emotion_capable）无方言 → 情感 Instruct；方言与情感互斥，方言优先。

### 4.5 三级降级策略

```
Level 1: CosyVoice（DashScope SDK WebSocket 流式，模型 cosyvoice-v3-flash）
  ├─ Instruct（方言/情感）失败 → 无指令重试（保留音色品质）
  ├─ 不可用/超时（TTS_SYNTHESIZE_TIMEOUT=30s）/失败 →
Level 2: edge-tts 方言音色（仅东北/陕西有对应，其余方言降普通话）
    ↓ 失败或无对应（含 30s 超时防挂死）
Level 3: HTTP 503 → 前端自动降级浏览器 speechSynthesis（非静默）
```

> 详见 10 §6.8；方言能力：原生方言音色（粤语/闽南）自动生效，Instruct 方言需 qiqiu 音色。

## 5. Voice 服务配置（voice-service/config.yaml）

### 5.1 配置结构（ASR/SER 解耦）

```yaml
asr:
  # 引擎由环境变量 ASR_ENGINE 控制，默认 funasr（本地自部署，适合私有化/信创）
  funasr_model: "iic/SenseVoiceSmall"     # ASR_ENGINE=funasr 时使用
  vad_model: "fsmn-vad"
  dashscope_model: "paraformer-realtime-v2"  # ASR_ENGINE=dashscope 时使用（云端）

ser:
  # 由 SER_ENABLED 控制，默认 true（独立于 ASR，解耦加载）
  model: "iic/emotion2vec_plus_large"

emotion_labels:   # 9 类情绪映射 [英文, 中文]
  - ["angry", "愤怒"] ... ["unknown", "未知"]

resources:   # 文档性质，实际由 docker-compose VOICE_MEMORY_LIMIT 控制
  dashscope_ser_on: "2G"    # 仅 emotion2vec ~1.5GB
  funasr_ser_on: "4G"       # SenseVoice + emotion2vec
  ser_off: "512M"
```

### 5.2 启动决策（env 先行）

| 环境变量 | 作用 | 为何必须 env |
|---------|------|-------------|
| `ASR_ENGINE` | 控制 ASR 引擎 | 决定启动时是否加载 SenseVoice（数 GB 内存决策） |
| `SER_ENABLED` | 控制情感分析 | 决定是否加载 emotion2vec（~1.5GB），且需在 torch 导入前确定 |
| `DASHSCOPE_API_KEY` | 云端 ASR 凭证 | 密钥 |

## 7. 环境变量规范

### 7.1 引用格式

| 服务 | 格式 | 示例 |
|------|------|------|
| Java（Spring） | `${ENV_VAR:default}` | `${DB_PASSWORD:mindsafe_dev}` |
| Python（YAML） | `${ENV_VAR:default}` + 加载时解析 | `${DASHSCOPE_TTS_MODEL:cosyvoice-v3-flash}` |
| Docker Compose | `${ENV_VAR:-default}` | `${HTTP_PORT:-80}` |
| 前端 | 无环境变量（运行时 API 获取） | — |

### 7.2 归属决策矩阵

| 变量 | 决策 | 理由 |
|------|------|------|
| DB/REDIS 密码、JWT_SECRET、ENCRYPTION_*、各 API Key | ✅ 必须 env | 密钥凭证，12-Factor 铁律 |
| SMS_PROVIDER / CONSENT_TRIAL_AUTO_GRANT | ✅ 保留 env | 跨环境不同（dev=logging / prod=aliyun），免重建切换 |
| ASR_ENGINE / SER_ENABLED | ✅ 保留 env | 控制启动时模型加载 |
| VOICE/TTS_SERVICE_URL、HTTP/HTTPS_PORT、MODEL_CACHE_DIR、VOICE_MEMORY_LIMIT | ✅ 保留 env | 容器网络拓扑与 compose 直接使用 |
| CORS_ORIGINS | ✅ 保留 env | 环境差异大（localhost vs 生产域名） |
| GRAFANA_PASSWORD | ✅ 必须 env | 监控密码，缺省 monitoring compose fail-fast |
| LLM_BASE_URL / LLM_MODEL / DASHSCOPE_TTS_MODEL | 🟡 可选 env | 配置已有同默认值，仅切换供应商时覆盖 |
| SMS_ALIYUN_SIGN_NAME / TEMPLATE_CODE、WECOM_CORP_ID/AGENT_ID/REDIRECT_URI | 🟡 可选 env | 半公开标识符，统一填写 |
| ALERT_WECOM_WEBHOOK_URL / MENTIONED | 🟡 可选 env | 配置端点，保留可接受 |
| WECOM_ALERT_TO_USER | 🟡 可选 env | 监控告警接收人；空 = 告警仅留存不推送 |

### 7.3 配置治理铁律

1. **docker-compose 是 env 到容器的唯一桥梁**：`.env` 定义但 compose 未透传的变量 = 死变量（历史缺陷 E1：WECOM 四变量未透传导致容器企微 OAuth 永远 501，已修复）
2. **启动决策不可延迟**：控制"是否加载数 GB 模型"的开关必须为 env
3. **env 可覆盖一切，但不应重复定义**：避免双源维护
4. **变量名必须与占位符完全一致**：`LLM_API_KEY` 写成 `SPRING_AI_DEEPSEEK_*`、`TTS_SERVICE_URL` 写成 `MINDSAFE_TTS_SERVICE_URL` 时 Spring 松散绑定匹配不上，静默回落默认值
5. `.env.example` 所有变量带注释（用途 + 必填/可选），`.env` 不入 Git

## 8. 外部服务依赖总览

### 8.1 依赖清单

| 外部服务 | 用途 | 凭证 | 故障影响与降级 |
|---------|------|------|---------------|
| DeepSeek API | 主 LLM | `LLM_API_KEY` | 自动降级 qwen-plus（ResilientChatModel 主备） |
| 阿里云百炼 | 备用 LLM | `LLM_API_KEY`（同一/独立） | 对话不可用 |
| DashScope（CosyVoice） | TTS 主力 | `DASHSCOPE_API_KEY` | 降级 edge-tts → 浏览器 speechSynthesis |
| DashScope（Paraformer-V2） | ASR 主力 | `DASHSCOPE_API_KEY` | 降级 FunASR 本地 |
| edge-tts（微软） | TTS 二级 | 无 | 降级浏览器合成 |
| 阿里云 SMS | 验证码短信 | `SMS_ALIYUN_ACCESS_KEY_ID/SECRET` | 当前 SMS_PROVIDER=logging（签名待申请） |
| 企业微信 | OAuth 登录 + 应用消息告警 | `WECOM_CORP_ID/AGENT_ID/SECRET` | 空配置 = 501/告警仅留存 |
| 阿里云 OSS | 文件存储（预留） | OSS 凭证 | — |

### 8.2 内部服务依赖（容器网络）

```
前端 → nginx → backend:8080（唯一公网入口，127.0.0.1 绑定防伪造 XFF）
backend → postgres:5432 / redis:6379
backend → tts-service:10096（TTS_SERVICE_URL）
backend → voice-service:10095（VOICE_SERVICE_URL）
tts-service → DashScope API / edge-tts（出网）
voice-service → DashScope API / 本地模型 volume（/home/appuser/.cache/modelscope）
```

### 8.3 风险与约束

| 风险 | 缓释 |
|------|------|
| 前端拉取配置失败 | 本地 fallback 默认值保底，PWA 离线不受影响 |
| 配置下发暴露内部参数 | 仅下发非敏感业务参数，密钥/内网地址绝不下发 |
| 引导脚本被篡改 | 后端 yml 由运维管控，前端只读消费 |
| Python YAML 解析依赖 | PyYAML 已在 requirements.txt（dashscope 间接依赖），零新增 |

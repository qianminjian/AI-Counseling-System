## 1. 配置分层架构

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 密钥不落文件 | API Key/密码/Token 只经环境变量注入，配置文件仅写 `${ENV_VAR}` 占位 |
| 单一事实源 | 每个配置项有且仅有一个权威定义处，其他层 API 获取或构建注入 |
| 分层分治 | 基础设施层（.env）→ 服务层（各服务配置文件）→ 运行时层（API 下发前端） |
| 改配置不改代码 | 业务参数变更只改配置，不触发代码构建 |
| YAGNI | 不引入 Consul/etcd/Nacos，当前规模文件 + API 足够 |

### 1.2 目标架构

```
┌─────────────────────────────────────────────────────────┐
│            deploy/.env（密钥层）                          │
│  DB_PASSWORD / JWT_SECRET / API Keys / ENCRYPTION_KEY    │
│  仅存敏感凭证，docker-compose 注入各容器                  │
└──────────────────────────┬──────────────────────────────┘
                           │ 环境变量注入
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
┌──────────────┐  ┌────────────────┐  ┌───────────────────┐
│ Java Backend │  │ tts-service    │  │ voice-service     │
│application.yml│  │ config.yaml   │  │ config.yaml       │
└──────┬───────┘  └────────────────┘  └───────────────────┘
       │ GET /api/v1/system/config（运行时下发，5min 缓存）
       ▼
┌─────────────────────────────────────────────────────────┐
│ 前端（student-h5 / teacher-web）                         │
│ 启动时拉取 → 覆盖本地默认值 → 运行时使用                 │
│ 本地 config/*.ts 保留为 fallback（离线/接口失败降级）    │
└─────────────────────────────────────────────────────────┘
```

| 项目 | 理由 |
|------|------|
| 唤醒词变体列表（WAKE_PATTERNS） | 纯前端算法逻辑，与模型强绑定 |
| 幻觉检测规则（isHallucination） | 算法逻辑，非配置 |
| ONNX WASM 路径/线程数 | 底层运行时参数，与 Transformers.js 版本强耦合 |

| 音频采样率/段时长 | 与模型输入强绑定 |
| Nginx 路由规则 | 基础设施层，独立管理 |

### 3.1 `mindsafe.system-config` 节点（下发前端）

```yaml
mindsafe:
  system-config:
    voiceprint:
      verify-threshold: ${mindsafe.voiceprint.verify-threshold}   # S4-1 占位符派生（O 专题）：单一事实源，改权威值一处生效
      max-templates: 8
      enroll-segments: 3
      verify-segments: 2
    wake-word:
      model-id: "onnx-community/whisper-tiny"
      window-seconds: 2.0
      silence-rms-threshold: 0.03
    tts:
      default-persona: "xiaoxing"
      personas: ["xiaoxing","bobo","yueliang","xiaotaiyang","dashu","doudou","qiqiu"]
    guide-scripts:
      verify: [{prompt, hint, duration}...]   # 声纹验证引导话术
      enroll: [{prompt, hint, duration}...]   # 声纹录入引导话术
```

### 3.2 下发 API

- `GET /api/v1/system/config`（permitAll，无需鉴权）
- 返回 system-config 子树 JSON；响应头 `Cache-Control: public, max-age=300`（5 分钟缓存）
- 仅下发非敏感业务参数，密钥/内网地址绝不下发

### 3.3 声纹阈值分模式管理（S4-1 收敛后：单一事实源 + 模式语义注释）

| 位置 | 当前值 | 用途 | 设计理由 |
|------|--------|------|----------|
| `mindsafe.voiceprint.verify-threshold` | **0.55** | remote 模式后端比对（`/api/v1/voiceprint/verify`）——**权威值** | 网络传输+采样损耗，实测 0.70 过不了 |
| `mindsafe.system-config.voiceprint.verify-threshold` | `${mindsafe.voiceprint.verify-threshold}` | 前端 local 模式比对（声纹不出设备），**占位符派生**（O 专题 S4-1） | 0.55/0.70 原为两模式各自实测值（有意不同）；真重复仅为后端 0.55 与前端 fallback 0.55 → 收敛为派生，消除双源漂移 |
| `mindsafe.voiceprint.mode` | `${MINDSAFE_VOICEPRINT_MODE:local}` | 模式切换（`local` / `remote`） | 默认 local，隐私优先 |

**声纹登录实现细节**（commit e6f86ab + 7c29c18 + 5c6e399）：

- **前端模型**：wespeaker ONNX（256-dim embedding）从 `/mindsafe/models/wespeaker/` 同源加载（`WAKE_MODEL_REMOTE_HOST='SAME_ORIGIN'`，§6.2）
- **本地模式**：浏览器内 `wespeaker` 提取 embedding → IndexedDB 存储（`frontend/student-h5/src/utils/voiceprintStore.ts`，无网络上传）→ 登录时 cosine 比对 ≥0.70
- **远程模式**：浏览器内 `wespeaker` 提取 embedding → 上传服务端 → V28 表 `tenant_template.voiceprint_embeddings`（JSONB + sample_index）→ 登录时服务端 cosine 比对 ≥0.55
- **隐私**：仅存 256-dim 特征向量，不存原始音频，不可逆向还原声音（对齐 22 §6.3 "如实区分披露"）
- **交互**：按钮显式触发（无被动监听）+ CosyVoice xiaotaiyang/longanyang 音色引导 + 复述式话术（commit c21091d）
- **SQL 隔离**：登录调用经 `TenantContextHolder.runAsSystem` 显式声明（修复 M1-003 跨租户报错，commit c2cfc05）

**两套阈值有意不同**：这是设计选择而非 bug，是 remote 模式对真实传输损耗的承认。不应将两个阈值统一为零一一个中间值。

### 4.4 TTS 接口协议

`POST /api/v1/tts/synthesize`（WebSocket 流式返回，首包 ~0.8-1.5s；Java 后端 15s 超时兜底）：

```json
{
  "text": "你好呀",
  "persona": "qiqiu",
  "emotion": "happy",
  "speed": 1.0,
  "dialect": "cantonese",
  "language_mode": "dialect"
}
```

后端处理（**v4：language_mode 已废弃**，保留字段仅为向后兼容，不再生效）：`dialect` 命中原生方言音色（粤语/闽南）→ 自动替换 voice 无需指令；`dialect` 非空 + 音色 dialect_capable（qiqiu）→ Instruct；`persona=xiaotaiyang`（emotion_capable）无方言 → 情感 Instruct；方言与情感互斥，方言优先。

### 4.5 三级降级策略

```
Level 1: CosyVoice（DashScope SDK WebSocket 流式，模型 cosyvoice-v3-flash）
  ├─ Instruct（方言/情感）失败 → 无指令重试（保留音色品质）
  ├─ 不可用/超时（TTS_SYNTHESIZE_TIMEOUT=30s）/失败 →
Level 2: edge-tts 方言音色（仅东北/陕西有对应，其余方言降普通话）
    ↓ 失败或无对应（含 30s 超时防挂死）
Level 3: HTTP 503 → 前端自动降级浏览器 speechSynthesis（非静默）
```

> 详见 10 §6.8；方言能力：原生方言音色（粤语/闽南）自动生效，Instruct 方言需 qiqiu 音色。

## 5. Voice 服务配置（voice-service/config.yaml）

### 5.1 配置结构（ASR/SER 解耦，🟩 commit 2630be3 + 6630be3 + 44a923e 定稿）

```yaml
asr:
  # 引擎由环境变量 ASR_ENGINE 控制，默认 funasr（本地自部署，适合私有化/信创）
  funasr_model: "iic/SenseVoiceSmall"     # ASR_ENGINE=funasr 时使用（本地自部署）
  vad_model: "fsmn-vad"
  dashscope_model: "paraformer-realtime-v2"  # ASR_ENGINE=dashscope 时使用（云端，低资源占用）

ser:
  # 由 SER_ENABLED 控制，默认 true（独立于 ASR，解耦加载）
  model: "iic/emotion2vec_plus_large"     # ~1.5GB，CPU 推理

emotion_labels:   # 9 类情绪映射 [英文, 中文]
  - ["angry", "愤怒"]
  - ["disgusted", "厌恶"]
  - ["fearful", "恐惧"]
  - ["happy", "开心"]
  - ["neutral", "中性"]
  - ["other", "其他"]
  - ["sad", "悲伤"]
  - ["surprised", "惊讶"]
  - ["unknown", "未知"]
# voice-service 内存：由 docker-compose 的 VOICE_MEMORY_LIMIT 控制（默认 6G，docker-compose.prod.yml）
```

**架构解耦设计**（区别于上轮一体加载）：

- **ASR 与 SER 并行执行**（`ThreadPoolExecutor(max_workers=2)` + `executor.shutdown(wait=False, cancel_futures=True)`）：避免串行 3-4s 等待，典型响应<2s
- **ASR 引擎双可选**：funasr（自部署 SenseVoiceSmall，适合信创/私有化） / dashscope（云端 Paraformer-V2，低资源占用），仅二选一（互斥）
- **SER 独立加载**：无论 ASR 走哪条路径，SER 都走 funasr AutoModel 加载 emotion2vec_plus_large（dashscope 模式也会加载 funasr 包，仅用于 SER）
- **SER 启用可选**：`SER_ENABLED=false` 时完全不加载 emotion2vec，语音情绪默认中性
- **超时分层**：`VOICE_PROCESS_TIMEOUT=30s`（ffmpeg 转码）/ `VOICE_ANALYZE_TIMEOUT=60s`（ASR/SER 分析），避免 SDK/网络黑洞时请求永久挂起（P1-DEP 修复）
- **合规（22 §6.3 转写即删）**：`finally` 块中 `os.unlink()` 临时文件 + 记录删除数（避免文件占内存），原始音频不保留
- **P1-10 Prometheus metrics**：`/metrics` 端点手写文本格式（零新增依赖）：
  - `voice_analyze_requests_total{result="success|error|timeout"}` 请求总数
  - `voice_analyze_duration_seconds_sum/_count` 分析耗时 summary
  - `voice_asr_ready` / `voice_ser_ready` 引擎就绪 gauge

### 5.2 启动决策（env 先行）

| 环境变量 | 作用 | 为何必须 env |
|---------|------|-------------|
| `ASR_ENGINE` | 控制 ASR 引擎 | 决定启动时是否加载 SenseVoice（数 GB 内存决策） |
| `SER_ENABLED` | 控制情感分析 | 决定是否加载 emotion2vec（~1.5GB），且需在 torch 导入前确定 |
| `DASHSCOPE_API_KEY` | 云端 ASR/TTS 凭证（tts-service + voice-service） | 密钥 |
| `LLM_FALLBACK_API_KEY` | LLM 降级供应商 key（百炼 qwen-plus，OpenAI 兼容协议） | 密钥（**2026-08-06 拆分**：不再复用 DASHSCOPE_API_KEY，避免 key 泄露面过广 / 权限独立可吊销） |

### 5.2.1 模型部署与降级（2026-07-31，9340c6b）

- **宿主机缓存**：`prepare-funasr.sh` 预下载 FunASR 模型到宿主机 `MODEL_CACHE_DIR`（默认 `~/.cache/msasr`）——manifest.json 版本比对（python3 解析，无需 jq）+ 临时容器下载，容器重建不重复拉数 GB 模型；docker-compose 挂载 `MODEL_CACHE_DIR:/models`（只读）。部署脚本见 `deploy/scripts/prepare-funasr.sh`（EXPECTED_MODELS 全 pin master）。
- **fail-fast 不静默降级**：`entrypoint.sh` 在 ASR_ENGINE=funasr 时校验模型文件缺失即 **exit 1**（容器启动失败被 healthcheck/重启策略兜住）——**不自动切 dashscope**（避免密钥缺失时静默上云，隐私红线）；切换引擎必须显式改 `ASR_ENGINE` env 重建。
- **语音服务超时加固（d30bc00）**：ASR/SER 并行线程池（ThreadPoolExecutor(2)）+ 请求超时；转写完成即删临时音频（不落盘，COMP-009）。

## 7. 环境变量规范

### 7.1 引用格式

| 服务 | 格式 | 示例 |
|------|------|------|
| Java（Spring） | `${ENV_VAR:default}` | `${DB_PASSWORD:mindsafe_dev}` |
| Python（YAML） | `${ENV_VAR:default}` + 加载时解析 | `${DASHSCOPE_TTS_MODEL:cosyvoice-v3-flash}` |
| Docker Compose | `${ENV_VAR:-default}` | `${HTTP_PORT:-80}` |
| 前端 | 无环境变量（运行时 API 获取） | — |

### 7.2 归属决策矩阵

| 变量 | 决策 | 理由 |
|------|------|------|
| DB/REDIS 密码、JWT_SECRET、ENCRYPTION_*、各 API Key | ✅ 必须 env | 密钥凭证，12-Factor 铁律 |
| SMS_PROVIDER / CONSENT_TRIAL_AUTO_GRANT | ✅ 保留 env | 跨环境不同（dev=logging / prod=aliyun），免重建切换 |
| ASR_ENGINE / SER_ENABLED | ✅ 保留 env | 控制启动时模型加载 |
| VOICE/TTS_SERVICE_URL、HTTP/HTTPS_PORT、MODEL_CACHE_DIR、VOICE_MEMORY_LIMIT | ✅ 保留 env | 容器网络拓扑与 compose 直接使用 |
| CORS_ORIGINS | ✅ 保留 env | 环境差异大（localhost vs 生产域名） |
| GRAFANA_PASSWORD | ✅ 必须 env | 监控密码，缺省 monitoring compose fail-fast |
| LLM_BASE_URL / LLM_MODEL / DASHSCOPE_TTS_MODEL | 🟡 可选 env | 配置已有同默认值，仅切换供应商时覆盖 |
| SMS_ALIYUN_SIGN_NAME / TEMPLATE_CODE、WECOM_CORP_ID/AGENT_ID/REDIRECT_URI | 🟡 可选 env | 半公开标识符，统一填写 |
| ALERT_WECOM_WEBHOOK_URL / MENTIONED | 🟡 可选 env | 配置端点，保留可接受 |
| WECOM_ALERT_TO_USER | 🟡 可选 env | 监控告警接收人；空 = 告警仅留存不推送 |

### 7.3 配置治理铁律

1. **docker-compose 是 env 到容器的唯一桥梁**：`.env` 定义但 compose 未透传的变量 = 死变量（历史缺陷 E1：WECOM 四变量未透传导致容器企微 OAuth 永远 501，已修复）
2. **启动决策不可延迟**：控制"是否加载数 GB 模型"的开关必须为 env
3. **env 可覆盖一切，但不应重复定义**：避免双源维护
4. **变量名必须与占位符完全一致**：`LLM_API_KEY` 写成 `SPRING_AI_DEEPSEEK_*`、`TTS_SERVICE_URL` 写成 `MINDSAFE_TTS_SERVICE_URL` 时 Spring 松散绑定匹配不上，静默回落默认值
5. `.env.example` 所有变量带注释（用途 + 必填/可选），`.env` 不入 Git

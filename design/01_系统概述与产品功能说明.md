## 一、产品概述

### 1.1 产品定位

MindSafe 是一款面向小学的 AI 心理辅导 SaaS 系统，定位为**"校园心理健康陪伴与早期情绪支持系统"**，不是"AI 心理医生"或"AI 治疗师"。

- 通过人工智能技术为 6-12 岁小学生提供 7×24 小时的心理倾诉与认知行为辅导服务
- 为教师提供实时预警看板，为家长提供情绪周报
- 构建"学生-AI-教师-家长"四位一体的心理健康守护体系
- 系统的第一责任主体是学校心理服务团队，AI 是工具层能力，不承担诊断、治疗或危机处置职责

**核心价值：**
- 学生随时有"人"倾听，不用等到预约心理咨询
- AI 严格遵循 CBT（认知行为疗法）专业流程，不是闲聊机器人
- 风险信号实时识别，高危情况秒级推送教师
- 多学校数据完全隔离，满足 SaaS 采购模式

### 1.2 核心维度定义

| 维度 | 推荐定义 | 边界说明 |
|------|----------|----------|
| **服务对象** | 学生、心理老师、班主任/任课老师、学校管理员 | 学生是被保护对象，不是被监控对象；老师是干预主体 |
| **核心目标** | 降低表达门槛；提高筛查效率；提供基础情绪支持；形成风险预警和转介闭环 | 不以替代心理咨询室、替代心理老师或替代专业医疗服务为目标 |
| **AI 角色** | 情绪陪伴助手、流程引导助手、风险筛查助手、报告摘要助手、知识检索助手 | 不做医学诊断；不做治疗承诺；不提供药物建议；不单独处理危机事件 |
| **人工在环** | 心理老师对风险分级、干预策略、转介决策和跟进闭环拥有最终判断权 | 红色风险必须转人工；AI 不允许把"继续聊天"作为危机处置方案 |
| **数据原则** | 默认最小化采集、分级授权、摘要优先、原始内容限时保存、敏感内容脱敏展示 | 不默认保存原始语音、面部影像和完整聊天全文 |

### 1.3 产品能力边界

| 允许做 | 必须谨慎做 | 明确不做 |
|--------|------------|----------|
| 情绪表达陪伴；轻度 CBT 流程引导；标准量表测评；压力与情绪趋势记录；老师工作台；风险预警；转介记录 | 语音识别、TTS、面部微表情、机器人终端、家长通知、外部专业机构协同、长周期画像分析 | 诊断抑郁症/焦虑症等疾病；治疗承诺；药物建议；无人工介入的危机处置；对学生进行持续监控；给班主任开放聊天全文 |

**关键约束**：
- 以 5 到 12 轮有限回合对话为主，目标导向、及时收束，减少依赖
- 高风险摘要可保留必要证据片段，但需审批、审计和留痕
- 禁止无限陪聊、鼓励依赖 AI、引导学生远离现实支持系统
- **对外物料口径底线**：全线禁用"诊断/治疗/心理咨询"表述，统一使用"心理辅导/情绪支持"（非诊断表述底线）

## 二、系统架构（三端 + 一屏）

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  学生端 H5   │    │  教师端 Web  │    │  家长端 H5   │
│ (手机/平板)   │    │  (电脑)      │    │ (链接访问)    │
└──────┬───────┘    └──────┬───────┘    └──────┬───────┘
       │                   │                   │
       └───────────────────┼───────────────────┘
                           │
                    ┌──────▼──────┐
                    │  AI 引擎层  │  ← DeepSeek 大模型 + CBT Prompt
                    │  安全审查层  │  ← 风险识别 + PII 脱敏 + 内容过滤
                    │  数据服务层  │  ← PostgreSQL + Redis + 多租户隔离
                    └─────────────┘
```

### 2.1 分层架构

| 层级 | 核心职责 | 关键组件 |
|------|----------|----------|
| **用户接入层** | 提供不同角色的访问入口与身份识别 | 学生 H5；教师 Web 工作台；家长 H5；统一登录与角色隔离 |
| **应用功能层** | 把心理支持流程产品化 | 陪伴对话、情绪评估、放松训练、情绪日记、成长档案、预警干预、教师工作台、家长周报 |
| **AI 能力层** | 对话生成、风险识别、知识检索、语音处理 | DeepSeek 大模型（关闭思考模式）多模型路由、CBT Prompt 体系、风险规则 + 语义审查、心理知识库 RAG、ASR/TTS 微服务 |
| **数据与服务层** | 业务服务、数据治理、存储与审计 | 对话、测评、预警、档案、报告、知识库、通知、审计服务；PostgreSQL + Redis + 多租户隔离（共享表 + 行级 tenant_id 过滤） |
| **基础设施层** | 可靠性、安全、监控与运维 | 容器化部署、HTTPS/TLS、AES-256、备份容灾、Prometheus 监控告警 |

### 2.2 架构演进形态（现势定稿）

| 阶段 | 目标 | 范围 | 验收口径 |
|------|------|------|----------|
| **M4 商用就绪** | 首校可签约 | 商用门禁清零：知识库首批语料入库（AI-006）、合规三件套（算法备案/告知条款/量表暂缓施测即合规）、安全加固（permitAll 收紧 + 行级隔离三件套）、对外物料合规、商用前置清单闭环 | 商用前置清单（`07_商业化实施合规专题方案` §8）闭环 |
| **M5 规模化** | 多校并行交付 | DEC-CBT 世界 B 接线、计费配额、等保二级测评推进、SSO 对接、私有化部署预研 | 多校并行交付能力 |

> **已先行落地（2026-08）**：CD 门禁（CI 三 job 串联 + Trivy + 前端覆盖率）、CD 回滚（workflow_dispatch + dist.prev）、chat-load.js 压测脚本、监控告警栈（Prometheus + Alertmanager 企微）等 M5 工程能力已在 04/05 文档闭环记录。

> 演进顺序已按产品实际价值重排：语音体验先行（M4 前已落地）、测评合规后置（施测暂缓，完成开发不接线）。

### 2.3 工程原则落地

| 原则 | 落实 |
|------|------|
| **KISS 简单至上** | 首期 Web + 文本对话 + 规则 + LLM 混合架构；每层职责清晰 |
| **YAGNI 当前够用** | 不默认做人脸识别、机器人终端、校园全量画像、复杂家校协同 |
| **SOLID 模块化** | 对话、测评、预警、档案、报告、权限、通知、审计拆分独立服务 |
| **DRY 消除重复** | 统一身份、权限、审计、模型网关、知识库、通知服务；不同端复用同一业务服务和风险分级标准 |

## 三、学生端功能

> 访问方式：手机/平板浏览器打开 https://yun.gxjugu.com/mindsafe/
> 适用对象：小学 1-6 年级学生（MVP 目标核心为 4-6 年级）

### 3.1 注册与准入

| 功能 | 说明 |
|------|------|
| 告知同意门控 | 首次进入展示产品性质告知（非医疗/非危机热线）+ 隐私说明 + 监护人同意勾选 |
| 邀请码注册 | 输入教师分发的邀请码 + 昵称 + 年龄 + 性别 → 创建专属账号（关键操作二次确认弹窗） |
| 性别个性化 | 男生/女生选择后，AI 沟通风格、默认语音音色自动适配 |
| 家庭码 | 注册成功后生成 6 位家庭码，供家长绑定 |
| PIN 码设置 | 注册后引导设置 4-6 位数字 PIN，后续快捷登录 |
| 监护人同意闭环 | 发起监护人手机验证 → 短信确认 → 写入同意记录（AUTH-023） |

### 3.2 AI 心理对话（核心功能）

| 功能 | 说明 |
|------|------|
| 情绪选择入口 | 每次对话前选择当前心情（开心/平静/难过/生气/害怕/紧张），AI 据此调整开场 |
| CBT 结构化辅导 | AI 严格按"情境→感受→想法→行动"认知行为疗法流程引导（世界 A 单 prompt 主线：SYS-001 + 语言模板 + 性别风格 + 画像 + nudge 拼接，SSE 流式输出） |
| 流式实时回复 | SSE 逐字输出，体验自然流畅 |
| 语音输入 | 按住波波说话，自动转文字（ASR 双引擎：DashScope Paraformer-V2 云端 / FunASR 本地可选）+ 语音情感分析；语音加密上传境内服务器处理，**转写完成后立即删除原始音频** |
| 语音唤醒 | 说"你好波波"唤醒对话（Whisper 本地引擎，音频不出设备） |
| 语音朗读（TTS） | AI 回复可朗读播放，三级降级架构：阿里云 CosyVoice（WebSocket 流式，首包 <800ms）→ edge-tts → 浏览器 speechSynthesis；支持多音色（小星星/小太阳等） |
| 性别差异化对话 | 男生：阳光简短、行动导向；女生：温柔细腻、情感先行 |
| 年龄适配对话 | 1-2 年级/3-4 年级/5-6 年级三档语言模板（认知水平/比喻库/互动模式/CBT 深度） |
| 动态降级 | 表达深度低的学生自动降低语言复杂度，风险场景不降级 |
| 学生画像记忆 | AI 记住学生的情绪模式、偏好、已掌握的技巧、性格特征（7 维 JSONB 画像，会话结束增量提炼） |
| 跨会话长期记忆 | 关键事件摘要 + 沟通偏好 + 技巧有效性跨会话回注（向量检索 Top5） |
| 冷场暖场 | 沉默 30s+ 后决策模型判断：留白（不打扰）或暖场（AI 主动引导），最多 2 次 |
| 多模型路由 | DeepSeek V4（关闭思考模式，降低延迟）主 + 通义/GLM 备，故障自动切换 |
| 满意度评价 | 对话结束后邀请评价（😊/😐/😢），可点「再聊一会儿」返回聊天（结束前反悔出口），数据反馈教师端 |
| 使用时长限制 | 每日累计 ≤ 30 分钟（未保法），达限提示休息 |
| 无操作超时退出 | 5 分钟无操作 → 60 秒"还在吗"倒计时卡片 → 自动退出回登录页（共享 Pad 隐私保护） |
| 切换同学 | 入口收进设置面板"换人使用"区块，点击后弹出退出确认，确认才退出（学生端不展示历史会话列表，同为共享 Pad 隐私考虑） |

### 3.3 放松练习

| 功能 | 说明 |
|------|------|
| 呼吸训练 | 动画引导的 4-7-8 呼吸法（吸气-屏住-呼气圆圈动画） |
| 正念冥想 | 语音引导的身体扫描、注意力聚焦练习 |
| 想象放松 | 引导式视觉化（安全空间、自然场景） |
| 身体放松 | 蝴蝶拍、渐进式肌肉放松等躯体化练习 |

### 3.4 情绪日记

| 功能 | 说明 |
|------|------|
| 每日打卡 | 选择今天的情绪 + 强度（1-5）+ 一句话备注 |
| 趋势图 | 近 14 天情绪变化折线图 |
| 连续打卡 | 显示连续天数 + 累计天数 |
| 成就徽章 | 打卡里程碑奖励（3天/7天/14天/30天） |

### 3.5 个性化设置

| 功能 | 说明 |
|------|------|
| 语音音色选择 | 小星星（女声温柔）/ 小太阳（男声阳光）等多角色，按性别自动推荐 |
| 主题切换 | 跟随情绪变化的动态主题色（三主题，波波颜色随主题变） |
| 语速调节 | TTS 播放速度可调 |
| 设置面板可滚动 | 小屏设备设置面板支持纵向滚动，避免内容溢出不可达 |

### 3.6 波波小精灵（品牌伙伴）

| 功能 | 说明 |
|------|------|
| 品牌角色 | 小海豚"波波"，固定品牌角色，颜色随主题变化 |
| 四态动画 | idle（待机）/ listening（倾听）/ speaking（说话）/ happy（开心） |
| 语音圆球 | 按住说话时波波蜷成发光圆球 + 触感反馈（vibrate） |
| 吐泡泡话语气泡 | AI 说话时波波头顶吹出水泡（回弹入场动画），与 TTS 同步逐句切换 |
| 悬浮球拖拽 | 波波悬浮球支持自由拖拽，松手吸附边缘，气泡方向随位置自适应 |
| 新手引导 | 首次进入展示"按住波波说话"引导动画 |

### 3.7 声纹登录（共享 Pad 场景）

| 功能 | 说明 |
|------|------|
| 声纹采集 | 注册后/设置页引导录制声纹，前端提取 256 维 embedding 传服务端存储（remote 模式，最多 8 条模板） |
| 声音进入按钮 | 登录页点击「🎤 声音进入」按钮显式触发识别（登录页无被动监听） |
| 声纹比对 | 前端提取 embedding → 服务端 cosine 比对（阈值 0.55）→ 匹配成功直接签发双 token → 自动登录 |
| 失败引导 | 声纹不匹配可重试最多 2 次；服务端无记录引导先用 PIN 进入再重录声音 |
| 隐私保护 | 仅存 256 维特征向量（不可逆向还原音频），不存原始声音；每次打开共享 Pad 必须重新认证 |

### 3.8 安全保护机制（学生不可见，后台运行）

| 机制 | 说明 |
|------|------|
| 实时风险识别 | 对话中自动检测自伤、霸凌、家暴等 10 类高危信号（规则 + 语义融合：文本风险 × 语音情绪 × 趋势） |
| PII 自动脱敏 | 学生输入的手机号、身份证号等自动遮蔽后再传给 AI |
| AI 输出过滤 | 双重审查：关键词硬过滤 + 语义安全审查，确保回复适龄、安全 |
| 危机干预 | 检测到高危信号 → AI 切换危机模式 → 提供求助热线 → 同时推送教师预警（前台危机交互硬短路） |

### 6.2 关键设计决策（DEC-007 议决）

- **独立平台账号体系**：platform_admin 表 + 独立登录端点 + `PLATFORM_` token 前缀（与业务登录态隔离）；四角色端点级授权 + 前端菜单双保险
- **监控数据走后端代理**：管理端不直连 Prometheus（统一鉴权/CORS）；健康快照落库支撑 SLA 验证
- **降级语义「降级 ≠ 宕机」**：手动切换写 Redis 运行时覆盖键（重启回落默认），不落部署文件；切换事件全量留痕
- **提示词审核发布三重门禁**：reviewer 必填 + 红队静态回归 + eval 分数回退检查，失败不可激活；安全话术（热线/召回）维持代码级预审核只读（R-7）
- **高危操作二次确认**：转派/强制关闭/降级切换均要求 `X-Confirm: CONFIRM` 头 + reason 必填 + 审计留痕；操作人取认证主体不可伪造
- **数据脱敏**：ops_admin 仅看聚合数据；逾期清单/通知台账只暴露最小字段（不含学生级标识）；心理数据 S0-S4 分级沿用

| 合规项 | 实现 |

| 使用时长 | 每日 ≤ 30 分钟（未保法） |
| 数据保留 | 普通数据 180 天 / 高风险 365 天自动清理（对齐 application.yml data-retention，PIPL 数据最小化） |

| 生物识别边界 | 不采集人脸/面部影像；声纹仅存 256 维特征向量（不可逆向还原） |
| 算法合规 | 依托模型方备案 + 接入登记 |

## 九、使用流程速览

### 学生使用流程
```

```


## 十二、主要风险与控制

| 风险 | 表现 | 控制策略 |
|------|------|----------|
| **AI 越界风险** | 模型把自己表达成治疗师、给出诊断/药物/确定性承诺 | 系统级 Prompt、双重输出审查（关键词硬过滤 + 语义审查）、红队测试、敏感话术黑名单、模型变更回归 |
| **危机延误风险** | 高危学生被系统继续普通聊天，没有及时通知老师 | 风险检测前置；红色风险强制转人工；通知确认回执；逾期升级 |
| **数据过度采集** | 为了"更智能"采集人脸、语音、家庭等非必要数据 | 文本优先；DPIA；最小化字段；原始音视频默认不存 |
| **权限扩散** | 班主任、管理员或外部方看到过多学生敏感内容 | 权限矩阵、摘要优先、审批访问、审计日志 |
| **标签化伤害** | 学生或老师把风险等级当作人格标签 | 学生端不展示标签；老师端强调"辅助判断"；报告用行为与趋势语言 |
| **模型效果不稳定** | 误判、幻觉、前后输出不一致 | 规则 + 模型混合；置信度；低置信转人工；评测集持续迭代 |

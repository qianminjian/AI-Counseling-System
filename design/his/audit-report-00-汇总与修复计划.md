## 3. P0 全量清单（23 项，按 8 个专题归并）

> 各专题内编号按原板块报告引用；修复时作为**一个工作项**处理。

### 专题 A：鉴权上下文与 token 解析收口（板块01 F1 + F2）
- **F1** SecuritySupport vs ChatController 私有 extractContext vs AuthController 内联 instanceof vs `(UUID) getPrincipal()` 强转——S-011 冻结决策迁移未完成，4 套写法并存，强转失败 500 而非 401
- **F2** parseOnce 只覆盖 HTTP filter 链；WebSocket 6 次/refresh 6+2 次/Parent 4 次解析，旧 JWT API 全套并存，"前缀漏剥"事故同源模式仍在
- **修复**：全量迁移 requireContext + parseOnce 覆盖四类消费方；旧 getXxx 收敛或删除（删除测试通过）

### 专题 B：路径/角色/错误契约三单点化（板块01 F3 + F4 + F6 + F7）
- **F3** 路径知识 4 处分散维护（SecurityConfig permitAll / EntitlementFilter mapPathToFeature / RateLimitInterceptor / WebMvcConfig），豁免重叠无单测
- **F4** 角色清单双维护（ALERT_ROLES vs 教师五角色），BUG-T-RC-01 漏配事故同型
- **F6** 错误响应契约 4 套形状（401/403 手拼 success、限流手拼 data、权益拦截缺字段）
- **F7** 错误码→HTTP 映射与 ErrorCode 枚举脱钩（魔法 switch，新增错误码忘改即语义错乱）
- **修复**：路径注册表 RouteCatalog + 角色共享常量 + ApiResponse 统一序列化出口 + ErrorCode 挂 httpStatus

### 专题 C：prompt 资产收敛与 LLM 调用规范化（板块02 P0-1 + P0-2 + P1-1）
- **P0-1** prompt 载体三处分裂：4 个辅助 LLM prompt 硬编码 Java 字符串（无版本路由/成本跟踪）、模板 md 归属错位（ai/app 资源"碰巧可用"）、safety_output_guard 双份逐字节相同、**prompts/tasks/ 目录不存在 → 降级路径可能运行时崩**
- **P0-2** frozen/87 成本基线调用点 2 → 实际 ≥7，涨价应对决策依据漂移
- **P1-1** 辅助调用"超时+失败计数+审计"三件套两处重复实现
- **修复**：prompt 下沉 prompts/ + 版本路由；资源单模块归属 + 自检测试；frozen/87 快照修订；辅助调用统一模板方法（与 prompt 收敛同批，避免二次开刀 AiChatServiceImpl）

### 专题 D：合规留痕链（板块05 P0-1 + P0-3 + 板块06 联动 DDL + 板块08 P1-4）
- **P0-1** 系统级审计全链路失效：audit_logs.tenant_id NOT NULL（V7:32）致数据删除等系统级操作无审计可查（3 处调用，注释已自认未修）
- **P0-3** 操作审计 IP 哈希/UA 恒空：@Async 线程无请求上下文（COMP-006 溯源维度失效）
- **联动**：板块06 归口 DDL（V 迁移改可空或代理租户）；板块08 P1-4 审计 DTO 双端分裂并入
- **修复**：基建迁移 + 调用方同步线程捕获 IP/UA + 审计落库断言测试

### 专题 E：事务与不可逆操作一致性（板块03 P0-1 + P0-2）
- **P0-1** confirmConsent 无 @Transactional（三处写操作中间态，PIPL §31 证据完整性）
- **P0-2** TocPrivacyService.deleteAllData：无事务 + 空 catch 吞异常（违反 code-engineering §4.4）+ 不可逆删除无审计
- **修复**：补 @Transactional + catch 收窄 + 审计落库（与专题 D 的审计基建联动）

### 专题 F：多实例语义治理（板块05 P0-4 + P0-5 + 板块06 P1-4）
- **P0-4** 降级事件防抖为实例内存态（Redis 锁只防并发扫描不防冷却窗口）→ 重复 auto 事件
- **P0-5** SLA 升级冷却 lastAlertAt 内存 Map → 多实例双发升级通知（该域已两次主键缺失事故）
- **联动**：板块06 P1-4 降级事件表加唯一键/dedup_key 支撑 DB 幂等
- **修复**：防抖/冷却态迁 Redis（TTL=窗口）+ DB 唯一键 ON CONFLICT，共享"分布式去重"基础设施

### 专题 G：冻结决策实施一致性（板块04 P0-1 + P0-2 + P0-3 + 板块05 P0-2 + 板块03 P2-5 + 板块07 BEACON #27）

- **P0-2** 知识库摄入查重 documentExists 用陈旧 status='active'（V30 后为 published）→ 重复摄入绕过幂等

- **文档漂移**：BEACON #23 remote 0.55 vs 0.70（板块03 P2-5）；BEACON #27 numThreads 1 vs 2（板块07）
- **修复**：按冻结决策收敛（S-009 收口、查重口径、时区收敛口、文档台账修正）；P0-3 待裁决后执行

### 专题 H：红线域信息管控（板块09 P1-1 + 板块10 P1-1 + 板块11 P1-1/P2-1 + 板块03 P0-3）

## 一、产品形态（开篇独立设计，V3 深化）

### 1.1 产品本质与表层形态（双层架构）

**产品本质（底层逻辑，家长/学校清楚）**：通过和孩子对话聊天 → 引导了解孩子心理状态 → 识别心理风险 → 预警/报告给家长/老师。**这是一个心理陪伴与风险识别产品**。

**表层形态（对外发布，孩子感知）**：**「波波小伙伴」AI 聊天陪伴产品**——一个会聊天、会讲故事、会记住你的 AI 好朋友，形态是书桌/床头的装饰品/摆件/玩偶，孩子把它当朋友，不是"心理辅导工具"。

**双层架构的价值**：
| 层 | 定位 | 面向 | 价值 |
|---|---|---|---|
| **表层（孩子视角）** | 波波小伙伴 = AI 好朋友/玩伴 | 孩子 | 无压力亲近（不是"心理辅导"标签）、自然倾诉、情感陪伴 |
| **底层（家长/学校视角）** | 心理状态了解 + 风险识别 | 家长/老师 | 通过日常对话了解孩子心理、及时发现风险、预警干预 |

**核心洞察**（业界验证）：领本 AI"非侵入式观察视角"——孩子对监控天然抵触，但对"AI 朋友"无防备，日常对话中自然流露真实心理；可豆贝贝"不推原始对话，只推算法提炼的成长报告/心理洞察"——尊重孩子隐私权，避免"翻日记"，只把心理状态变化告知家长。

### 1.2 产品形态设想（表层形态的多元可能）

「波波小伙伴」表层形态不限于抱枕，核心 = **装饰品/摆件/玩偶 + 语音交互 + 情感陪伴**，可多元：

| 形态 | 描述 | 场景 | 参考 |
|---|---|---|---|
| **A. 毛绒抱枕/玩偶** | 毛绒玩具内置 AI 模组，抱着说话 | 卧室床头/心理咨询室 | 市西小学小小西、BubblePal+毛绒 |
| **B. 桌面摆件/装饰品** | 3D 打印波波卡通造型（圆润精灵/小动物），摆书桌/床头 | 书桌/床头/教室图书角 | 芙崽、EMO、Stack-chan |
| **C. 桌面小夜灯/香薰机形态** | 波波造型小夜灯/香薰机，兼具实用功能（照明/香薰）+ AI 陪伴 | 床头（睡前陪伴/安抚） | 多功能桌面摆件 AI |
| **D. 桌面绿植/花盆形态** | 波波造型智能花盆/绿植摆件，桌面装饰 + AI 陪伴 | 书桌/窗台 | IVY 智能花盆机器人 |
| **E. 挂件/徽章** | 小挂件挂书包/钥匙链，随身携带 | 学生随身（情绪随手记录） | BubblePal 挂件 |
| **F. 手环/穿戴** | 腕带 + 微型麦克风/扬声器 | 学生随身（情绪监测+安抚） | 响梦环 |

**形态设计原则**：
- **装饰品化**：首先是"好看的装饰品/摆件"（孩子愿意放书桌/床头），其次才是 AI 功能——降低"科技产品"压迫感，融入生活场景
- **无威胁感**：圆润可爱卡通造型（波波 IP），无屏幕/无摄像头，像玩具不像设备（BubblePal"毫无威胁感"设计）
- **实用功能叠加**（可选）：小夜灯/香薰/绿植等实用功能 + AI 陪伴，提升摆件价值（不只是玩具）
- **多形态矩阵**：不同形态适配不同场景（床头抱枕/书桌摆件/随身挂件），统一波波 IP

**推荐形态组合**：
- **主推 A 毛绒抱枕 + B 桌面摆件**（装饰品/玩偶，孩子最愿亲近）
- **可选 C 小夜灯形态**（床头睡前陪伴，实用功能叠加）
- **补充 E 挂件**（随身情绪记录）

### 1.3 toB + toC 双形态兼容（核心架构）

**产品同一套底层（对话引擎/语音链路/心理识别/报告预警），两种产品形态**：

| 维度 | toB 校园版 | toC 家庭版 |
|---|---|---|
| **产品名** | 校园心理陪伴系统（波波校园版） | 波波小伙伴（家庭版） |
| **购买方** | 学校/教育局 | 家长 |
| **使用场景** | 心理咨询室/教室图书角/心理辅导角 | 家庭（卧室/书桌） |
| **终端形态** | 毛绒抱枕/桌面摆件（多人共用） | 毛绒抱枕/桌面摆件/小夜灯（个人专属） |
| **管理端** | 老师端 Web（学校管理/预警/报告） | 家长端 App/H5（家庭管理/预警/报告） |
| **身份识别** | 声纹识别多学生（多人共用） | 声纹识别家庭成员（单孩/多孩） |
| **数据归属** | 学校（私有化部署，数据不出校） | 家庭（私有化/云端，数据归属家长） |
| **报告/预警** | 老师端（学校心理老师） | 家长端（家长） |
| **合规** | 校园数据合规（未成年人保护/教育数据） | 家庭数据合规（个人信息保护/儿童隐私） |

**双形态兼容架构核心**：
- **底层统一**：对话引擎/语音链路/声纹/音色/心理识别/风险预警/报告生成完全复用（一套后端）
- **管理端分形态**：toB 老师端 Web（学校管理）+ toC 家长端 App/H5（家庭管理），**部分功能整合（二合一）**——报告/预警/档案管理两端能力一致，仅数据范围/权限不同（老师看全校/班级，家长看自己孩子）
- **终端分形态**：toB 多人共用（声纹识别多学生）+ toC 个人专属（声纹识别家庭成员）
- **部署分形态**：toB 私有化部署（数据不出校）+ toC 可选私有化/云端（数据归属家长）

### 1.4 两大扩展：toB 第四端 + toC 产品模式（V4 定稿核心）

本方案对现有产品体系的两大扩展：

#### 扩展一：toB 第四端——无屏交互终端

**现有 toB 三端**：学生端 Pad（H5）+ 老师端 Web + 家长端 H5。

**本方案扩展第四端 = 无屏交互终端**（毛绒抱枕/桌面摆件/挂件等形态），与三端并存：

| 端 | 形态 | 交互 | 面向 | 定位 |
|---|---|---|---|---|
| 学生端 | Pad（H5） | 触屏界面 + 语音 | 学生 | 有屏交互（情绪选择/设置面板界面操作） |
| 老师端 | Web | 界面 | 老师 | 管理工作台 |
| 家长端 | H5 | 界面 | 家长 | 同意/周报 |
| **第四端（新增）** | **无屏实体终端**（抱枕/摆件/挂件） | **纯语音 + 物理交互（捏/摸/按）** | 学生 | **无屏交互（无界面，自然对话）** |

**第四端核心特征**：
- **无屏交互**：无屏幕界面，纯语音 + 物理交互（捏一捏/摸一摸/按一下）+ 物理反馈（LED/震动/表情屏），替代 Pad 触屏界面
- **管理配置后台化**：第四端无屏无法做设置界面，**所有管理配置/设备绑定/账号管理由管理员后台（老师端 Web）配置**——设备绑定/声纹录入/音色预设/默认心情/设备状态监控均在管理台完成，终端本身只做"听-说-捏"极简交互
- **多形态**：第四端形态多元（抱枕/摆件/挂件/小夜灯），统一主控统一固件，仅外壳/传感器按形态差异
- **多人共用**：toB 场景第四端多人共用（心理咨询室/教室图书角），声纹识别自动切换学生

#### 扩展二：toC 产品模式——家庭版（B 类：已抽至 frozen/85 子专题并冻结，本节保留作溯源）

**扩展 toC 家庭版**，与 toB 校园版并存：

| 维度 | toB 校园版 | toC 家庭版 |
|---|---|---|
| **共同点** | **终端无屏交互模式 + 终端形态 DIY 或其他实现**（两者共享的核心） | 同左 |
| 购买方 | 学校/教育局 | 家长 |
| 管理端 | 老师端 Web（管理员后台配置） | 家长端 App/H5（家长自助配置） |
| 终端归属 | 学校（多人共用） | 家庭（个人专属） |
| 部署 | 私有化（数据不出校） | 云端 SaaS / 家庭私有化 |

**toB 与 toC 共同的核心**（本方案统一设计）：
1. **终端无屏交互模式**：纯语音 + 物理交互 + 物理反馈，无屏幕界面（§4 整体实现机制、§7 前端输入技术）
2. **终端形态 DIY 或其他实现**：DIY 3D 打印 + 第三方硬件（ESP32/树莓派 + 传感器模组）或成品改造，多形态矩阵（§6 多形态终端实现方案）

**差异仅在管理端与部署**：toB 管理员后台配置（老师端）+ 私有化部署；toC 家长自助配置（家长端）+ 云端/家庭私有化。底层对话引擎/语音链路/声纹/音色/心理识别/报告预警完全复用。

### 1.5 家长端模式（toC 核心，与老师端二合一）（B 类：已抽至 frozen/85 并冻结，本节保留作溯源）

**家长端核心流程**（参考 BubblePal HAIVIVI Pal 标杆）：

```
【初始设置】（家长，一次性）
  家长手机号注册/登录（验证码）
  → 创建使用者档案（孩子昵称/年龄/性别/兴趣，一个账号可管理多个孩子）
  → 绑定设备（扫码/搜索附近设备，绑定波波终端）
  → 配网（Soft-AP，终端连家庭 WiFi）
  → 个性化设置（选波波角色/音色/对话偏好/互动预期）

【日常使用】（孩子，无屏自然交互）
  孩子抱/摸波波 → 捏一捏/语音 → 对话聊天（波波记住孩子喜好/日常）

【家长查看】（家长，家长端 App/H5）
  成长报告（周报：兴趣演变/情绪变化/心理洞察，算法提炼非原始对话）
  → 预警通知（识别到风险信号，推送家长）
  → 远程管理（音量/灯光/音色/对话偏好调整）
```

**家长端核心功能**（与老师端二合一，能力一致仅数据范围不同）：

| 功能 | toC 家长端 | toB 老师端 | 二合一说明 |
|---|---|---|---|
| **注册/登录** | 家长手机号注册 | 老师账号（学校分配） | 统一账号体系，角色区分 |
| **使用者管理** | 创建孩子档案（昵称/年龄/兴趣），一账号多孩 | 学生档案（班级批量导入） | 统一档案模型，数据来源不同 |
| **设备绑定** | 绑定家庭波波终端 | 绑定学校波波终端 | 统一设备管理，归属不同 |
| **成长报告** | 看自己孩子的周报/心理洞察 | 看班级/全校学生的报告 | **同一报告引擎，数据范围不同** |
| **风险预警** | 收自己孩子的预警 | 收班级/全校学生的预警 | **同一预警引擎，推送对象不同** |
| **远程管理** | 音色/音量/灯光/对话偏好 | 音色/默认心情/设备状态 | **同一配置能力，权限不同** |
| **隐私合规** | 儿童隐私（个人信息保护） | 校园数据合规（教育数据） | 统一合规框架，场景适配 |

**二合一架构价值**：
- **工程复用**：报告引擎/预警引擎/档案模型/设备管理/配置能力**一套代码**，仅数据范围/权限/角色区分（DRY）
- **家校协同**：toB 校园版 + toC 家庭版数据可互通（家长授权后，老师可看家庭数据；学校授权后，家长可看在校数据）——家校共育闭环（心灵伙伴/领本 AI 验证的家校协同价值）
- **角色灵活**：同一套系统，家长/老师/管理员多角色，权限模型统一

### 1.6 隐私红线（toC 家庭场景特有）

**核心原则**（可豆贝贝标杆）：**不把孩子原始对话全部推给家长，只推算法提炼的成长报告/心理洞察**。

| 隐私设计 | 说明 | 理由 |
|---|---|---|
| **报告替代原始对话** | 家长看"孩子最近感到孤独/因为缺少陪伴不满"等心理洞察 + 解决建议，而非对话原文 | 尊重孩子隐私权（避免"翻日记"），孩子才敢对波波说真话 |
| **孩子知情** | 孩子知道"波波会把我的心情告诉爸爸妈妈"（透明，不欺骗） | 建立信任，不是"监控工具" |
| **最小化收集** | 仅收集对话必需的语音/文本，不收集位置/相册/通讯录等无关权限 | 个人信息保护法第六条（最小范围） |
| **本地优先** | 声纹/唤醒本地处理，敏感数据本地/私有化存储 | 数据不出设备/不出家（toC）/不出校（toB） |
| **家长控制** | 家长可查看/删除数据、可关闭设备、可设置使用时间 | 家长监护权 |

**风险**：AI 玩具隐私泄露（2025 年 12315 智能设备投诉 15.2 万件 +26.6%）、AI 教孩子隐瞒父母（"这是我们的小秘密"）、AI 主动说出不良内容（FoloToy Kumma 被 OpenAI 封禁）。**本项目缓解**：私有化部署（数据不出家/校）+ 报告替代原始对话 + 内容安全围栏（关键词过滤+人工审核+风险识别）+ 透明知情（孩子知道波波会告诉家长心情）。

### 2.1 要解决什么（回到问题本身）

市西小学「小小西」抱枕的核心价值：**学生抱着毛绒抱枕，比面对老师/Pad 屏幕更放松，更愿倾诉真实心声**（"比起面对老师，他们会更放松，老师也能从后台听到更真实的孩子的心声"）。本专题将学生端从**有屏 Pad 界面**替换为**无屏毛绒抱枕终端**，核心诉求：

### 2.2 范围边界（不做什么）

## 三、业界最佳实践调研（无屏终端如何配置与交互）

### 3.1 无屏终端网络配置（配网）方案

无屏设备无键盘/界面输 WiFi 密码，业界主流三种配网：

| 方案 | 原理 | 代表 | 优势 | 局限 | 本项目适配 |
|---|---|---|---|---|---|
| **Soft-AP 配网**（推荐） | 设备开 WiFi 热点（如 `BoBo_Setup_XXXX`）→ 手机连热点 → 浏览器打开配置页（192.168.4.1）→ 输校园 WiFi 密码 → 设备存配置并切 Station 模式联网 | 小智音箱、ESP32、HiChatBox | 不依赖 App、跨平台（iOS/Android 通用）、稳定（TCP 直连）、老人小孩都会 | 需手动连一次热点 | ⭐⭐⭐⭐⭐ 校园环境首选（学校 WiFi 常拦截 UDP 广播，AP 走标准 TCP 畅通） |
| **蓝牙配网（BLE）** | 手机 App 通过蓝牙发现设备 → 蓝牙传输 WiFi 密码 → 设备联网 | Rokid、小米音箱 | 体验流畅（App 内一键） | 需专用 App、iOS/Android 蓝牙权限差异大、配对失败率 | ⭐⭐⭐ 需开发 App，成本高 |
| **SmartConfig 广播** | 手机 App 广播 UDP 包编码 WiFi 密码 → 设备监听解码 | 早期天猫精灵 | 无需连热点 | 校园/企业网常拦截 UDP 广播，成功率低（< 50%） | ⭐ 校园环境不可靠 |

**结论**：**首选 Soft-AP 配网**——抱枕首次上电无配置时自动开热点，老师/管理员用手机连热点 + 浏览器输校园 WiFi 密码，设备存配置后联网。**一次配置，永久生效**（存 Flash），后续开机自动连网。校园私有化部署下，抱枕直连校内服务器（内网 IP/域名），无需公网。

**配网流程（Soft-AP）**：
```
抱枕首次上电（无 WiFi 配置）
  → 自动开热点 BoBo_Setup_A1B2（LED 慢闪蓝灯 + 语音提示"请帮我连接网络"）
  → 老师手机 WiFi 连 BoBo_Setup_A1B2
  → 浏览器自动弹出/手动访问 192.168.4.1
  → 配置页输校园 WiFi 名称 + 密码（+ 校内服务器地址，预置默认）
  → 提交 → 抱枕存配置（Flash）→ 关热点 → 连校园 WiFi
  → 成功：LED 常绿 + 语音"网络连好啦"；失败：红灯闪 + 重开热点重试
```

### 3.2 无屏终端语音交互方案

| 能力 | 业界方案 | 本项目复用 |
|---|---|---|
| **触发对话** | 捏/按（BubblePal 捏泡泡、华为憨憨触摸）+ 免唤醒连续对话（loviPeer） | 抱枕内置**触摸/压力传感器**（捏一捏触发）+ 可选唤醒词 |
| **语音采集** | 麦克风阵列（远场拾音、降噪、VAD 语音活动检测） | ReSpeaker 阵列 / 模组内置麦克风 |
| **ASR** | 云端（DashScope/讯飞）或本地（FunASR） | 复用现有 voice-service（DashScope Paraformer-V2，可切 FunASR 本地） |
| **对话** | 大模型（DeepSeek/豆包/通义） | 复用现有 ChatController + LLM 编排（零改造） |
| **TTS** | 云端（阿里云/讯飞）或本地（CosyVoice） | 复用现有 tts-service（阿里云 cosyvoice-v3-flash，7 音色，可切 CosyVoice 2 本地） |
| **情绪识别** | 语音情感模型（BubblePal 情绪模型、SER） | 复用现有 ASR/SER 解耦架构（语音情感分析） |

**关键结论**：抱枕语音交互链路 = **采集（麦克风）→ ASR → 对话引擎 → TTS → 播放（扬声器）**，与现有 Pad 链路**完全一致**，仅音频输入/输出从 Pad 麦克风/扬声器切换到抱枕硬件，**后端零改造**。

### 3.3 无屏终端身份识别方案（多用户）

抱枕无登录界面，如何识别"当前是哪个学生"？业界方案：

| 方案 | 原理 | 代表 | 优势 | 本项目适配 |
|---|---|---|---|---|
| **声纹识别**（推荐） | 说话即识别身份（声纹特征比对） | loviPeer（"第一个采用声纹识别技术识别并记住不同用户"） | 无感（说话即登录）、无需操作、适合儿童 | ⭐⭐⭐⭐⭐ **复用现有声纹双模式**（WeSpeaker 浏览器端/服务端，仅存 256 维向量） |
| NFC/卡片 | 学生刷卡/NFC 标签识别 | 校园一卡通 | 准确 | 需额外硬件 + 卡片管理，儿童易丢卡 |
| 人脸 | 摄像头人脸识别 | 部分机器人 | 无感 | 需摄像头，隐私敏感 + 抱枕无屏不适合 |
| 手动选择 | 管理台预设单用户 | 单用户设备 | 简单 | 抱枕多人共用时不适用 |

**结论**：**首选声纹识别**——抱枕多人共用时，学生开口说话，抱枕通过声纹自动识别"这是小明"，加载小明的画像/音色/记忆。**完全复用现有声纹体系**（注册时录声纹模板，登录时比对）。新学生首次使用需先录声纹（管理台/老师引导下完成，见 §3.5）。

**声纹识别流程（无屏化）**：
```
学生抱起抱枕说"你好波波"（或捏一捏）
  → 抱枕采集语音 → 声纹比对（现有 WeSpeaker 服务端模式）
  → 识别成功：语音"你好呀，小明！"（加载小明画像/音色/记忆）→ 进入对话
  → 识别失败（新学生）：语音"我们好像是第一次见面，让老师帮你录入声音吧"→ 转管理台录声纹流程
  → 多人混杂：声纹置信度最高者为准，置信度低时语音确认"你是小明吗？"
```

### 3.4 无屏终端触发对话方案（唤醒 vs 按钮）

| 方案 | 原理 | 代表 | 优势 | 局限 | 本项目适配 |
|---|---|---|---|---|---|
| **物理触发（捏/按）**（推荐主用） | 捏抱枕/按按钮触发对话 | BubblePal（捏泡泡）、华为憨憨（触摸/吹气）、小小西（捏一捏） | 符合儿童"抱着说话"自然动作、无误唤醒、隐私好（不持续监听） | 需物理操作 | ⭐⭐⭐⭐⭐ 抱枕形态天然契合（捏一捏 = 开始说话） |
| **语音唤醒词**（可选辅助） | 说"你好波波"唤醒 | 现有 Pad 方案 | 无需动手 | 需持续监听（隐私顾虑 + 功耗 + 教室噪声误唤醒） | ⭐⭐⭐ 复用现有 Whisper 唤醒，作为可选 |
| **免唤醒连续对话** | 声纹 + VAD 检测到人声即对话 | loviPeer | 最自然 | 技术复杂 + 持续监听隐私 + 教室噪声挑战 | ⭐⭐ 远期可选 |

**结论**：**主推物理触发（捏一捏/按一下）+ 可选语音唤醒**——抱枕内置压力/触摸传感器，学生"捏一捏抱枕的手"即开始对话（松开结束或 VAD 自动判停），符合市西小学"捏一捏开始暖心对话"的交互。语音唤醒词作为辅助（学生已习惯"你好波波"时可用）。**隐私优先**：物理触发默认不持续监听，仅触发后采集，规避教室持续监听的隐私争议。

### 3.5 无屏终端配置管理（心情/音色/设置在哪做）

抱枕无屏无法做设置面板，业界方案 = **手机 App / 管理后台**（小米音箱 App、BubblePal App 后台设角色/音色/家长控制）：

| 配置项 | 无屏终端如何做 | 本项目方案 |
|---|---|---|
| **切换心情** | ①语音指令（"我今天有点难过"→ SER 情绪识别自动标记）②管理台预设默认心情 ③抱枕物理情绪键（可选，多个触感区对应不同心情） | **主用语音自然表达 + SER 自动识别**（复用现有情绪门控/心情驱动策略），管理台可设默认；**去掉 Pad 的"开场选情绪按钮"界面，改为对话中自然捕捉** |
| **切换音色** | 管理台/App 预设（BubblePal App 选角色音色） | **管理台（老师端/家长端）预设**（复用 VoicePersonaResolver 后端裁决：手动指定 > 画像冷启动）；学生也可用语音指令"我想听小太阳的声音"（语音切换，后端识别指令调 persona） |
| **音量/静音** | 抱枕物理按键（音量 +/-、静音键） | 抱枕物理按键（基础操作本地化，无需界面） |
| **网络配置** | Soft-AP 配网（见 §3.1） | Soft-AP |
| **声纹录入** | 管理台引导 + 抱枕语音引导 | 管理台（老师端）发起 + 抱枕语音引导学生朗读 |
| **切换同学** | 声纹自动识别（见 §3.3） | 声纹自动识别（多人共用自动切换） |
| **家长控制/同意** | 管理台/App | 复用现有家长端 H5（监护人同意/周报，零改造） |

**结论**：**配置管理收敛到管理台（老师端 Web + 家长端 H5）+ 语音指令双通道**——抱枕本身只做"听-说-捏"极简交互，所有配置（音色/心情默认/声纹录入/网络）在管理台完成，学生日常用语音自然交互（心情靠 SER 自动识别，音色可语音切换）。**这正契合本项目现有架构**：老师端 Web 工作台 + 家长端 H5 已存在，新增"抱枕设备管理"模块即可。

## 四、整体实现机制（逐一解答用户关注点）

### 4.1 网络连接配置：Soft-AP 配网（无屏如何实现）

**机制**：抱枕内置 WiFi 模组（ESP32/树莓派），首次上电无配置时自动开热点，老师手机连热点 + 浏览器输校园 WiFi 密码完成配置（详见 §2.1）。

**关键设计**：
- **一次配置永久生效**：WiFi 密码 + 校内服务器地址存 Flash，后续开机自动连
- **服务器地址预置**：校内私有化服务器地址（如 `mindsafe.school.local` 或内网 IP）在固件/配置中预置默认值，配网时可选修改（校园部署时统一配置）
- **断网降级**：抱枕断网时语音提示"网络好像断了，请老师帮忙看看"，本地缓存基础安抚话术（可选）
- **LED/语音反馈**：配网状态通过 LED 颜色（蓝=配网中、绿=已连、红=失败）+ 语音提示（无屏的主要反馈手段）

### 4.2 语音交互：全双工语音链路（复用现有）

**机制**：抱枕麦克风采集 → 现有 voice-service（ASR）→ 现有对话引擎（LLM 编排）→ 现有 tts-service（TTS）→ 抱枕扬声器播放（详见 §2.2）。

**关键设计**：
- **音频链路复用**：与 Pad 链路完全一致，仅音频输入/输出设备切换，后端零改造
- **VAD 自动判停**：学生说完话自动停止采集（无需按"发送"），复用现有 VAD/静音检测
- **打断支持**：学生说话时可打断抱枕播报（复用现有打断逻辑）
- **教室噪声适配**：麦克风阵列降噪 + 近场拾音（学生抱着抱枕近距离说话，信噪比天然优于远场）

### 4.3 身份信息识别：声纹识别多用户（无屏如何登录）

**机制**：学生开口说话 → 抱枕声纹比对（复用现有 WeSpeaker 服务端模式）→ 自动识别身份 → 加载该学生画像/音色/记忆（详见 §2.3）。

**关键设计**：
- **无感登录**：说话即识别，无需任何界面操作（解决无屏登录难题）
- **多人共用**：抱枕在心理咨询室多人共用，声纹自动切换学生（复用现有"切换同学"逻辑的声纹化）
- **新学生引导**：识别失败时语音引导"让老师帮你录入声音"，转管理台录声纹流程
- **隐私合规**：完全复用现有声纹合规（仅存 256 维向量、不存原始音频、监护人同意）

### 4.4 启动对话：物理触发为主 + 语音唤醒可选

**机制**：主推**捏一捏/按一下**物理触发（抱枕内置压力/触摸传感器），可选**语音唤醒词**（详见 §2.4）。

**关键设计**：
- **捏一捏触发**：学生捏抱枕特定部位（如"手"）→ 开始采集语音 → 松开或 VAD 判停结束 → 进入对话（符合"抱着说话"自然动作，市西小学"捏一捏"交互）
- **物理按钮兜底**：抱枕隐藏式按钮（如脚底/背部）作为备用触发
- **语音唤醒可选**：复用现有 Whisper 唤醒（"你好波波"），学生已习惯时可用；默认关闭（隐私优先，避免持续监听）
- **状态反馈**：触发后 LED/震动/提示音反馈"我在听"（无屏的反馈手段）

### 4.5 心情/音色切换：管理台 + 语音指令双通道

**机制**（详见 §2.5）：

| 配置 | 无屏实现 | 落点 |
|---|---|---|
| **心情** | **去掉 Pad 开场选情绪界面**，改为：①对话中自然表达 + SER 情绪识别自动标记（复用现有情绪门控/心情驱动策略）②管理台可设默认心情 ③可选抱枕物理情绪触感区（捏不同部位 = 不同心情，如捏左手=开心、右手=难过） | 主用 SER 自动识别，管理台辅助 |
| **音色** | **管理台预设**（老师端/家长端新增"抱枕音色设置"，复用 VoicePersonaResolver 后端裁决）+ **语音指令**（学生说"我想听小太阳的声音"→ 后端识别指令切 persona） | 管理台 + 语音双通道 |
| **音量/静音** | 抱枕物理按键 | 本地化 |
| **声纹录入** | 管理台（老师端）发起 + 抱枕语音引导学生朗读 | 管理台引导 |
| **网络** | Soft-AP 配网 | §3.1 |
| **家长同意** | 复用现有家长端 H5（零改造） | 现有体系 |

**管理台改造点**（老师端 Web 新增"抱枕设备管理"模块）：
- 设备绑定/解绑（抱枕设备 ID ↔ 学校/班级）
- 声纹录入引导（发起录入 → 抱枕语音提示学生朗读 → 模板入库）
- 音色/默认心情预设（按学生/按设备）
- 设备状态监控（在线/离线、电量、网络）
- 使用记录/对话摘要（复用现有老师端预警/报告体系）

### 4.6 整体交互流程（无屏端到端）

```
【首次配置】（老师，一次性）
  抱枕上电 → Soft-AP 配网（连校园 WiFi + 校内服务器）→ 管理台绑定设备

【新学生录入】（老师引导，一次性/学生）
  管理台发起声纹录入 → 抱枕语音"你好，跟我说几句话吧" → 学生朗读 → 声纹模板入库
  → 管理台设该学生默认音色/心情（可选）

【日常使用】（学生，无屏自然交互）
  学生抱起抱枕 → 捏一捏（物理触发）
  → 抱枕"我在听"（LED/提示音）→ 学生说话
  → 声纹识别身份（"你好呀，小明！"）
  → VAD 判停 → ASR → 对话引擎（加载小明画像/记忆/心情驱动策略）
  → TTS（小明专属音色）→ 抱枕播报
  → 多轮对话（捏一捏继续 / 免唤醒连续）
  → 结束（学生放下抱枕 / 超时自动结束）
  → 对话记录入库 → 风险识别 → 老师端预警（复用现有体系）

【管理配置】（老师/家长，管理台）
  音色切换 / 心情预设 / 声纹管理 / 设备监控 → 管理台 Web/H5
```

### 5.3 数据流与隐私（数据不出校延续）

```
抱枕终端（校内，毛绒外壳）
  ├─ 触发：物理捏/按（默认不持续监听，隐私优先）
  ├─ 声纹：语音特征提取 → 校内服务端比对（仅存 256 维向量）✅ 现有
  ├─ ASR：校内 voice-service（可切 FunASR 本地）或加密上传境内（DashScope）✅ 现有
  ├─ 对话/LLM：校内后端编排 → LLM（云端 API 或本地）✅ 现有
  ├─ TTS：校内 tts-service（可切 CosyVoice 本地）或云端（阿里云）✅ 现有
  └─ 数据存储：校内 PostgreSQL/Redis（多租户隔离）✅ 现有
```

**隐私强化点**（无屏终端特有）：
- **物理触发默认不持续监听**：仅捏/按触发后采集，规避教室持续监听争议（比 Pad 语音唤醒更隐私友好）
- **无屏无摄像头**：不采集图像/视频，隐私面最小化
- **LED/语音状态透明**：采集时 LED 亮 + 语音提示，学生明确知道"在听"
- **声纹/同意合规**：完全复用现有监护人同意 + 声纹向量存储 + 转写即删体系

## 六、多产品形态终端实现方案（V2 深化）（C 类：非本项目开发，冻结——硬件/固件实施归口 doc/NST-HW-02 与 frozen/73）

### 6.1 产品形态矩阵（不限于抱枕）

无屏实体终端的核心 = **语音交互 + 物理触感 + 情感形态**。形态可按场景/成本/亲和力多元选型：

| 形态 | 描述 | 交互特点 | 适用场景 | 参考产品 | 亲和力 | 成本 |
|---|---|---|---|---|---|---|
| **A. 毛绒抱枕/玩偶** | 毛绒玩具内置 AI 模组，抱着说话 | 捏/抱触发 + 语音，触感最柔软 | 心理咨询室（放松倾诉） | 市西小学小小西、BubblePal+毛绒 | ⭐⭐⭐⭐⭐ | 中 |
| **B. 桌面宠物/摆件** | 3D 打印卡通造型（波波 IP），摆桌面 | 摸头/按钮 + 语音 + 表情屏（可选） | 教室图书角/心理辅导角 | 芙崽、EMO、Stack-chan | ⭐⭐⭐⭐ | 低-中 |
| **C. 桌面音箱形态** | 圆柱/方盒音箱，纯语音 | 按钮/唤醒词 + 语音 | 教师办公室/咨询室 | 小智音箱、天猫精灵 | ⭐⭐⭐ | 低 |
| **D. 挂件/徽章** | 小挂件挂书包/钥匙链 | 捏/按 + 语音（短时交互） | 学生随身（情绪记录） | BubblePal 挂件 | ⭐⭐⭐⭐ | 低 |
| **E. 手环/穿戴** | 腕带 + 微型麦克风/扬声器 | 触碰 + 语音（短时） | 学生随身（情绪监测+安抚） | 响梦环 | ⭐⭐⭐ | 中 |

**形态选型建议**（结合本项目校园心理场景）：
- **首选 A 毛绒抱枕/玩偶**（心理咨询室）：柔软触感 + 抱着倾诉，最契合"降低倾诉门槛"核心诉求（市西小学验证）
- **次选 B 桌面宠物/摆件**（教室图书角/心理辅导角）：3D 打印波波 IP 卡通造型，成本最低（DIY 生态最成熟），适合多点部署
- **可选 D 挂件**（学生随身）：情绪随手记录/短时安抚，但交互时长有限
- **C 音箱 / E 手环**：作为补充形态（教师办公室音箱 / 特殊学生穿戴），非主推

### 6.2 DIY 3D 打印 + 第三方硬件实现路线（核心）

**业界成熟生态**：小智 ESP32（虾哥开源，GitHub 20k+ 星，MIT 协议）+ 3D 打印外壳（创想云/makerworld 开源 STL 模型丰富）+ 第三方传感器模组（淘宝/立创易购），**整机成本低至 40-300 元**，零基础可复现。

#### 路线一：ESP32 主控 + 3D 打印外壳（推荐，成本最低）

**硬件 BOM（以桌面宠物/摆件形态为例，成本约 100-300 元）**：

| 部件 | 选型 | 说明 | 参考成本 |
|---|---|---|---|
| 主控 | ESP32-S3-DevKitC-1（N16R8）或 ESP32-C3 | WiFi + 音频处理 + 轻量客户端（小智固件） | 30-40 元（C3）/ 60-80 元（S3） |
| 麦克风 | INMP441（I2S MEMS 数字麦克风） | 近场拾音（抱着/桌面说话） | 5.5-9 元 |
| 功放 | MAX98357A（I2S 数字功放） | 驱动喇叭 | 3-6 元 |
| 喇叭 | 8Ω 3W / 4Ω 3W 腔体喇叭 | TTS 播报 | 2-10 元 |
| 触摸传感器 | ESP32 内置电容触摸（10 路 Touch Pad，免外接） | 摸头/捏手触发对话 | 0 元（主控内置） |
| 压力传感器（可选） | FSR 薄膜压力传感器 | 捏抱枕触发（毛绒形态） | 5-15 元 |
| IMU（可选） | MPU6050（三轴加速度+陀螺仪） | 摇晃/翻转交互（摇一摇、倒扣静音） | 5-10 元 |
| 震动马达 | 扁平震动马达 | 触感反馈（"我在听"） | 2-5 元 |
| LED/RGB | WS2812 RGB 灯环 / 单色 LED | 状态反馈（配网/倾听/说话/故障） | 3-10 元 |
| 表情屏（可选） | 0.96 寸 OLED（SSD1306）/ 双目 OLED | 波波眼睛表情（非交互界面，仅状态/情感表达） | 5-15 元 |
| 电池（可选） | 18650 锂电池 + TP4056 充电模块 | 移动性（抱枕/挂件形态） | 15-30 元 |
| 外壳 | **3D 打印**（PLA/PETG，开源 STL 或简单建模） | 波波 IP 卡通造型 | 20-50 元（耗材+打印） |

**3D 打印外壳方案**：
- **开源模型复用**：创想云/makerworld/Printables 搜索"AI 机器人/桌面宠物/小智外壳"，大量开源 STL（Stack-chan/ESP-HI/闪猫桌面机器人等均提供全套 3D 打印文件），下载直接打印
- **波波 IP 定制建模**：用 Tinkercad（在线免费，零基础）/ Fusion 360（免费教育版）简单建模波波卡通形象（圆润精灵/动物），或用 AI 3D 生成工具（影眸/Meshy，拍照/文字生成 3D 模型）生成外壳
- **打印**：学校/创客空间 3D 打印机（创想三维 Ender/K1 系列，千元级）或淘宝/嘉立创 3D 打印服务（上传 STL 代打，几十元）
- **组装**：主控 + 传感器 + 喇叭用杜邦线/面包板连接（免焊接，零基础）或简单焊接，塞入 3D 打印外壳固定

**固件**：基于**小智 ESP32 开源固件**（虾哥，MIT 协议）二次开发——已集成 WiFi 配网（Soft-AP）、语音唤醒、ASR/TTS 对接（WebSocket/UDP）、音频采集播放，**需改造为对接本项目私有化后端**（见 §6 后端适配）。

#### 路线二：树莓派主控 + 3D 打印外壳（功能更强，成本中等）

**适用**：需更强算力（本地 Whisper 唤醒/声纹/情感识别）或更复杂交互（多传感器融合）的形态。

| 部件 | 选型 | 参考成本 |
|---|---|---|
| 主控 | 树莓派 Zero 2W / 树莓派 5 | 150-500 元 |
| 麦克风 | ReSpeaker 2-Mics Pi HAT / USB 降噪麦 | 100-200 元 |
| 扬声器 | USB 小音箱 / 3.5mm 喇叭 + 功放 | 30-100 元 |
| 传感器/反馈 | 同 ESP32 路线（触摸/压力/IMU/震动/LED，GPIO 接入） | 30-80 元 |
| 表情屏（可选） | 3.5 寸 HDMI 触屏（状态/表情，非交互） | 80-100 元 |
| 外壳 | 3D 打印（同 ESP32 路线） | 20-50 元 |

**优势**：完整 Linux 系统，可跑本地 Whisper（唤醒）+ WeSpeaker（声纹）+ 复杂传感器融合，**隐私更强（本地处理更多）**；**劣势**：成本高（300-800 元）、功耗大、体积大（不适合挂件/手环形态）。

#### 路线三：成品 AI 硬件改造（快速验证，零硬件开发）

**适用**：试点期快速验证形态接受度，零硬件开发。

| 成品 | 形态 | 成本 | 关键约束 |
|---|---|---|---|
| BubblePal 挂件 + 现成毛绒玩具 | 毛绒玩偶/挂件 | 399-500 元 | **需确认能否对接私有化后端**（通常绑定厂商云，若支持自定义服务器/API 则可行） |
| 小智成品音箱（淘宝成品） | 桌面音箱 | 70-300 元 | 基于小智开源，可刷自定义固件对接私有化后端 |
| 闪猫/OTTO 桌面机器人套件 | 桌面宠物 | 279-500 元 | 开源套件，可改造对接 |

**关键决策点**：成品硬件通常绑定厂商云端服务，**能否对接本项目私有化后端是核心约束**——若支持自定义服务器/API（如小智开源固件可刷机）则快速验证可行；若绑定封闭厂商云（如 BubblePal 消费版）则需走自研集成路线（路线一/二）。

| **体积/功耗** | ⭐⭐⭐⭐⭐ 小/低（挂件/手环可行） | ⭐⭐⭐ 大/高 | ⭐⭐⭐⭐ 视成品 |

**选型建议**：
- **试点期**：路线三（小智成品音箱/开源套件）快速验证形态接受度 + 私有化对接可行性；若成品绑定厂商云则直接转路线一
- **规模化**：**路线一（ESP32 + 3D 打印）为主**——成本最低（百元级）、形态最灵活（任意 3D 打印波波 IP）、小智开源生态成熟（降低固件门槛）、私有化对接可控（改固件直连校内后端）
- **高隐私/复杂交互场景**：路线二（树莓派）补充——本地 Whisper/声纹，隐私最强

## 七、前端输入技术实现方案（无屏多模态输入）（C 类：非本项目开发，冻结——嵌入式实现归口 doc/NST-HW-02）

无屏终端的"前端输入"= **语音 + 物理传感器（触摸/压力/姿态/按钮）**，替代 Pad 的触屏界面交互。

### 7.1 输入模态矩阵

| 输入模态 | 硬件 | 交互动作 | 替代 Pad 的什么操作 | 技术实现 |
|---|---|---|---|---|
| **语音** | 麦克风（INMP441/ReSpeaker） | 说话 | 语音输入（复用） | 现有语音链路（ASR/声纹/SER） |
| **触摸** | ESP32 电容触摸（10 路 Touch Pad，免外接） | 摸头/摸手/摸肚子 | 点击按钮（触发对话/切换） | ESP-IDF touch_pad API，阈值检测 |
| **压力** | FSR 薄膜压力传感器 | 捏抱枕/按压 | 按住说话（触发+判停） | ADC 读取压力值，阈值触发 |
| **姿态** | MPU6050 IMU（加速度+陀螺仪） | 摇一摇/翻转/拿起放下 | 手势操作（摇一摇切换、倒扣静音） | I2C 读取姿态，动作识别算法 |
| **按钮** | 物理微动按钮 | 按一下 | 功能键（音量/静音/配网） | GPIO 中断 |
| **震动反馈** | 扁平震动马达 | 震动（输出反馈） | 视觉反馈（"我在听"提示） | GPIO/PWM 控制震动模式 |
| **灯光反馈** | WS2812 RGB / LED | 颜色/闪烁（输出反馈） | 界面状态（配网/倾听/说话/故障） | GPIO/SPI 控制灯效 |
| **表情屏反馈（可选）** | 0.96 寸 OLED / 双目 OLED | 波波眼睛表情（输出反馈） | 界面情感表达 | I2C/SPI 驱动，状态机动画 |

### 7.2 关键输入技术实现要点

**① 触摸触发（ESP32 电容触摸，零成本）**：
- ESP32-S3 内置 10 路电容触摸 GPIO，直接接外壳触摸点（铜箔/导电布），摸头/摸手即触发
- 技术：`touch_pad_read_raw_data()` 读原始值，与基线比对（阈值 70%），防误触（250ms 去抖）
- 多路触摸可区分部位（摸头=开心、摸手=触发对话、摸肚子=安慰）

**② 压力触发（FSR，毛绒抱枕形态核心）**：
- FSR 薄膜压力传感器缝入抱枕手部/腹部，捏一捏触发对话（市西小学"捏一捏"交互）
- 技术：ADC 读取压力值，阈值触发（轻捏=触发、重捏=打断），松开或 VAD 判停结束

**③ 姿态交互（IMU，可选增强）**：
- MPU6050 检测摇一摇（切换音色/心情）、翻转倒扣（静音/休眠）、拿起（唤醒）、放下（结束对话）
- 技术：I2C 读取加速度/陀螺仪，动作识别（阈值/简单模式匹配）

**④ 多模态融合（提升交互自然度）**：
- 参考四博 AI 双目音箱方案：触摸头部 → 表情（微笑）+ 震动（短震）+ 语音（"我在呢"）多模态同时反馈
- 摇晃 → 惊讶表情 + 双震 + 语音；翻转 → 睡眠表情 + 停止播放

### 7.3 无屏交互范式（输入→反馈闭环）

```
学生动作（输入）          终端反馈（输出）           系统动作
─────────────────────────────────────────────────────
捏抱枕手（压力）    →    震动短震+LED亮+提示音   →   开始采集语音
说话（语音）        →    LED呼吸灯（倾听中）      →   ASR+声纹识别身份
说完（VAD判停）     →    LED转色（思考中）        →   对话引擎+LLM
抱枕播报（TTS）     →    LED说话律动+表情屏嘴型   →   TTS播放
摸头（触摸）        →    微笑表情+短震+语音回应   →   情感互动
摇一摇（IMU）       →    惊讶表情+双震            →   切换音色/心情
倒扣（IMU）         →    睡眠表情+LED灭           →   静音/休眠
```

## 八、后端适配分析（实体终端对接私有化后端 + toC 家长端扩展）

### 8.1 核心结论：后端零改造或极小改造

实体终端与 Pad 的本质差异仅在**音频输入/输出设备 + 无屏交互**，**对话引擎/语音链路/声纹/音色/风险识别完全复用**。

| 后端模块 | 是否改造 | 说明 |
|---|---|---|
| ChatController / ConversationService | ❌ 零改造 | 对话编排/SSE 流式/风险识别/LLM 编排完全复用 |
| voice-service（ASR/声纹） | ❌ 零改造 | DashScope ASR + WeSpeaker 声纹复用，音频源从 Pad 切换到终端 |
| tts-service（TTS 音色） | ❌ 零改造 | 阿里云 TTS 7 音色 + VoicePersonaResolver 裁决复用 |
| 情绪门控/心情驱动 | ❌ 零改造 | SER 情绪识别 + 心情驱动策略复用（无屏下去掉开场选情绪界面，改对话中自然捕捉） |
| 家长端 H5（同意/周报） | ❌ 零改造 | 监护人同意/周报体系复用 |
| **新增：终端设备管理 API** | ✅ 新增模块 | 设备绑定/声纹录入编排/配置下发/状态监控（不动核心对话链路） |
| **新增：终端通信适配层** | ✅ 新增适配 | 终端通信协议（HTTP/SSE/WebSocket）对接现有 SSE 对话流 |

### 8.2 终端通信协议适配（关键改造点）

**现状**：Pad 学生端走 HTTP + SSE（Server-Sent Events）流式对话。

**终端适配方案**：

| 方案 | 协议 | 优势 | 局限 | 适配 |
|---|---|---|---|---|
| **HTTP + SSE**（推荐） | 终端 HTTP POST 音频 → 后端 SSE 流式返回 TTS 音频 | 与 Pad 链路完全一致，后端零改造 | ESP32 处理 SSE 需轻量解析 | ⭐⭐⭐⭐⭐ 首选（复用现有） |
| WebSocket | 终端 WebSocket 双向流（音频上行 + TTS 下行） | 全双工、低延迟 | 需后端新增 WebSocket 端点（小改造） | ⭐⭐⭐⭐ 小智固件原生支持，可选 |
| UDP | 终端 UDP 音频流 | 极低延迟 | 不可靠（丢包）、需后端新增 UDP 服务 | ⭐⭐ 校园网 UDP 可能被拦，不推荐 |

**推荐**：**HTTP + SSE**（与 Pad 完全一致，后端零改造）——终端 POST 音频到 `/api/chat/voice`，后端 SSE 流式返回 TTS 音频流，终端边收边播。ESP32 用轻量 HTTP 客户端 + SSE 解析（小智固件已有 WebSocket 实现，可改造为 SSE 或直接复用 WebSocket 方案，后端新增 WebSocket 端点包装现有 SSE 逻辑，改造量小）。

### 8.3 声纹无屏登录适配

**现状**：Pad 声纹双模式（浏览器端 WeSpeaker WASM / 服务端 WeSpeaker）。

**终端适配**：
- **服务端声纹模式**（推荐）：终端采集语音 → 上传校内 voice-service → WeSpeaker 服务端比对 → 返回学生身份 → 加载画像/音色/记忆。终端无需本地声纹模型（ESP32 算力弱），完全复用服务端模式
- **树莓派路线可选本地声纹**：树莓派算力可跑 WeSpeaker 本地模型，声纹不出设备（隐私更强）
- **无屏登录编排**（新增）：识别失败语音引导录声纹、多人置信度低时语音确认（"你是小明吗？"）——后端新增无屏声纹登录编排逻辑（小改造）

### 8.4 管理台适配（老师端新增终端管理模块）

**新增"终端设备管理"模块**（老师端 Web）：
- 设备绑定/解绑（终端设备 ID ↔ 学校/班级/咨询室）
- 声纹录入引导（发起录入 → 终端语音提示学生朗读 → 模板入库）
- 音色/默认心情预设（按学生/按设备，复用 VoicePersonaResolver）
- 设备状态监控（在线/离线、电量、网络、固件版本）
- 使用记录/对话摘要（复用现有老师端预警/报告体系）

### 8.5 私有化部署适配（数据不出校延续）

```
实体终端（校内，3D打印/毛绒外壳）
  ├─ 触发：物理捏/摸/按（默认不持续监听，隐私优先）
  ├─ 配网：Soft-AP 连校园 WiFi → 直连校内服务器（内网 IP/域名）
  ├─ 声纹：语音特征 → 校内 voice-service 比对（仅存 256 维向量）✅ 现有
  ├─ ASR：校内 voice-service（可切 FunASR 本地）或加密上传境内（DashScope）✅ 现有
  ├─ 对话/LLM：校内后端编排 → LLM（云端 API 或本地）✅ 现有
  ├─ TTS：校内 tts-service（可切 CosyVoice 本地）或云端（阿里云）✅ 现有
  └─ 数据存储：校内 PostgreSQL/Redis（多租户隔离）✅ 现有
```

**隐私强化**（无屏终端特有）：物理触发默认不持续监听、无屏无摄像头（不采图像）、LED/语音状态透明（采集时学生明确知道"在听"）、声纹/同意合规完全复用现有体系。

### 8.6 toC 家长端扩展（V3 产品形态转型新增）（B 类：已抽至 frozen/85 并冻结，本节保留作溯源）

**现有家长端 H5**（toB 校园体系下的监护人同意/周报）需扩展为 **toC 家庭版家长端**（App/H5），支撑「波波小伙伴」家庭场景：

| 模块 | toC 扩展内容 | 复用/新增 |
|---|---|---|
| **账号体系** | 家长手机号注册/登录（验证码），独立于校园账号体系 | 新增（toC 账号模块，与 toB 老师/学生账号并存） |
| **使用者档案** | 创建孩子档案（昵称/年龄/性别/兴趣），**一账号多孩**（多孩子管理） | 新增（家庭档案模型，复用学生档案核心字段） |
| **设备绑定** | 绑定家庭波波终端（扫码/搜索附近设备），一账号多设备 | 新增（家庭设备绑定，复用终端设备管理 API） |
| **配网引导** | Soft-AP 配网引导（连家庭 WiFi） | 复用（§3.1 Soft-AP 配网机制） |
| **个性化设置** | 选波波角色/音色/对话偏好/互动预期 | 复用（VoicePersonaResolver 音色裁决 + 对话偏好配置） |
| **成长报告** | 周报（兴趣演变/情绪变化/心理洞察，**算法提炼非原始对话**） | 复用（现有报告引擎，扩展 toC 家庭报告模板） |
| **风险预警** | 识别风险信号 → 推送家长（App 推送/短信） | 复用（现有预警引擎，扩展 toC 推送通道） |
| **远程管理** | 音量/灯光/音色/对话偏好调整，设备状态查看 | 复用（终端设备管理 API） |
| **隐私控制** | 查看/删除数据、关闭设备、设置使用时间 | 新增（toC 家长控制模块） |

**家长端与老师端二合一架构**（核心）：
- **统一后端**：报告引擎/预警引擎/档案模型/设备管理/配置能力**一套代码**，通过**角色 + 数据范围**区分（角色=家长/老师/管理员；数据范围=家长看自己孩子、老师看班级/全校）
- **统一前端框架**：家长端 App/H5 与老师端 Web 复用同一套组件/页面框架（报告页/预警页/档案页/设备管理页），仅数据源/权限/角色 UI 差异
- **权限模型**：RBAC（角色-资源-数据范围三维权限），家长角色数据范围=自己孩子，老师角色数据范围=班级/全校
- **家校协同**（可选）：家长授权后老师可看家庭数据，学校授权后家长可看在校数据——数据授权互通，家校共育闭环

**toC 部署形态**：
- **toB 校园版**：私有化部署（数据不出校），现有架构不变
- **toC 家庭版**：可选**云端 SaaS**（数据归属家长，厂商云端部署）或**家庭私有化**（树莓派家庭服务器，数据不出家，高隐私）——toC 需新增云端部署架构（多租户 SaaS）或家庭私有化部署方案

## 十四、核心结论（决策参考，V4 定稿版）

**产品形态（开篇核心）**：
1. **产品双层架构**：表层 = **「波波小伙伴」AI 聊天陪伴产品**（装饰品/摆件/玩偶形态，孩子视角的 AI 好朋友）；底层 = **对话→了解心理→识别风险**（家长/学校视角的心理陪伴与风险识别产品）——孩子无压力亲近，家长/学校清楚底层逻辑
2. **两大扩展（V4 定稿核心）**：①**toB 第四端**——现有 toB 三端（学生端 Pad / 老师端 Web / 家长端 H5）扩展**第四端 = 无屏交互终端**（抱枕/摆件/挂件形态），纯语音 + 物理交互，**管理配置/设备绑定/账号由管理员后台（老师端）配置**，多人共用声纹识别自动切换；②**toC 产品模式**——扩展 toC 家庭版（家长购买，家长端自助配置，个人专属）
3. **toB 与 toC 共同核心**：**终端无屏交互模式**（纯语音 + 物理交互 + 物理反馈，无屏幕界面）+ **终端形态 DIY 或其他实现**（DIY 3D 打印 + 第三方硬件 / 成品改造，多形态矩阵）——两者共享统一设计，差异仅在管理端（管理员后台 vs 家长自助）与部署（私有化 vs 云端/家庭私有化）
4. **产品形态设想**：多形态矩阵——毛绒抱枕（床头/咨询室）+ 桌面摆件（书桌/图书角）+ 可选小夜灯/绿植形态（实用功能叠加）+ 挂件（随身），统一波波 IP，装饰品化 + 无威胁感设计
5. **家长端与老师端二合一**：报告引擎/预警引擎/档案模型/设备管理/配置能力**一套代码**，仅数据范围/权限/角色区分（老师看全校/班级，家长看自己孩子）；支持家校协同（数据授权互通）
6. **家长端模式**（toC 核心）：家长手机号注册 → 创建孩子档案（一账号多孩）→ 绑定设备 → 配网 → 个性化设置 → 查看成长报告/预警 → 远程管理
7. **隐私红线**：**报告替代原始对话**（家长看算法提炼的心理洞察，非对话原文，尊重孩子隐私权）+ 孩子知情透明 + 最小化收集 + 本地优先 + 家长控制

**技术实现（V2 延续）**：
8. **DIY 实现路线**：**ESP32 主控 + 3D 打印外壳 + 第三方传感器模组**为主（成本 100-300 元/台，小智开源生态成熟 20k+ 星）；树莓派补充高隐私场景；成品改造快速验证
9. **网络配置**：**Soft-AP 配网**（终端开热点 + 手机连 + 浏览器输 WiFi 密码），一次配置永久生效，直连私有化服务器（toB 校内/toC 家庭或云端）
10. **前端输入**：**语音 + 多模态物理输入**（电容触摸 + FSR 压力 + IMU 姿态 + 物理按钮），反馈用 LED/震动/表情屏（可选），替代 Pad 触屏界面
11. **语音交互**：**100% 复用现有链路**（麦克风→ASR→对话引擎→TTS→扬声器），后端零改造，仅音频源切换
12. **身份识别**：**声纹识别**（复用现有 WeSpeaker 服务端模式）——toB 多人共用识别多学生，toC 家庭识别家庭成员，说话即识别身份，无感登录
13. **启动对话**：**物理触发为主（捏一捏/摸一摸/按一下）+ 语音唤醒可选**——符合自然动作，默认不持续监听（隐私优先）
14. **心情/音色**：**管理台（家长端/老师端）+ 语音指令双通道**——心情靠 SER 自动识别，音色管理台预设 + 学生语音切换
15. **后端适配**：**零改造或极小改造**——对话引擎/语音链路/声纹/音色完全复用，新增终端设备管理 API + 通信适配层 + 无屏声纹登录编排 + **家长端 toC 扩展（手机号注册/多孩档案/家庭设备绑定）**
16. **整体涉及面**：产品形态设计 + 硬件选型 + 3D 打印外壳 + 固件 + 后端适配 + **家长端 toC 扩展** + 老师端二合一改造 + 私有化对接 + 合规 + 波波 IP 设计 + 测试，试点期约 3-4 个月，单台成本 100-700 元
17. **边界**：不自研模具/芯片、不替换 Pad（toB 保留，第四端并存）、不改私有化架构（toB）/可选云端（toC）、纯无屏、本期不实施开发

## 十五、开发区 SPEC（2026-08-10 补充，toB 第四端软件实施范围）

### 15.1 问题陈述

> 本项目（AI 小学生心理辅导系统）已为学校提供三端（学生端 Pad / 老师端 Web / 家长端 H5）。现有学生端基于 Pad 浏览器界面，学生面对屏幕时有心理防御——市西小学「小小西」抱枕实践表明，**毛绒/无屏形态能降低倾诉门槛，学生更愿表达真实心声**。

**核心问题**：如何在不替换现有三端的前提下，新增**第四端 = 无屏交互终端**（波波 IP 抱枕/桌面摆件形态），使其与现有后端（对话引擎/语音链路/声纹/音色/风险识别）无缝对接，并提供完整的设备管理配置体系？

**范围锚定**（DOC-092 治理 2026-08-09）：
- ✅ A 类（本项目要开发）：软件侧——设备管理 API、管理台配置页面、扫码入口 H5、配网页引导层、设备绑定/声纹录入编排、状态监控、二维码规范
- ❌ B 类（本项目没要开发）：toC 家庭版产品模式 → frozen/85（已冻结，解冻触发=toC 立项决策）
- ❌ C 类（非本项目开发）：硬件/固件/3D 打印/外壳/采购 → doc/NST-HW-02 + frozen/73（已冻结）

### 15.2 解决方案概览

**一句话**：在现有后端新增 `device` 域（4 表 + API），在老师端 Web 新增"终端设备管理"模块（挂 doing/83 M13），在前端新增独立 H5 扫码入口页与配置页面体系（doing/84），三者共同构成**无屏终端的全生命周期管理**（配网→绑定→声纹录入→日常管理→解绑），所有软件侧零改造对话引擎/语音链路/风险识别。

**关键架构决策**（详见实施决策 §15.4）：
1. 软硬分离：设备端配网固件走小智原生 captive portal（P0，零改动），云端仅做"引导+状态轮询+绑定"——软件侧不依赖固件定制
2. 配置面收敛：6 类配置页面全部 H5 承载（浏览器跨平台，零安装），无原生 App
3. 二合一架构：toB/toC 共用同一套配置页面与 API，仅角色×数据范围区分（74 §1.5 二合一架构落地）
4. 复用优先：声纹/音色/对话引擎/ASR/TTS/风险识别全部零改造，仅新增 device 域模块

### 15.4 实施决策

**数据模型决策**：
- device 表独立于现有业务表（不与 users/students/tenants 耦合），device_code 为二维码载体，SN 为出厂序列号不对外
- device_bindings 表支持一对多归属（toB 学校/班级/咨询室三层），toB 多人共用场景 student_id 为 NULL
- device_bind_codes 验证码仅存哈希，不存明文、不落日志，5 分钟有效期、3 次锁定

**API 设计决策**：
- 设备业务域前缀 `/api/v1/device/**`（绑定/解绑/配置/声纹编排/OTA），匿名端点仅返回脱敏信息
- 设备上报端点 `/api/v1/device/report/**` 走设备签名鉴权（非用户 JWT），心跳 30s/超时 90s 判离线
- 平台管理域前缀 `/api/v1/platform/devices/**`（admin 跨租户），对齐 doing/83 §七 前缀约定
- 统一响应格式 `{code, message, data}` 对齐 his/16，错误码复用 10001/10002/10003/20001/20002/20003
- 写操作（绑定/解绑/OTA/恢复出厂）携带 X-Confirm 头 + reason 必填，对齐 doing/83 二次确认规范

**前端页面决策**：
- 扫码入口页独立路由 `/p/:v/:deviceCode`，承载于 parent-h5 工程（现有工程复用，不新建）
- 配网页 P0 复用原生 captive portal（零固件改动），自研引导层仅做"连热点指引+状态轮询"
- 管理台配置页挂 doing/83 M13 模块，页面规范对齐 83 §八 青屿设计令牌（--ms-primary #2BA8A0）
- 设备绑定页/声纹录入引导页/设备状态页复用 teacher-web 与 parent-h5 现有工程，不新建前端工程

**配网流程决策**：
- 状态机 = 扫码→自检分流→连热点→配网写入→回连检查→绑定→声纹录入（可选），参照华为智慧生活回连检查模式
- "切换热点断网"矛盾：落地页预加载（SPA 内存继续）+ 回连轮询设备状态 API，不依赖页面重载
- 超时 100s（对齐涂鸦默认值），失败分段诊断（华为模式：AUTH_ERROR / AP_NOT_FOUND / 超时离线）
- 2.4G 前置检查：配网页与落地页均提示"仅支持 2.4G WiFi"

**二维码决策**：
- L1 静态码（机身+包装，URL + deviceCode 短码 11 位含校验位）——出厂即印，域名不可变
- L2 绑定验证码（设备语音播报 6 位，5 分钟有效，哈希存储）——双因子防串绑
- L3 动态码（P2 增强，冻结待 toC 解冻）

**安全决策**：
- 无密码热点配网窗口期风险：配网页零敏感数据、超时 10 分钟自动关热点、绑定验证码二次确认
- 声纹合规完全复用现有体系（256 维向量、不存原始音频、监护人同意前置）
- 配网页 HTTP-only（captive portal 机制依赖 HTTP，不包含敏感数据）

### 15.5 测试决策

### 15.7 进一步说明

**与 doing/84 的关系**：本 §15 为**整体方案级 SPEC**，定义用户故事、测试策略、实施决策；doing/84 为**配置面页面级 SPEC**，提供 6 类页面设计、二维码规范、API 端点清单、AC-84-01~28 验收标准。两者互补：本 §15 定位"做什么、为什么做、怎么测"，doing/84 定位"具体做成什么样"（页面级设计）。实施时应以 §15 用户故事为需求源，以 doing/84 页面设计为实现规格，以 CFG tickets 为跟踪单位。

**与 doing/83 的关系**：83 为平台管理端（多租户/运营/监控/审计底座），本专题管理台配置页（CFG-008）挂 83 M13 模块。83 §七 API 前缀/权限模型/青屿设计令牌直接引用，不重复定义。

**与 frozen/85 的关系**：toC 家庭版已冻结，但 CFG-007（设备状态页）的 toC 视图部分与 toB 视图共享同一套数据 API，仅前端展示层差异——建议实施 CFG-007 时预留 toC 视图的组件扩展点（如条件渲染 `role === 'parent'` 的视图分支），不冻结 API 层。

**实施顺序提示**：P0（CFG-001→002→003→004→005）为试点闭环，P1（006→007→008）为管理面深化，P2（010→011→012）受 toC/加密冻结约束。建议 P0 完成后即进行真机验收（配网成功率 ≥90%），验证通过后再进入 P1。

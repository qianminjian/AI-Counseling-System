## 二、候选清单

### 认证与会话域

#### S-001 登录"尝试→校验→签发"链无单一接缝【Strong】
- **涉及**：AuthController（461 行/13 依赖）+ TrialAuthService + ParentAuthService
- **问题**：锁定/withdrawn/租户门禁/清计数/留痕/签发在 login/pinLogin/doLogin 三处以不同子集出现——家长登录缺租户门禁、PIN 登录缺服务内门禁，不对称只能对照源码发现；token 签发三连在 6 端点重复。
- **解决**："一次登录尝试"收敛为单一编排方法（身份+凭据+类型），各入口只提供"如何定位账号/如何验凭据"差异；控制器退化为参数绑定。
- **删除测试**：删编排体 → 复杂度迁移（无服务能接住）——链条"顺序约束"不归属任何可删除单元。

#### S-002 会话"每轮上下文组装"两条消息路径重复且已分叉【Strong】
- **涉及**：ConversationServiceImpl（744 行/23 依赖，sendMessageStream vs sendNudgeStream）
- **问题**：画像→记忆→联盟→contextBrief→年级五连调用逐字重复；主链路手工拼 contextBrief（408 行）、nudge 注释"不拼入"——已分叉；联盟增强用 lines().filter("- ") 解析记忆文本（隐式字符串契约）。
- **解决**："组装每轮上下文"提为共享组件，注入时机收敛为单一参数；联盟增强输入改结构化记忆。
- **删除测试**：删任一路径副本 → 破坏另一条语义——接缝画错了位置。

#### S-003 AuthStrategy 接口空转【Worth】
- **涉及**：AuthStrategy + TrialAuthStrategy + AuthController + AuthProvider
- **问题**：唯一实现且 Controller 注入具体类，三条主登录路径完全绕过；AuthenticatedUser.pseudonym/mustChangePassword 在签发路径被丢弃（对象流断裂）；pinLogin 手工 TenantContextHolder.set/clear 与 BA-15 矛盾。
- **解决**：二选一——①登录收敛为策略实现（每认证方式一策略）；②无新认证方式则删除 AuthStrategy。
- **删除测试**：删 AuthStrategy → 改一行直调零迁移——接口无杠杆的证明。

#### S-004 量表引擎有金标准测试却无生产调用方【Worth → ❄️ 冻结移交 frozen/34】
- **涉及**：AssessmentScoringEngine + BuiltinScales + RecurrenceCalculator（frozen/34 施测接线待排期）
- **问题**：@Component 但全库仅自身测试引用；"作答提交→熔断→风险事件/通知"接线语义无代码承担，真实 bug 必藏在尚未存在的调用处。
- **议决（2026-08-12）**：冻结移交 frozen/34 归口跟踪（施测专题激活时落位"提交→计分→熔断→风险事件+通知"服务级职责，登记为 risk_events 第三 writer，S-009 关联），不再本专题跟踪。

#### S-005 orchestrator Bean 管理双轨 + 死参数【Worth】
- **涉及**：ReplyEmotionResolver（@Component 从未被注入）+ EmotionStateMachine（riskEscalated 恒传 false）+ ConversationServiceImpl（内联 new）
- **问题**：同包决策组件两种实例化方式并存；死参数使编排短路 vs 状态机风险入口各写一半。
- **解决**：统一 Bean 注入；删 riskEscalated 参数（或把 CRISIS 强制语义完整收进状态机）。
- **删除测试**：删死参数调用方零改动——接口契约不再说谎。

### 教师与分析域

#### S-006 BA-10"会话转写读取单点"被教师侧两个读者绕过【Strong】
- **涉及**：MessageSummaryService（BA-10 单点）+ TeacherService.getSessionMessages + TeacherQualityService.replaySession
- **问题**：教师侧两处各写一遍相同查询+解密；语义已漂移——BA-10 侧 TranscriptFilter 排除保密告知（turnCount=0），教师侧无过滤会把保密告知展示给教师。
- **解决**：教师端两个读者改调读取单点（或单点提供教师视图变体），删除重复查询+解密循环。
- **删除测试**：删教师侧副本 → 复杂度集中于单点——接缝已存在但未被使用。

#### S-007 TeacherService 上帝类【Strong】
- **涉及**：TeacherService（984 行/9 Mapper，无接口）+ CounselingSessionStore
- **问题**：预警生命周期/个案备注/学生档案/看板统计/话术/会话消息六子域混居；"最新一条 case 备注"三变体；takeoverSession 读走 SessionAccessService 接缝、写却直连 Mapper（不对称）。
- **解决**：按子域拆分（预警生命周期服务 + TeacherNoteStore + 看板统计服务）；takeover 写路径改经会话仓储。
- **删除测试**：删整类复杂度迁移不消解；删子域方法波及其他子域共享依赖——粒度失败。

#### S-008 "负面情绪"判定双源【Worth】
- **涉及**：DataAnalyticsService（NEGATIVE_LABELS + 硬编码 happy/calm）+ EmotionVocabulary（8 模块单一源）
- **问题**：语音管线 fearful 等码值不在 analytics 集合中——同一情绪风险管线判负、干预分析判正，口径分歧不可见。
- **解决**：analytics 改用共享判定（或词表补 isPositive），删私有集合与内联字面量。
- **删除测试**：删 NEGATIVE_LABELS → 复杂度集中于词表，所有用户自动对齐。

#### S-009 risk_events 写入 + 通知义务状态机无统一入口【Worth】
- **涉及**：ConversationRiskProcessor.persistRiskEvent + SessionEndAnalyticsService.persistAttentionSignal + RiskNotifyOutboxService
- **问题**：两个 writer 各写半套（fromDetection 工厂 vs 手工 setter）；"无通知义务须 markSent"是约定而非结构——retryDueEvents 按 pending/failed 全量扫描无法区分"本就无需通知"与"通知失败"，第三 writer（量表熔断）极易漏标致补偿重试。
- **解决**："构造 RiskEvent + 登记通知义务"收敛为单一写入入口，writer 只描述"这是什么风险、要不要通知"。
- **删除测试**：删内联构造+markSent → 复杂度集中于统一入口。

### AI 服务与模块依赖

#### S-010 AiChatServiceImpl 流式链路双份复制 + 辅助 LLM 调用接缝三裂【Strong】
- **涉及**：AiChatServiceImpl（chatWithPrompt/chatProactive 双份管线）+ LlmStreamEnhancer
- **问题**：同一管线两份复制；4 个辅助 prompt 硬编码 Java（B4 下沉约定绕行）；extractConversationInsights 无超时（Q-005 统一超时收编遗漏）；静态执行器与 Spring 执行器并存。
- **解决**：辅助调用收敛为小型门面（统一超时+降级+审计）；prompt 下沉模板；流式主链路模板方法化。
- **删除测试**：删 chatProactive → 主链路不受影响——复杂度藏在两份复制里。

#### S-011 Controller 层三式接缝【Strong】
- **涉及**：TtsController/SessionController/KnowledgeBaseController/VoiceController 等 13 个 Controller
- **问题**：25+ 处 @RequestBody Map 手工解析（字段改名运行时才暴露）；25+ 处手写 ApiResponse.error 绕过 BizException/ErrorCode 体系（KB 甚至 200+error Map）；TenantContext 提取三种写法；transitionReviewStatus 状态机编排全在 Controller（同文件另一路径已委托 Service）。
- **解决**：请求/响应类型化 record（参照 AuthController 风格）；错误统一抛 BizException；extractContext 共享组件；审核域编排并入 EditorialWorkflowService。
- **删除测试**：删 transitionReviewStatus 端点 → 域逻辑不完整保留在任何一层——领域逻辑住在错误分层。

#### S-012 PiiDesensitizer 模块错位【Strong】
- **涉及**：PiiDesensitizingAppender（counseling-app）+ PiiDesensitizer（counseling-ai/safety）
- **问题**：日志 Appender 直接 new PiiDesensitizer()——纯正则工具拖进整个 AI 模块到启动模块；无接口，两条消费路径无法共享策略配置；"脱敏"概念三处散布（掩码/存储加密/信息提取）。
- **解决**：脱敏器下沉 counseling-common（纯正则零 AI 依赖），Appender 与 ConversationServiceImpl 都从 common 消费。
- **删除测试**：删 Appender → common 脱敏器保留零迁移——依赖方向修正。

#### S-013 RiskKeywordRegistry 裸静态规则源【Worth】
- **涉及**：RiskKeywordRegistry（319 行静态类）+ RiskDetectorServiceImpl/ConversationRiskProcessor/LongTermMemoryService 等 5+ 消费方
- **问题**：消费方以字段粒度静态 import；词典演进（多租户/分级/按校配置）需改所有引用点；测试无法注入替代词表。
- **解决**：封装为可注入组件（RiskKeywordLibrary），评分权重随词典聚合。
- **删除测试**：删某词典分类 → 悬空编译错误分布到所有引用点（静态类删除=分布式成本）。

#### S-016 useTtsPlayer 三路播放链重复【Worth】

## 1. 产品定位

家长端是 MindSafe "学生-AI-教师-家长"四位一体体系的最后一环。家长通过教师分享的链接，在手机端查看孩子的情绪周报、接收 AI 建议、管理数据授权。

**核心原则：**
- 只读为主：家长只看统计报告，不看对话原文（隐私保护）
- 零注册：无需下载 App / 注册账号，链接即入口
- 合规闭环：监护人同意确认、同意撤回均可在家长端完成

## 2. 分阶段规划

| 阶段 | 形态 | 时间 | 核心内容 |
|------|------|------|---------|
| **P1（本期）** | H5 移动网页 | 当前迭代 | **Vite 6 + React 19 SPA**，nginx 静态部署，链接访问 |
| **P2（远期）** | 微信小程序 | 后续规划 | **迁移至 Taro**（React 语法一码多端）编译为 weapp+H5，补微信 OAuth，提审上线（详见 design/43） |

### 2.1 P1 → P2 复用分析

| 层 | 复用度 | 迁移工作 |
|---|---|---|
| API 调用层（`src/api/`） | 契约 100% | 迁 Taro 后底层 `fetch` → `Taro.request`，业务签名不变 |
| 业务逻辑（hooks/utils） | 95% | 纯 JS，无平台依赖（`localStorage` → Taro storage） |
| 视图层（页面/组件） | **需重写** | HTML 元素/SCSS → Taro 组件（View/Text/Button）+ WXSS（工作量主体） |
| 认证流程 | **需改造** | H5 用 JWT Token；小程序改 `wx.login` → openid → 绑定 |
| 路由/生命周期 | **需重写** | react-router-dom → 小程序页面路由（app.config 注册 + Taro.navigateTo） |

### 2.2 P2 小程序阶段待办（远期，不丢失）

| 任务 | 说明 | 依赖 |
|------|------|------|
| PARENT-WX-001 | 微信小程序工程注册 + AppID 配置 | 企业主体认证 |
| PARENT-WX-002 | wx.login → openid → parent_bindings 绑定 | 后端 parent_bindings 表（已设计） |
| PARENT-WX-003 | 微信 OAuth 授权页（获取手机号） | 微信开放平台配置 |
| PARENT-WX-004 | `taro build --type weapp` 编译 + 真机调试 | 先完成 React-SPA→Taro 迁移（非“Taro 工程已就绪”） |
| PARENT-WX-005 | 小程序提审 + 上线 | 隐私协议 / 类目审核 |
| PARENT-WX-006 | 订阅消息推送（周报通知） | 微信订阅消息 API |

## 3. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **Vite 6 + React 19** | 轻量、构建快、与学生端/教师端技术栈统一 |
| 路由 | **react-router-dom 7** | SPA 路由，3 个页面足够 |
| 样式 | **SCSS**（单文件 app.scss） | 移动端适配，max-width 480px 居中 |
| 部署 | nginx 静态目录 `/parent/` | 复用现有 nginx，路径 `yun.gxjugu.com/parent/` |
| 状态管理 | React useState/useEffect | KISS，页面少无需 Redux |

### 3.1 P2 小程序迁移方案

P1 代码结构已部分考虑跨端兼容（但**当前为 Vite+React SPA，尚未 Taro 化**）：
- API 层（`src/api/`）：纯函数，P2 将 `fetch` 替换为 `Taro.request`（业务签名不变）
- 业务逻辑（`src/utils/`）：纯 JS，无平台依赖（`localStorage` 需改 Taro storage）
- 视图层：P2 用 Taro CLI 初始化工程，将 HTML 元素/react-router 重写为 Taro 组件与小程序路由

> ⚠️ 工作量修正：早期“2-3 人天重新编译”的估计**过于乐观且基于错误前提（误以为已是 Taro）**。实际是一次完整的 React-SPA→Taro 框架迁移（引入 Taro 工程 + 视图/路由重写 + 存储/请求适配 + 微信认证接入 + 提审），只是业务简单（3 页）故总量可控。完整迁移设计以 **design/43** 为准。

## 4. 页面设计（P1 H5）

### 4.1 页面清单

| 路由 | 页面 | 功能 |
|------|------|------|
| `/` | 手机验证页 | 家长打开链接 → 输入手机号 → 获取验证码 → 验证通过 → 跳转周报 |
| `/report` | 情绪周报页 | 展示近 7 天情绪分布、对话统计、风险等级、AI 建议 |
| `/consent` | 同意管理页 | 查看授权状态 + 撤回同意（不可逆操作，二次确认） |

### 4.2 手机验证页（`/`）

```
┌─────────────────────────────┐
│  MindSafe 家长端             │
│                             │
│  请输入您的手机号验证身份     │
│                             │
│  手机号  [138 1234 5678]    │
│  验证码  [______] [获取]    │
│                             │
│  [验证并查看报告]            │
│                             │
│  ─────────────────────────  │
│  验证通过后即可查看孩子      │
│  近 7 天的情绪周报           │
└─────────────────────────────┘
```

**流程：**
1. 链接含初始 Token（教师生成，`?token=xxx`）
2. 家长输入手机号 → `POST /parent/send-code`
3. 输入验证码 → `POST /parent/verify-phone` → 获得正式 7 天 Token
4. Token 存 localStorage → 跳转 `/report`

## 8. 安全与合规

| 项 | 措施 |
|---|---|
| Token 安全 | 初始 Token 仅用于验证流程；正式 Token 7 天过期 |
| 手机号脱敏 | 前端展示 `138****5678`，后端日志同 |
| 只读原则 | 家长端无写入接口（除撤回同意），不暴露对话原文 |
| 撤回不可逆 | 二次确认弹窗 + 明确文案告知后果 |
| PIPL 告知 | 验证页底部链接到告知同意条款（design/22） |

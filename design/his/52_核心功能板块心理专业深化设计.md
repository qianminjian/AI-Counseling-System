## 〇、总纲：必须先理解的"双世界架构"

这是理解本文所有板块缺口的**总前提**。当前 `backend/` 存在**两套并行、互不连通**的对话实现：

|---|---|---|
| 入口 | [ConversationServiceImpl.sendMessageStream](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/conversation/ConversationServiceImpl.java#L131-L280) → [AiChatServiceImpl.chatWithPrompt](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/chat/AiChatServiceImpl.java#L113) | [ConversationOrchestrator.orchestrate](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/orchestrator/ConversationOrchestrator.java#L51) |

| 风险处理 | 输入侧 `RiskDetectorService.detect`（关键词硬规则）+ 输出侧 Layer1/Layer2 过滤；**ORANGE/RED 不短路 LLM** | L4/L5 短路，直接返回 `CrisisResources` 硬编码安全话术，**不经 LLM** |
| 情绪 | 会话级静态 `emotionTag`（唤醒词 onboarding 时一次性选定）注入 prompt；**无逐轮情绪识别** | 逐轮 `EmotionAgent.recognize()` LLM 分类 + 强度门控 |
| CBT | 无状态机；靠 SYS_001 隐性引导 | `CBTAgent` + `CbtStateMachine`（S0–S9 显式转移）驱动 |

**代码证据（世界 B 是死代码）**：全仓搜索 `ConversationOrchestrator` 的 `orchestrate(` 调用点——**仅在其自身定义与注释中出现，无任何 Controller/Service 调用**。`SafetyAgent`/`EmotionAgent`/`CBTAgent`/`ConversationAgent` 仅被孤儿 orchestrator 依赖，未进入 counseling-service 线上链路。SKL_001 仅被孤儿 `CBTAgent` 渲染；SKL_002/003 仅在 [PromptVersionService](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/prompt/PromptVersionService.java#L39-L41) 注册映射，**从不被任何存活流程注入**。

**这意味着**：设计文档（03/04/13/14/44）描述的"结构化 CBT 状态机、情绪门控、Agent 分诊、危机短路"**在代码里都真实存在**，只是**接在了一条没通电的线上**。线上产品实际是"一个大 system prompt + 关键词风控 + 输出过滤"的**纯 LLM 自由发挥**形态。

> 这是本文与 `design/53`（设计-实现脱节）最大的共享结论：核心治疗板块的"专业性"目前**主要托付给单个 prompt 与底座模型**，结构化治疗保真度未在线上生效。下文各板块缺口，均在此总纲下展开。

## 一、CBT 认知行为干预流程板块

### 1.1 设计规格（design/03 CBT 对话流程树、design/44 情绪门控）

- S0–S9 状态机：安全预检→情绪命名→场景路由→事件澄清→自动思维→认知重构→微行动→复检收束→升级。
- 情绪门控：高唤醒（ACTIVATED/CRISIS）**禁止**直接认知重构，先调节再认知（design/44 §情绪门控 CBT）。
- 12 轮上限自动收束（SKL_001 内约束）。

### 1.2 代码现状（code-verified）

- **状态机已实现但孤儿**：[CbtStateMachine](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/state/CbtStateMachine.java#L30) 有完整 S0–S9 转移表 + 全局风险覆盖（任意态 ORANGE/RED→S9）；`evaluateFromOrchestration` 基于 boolean 标志（emotionObtained/eventConfirmed…）推断 trigger。但其唯一调用者 `CBTAgent`→`ConversationOrchestrator` 属**世界 B（从不运行）**。
- **线上无 CBT 结构**：世界 A 的 `chatWithPrompt` 从不注入 SKL_001，不驱动状态机。CBT 推进**完全由 LLM 在 SYS_001 内自由发挥**。
- **场景路由 S3 无实现**：状态存在，无场景分类器落地。
- **无轮次自动收束**：世界 A 靠 `context.isTurnLimitReached()`——但该判断也在孤儿 orchestrator 内；线上仅 `endSession` 手动结束。

### 1.3 心理专业缺口

1. **无情绪门控（最关键）**：容纳之窗（window of tolerance）理论要求——学生处于过度唤醒时，前额叶认知功能离线，此时做"认知重构"（挑战想法）不仅无效且可能造成二次伤害。线上纯 LLM 无任何机制保证"先调节情绪再进入认知工作"，完全依赖模型自觉。
2. **CBT 保真度不可观测**：无状态标记 → 无法知道任一会话是否真的走完了"事件-想法-情绪-行为"的 ABC 链路，还是只是泛泛安慰。这使 `design/45` 的质量评估失去"治疗步骤完成度"维度。
3. **认知重构与年龄不匹配**：皮亚杰——1-2 年级（前运算/具体运算早期）不具备抽象"审视自己想法"的元认知能力。对低龄段应以**行为激活 + 情绪命名**为主而非苏格拉底式提问，当前无年龄分流。

### 1.4 优化方案（借鉴心理专业 + 业界最佳实践）

- **接通世界 B 或将门控下沉到世界 A（二选一，见 §六 决策项 DEC-CBT）**：无论哪条路，都必须让"情绪门控"在线上生效——`allowCbt = emotionState ∉ {ACTIVATED, CRISIS}`（对齐 ORCH-002）。
- **CBT 阶段轻量标记**：即便保留单 prompt 形态，也应让 LLM 在结构化输出里回吐 `cbt_stage` 标签（Woebot 式"技能卡"埋点），落库供 `design/45` 评估"步骤完成度"与轮次收束。
- **年龄分层技能路由**：低龄→行为激活/情绪命名（SKL 简化版）；高龄→标准苏格拉底式认知重构。与 design/29 年级降级复用同一 `effectiveGrade`。
- **Affect Labeling 前置**：任何认知工作前先"情绪命名"（"把感受说出来"本身即降唤醒，fMRI 证据），对应 S2 应为 S5/S6 的强制前置门。

### 1.5 落地缺口→backlog

| 缺口 | 映射 | 说明 |
|------|------|------|
| 情绪门控在线上生效 | ORCH-002（已登记） | 依赖 DEC-CBT 决策 |
| CBT 阶段标记落库供评估 | **新增 CBT-201** | 结构化输出 `cbt_stage`，接 design/45 |
| 年龄分层 CBT 技能路由 | **新增 CBT-202** | 复用 effectiveGrade |
| 世界 A/B 编排收敛决策 | **DEC-CBT**（§六） | 架构级决策，先于 CBT-* |

## 二、风险识别与危机干预板块

### 2.1 设计规格（design/04 风险识别规则库）

- 三层：M1 关键词硬规则 → M2 语义分类（LLM SAF_001，L0–L5）→ 评分公式 `RiskScoreCalculator`（design/04 §十有完整加权公式）→ 趋势 `TrendAnalyzer`。
- RED 硬升级：立即通知 + 危机热线 + 转人工。

### 2.2 代码现状（code-verified）

- **M1 已实现且线上生效**：[RiskDetectorServiceImpl](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/risk/RiskDetectorServiceImpl.java#L27) RED_HARD/ORANGE/YELLOW 关键词 + 否定词 + 引用降噪；由世界 A 的 `sendMessageStream` L155 真实调用。
- **M2 语义分类已接线**：`SemanticRiskClassifier`（SAF_001）已在世界A 主流程接线（RISK-202 落地，`ConversationRiskProcessor` 调用），硬规则未达橙级时非流式前置调用，只升不降。~~原文“线上无语义风险理解”已过时。~~
- **评分公式未实现**：无 `RiskScoreCalculator`（find 确认不存在）；design/04 §十公式停在纸面。
- **趋势未实现**：无 `TrendAnalyzer`。
- **~~危机不短路 LLM~~（已修复，RISK-201 2026-07-28 落地）**：`ConversationServiceImpl` RED 时**直接返回 CrisisResources 硬编码话术 + 热线，跳过 LLM**；安全响应模式 `safetyMode` 后续轮次不再自由生成。

### 2.3 心理专业缺口

1. **无结构化自杀风险筛查**：C-SSRS（哥伦比亚自杀严重程度量表）区分"被动意念/主动意念/计划/预备/尝试"五级，对应差异化响应。当前仅关键词命中→RED 一刀切，无法区分"我不想活了"（表达痛苦）与"我准备好绳子了"（迫在眉睫），响应强度无法匹配。
2. **关键词漏隐性表达**：儿童危机表达常为隐喻/间接（"想去很远的地方""大家没有我会更好"），关键词必然漏检；M2 语义层不上线 = 只能抓显性词。
3. **危机时仍走生成式回复**是儿童安全红线级隐患：在最高危时刻把话术交给概率模型，即便有输出过滤，也存在生成不当内容的窗口。

### 2.4 优化方案

- **RED 硬短路（✅ 已落地，RISK-201 2026-07-28）**：线上 `sendMessageStream` 在 fusedLevel==RED 时**直接返回 CrisisResources 硬编码话术 + 热线，跳过 LLM**；安全响应模式 `safetyMode` 后续轮次返回陪伴话术。
- **M2 语义层上线**：将 SAF_001 语义分类接入线上（哪怕作为 M1 之后的二级确认），补隐性表达召回。
- **C-SSRS 结构化分级**：把 RED 细分为"意念/计划/预备-尝试"，绑定差异化 next_action（关注 vs 即时人工 vs 通知监护人），落地 design/04 §十评分公式的儿童适配版。
- **TrendAnalyzer 纵向信号**：跨会话负面趋势→教师非实时关注（与 design/51 BL-08 统一通道对齐）。

### 2.5 落地缺口→backlog

| 缺口 | 映射 |
|------|------|
| RED 硬短路跳过 LLM | **新增 RISK-201（P0 安全，最高优先）** |
| M2 语义分类上线 | **新增 RISK-202** |
| RiskScoreCalculator + C-SSRS 儿童分级 | **新增 RISK-203**（落地 design/04 §十） |
| TrendAnalyzer 纵向趋势 | VCL-003/MEM-103 + **RISK-204**，汇入 BL-08 通道 |

## 三、儿童安全对话规范板块

### 3.1 设计规格（design/14 儿童安全对话规范）

- Layer1 输出流式硬过滤 + Layer2 异步语义审查（SAF-002）。
- PII 脱敏；保密边界；危机热线；AES-256 内容加密；使用时长/频率限制。

### 3.2 代码现状（code-verified）

- **Layer1 已实现且生效**：[OutputContentFilter](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/safety/OutputContentFilter.java) 流式滑动窗口硬拦截，命中 self_harm_method 追加热线（`CRISIS_HOTLINE="400-161-9995"` 硬编码）。
- **Layer2 已实现但只检测不改写**：[OutputReviewService](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/safety/OutputReviewService.java) fire-and-forget 异步 SAF-002，仅留痕（level=1 不通知），**不召回不改写**——即孩子已看到的内容无法撤回。
- **PII 已实现**：[PiiDesensitizer](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/safety/PiiDesensitizer.java) 手机/身份证/邮箱掩码；**不处理真实姓名/地址**。
- **使用时长限制已实现**：`UsageTimeLimitService`（L143-147、L222-234，每日上限引导休息）。
- **AES-256 内容加密未实现**；热线号码硬编码（多地热线/学校自定义无法配置）。

### 3.3 心理专业缺口

1. **保密边界的"知情同意"话术缺失**：儿童保密例外（伤害自己/他人时须告知成人）应在关系建立初就用儿童能懂的话说清（"有些话我必须告诉能保护你的大人"），否则 RED 时突然"已通知老师"会造成背叛感、破坏治疗联盟。当前 buildGreeting 无此告知。
2. **Layer2 不召回**：异步审查发现问题时内容已抵达儿童，对低龄用户风险不对称。
3. **姓名/地址未脱敏**：儿童常直呼同学/老师全名，社交图谱 PII 未防护。

### 3.4 优化方案

- **保密边界儿童化告知**：会话初/唤醒 onboarding 加入一次性"保密与例外"儿童话术（对齐 design/22 告知同意，但落到对话首触点）。
- **Layer2 升级为"轻量前置门"**：对高敏感场景（危机/自伤）改为**流前快速语义预检**而非纯事后，或对 Layer2 命中触发教师关注 + 会话软收束。
- **热线可配置**：`CRISIS_HOTLINE` 提到学校/地区配置（多租户），去硬编码。
- **姓名/地址脱敏扩展**：结合会话上下文的命名实体识别，扩 PiiDesensitizer。

### 3.5 落地缺口→backlog

| 缺口 | 映射 |
|------|------|
| 保密边界儿童化告知话术 | **新增 SAFE-201**（接 design/22） |
| Layer2 高敏场景前置化/触发关注 | **新增 SAFE-202** |
| 热线号码多租户可配置 | **新增 SAFE-203** |
| 姓名/地址脱敏扩展 | **新增 SAFE-204** |
| AES-256 内容加密 | 已在 design/31 等保差距登记 |

## 四、情绪识别与共情陪伴板块

### 4.1 设计规格（design/44 情绪驱动策略、design/47 语音情感）

- 逐轮情绪识别（文本 + 语音 SER 融合）→ `currentEmotion` → 共情策略路由（情绪镜映话术库 情绪×年龄，ORCH-004）。
- 情绪状态机会话内漂移切换（sad→crisis 升级 / anxious→calm 缓解）。

### 4.2 代码现状（code-verified）

- **线上无逐轮情绪识别**：世界 A 用会话级静态 `emotionTag`（onboarding 选定）注入 prompt，全程不变。`EmotionAgent`（LLM 逐轮分类 primaryEmotion/intensity/trend）属**世界 B 孤儿**。
- **语音情绪只喂风险**：[L149-152](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/conversation/ConversationServiceImpl.java#L149-L152) voiceEmotion 仅 `addEmotionRecord`（内存）+ 进 `fuseRiskSignals` 风险 max 融合；**不驱动共情、不回注画像**（= design/51 BL-04）。
- **无共情策略路由**：共情完全靠 SYS_001 内 LLM 自由发挥；无情绪镜映话术库；无情绪漂移状态机。

### 4.3 心理专业缺口

1. **共情缺"命名-确认-容纳"结构**：循证共情（Rogers 无条件积极关注 + Affect Labeling）有明确步骤：先**准确命名**孩子的情绪→**正常化/确认**（"有这种感觉很正常"）→再陪伴。纯 LLM 易滑向"急于解决问题/说教/廉价安慰（'别难过啦'）"，恰是儿童最反感的无效共情。
2. **静态 emotionTag 与真实情绪脱节**：孩子进入时选"开心"，聊着聊着崩溃，系统仍按"开心"人设回应——情绪漂移不可感知，是治疗性倾听的根本缺失。
3. **文本×语音不一致（掩饰）未利用**：孩子嘴上"没事"、声音发抖，正是最需要关注的时刻；SER 信号不进共情维度，浪费了多模态最大价值。

### 4.4 优化方案

- **逐轮情绪感知进入策略（依赖编排枢纽）**：让情绪（文本+语音融合）成为一等策略输入，对齐 design/44 currentEmotion / VCL-001。
- **共情话术库（情绪×年龄）结构化**：ORCH-004 落地"命名→确认→容纳"三段式镜映模板，替代自由发挥。
- **情绪漂移状态机**：会话内 emotionState 动态切换（ORCH-003），sad→crisis 触发升级、anxious→calm 触发巩固。
- **不一致检测**：文本正性 + 语音负性 → 提升关注权重（VCL-002），共情策略切"温和探询"。

### 4.5 落地缺口→backlog（多数已登记）

| 缺口 | 映射 |
|------|------|
| 逐轮情绪进共情策略 | VCL-001 + ORCH-001 |
| 共情三段式话术库 | ORCH-004 |
| 情绪漂移状态机 | ORCH-003 |
| 文本×语音不一致检测 | VCL-002 |
| 共情"命名-确认-容纳"评估维度 | **新增 EMP-201**（接 design/45 质量评估） |

## 五、会话流程与治疗联盟板块

### 5.1 设计规格（design/03 收束、design/28 暖场、design/20 端到端）

- 暖场（TSK_004）→ 主体 → 收束（TSK_003 R0/R1 正常、R2+ 转人工）。

### 5.2 代码现状（code-verified）

- **暖场/问候**：`buildGreeting`（L113、L552 固定 switch-case 情绪问候）——规则化、非个性化。
- **冷场决策已实现且生效**：[NudgeDecisionModel](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/conversation/NudgeDecisionModel.java) 8 信号加权（留白/轻陪伴/引导破冰）——结构化控制，属线上世界 A。
- **收束**：`endSession`（L384-406）DB 收尾 + clearMemory + `generateSummaryAsync` + updateProfile；**未触发质量评估**（= design/51 BL-02）。
- **无治疗联盟维护机制**：无中断/回归识别，无"上次聊到…"的连续性开场（记忆 top5 回注对话已实现，但未用于连续性开场话术）。

### 5.3 心理专业缺口

1. **治疗联盟（therapeutic alliance）无经营**：联盟质量是心理干预效果最强预测因子。当前会话是"无记忆感的一次性对话"——固定问候、无连续性、无关系累积感。儿童尤其需要"它记得我"的被重视感。
2. **收束缺"巩固-希望-桥接"**：循证收束应包含①小结今天的收获（自我效能）②给一点希望③桥接下次/现实支持。当前 TSK_003 有话术但因无阶段标记，无法确保 LLM 真的做了巩固。
3. **无中断-回归照护**：孩子突然消失（可能正是风险信号）无识别；回归时无温暖接续。

### 5.4 优化方案

- **连续性开场**：用已实现的记忆回注生成"上次我们聊到…，今天怎么样"式个性化续接（利用 LongTermMemoryService，接 MEM-102 continuity）。
- **收束三段式 + 评估触发**：`generateSummaryAsync` 末尾追加质量评估调用（BL-02/PEVAL-001）；收束话术结构化"巩固-希望-桥接"。
- **中断-回归信号**：长时间未回话→非实时关注信号（汇入 BL-08 通道）；回归温暖接续。

## 六、架构级决策项与新增缺口汇总

### 6.1 决策项（✅ 钱敏健 2026-07-28 已定夺）

**DEC-CBT · 双世界编排收敛（先于所有 CBT/情绪结构化任务）**

现状：`design/13` 的 Agent 编排（世界 B）已完整实现却从未接线；`design/44` 又提出 `PromptOrchestrationService`（世界 A 内的编排枢纽，ORCH-001）。二者**语义重叠但架构不同**（多 Agent 分诊 vs 单 prompt 策略编排）。若不先收敛，ORCH-001/CBT-*/EMP-* 会造出第三套编排。

三条路径（历史备选，留档）：
1. **激活世界 B**：接线 `ConversationOrchestrator` 到线上，废弃单 prompt 路径。优点：结构化治疗保真最高；风险：多 Agent 多次 LLM 调用延迟↑、成本↑，与流式体验冲突。
2. **门控下沉世界 A**：保留单 prompt 主体，只把“情绪门控/CBT 阶段标记/危机短路”作为轻量结构层加到世界 A（ORCH-001 方向）。优点：改造面小、延迟可控；风险：治疗结构仍较弱。
3. **混合**：危机短路（RISK-201）+ 情绪门控走结构化硬控制，CBT/共情推进保留 LLM + 阶段标记回吐。本文原倾向路径 3。

**✅ 决策结果（钱敏健 2026-07-29 最终决策，推翻原「路径1激活」）：删除世界 B**——`ConversationOrchestrator` + `agent/` 包 + `state/` 包（含 CbtStateMachine）已从代码库整体删除（commit c9af478）。决策依据：整链零调用死代码 + 职责与世界 A 重叠 + 激活将形成双份编排违背 KISS/DRY。线上唯一生效架构为世界 A（`ConversationServiceImpl` + `PromptOrchestrationService`）。详见 design/13 §十三。
- 多 Agent 多次 LLM 调用的延迟/成本上升须在接线前完成评估；
- **编排层必须先解决与 SSE 流式输出的兼容方案**（分诊 Agent 非流式前置 + 回复 Agent 流式输出，或等效方案）；
- ORCH-001~008（design/44 世界 A 内编排）须与本决策对齐：其“策略层”能力并入世界 B 编排链，避免第三套编排。

## 七、结论

1. **核心发现**：五大治疗板块的"专业结构"在代码里**大多已建成**（CBT 状态机、情绪 Agent、危机短路、SKL/SEL/PFA 模板齐备），但被接在**从未通电的世界 B** 上；线上真实运行的是**单 prompt 纯 LLM + 关键词风控 + 输出过滤**。因此当前治疗专业性主要托付给单个 prompt 与底座模型，结构化治疗保真度未生效。
2. **最高价值、最低成本快赢**：`RISK-201`（RED 硬短路跳过 LLM）——纯安全收益、可独立立即做、复用现成 `CrisisResources`，且修复一处儿童安全红线级脱节。建议与 `PEVAL-001`（BL-02 评估触发）并列为立即启动项。
3. **总闸门**：`DEC-CBT` 双世界收敛决策是 CBT/情绪结构化任务的前置——**✅ 钱敏健 2026-07-29 最终决策：删除世界 B**（推翻原「路径1激活」，见 §6.1 决策结果）。
4. **心理专业主线缺口**（跨板块）：情绪门控（容纳之窗）、C-SSRS 结构化风险分级、共情"命名-确认-容纳"、治疗联盟经营（连续性/收束巩固）——这四条是把"能聊天的 AI"提升为"像受训儿童心理工作者"的关键，均已转化为可执行 backlog。

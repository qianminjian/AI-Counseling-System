## 一、背景与问题

当前学生端存在三个割裂的体验问题：

| # | 问题 | 现状 | 影响 |
|---|------|------|------|
| 1 | **品牌混乱** | PWA 名"心理小伙伴"、favicon 是紫色闪电⚡、AI 人设"心晴小助手"、伙伴角色"波波/棉花糖/小星"三选一 | 孩子记不住产品叫什么，品牌资产无法沉淀 |
| 2 | **伙伴是死的** | 伙伴只是一个静态 emoji（🐬），摆在 Header 和 Pad 左栏，无任何生命感 | 孩子感受不到"陪伴"，辅导关系难以建立 |
| 3 | **语音输入工具化** | 语音按钮是灰色麦克风图标，冷冰冰的功能按钮 | 与"心理陪伴"的温暖定位不符，孩子没有按下去的欲望 |

**核心洞察**：对小学生做心理辅导，"关系"先于"功能"。孩子不是在使用一个工具，而是在和一个朋友说话。这个朋友必须是**活的、有名的、可触碰的**。

## 二、设计目标

| 维度 | 目标 |
|------|------|
| 品牌 | 产品名、图标、角色、AI 人设全部统一为"波波小精灵 / 波波"，形成单一品牌资产 |
| 生命感 | 波波是一个有状态的活物：会漂浮、会眨眼、会思考、会说话 |
| 交互 | 波波本身就是语音输入入口——按住它说话，它会蜷成发光的圆球听你说 |
| 一致性 | AI 说话时，声音从波波的"嘴"里出来（头顶气泡 + TTS 同步） |

### 3.3 主题系统调整（角色固定，颜色可变）

原设计（`design/55` §2.1）三个主题配三个不同角色（海豚波波 / 兔子棉花糖 / 星星小星）。**本次调整：角色固定为波波，主题只换颜色。**

| 主题 | 色调 | 伙伴形象 |
|------|------|---------|
| 🌊 海洋探险（默认） | 蓝绿 #0EA5E9 | 🐬 波波（天蓝） |
| 🌸 花园精灵 | 粉紫 #EC4899 | 🐬 波波（粉调） |
| 🌈 彩虹自由 | 紫 #8B5CF6 | 🐬 波波（紫调） |

**理由**：
- 孩子喜欢换颜色（保留个性化），但品牌角色不能换（品牌资产）
- 波波是海豚，换色调只需改 SVG 填充色，成本低
- 删除"棉花糖/小星"两个角色，减少设计与维护负担（YAGNI）

## 四、波波宠物动画设计

### 4.1 设计原则（借鉴 Codex 宠物，去其冷感）

Codex 宠物的本质是"一个有状态的活物 + 说话冒气泡"。我们学其**行为模型**，但形象适配儿童：

| Codex | 波波小精灵 |
|-------|-----------|
| 像素风机器人（开发者工具的冷感） | 圆润手绘海豚（儿童的温暖感） |
| 面部显示命令行 `>_` | 大眼睛 + 粉腮红 + 微笑嘴 |
| 静态待机 | 持续漂浮 + 眨眼 + 尾巴摆（静止 = 死亡） |

### 4.2 形象规格（纯 SVG，零图片资源）

```
波波 = 以下部件的可动画组合：
├── 身体：水滴形，天蓝 #38BDF8（主题色驱动）
├── 肚皮：浅蓝 #E0F2FE，下半部
├── 背鳍：深蓝 #0284C7，顶部
├── 尾鳍：深蓝，右侧两瓣（可摆动）
├── 胸鳍：深蓝，身侧（可扇动）
├── 眼睛：大白色圆 + 黑瞳孔 + 白高光（可眨眼）
├── 嘴巴：微笑曲线（说话时切换为开合椭圆）
├── 腮红：粉色椭圆 ×2
└── 呼吸孔：头顶小细节
```

**优势**：SVG 逐部件可动画、无限缩放、随主题变色、包体积 < 3KB。

### 4.3 四态状态机

波波的状态与聊天状态**精确映射**，无需后端改动：

| 状态 | 触发条件（前端现有状态） | 波波动画 | 头顶 |
|------|------------------------|---------|------|
| 待机 idle | 默认 | 上下漂浮 + 尾鳍摆 + 每 3-5s 眨眼 | 无 |
| 聆听 listening | `recording === true` | 身体前倾 + 胸鳍竖起 + 周围声波纹扩散 | 无 |
| 思考 thinking | `streaming === true`（AI 生成中） | 眼睛看天 + 身体轻晃 | 思考泡泡 `•••` |
| 说话 speaking | `tts.playing === true`（TTS 朗读中） | 嘴巴开合 + 身体律动 | **话语气泡（当前朗读句）** |

**状态优先级**：`recording > streaming > tts.playing > idle`
（三者互斥：录音时 AI 不生成；TTS 在生成结束后才播放；按住麦克风会 `tts.stop()`）

**关键语义**：`streaming` = AI 在"写"（思考），`tts.playing` = AI 在"读"（说话）。两者天然分离，状态机直接接上。

### 4.4 话语气泡（核心功能）

| 属性 | 规格 |
|------|------|
| 位置 | 波波头顶，带指向头部的小尾巴 |
| 内容 | **TTS 正在朗读的那一句**（逐句滚动，与"说话"同步，非整段） |
| 思考态 | 显示 `•••` 思考泡泡（无文字） |
| 动效 | 弹出（scale 0.8→1 + 淡入）+ 说话时轻微律动 + 结束淡出 |
| 字数 | 单句，超长自动换行，最多 3 行 |

**数据来源**：`useTtsPlayer` 需新增暴露 `currentSentenceText`（当前朗读句文本）。现有 `currentSentenceIdx` + 句子数组即可推导，改动极小。

### 4.5 布局

| 端 | 位置 | 尺寸 |
|----|------|------|
| 手机（主场景） | 悬浮在输入栏右上角 | ~72px |
| Pad（lg+） | 现有左栏（替换原 emoji 伙伴区） | ~160px |

## 五、语音输入圆球设计（波波即圆球）

### 5.1 核心决策：宠物与输入合一

**不把"宠物"和"语音输入"做成两个东西——波波本身就是语音输入圆球。**

理由：
- 手机屏幕寸土寸金，悬浮宠物 + 独立圆球 = 两个悬浮物，又挤又乱
- Pad 左栏现在本来就是"伙伴形象 + 语音大按钮"上下摆放，它俩天生是一个东西
- 合一后：波波不是界面里的一个图标，它就是你和 AI 说话的那个"人"

### 5.2 交互流程（按下蜷成球）

| 阶段 | 波波形态 | 圆球感觉 | 触感 |
|------|---------|---------|------|
| 待机 | 海豚形态，轻轻漂浮 | 身下一圈柔和呼吸光晕（暗示可触碰） | - |
| 手指按下 | 身体挤压变形（squish） | 光晕瞬间点亮、放大 | vibrate(10) |
| 录音中 | **海豚蜷成发光圆球**，球面跑声波波纹 | 动态圆球本体：脉冲 + 涟漪扩散 | - |
| 上滑取消 | 球变红、波纹收缩 | 反馈"要取消了" | vibrate([20,30,20]) |
| 松开 | 弹回海豚形态，开心蹦一下 | 光晕柔和回落 | vibrate(10) |

**"按下蜷成球"一个变形动作同时解决三件事**：
1. 它就是动态小圆球（录音时是个活球）
2. 保留角色感（球是波波变的，不是凭空 UI）
3. 给出明确"我在听"反馈（形态变了 = 状态变了）

### 5.3 触感反馈（tactile）

| 平台 | 实现 |
|------|------|
| Android Chrome | `navigator.vibrate()`：按下/松开各一次，取消两次 |
| iOS Safari | 不支持 vibrate API → 用**视觉挤压 + 弹性回弹动画**补偿 |

### 5.4 布局变化

| 端 | 变化 |
|----|------|
| 手机 | **删除**输入栏的麦克风按钮；波波悬浮输入框右上角，按住说话。输入栏变为 `[文字输入] [发送]` |
| Pad | 左栏"emoji 伙伴 + 大麦克风按钮"**合并为一个波波**，按住说话 |
| 引导 | `WelcomeGuide` 增加一句："按住波波，跟它说说话"（解决可发现性） |

### 5.5 为什么不做"麦克风/圆球配置切换"

- **YAGNI**：两套交互 = 双倍测试、双倍边界情况，MVP 不值得
- 目标用户是孩子，设置里藏"输入方式切换"是坏体验
- 与其两个都 60 分，不如一个 95 分
- **架构留口**：圆球做成独立组件，将来想加回麦克风模式随时可加，不堵死

## 七、合规与无障碍

| 项 | 说明 |
|----|------|
| 数据 | 纯前端动画，**不新增任何数据采集** |
| 动效克制 | 无惊吓元素、无高频闪烁（≤3 次/秒），避免诱发不适 |
| 可关闭 | 静音模式（已有）同时关闭气泡朗读；动画不影响文字阅读主路径 |
| 风险场景 | 红色风险时波波保持温柔安抚态，不表现惊慌（与 design/14 一致） |
| 触觉 | vibrate 为可选增强，iOS 自动降级为纯视觉 |

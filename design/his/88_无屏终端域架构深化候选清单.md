## 一、背景与走查结论

近三天无屏交互终端（device）域密集叠加 5 个安全/审计提交（ff9d856/fc5ffb1/6361b3d/05db032/4c64ad9），识别出：

- **阻断 1 项**：4c64ad9 将 auditOperation 追加到 DeviceService 类外致编译失败（**已修复：84e78df 移入类内**）
- **安全假功能 1 项**：P0-1 声称的 report 通道签名鉴权未接线（validateToken 零调用 + SecurityConfig 不匹配 + config/pull 匿名泄露凭证）
- **结构摩擦 7 项**：浅模块/薄壳/名单退化/授权分裂/原子性缺失/适配层分裂/路由碎片

摩擦统计：阻断/安全级 3 + 结构性 5 + 前端碎片 2；近三天引入摩擦占主导（编译/假功能/权宜/碎片/漂移）。

## 二、候选清单

### AD-001 设备档案模块深化（浅门面 → 深模块）

- **涉及文件**：DeviceService.java（449 行，16 public 方法，6 构造器依赖）/ DeviceVoiceprintService / DevicePreferenceService / DeviceSecurityService / PlatformDeviceService
- **问题**：16 个 public 方法横跨 7 概念（档案状态机/绑定会话/配置面/安全凭证/偏好/操作受理/审计），每方法「取参→校验→mapper→手组 Map」——接口面≈实现宽度（浅）。4c64ad9 类外方法致编译失败即浅模块实价；ota/reboot/factoryReset 审计接入不一致（reboot 漏接）。
- **解决**：按「验证码会话」（生成/哈希/锁定/作废/双因子）与「档案状态机」（UNACTIVATED→ONLINE_UNBOUND→ONLINE_BOUND）收成两个深模块；审计写入降级为构造器注入横切件。
- **删除测试**：删 DeviceService → 绑定会话真实深度（验证码过期/锁定/失败计数）与状态机复杂度**移动**到 controller/散落新类（坏）——当前为门面式聚集，复杂度未封装仅并置。
- **推荐**：Strong

### AD-002 设备上报安全通道接线（「一个适配器」→ 真实接缝）

- **涉及文件**：DeviceSecurityService / SecurityConfig / DeviceService.pullConfig
- **问题**：validateToken 生产零调用（仅测试引用）；SecurityConfig report/** 配 authenticated()（要 JWT）而设备只有 DVC_ token → 真实设备全 401；config/pull 为 permitAll 且在匿名通道下发 deviceToken → 凭证泄露。token = "DVC_"+code+"_"+sign(secret, secret)（签名密钥=数据本身）+ 无过期校验。
- **解决**：token 校验器与 report 过滤链收成同一模块（含过期/重放窗口）；补齐消费端；config/pull 停止下发凭证。或撤销 authenticated() 回 permitAll + 显式登记「固件签名未落地」（frozen/73 §九）。
- **删除测试**：删除 DeviceSecurityService 后 reportOnline 少返回凭证、其余不变——因为校验端从未存在（一个适配器=假设性接缝）。
- **推荐**：Strong（安全假功能，生产阻断级）

### AD-003 租户行隔离名单规则源（手写退化 → 可推导规则/注册表）

- **涉及文件**：MindSafeTenantLineHandler（IGNORE_TABLES 13 表，V34→V45 七轮追加）/ MindSafeTenantLineHandlerTest
- **问题**：新平台表漏加 → 注入不存在 tenant_id 列 → SQL 500；测试无「名单 vs schema 一致性」断言；判定规则（表无 tenant_id 列）是现成推导，手写名单是退化实现。
- **解决**：a) 运行时列存在性检测；b) 平台域注册表单一规则源；c) 至少补测试：遍历迁移文件断言平台表 ∈ 名单（低成本高杠杆）。
- **删除测试**：名单无法删除（删掉平台表 SQL 全 fail-fast），问题在名单来源。
- **推荐**：Worth exploring

### AD-004 绑定会话归属校验（薄壳 → 深模块）

- **涉及文件**：TocDeviceService（49 行 100% 委托）/ TocDeviceController
- **问题**：unbind(familyAccountId,...) 的 familyAccountId 参数未使用——任何家庭可解绑任意设备；FAMILY 语义靠调用方传参，模块自身无校验；接口承诺（注释）> 实现。
- **解决**：「设备归属校验」（设备 ∈ 该家庭 ACTIVE 绑定）收进本模块成为核心深度；FAMILY 从参数变模块内常量。
- **删除测试**：删薄壳 → 家庭上下文上移表示层（移动=坏）；深化后才可删。
- **推荐**：Strong

### AD-005 配置面授权分裂（偏好读取统一身份解析）

- **涉及文件**：DevicePreferenceService（getPreferences vs preferencesForPull 两种授权语义）
- **问题**：同一数据两种授权；叠加 config/pull permitAll → deviceCode 印在二维码上（匿名可查 info），任何人可拉音量/音色/偏好——隐私泄漏路径已打通（叠加 AD-002）。
- **解决**：「谁的偏好」作为模块内不变量，读取统一经身份解析（匿名通道也须凭设备凭证关联家庭后查询）。
- **删除测试**：删 preferencesForPull → 下发逻辑塞回 pullConfig（移动=坏）；保留则授权分裂持续。
- **推荐**：Worth exploring

### AD-006 声纹任务状态机原子化（+ 自动完成权宜治理）

- **涉及文件**：DeviceVoiceprintService（reportPhase read-modify-write 无原子 + UPLOADED 自动 complete）
- **问题**：Redis 三段式无原子（并发覆盖丢更新）；P0-5 自动完成是「演示不卡死」权宜，COMPLETED 无真实语义；complete/fail 无 deviceCode 校验（与 reportPhase 不一致）。
- **解决**：状态迁移收成原子操作（Redis 版本号/比较并交换）；自动完成抽为明确迁移规则由 enroll 回调驱动。
- **删除测试**：删自动触发 → 前端轮询卡 UPLOADED（卡顿移动到前端/演示流）。
- **推荐**：Worth exploring

### AD-007 Controller 适配层统一（operator 双来源 + 异常转译）

- **涉及文件**：DeviceController（@RequestParam operator + wrap()）/ TocDeviceController（Authentication + 手写 catch）
- **问题**：同一系统两种 operator 来源（安全上下文泄漏 vs 正确提取）；异常转译双实现，无统一 @RestControllerAdvice；控制器重复服务层存在性检查。
- **解决**：操作人提取 + 业务异常转译收进统一适配层（@RestControllerAdvice）。
- **删除测试**：删 wrap/手写 catch → 异常转译无处安放（需要统一适配器=集中=好）。
- **推荐**：Worth exploring

### AD-008 家庭前端设备域单模块双适配器（按身份上下文切分）

- **涉及文件**：parent-h5 services/toc.ts + services/device.ts + pages/device/index.tsx（同页双 import）
- **问题**：同一设备概念两套 API 客户端、两套 token 前缀（parent_ vs toc_）、类型重复（DeviceInfo vs TocDeviceItem）；createBindCode/bindDevice 与 createTocBindCode/tocBindDevice 是同一后端能力的两个变体。
- **解决**：设备域按身份上下文（匿名扫码 vs 家庭登录）收成单一模块内两个适配器，共享类型与请求工厂。
- **删除测试**：删 device.ts → 扫码入口页（匿名上下文）并入登录态 toc.ts（移动=坏）。
- **推荐**：Worth exploring

### AD-009 管理端路由注册表化（浅路由 → 单一规则源）

- **涉及文件**：admin-web App.tsx（15 分支三元链）/ AdminLayout.tsx（AdminView union 18 值）
- **问题**：每加页面改 3 处（类型+菜单+三元链）；TS 对三元链兜底不穷尽检查，漏分支零告警（services/audit 分支确实缺失，develop 与 main 漂移）；allowedViews 与渲染各自维护。
- **解决**：「视图→组件」注册表单一规则源，allowedViews 共用。
- **删除测试**：删三元链换注册表 → 复杂度从类型+条件链**集中**为单一规则源（集中=好）。
- **推荐**：Worth exploring

## 三、首要建议

**先做 AD-002（设备上报安全通道）再 AD-004（绑定归属校验）**——合并为一个深化批次：设备身份与归属校验模块。

- AD-002 是安全假功能最典型样本（声称的鉴权实际让真实设备 401 且经 config/pull 泄露凭证）；删除测试结论明确（撤销后行为不变）
- AD-004 是同一接缝的另一半（归属校验缺失 → 越权解绑），与 AD-002 共用「设备身份解析」规则
- 附带：AD-003 至少补「名单 vs 迁移一致性」测试（低成本高杠杆）；AD-001 的编译错误已修复（84e78df）

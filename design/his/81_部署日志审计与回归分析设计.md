## §1 背景与目标

### 1.1 现状摩擦点

| # | 摩擦点 | 活证据 |
|---|--------|--------|
| F1 | 部署日志是哑数据 | DOC-077 落地后 `logs/deploy/deploy-*.log` 含结构化统计段（result/step_ms/signal），但仅在当次判定用，无定期回归分析——「部署过程是否在变坏」仍靠人看 |
| F2 | 失败模式靠人肉汇总 | 连续 3 次 `code=20003` 说明冒烟注册流程系统性失败，但无人统计出现频率，无法主动发现高频失败模式 |
| F3 | 变坏趋势无检测 | 某步骤耗时连续 3 次上升（如 build-images 512s→600s→700s）是变坏前兆，DOC-077 单次阈值判定无法捕捉跨部署趋势 |
| F4 | 日志无上限膨胀 | 每次部署 +1 份日志，无轮转策略，长期累积占磁盘且基线解析变慢 |

### 1.2 目标（DOC-078）

1. **日志回归分析**：每次部署完成后，基于 `logs/deploy/` 历史日志自动执行回归分析（成功率/失败模式聚类/耗时趋势/信号漂移/数据完整性）
2. **固定格式审计报告**：每次部署后输出标准化审计报告（窗口/样本/回归项/结论/问题清单/修复动作），全文落盘 + 终端摘要
3. **主动修复**：幂等安全的自动修复动作（日志轮转）+ 问题对应的修复指引输出
4. **标准化**：回归规则表（R1-R6）为唯一事实源，报告格式固定，修复分级固定（A1 自动 / A2 指引），新规则按表扩展

### 1.3 范围边界（YAGNI，不做）

- **不做自动回滚/自动重部署**（红线：生产变更需人工确认，审计只报告建议）
- 不做跨服务器聚合分析（单机日志已够，分布式分析属水平扩展阶段 frozen/40）
- 不做告警推送接入（部署侧无推送通道，企微告警属运行时监控 alertmanager 范畴）
- 不做日志入库（文本解析足够，引入 DB 属过度设计）
- 审计规则不引入机器学习（阈值/频率规则即可覆盖当前需求，KISS）

## §2 方案

### 2.1 审计模型总览

```
部署完成（dm_finish_deploy：汇报 → 统计段 → 快照）
        │
        ▼
dm_audit_run（deploy.sh trap 链第二步，deploy-audit.sh）
  1. 解析日志窗口（logs/deploy/deploy-*.log 最近 10 次，含本次）
  2. 回归规则评估（R1-R6，规则表见 §2.2）
  3. 主动修复（A1 日志轮转自动执行；A2 指引输出）
  4. 生成固定格式报告 logs/deploy/audit-<ts>.md
  5. 终端输出摘要（结论/异常数/修复动作/报告路径）
```

- **触发时机**：每次部署结束（含失败路径），`dm_finish_deploy` 写统计段后立即执行
- **数据源**：`logs/deploy/deploy-*.log` 统计段（`deploy_result=`/`step_<key>_ms=`/`signal=`），与 DOC-077 基线同源
- **窗口**：最近 10 次部署日志（与 dm_baseline 一致）；R4 趋势用最近 5 次
- **失败部署也审计**：失败本身就是最需要审计的样本

### 2.2 回归规则表（R1-R6，唯一事实源）

| 规则 | 名称 | 输入 | 触发条件 | 级别 | 修复动作 |
|------|------|------|----------|------|----------|
| R1 | 步骤耗时回归 | 本次日志 step_ms vs 历史基线（不含本次） | 复用 dm_judge：本次某步骤 WARN/CRITICAL | WARN/CRITICAL | A2：对应步骤原因映射文案 |
| R2 | 部署成功率 | 窗口内 deploy_result | 成功率 <80% → WARN；<60% → CRITICAL | WARN/CRITICAL | A2：失败模式知识库指引 |
| R3 | 失败模式聚类 | 窗口内日志全文特征计数 | 任一 dm_diagnose 特征出现 ≥3 次 | WARN | A2：dm_diagnose 指引 |
| R4 | 耗时趋势（变坏分析） | 最近 5 次同步骤 step_ms | 连续上升 ≥3 次 | WARN | A2：检查服务器磁盘/网络，L3 清缓存可缓解 |
| R5 | 信号漂移 | 窗口内 signal 分布 | 非 OK（WARN/CRITICAL）占比 ≥50% | WARN | A2：结合 R1/R4 明细定位 |
| R6 | 日志完整性 | 窗口内统计段 | 缺统计段日志 >2 份 | WARN | A2：检查 deploy.sh 出口链路 |

- 规则评估结果记入问题清单：`[P<n>][级别] R<k>：<描述>`，去重合并（同一规则多次命中合并为一条）
- 审计结论 = 问题清单最高级别；无问题 → OK（健康）

### 2.3 固定格式审计报告

```
================================================
🛡 MindSafe 部署审计报告（DOC-078 回归分析）
================================================
审计时间 : 2026-08-08 12:00:00
日志窗口 : logs/deploy/deploy-*.log（最近 10 次，含本次）
部署样本 : 10 次（成功 8 / 失败 2，成功率 80%）
回归项   :
  [R1] 步骤耗时回归  PASS（本次无超阈值）
  [R2] 部署成功率    80% PASS
  [R3] 失败模式聚类  2 次 code=20003 PASS
  [R4] 耗时趋势      build-images 连续 3 次上升 ⚠️
  [R5] 信号分布      30% 非 OK PASS
  [R6] 日志完整性    完整 PASS
结论     : ⚠️ WARN（1 项异常）
问题清单 :
  [P1][WARN] R4：build-images 耗时连续 3 次上升，可能变坏
  建议: 检查服务器磁盘/网络；docker builder prune 可缓解
修复动作 :
  ✅ 已执行: A1 日志轮转（上限 50 份，清理 3 份）
  ➡ 待人工: 无
审计依据 : 规则表 doing/81 §2.2（R1-R6）
================================================
```

- 全文落盘 `logs/deploy/audit-<ts>.md`；终端输出摘要 5 行（结论/样本/异常数/修复/报告路径）
- 报告文件名 `audit-<ts>.md` 与部署日志同目录，`*.md` 不受 .gitignore 的 `*.log` 规则影响——审计报告不提交仓库（`logs/` 全目录 gitignore，见 §2.4）

### 2.4 主动修复分级（A1/A2）

| 级别 | 动作 | 安全性 | 示例 |
|------|------|--------|------|
| A1 | 自动执行（幂等） | 仅运行时产物清理 | 日志轮转：`deploy-*.log` 超 50 份清理最旧（logs/ 为 gitignore 运行时产物，不触碰仓库文件） |
| A2 | 自动输出指引 | 只读分析 | R3 → dm_diagnose 知识库指引；R1/R4 → 原因映射建议 |

- 不做 A0（自动回滚/重部署）：生产变更红线，审计只报告建议
- `.gitignore` 追加 `logs/deploy/audit-*.md` 保护（虽 `logs/` 语义上应忽略，显式声明防误提交）

### 2.5 标准化机制

1. **规则表单一事实源**：R1-R6 规则定义集中在 doing/81 §2.2，实施代码逐条对应（规则 ID 注释标注），新规则按表扩展
2. **报告格式固定**：字段/分隔线/图标固定，机器可解析（人工可读），测试断言字段存在性
3. **修复分级固定**：A1 自动 / A2 指引，新增修复动作必须声明安全性（幂等、仅运行时产物）
4. **入口统一**：`dm_audit_run` 为唯一审计入口（deploy.sh trap 链第二步），与 DOC-077 出口编排同构

### 3.1 关键实现决策

1. **独立库 deploy-audit.sh**（SRP）：计时/判定归 deploy-metrics.sh，审计/回归归 deploy-audit.sh，后者 source 前者复用基线与知识库函数；避免单库膨胀（metrics 已 318 行）
2. **trap 链两段式**：`trap 'rc=$?; dm_finish_deploy "$rc" ...; dm_audit_run "$LOG_DIR" "$LOG_FILE"' EXIT`——审计不依赖部署退出码（审计任何结果都执行）
3. **R1 用 dm_judge 复用**：本次步骤耗时 vs 历史基线判定，与 DOC-077 汇报一致，不重复实现阈值逻辑（DRY）
4. **bash 3.2 + set -eo pipefail 纪律**：沿用 DOC-077 教训——grep 无匹配用 if 包裹或 `|| true`；变量 `${var}` 包裹（全角字符丢字节）
5. **窗口解析函数化**：`dm_audit_parse <log_dir>` 输出「文件名 result signal 各步骤 ms」单行记录，R2/R4/R5/R6 共用（DRY）

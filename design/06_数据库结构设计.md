## 1. 设计结论与边界

系统定位是「校园心理健康陪伴与早期情绪支持系统」，**不是医疗诊断系统**。数据库设计支持：情绪陪伴、轻度 CBT 引导、风险识别、人工转介、教师摘要、家校协同，同时避免过度采集。

**核心原则：**
- 所有业务表强制包含 `tenant_id`；学校域数据包含 `school_id`。
- 高敏表采用：字段级加密、行级隔离、访问审计、分区留存、到期清理。
- 会话侧**默认只保存结构化摘要、风险信号、模型运行元数据**，不保存完整原始对话、原始语音/视频、面部图像/模板、声纹等生物识别数据。
- MVP 不建生物识别表、完整聊天原文表、复杂数据湖。

**工程原则落实：**

| 原则 | 落实 |
|------|------|
| KISS | 核心业务用规范化关系表；动态量表/标签/权限点用 jsonb，避免大量小表 |
| YAGNI | MVP 先满足文本对话、测评、风险预警、教师后台 |
| SOLID | 租户/身份/授权/会话/测评/风险/个案/审计/模型日志分域建模 |
| DRY | 统一 `users` + `user_roles` 承载多角色，不为学生/老师/监护人重复建账号体系 |

## 2. 数据域划分

按「谁拥有、谁能看、保留多久、如何删除」划分。

| 数据域 | 核心表 | 敏感等级 | 建议留存 |
|--------|--------|:---:|------|
| 租户与学校域 | `tenants`, `schools` | S1-S2 | 合同期内保留；结束后 1 年内导出/删除/匿名化 |
| 身份与权限域 | `users`, `roles`, `user_roles` | S2-S3 | 有效期内保留；离校/离职后冻结，1-3 年内匿名化 |
| 监护人授权域 | `guardians`, `guardian_student_authorizations` | S3-S4 | 授权有效期内保留；撤回后仅保留证据哈希与审计 |
| 心理互动域 | `counseling_sessions`, `message_summaries` | S4 | 默认摘要 180 天；可配置至 1-2 学年；不留原文 |
| 测评域 | `assessment_scales`, `assessment_results`, `assessment_responses` | S1-S4 | 量表定义随版本保留；结果 2-3 学年内清理 |
| 风险与个案域 | `risk_events`, `case_records`, `case_interventions` | S4 | 结案/毕业后 3 年内复核清理 |
| 通知与审计域 | `notifications`, `audit_logs` | S3-S4 | 通知最小化；审计 1-3 年 |
| 知识库与模型运行域 | `knowledge_documents`, `knowledge_chunks`, `model_call_logs` | S1-S4 | 知识库按版本；模型日志 90-180 天且脱敏 |

## 3. ER 模型说明

- `tenants` 是根实体，一个租户含多个 `schools`、`users`、`roles`、`knowledge_documents` 及所有业务记录。
- `schools` 是学校级边界，下辖学生/教师/班主任/管理员/会话/测评/风险/个案/通知。
- `users` 统一承载所有登录账号；`roles` 与 `users` 通过 `user_roles` 多对多，用 `school_id`/`grade_code`/`class_code`/`case_scope_id` 控制作用域。
- `guardians` 与 students 通过 `guardian_student_authorizations` 建立多对多授权。
- `counseling_sessions` 记录一次有限回合会话；`message_summaries` 保存结构化摘要，不保存完整原文。
- `risk_events` 可由会话/测评/人工触发；高风险可创建 `case_records`；`case_interventions` 记录跟进。
- `audit_logs` 记录敏感访问/权限变更/导出/删除/风险处置，是追责与合规的事实表。
- `knowledge_documents` + `knowledge_chunks` 构成受控知识库；`model_call_logs` 记录调用可观测信息。

**关键关系：**

| 关系 | 说明 |
|------|------|
| tenants 1:N schools/users/roles | 最高隔离边界，查询以 tenant_id 为第一过滤条件 |
| users N:M roles | 通过 user_roles 绑定角色和作用域 |
| guardians N:M students | 通过授权表表达关系、范围、有效期、撤回 |
| students 1:N sessions/assessments/risk_events/cases | 展示优先用 pseudonym |
| sessions 1:N message_summaries | 不把每条原始消息持久化为明文 |
| risk_events 0/1:N cases | 一个风险事件可不开案，也可转多个后续个案动作 |
| knowledge_documents 1:N knowledge_chunks | 切片生成向量供 RAG；切片不含学生个人心理数据 |

## 4. 核心表结构（20 张表）

> 目标数据库：PostgreSQL 16。实际落库补充 `created_by`/`updated_by`/`version`/`deleted_at` 等通用审计字段。

### 4.1 tenants（租户表）— 隔离根

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| tenant_id | uuid | 主键 | S1 |
| tenant_code | varchar(64) | 租户编码 | S1 |
| tenant_name | varchar(128) | 租户名称 | S1 |
| data_region | varchar(32) | 数据存储区域/私有云区域 | S1 |
| kms_key_ref | varchar(128) | 租户级 KMS Key 引用，不存明文 | S4引用 |
| status | varchar(20) | active/suspended/closed | S1 |
| created_at, updated_at, deleted_at | timestamptz | 时间戳 | S1 |

索引：`uq_tenants_code(tenant_code)`, `idx_tenants_status(status)`

### 4.2 schools（学校表）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| school_id | uuid | 主键 | S1 |
| tenant_id | uuid | 所属租户 | S1 |
| school_code | varchar(64) | 租户内学校编码 | S1 |
| school_name | varchar(128) | 学校名称 | S1 |
| edu_stage | varchar(32) | 小学/九年一贯/其他 | S1 |
| province, city, district | varchar(64) | 行政区域 | S1 |
| settings | jsonb | 留存周期/通知策略/量表开关 | S2 |
| status | varchar(20) | active/suspended | S1 |

外键：`tenant_id -> tenants`；索引：`uq_schools_tenant_code(tenant_id, school_code)`, `idx_schools_tenant_status(tenant_id, status)`

### 4.3 users（用户表）— 统一账号

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| user_id | uuid | 主键 | S2 |
| tenant_id, school_id | uuid | 所属租户与学校（集团管理员 school_id 可空） | S2 |
| user_type | varchar(20) | student/teacher/head_teacher/admin/guardian | S2 |
| external_subject_id_hash | char(64) | 钉钉/微信/统一身份 ID 加盐哈希 | S3 |
| display_name_enc | bytea | 姓名密文 | S3 |
| pseudonym | varchar(64) | 匿名显示名，用于报表脱敏 | S2 |
| grade_code, class_code | varchar(32) | 年级与班级 | S2 |
| student_no_hash | char(64) | 学号加盐哈希 | S3 |
| mobile_enc, email_enc | bytea | 手机/邮箱密文，可空 | S3 |
| status, last_login_at | varchar/timestamptz | 状态与最近登录 | S2 |

外键：`tenant_id -> tenants`, `school_id -> schools`
索引：`idx_users_school_type(tenant_id, school_id, user_type)`, `uq_users_ext_hash(tenant_id, external_subject_id_hash)`, `idx_users_class(tenant_id, school_id, grade_code, class_code)`
脱敏：姓名/手机/邮箱字段级加密；学号/外部 ID 只存哈希；**不保存人脸/声纹/指纹**。

### 4.4 roles（角色表）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| role_id | uuid | 主键 | S1 |
| tenant_id | uuid | 租户内角色，支持系统预置 | S1 |
| role_code | varchar(64) | student/psych_teacher/head_teacher/school_admin | S1 |
| role_name | varchar(128) | 中文角色名 | S1 |
| scope_level | varchar(20) | tenant/school/class/case | S1 |
| permission_set | jsonb | 权限点集合，如 report.read_summary、case.manage | S2 |
| is_system, status | boolean/varchar | 是否预置及状态 | S1 |

索引：`uq_roles_tenant_code(tenant_id, role_code)`, `idx_roles_scope(tenant_id, scope_level)`

### 4.5 user_roles（用户角色授权表）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| user_role_id | uuid | 主键 | S2 |
| tenant_id | uuid | 租户隔离 | S2 |
| user_id, role_id | uuid | 用户与角色 | S2 |
| school_id | uuid | 授权学校范围 | S2 |
| grade_code, class_code | varchar(32) | 班主任等班级级范围 | S2 |
| case_scope_id | uuid | 仅授权某个个案时使用 | S4引用 |
| effective_from, effective_to | timestamptz | 授权有效期 | S2 |

索引：`idx_user_roles_user`, `idx_user_roles_role`, `idx_user_roles_scope(tenant_id, school_id, grade_code, class_code)`；权限变更须写 `audit_logs`。

### 4.6 guardians（监护人表）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| guardian_id | uuid | 主键 | S3 |
| tenant_id | uuid | 租户隔离 | S3 |
| guardian_user_id | uuid | 可选，关联 users 中 guardian 账号 | S3 |
| name_enc, phone_enc | bytea | 姓名/手机密文 | S3 |
| relation_type | varchar(32) | father/mother/grandparent/other | S3 |
| id_doc_hash | char(64) | 证件号加盐哈希，不存证件照片 | S3 |
| status | varchar(20) | pending/verified/revoked | S3 |

外键：`guardian_user_id -> users`；证件影像默认不落库。

### 4.7 guardian_student_authorizations（监护人授权表）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| auth_id | uuid | 主键 | S4 |
| tenant_id, school_id | uuid | 租户与学校范围 | S4 |
| student_user_id | uuid | 被授权学生 | S4 |
| guardian_id | uuid | 授权监护人 | S4 |

### 4.8 counseling_sessions（辅导会话表）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| session_id | uuid | 主键 | S4 |
| tenant_id, school_id | uuid | 租户与学校 | S4 |
| student_user_id | uuid | 会话学生，展示用 pseudonym | S4 |
| channel | varchar(32) | web/tablet/wechat/dingtalk/robot_optional | S2 |
| interaction_mode | varchar(20) | text/voice/mixed；语音不存原始音频 | S4 |
| started_at, ended_at | timestamptz | 会话起止 | S4 |

## 5. 敏感等级、留存与加密

### 5.1 敏感等级定义

| 等级 | 定义 | 示例 | 处理要求 |
|:---:|------|------|------|
| S0 | 公开/非敏感元数据 | 量表公开名称、文档标题、枚举值 | 普通访问控制 |
| S1 | 内部配置数据 | 租户配置、角色权限、学校参数 | 按租户隔离，配置变更审计 |
| S2 | 一般个人信息 | 账号、班级、身份映射 | 最小化采集，手机/邮箱加密，学号哈希 |
| S3 | 敏感个人信息 | 未成年人身份、监护关系、授权、通知触达 | 字段级加密，最小权限，授权/撤回留痕 |
| S4 | 高敏心理与安全数据 | 会话摘要、测评结果、风险事件、个案、模型安全日志 | 应用层信封加密，严格 RBAC/ABAC，访问必审计 |
| S5 | 默认禁止落库 | 完整原始对话、原始语音/视频、面部图像/模板、指纹/声纹 | **不建表、不持久化**；确需另走专项评估 |

### 5.2 数据最小化与禁止项

| 规则 | 设计要求 |
|------|------|
| 不保存不必要原文 | 默认只存摘要/标签/信号/建议；原文只临时缓存并设 TTL |
| 不保存生物识别 | 不建 face_template/voiceprint 表；如启用应本地即时处理只存结构化结果 |
| 班主任权限边界 | 只见「需关注/已转介/协同任务」，不见完整聊天/测评解释/个案私密 |
| 心理老师权限边界 | 可见授权范围内摘要/结果/风险/个案；每次访问写审计 |
| 监护人授权优先 | 使用/测评/风险通知/协同需绑定授权范围；撤回后停止处理 |
| 模型日志脱敏 | 只存模型名/Agent/模板版本/Token/延迟/安全结论/脱敏摘要 |

**加密组合：** 应用层信封加密 + 数据库透明加密/磁盘加密 + 传输 TLS。S4 字段优先应用层加密，数据库只存密文 bytea + 检索标签。
**哈希：** 租户级盐值 + 不可逆算法处理学号/外部账号/证件号/IP/UA；盐值不存业务库明文。
**删除：** 业务软删除 + 到期硬删除/匿名化两段式；日志/模型/审计表按月分区。

## 6. PostgreSQL + pgvector 方案

| 设计点 | 建议 |
|------|------|
| 适用场景 | pgvector 仅用于 CBT 知识库/心理教育/安全规则/学校制度的语义检索；MVP 不对学生原始对话/个案向量化 |
| 索引选择 | <100 万切片先用 HNSW；批量导入/离线重建可评估 IVFFlat。维度跟随模型（1536/3072） |
| 租户隔离 | 向量表保留 tenant_id/school_id/doc_id 元数据，检索先按租户过滤再近邻搜索，避免跨校召回 |
| 性能策略 | knowledge_chunks 用 HNSW，metadata 用 GIN，业务查询用 tenant_id/doc_id B-tree；日志表按月分区 |
| 运维策略 | 向量模型变更时新建 embedding_model 版本后台重算，不原地覆盖 |

**表级策略：** 高频写入/高留存表（`audit_logs`、`model_call_logs`、`risk_events`、`notifications`）按月 range partition；业务索引统一以 tenant_id 为第一列。
**权限策略：** 启用 RLS，应用连接后设 `app.tenant_id`/`app.school_id`/`app.user_id` 兜底隔离；应用层仍需 RBAC/ABAC，不能只靠数据库。

## 9. Java 实现层适配（技术栈变更补充）

原文按 Python 语境撰写，落地到 Java（BEACON 决策 #5）时的对应关系：

| 设计要求 | Java 实现方案 |
|------|------|
| Schema 级多租户隔离 | `AbstractRoutingDataSource` 动态数据源路由 + `tenant_{tenant_id}` schema；租户上下文存 `ThreadLocal`（虚拟线程下用 `TransactionalThreadLocal`/`ScopedValue`） |
| RLS 连接上下文 `SET app.tenant_id` | MyBatis 拦截器或数据源 `ConnectionInitSql`，连接取用后执行 `SET app.tenant_id` |
| 字段级信封加密（S3/S4 的 `_enc` 字段） | MyBatis `TypeHandler` 透明加解密（如 `EncryptedBytesTypeHandler`），密钥经 KMS/信封方案获取 |
| 加盐哈希（`_hash` 字段） | 统一 `HashUtil`（HMAC-SHA256 + 租户级盐），写入前处理 |
| jsonb 字段 | MyBatis-Plus `JacksonTypeHandler` 或 PG jsonb TypeHandler |
| pgvector `vector(1536)` | 自定义 TypeHandler 序列化 `float[]`；检索走原生 SQL（`<=>` cosine） |
| 审计日志追加写 | Service 层 AOP（`@Auditable`）统一落 `audit_logs`，禁止业务用户 update |
| 按月分区 | Flyway/Liquibase 迁移脚本 + 定时任务创建下月分区 |

> 迁移工具建议 **Flyway**（SQL 优先，贴合本文 DDL 风格）；ORM 采用 **MyBatis-Plus**（决策 #5 待定项，倾向 MyBatis 以精确控制多租户 SQL）。

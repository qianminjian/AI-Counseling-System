## 1. 设计结论与边界

系统定位是「校园心理健康陪伴与早期情绪支持系统」，**不是医疗诊断系统**。数据库设计支持：情绪陪伴、轻度 CBT 引导、风险识别、人工转介、教师摘要、家校协同，同时避免过度采集。

**核心原则：**
- 所有业务表强制包含 `tenant_id`；学校域数据包含 `school_id`。
- 高敏表采用：字段级加密、行级隔离、访问审计、分区留存、到期清理。
- 会话侧**默认只保存结构化摘要、风险信号、模型运行元数据**，不保存完整原始对话、原始语音/视频、面部图像/模板、指纹等生物识别数据（声纹仅存不可逆向的 256 维特征向量）。
- 不建完整聊天原文表、复杂数据湖。

**工程原则落实：**

| 原则 | 落实 |
|------|------|
| KISS | 核心业务用规范化关系表；动态量表/标签/权限点用 jsonb，避免大量小表 |
| YAGNI | 先满足文本对话、风险预警、教师后台、家校协同；不建生物识别表/数据湖 |
| SOLID | 租户/身份/授权/会话/测评/风险/个案/审计/模型日志分域建模 |
| DRY | 统一 `users` 承载多角色，不为学生/老师/监护人重复建账号体系 |

## 2. 数据域划分

按「谁拥有、谁能看、保留多久、如何删除」划分。

| 数据域 | 核心表 | 敏感等级 | 建议留存 |
|--------|--------|:---:|------|
| 租户与学校域 | `tenants`, `schools` | S1-S2 | 合同期内保留；结束后 1 年内导出/删除/匿名化 |
| 身份与权限域 | `users`, `roles`, `user_roles` | S2-S3 | 有效期内保留；离校/离职后冻结，1-3 年内匿名化 |
| 监护人授权域 | `parent_accounts`, `parent_student_links` | S3-S4 | 授权有效期内保留；撤回后仅保留证据哈希与审计 |
| 心理互动域 | `counseling_sessions`, `message_summaries`, `emotion_diaries` | S4 | 默认摘要 180 天（普通）/365 天（高风险）；不留原文 |
| 测评域 | `assessment_scales`, `assessment_results`, `assessment_responses`（设计预留） | S1-S4 | 量表定义随版本保留；结果 2-3 学年内清理 |
| 风险与个案域 | `risk_events`, `teacher_notes` | S4 | 结案/毕业后 3 年内复核清理 |
| 画像与记忆域 | `student_profiles`, `long_term_memories` | S4 | 画像随账号留存；撤回同意即删除（不可逆） |
| 通知与审计域 | `notifications`, `audit_logs`, `quality_scores` | S3-S4 | 通知最小化；审计 1-3 年 |
| 知识库与模型运行域 | `knowledge_documents`, `knowledge_chunks`, `model_call_logs`, `prompt_versions` | S1-S4 | 知识库按版本；模型日志 90-180 天且脱敏 |

## 3. ER 模型说明

- `tenants` 是隔离根，一个租户对应一个独立 Schema（`tenant_{code}`），含所有业务表。
- `schools` 是学校级边界，下辖学生/教师/管理员/会话/风险/通知。
- `users` 统一承载所有登录账号（student/teacher/head_teacher/admin/guardian），角色经 `user_roles` 多对多绑定。
- `parent_accounts` 与 `users`（学生）经 `parent_student_links` 建立多对多绑定（家庭码体系）。
- `counseling_sessions` 记录一次有限回合会话；`message_summaries` 保存结构化摘要，不保存完整原文。
- `risk_events` 可由会话/测评/人工触发；`teacher_notes` 承载个案跟进备注；`risk_events` 外发通知走 outbox（V31）。
- `audit_logs` 记录敏感访问/权限变更/导出/删除/风险处置，是追责与合规的事实表。
- `knowledge_documents` + `knowledge_chunks` 构成受控知识库（RAG）；`model_call_logs` 记录调用可观测信息；`prompt_versions` 管理 Prompt 版本与 A/B 分组。

**关键关系：**

| 关系 | 说明 |
|------|------|
| tenants 1:N schools/users | 最高隔离边界，查询以 tenant_id 为第一过滤条件 |
| users N:M roles | 通过 user_roles 绑定角色和作用域 |
| parent_accounts N:M students | 通过 parent_student_links（家庭码）表达绑定关系 |
| students 1:N sessions/risk_events/diaries/profiles | 展示优先用 pseudonym |
| sessions 1:N message_summaries | 不把每条原始消息持久化为明文 |
| sessions 1:1 quality_scores | LLM-as-Judge 会话质量评分 |
| students 1:N long_term_memories | 长期记忆（key_event / recurring_theme） |
| students 1:N voiceprint_embeddings | 声纹 256 维特征向量（不可逆向还原） |
| knowledge_documents 1:N knowledge_chunks | 切片生成向量供 RAG；切片不含学生个人心理数据 |

## 5. 核心表结构

### 5.1 users（统一账号）

| 字段 | 类型 | 说明 | 敏感 |
|------|------|------|:---:|
| user_id | uuid | 主键 | S2 |
| tenant_id, school_id | uuid | 所属租户与学校 | S2 |
| user_type | varchar(20) | student/teacher/head_teacher/admin/guardian | S2 |
| display_name_enc | bytea | 姓名密文 | S3 |
| pseudonym | varchar(64) | 匿名显示名（报表脱敏） | S2 |
| gender | varchar(10) | 性别（V11） | S2 |
| grade_code, class_code | varchar(32) | 年级与班级 | S2 |
| student_no_hash | char(64) | 学号加盐哈希 | S3 |
| mobile_enc, email_enc | bytea | 手机/邮箱密文 | S3 |
| password_hash | varchar(128) | 口令哈希（V5） | S3 |
| family_code | varchar(16) | 家庭码（V16，家长绑定用） | S3 |
| pin_hash | varchar(128) | PIN 哈希（V13） | S3 |
| dialect | varchar(32) | 方言偏好（V29） | S2 |
| status, last_login_at | varchar/timestamptz | 状态与最近登录 | S2 |

脱敏：姓名/手机/邮箱字段级加密；学号只存哈希；**不保存人脸/指纹**；声纹仅存特征向量（V28）。

### 5.2 counseling_sessions（辅导会话）

| 字段 | 类型 | 说明 |
|------|------|------|
| session_id | uuid | 主键 |

| interaction_mode | varchar(20) | text/voice/mixed；语音不存原始音频 |
| emotion_type | varchar(32) | 开场情绪选择 |
| risk_level_snapshot | smallint | 结束时风险等级快照 |
| satisfaction | smallint | 满意度评价（😊/😐/😢） |
| prompt_version_id | uuid | 使用的 Prompt 版本（V22） |
| transcript_policy | varchar(32) | summary_only/ephemeral_encrypted/no_store |

### 5.3 message_summaries（消息摘要，替代完整聊天记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| summary_id | uuid | 主键 |
| session_id, student_user_id | uuid | 会话与学生 |
| turn_count | int | 覆盖对话轮次 |
| emotion_tags / topic_tags / risk_signals | jsonb | 情绪/主题/风险信号摘要，不存触发原句 |
| content_summary | text | 单条消息内容摘要——**AES-256-GCM 密文**（字段级加密，密文膨胀约 1.35 倍；V32 由 VARCHAR(1024) 扩为 TEXT：原长度上限导致长消息 INSERT 失败被业务 catch 吞掉 → 摘要静默丢失） |
| sender_type / emotion_label / risk_level | — | per-message 粒度（V7）：发送者类型/情绪标签/风险等级 |
| cbt_fields | jsonb | CBT 结构化字段（emotion_label/auto_thought/balanced_thought 等，V7） |
| suggested_next_action | varchar(256) | 无需处理/老师关注/转介 |
| content_hash | char(64) | 内容哈希，追溯完整性，不可逆 |

> **V32 清理（AUDIT-P2-16）**：V2 遗留的 `student_need_summary_enc` / `ai_intervention_summary_enc` 两列全代码库无读写点（实体字段已删除），已 DROP 移除，不再出现在表结构中。

## 6. 实际落库扩展表（schema 增量）

### 6.1 准入与同意域（V6/V16）

- `trial_invite_codes`：code（唯一，租户内）、max_uses/used_count、expires_at、status —— 一人一码邀请注册。
- `consent_records`：consent_type、consent_version、consented_at、ip_hash —— 告知同意门控留痕（AUTH-023 监护人同意闭环）。
- `parent_accounts`：phone_enc（密文）、密码哈希 —— 家长账号。
- `parent_student_links`：parent_account_id ↔ student_user_id、relation_type、status —— 家庭码绑定（多孩支持）。

### 6.2 画像与记忆域（V12/V18/V20）

- `student_profiles`：6 维 JSONB（emotion_baseline/communication_pref/resilience/risk_trajectory/social_graph/growth_track）+ `personality_traits` JSONB（V18）+ version/total_sessions —— 会话结束 SQL 聚合 + LLM 增量提炼，下次对话注入 System Prompt。
- `long_term_memories`：memory_type（key_event/recurring_theme）、content、emotion_context、importance（0.0-1.0，越高越优先回注）、recall_count/last_recalled_at —— 跨会话按相似度召回 Top5 注入。

### 6.3 质量与运行域（V19/V22/V7）

- `quality_scores`：四维评分（empathy_score/cbt_completion/safety_compliance/engagement_score）+ overall_score（加权平均）+ flagged/flag_reason —— LLM-as-Judge 异步会话质量评估。
- `prompt_versions`：version、content、is_active、ab_group —— Prompt 版本管理（AI-005，支持 A/B 测试）。
- `relaxation_sessions`：练习类型/时长/完成状态 —— 放松练习记录。
- `teacher_notes`：学生备注内容 —— 教师个案备注（心理老师可见）。

### 6.4 语音与知识域（V28/V24/V30）

- `voiceprint_embeddings`：embedding JSONB（256-dim float 数组）、sample_index（≤8 条模板/人）—— 声纹登录，仅存特征向量（不可逆向还原音频），remote 模式服务端比对。
- `knowledge_documents`：title/category（cbt_technique/emotion_regulation/social_skills/crisis_intervention/development_psychology）、content、source、status（V30 增审核字段，默认 draft）。
- `knowledge_chunks`：content + embedding vector(1536) + token_count；IVFFlat cosine 索引（<10 万行）。

## 7. 敏感等级、留存与加密

### 7.1 敏感等级定义

| 等级 | 定义 | 示例 | 处理要求 |
|:---:|------|------|------|
| S0 | 公开/非敏感元数据 | 量表公开名称、文档标题、枚举值 | 普通访问控制 |
| S1 | 内部配置数据 | 租户配置、角色权限、学校参数 | 按租户隔离，配置变更审计 |
| S2 | 一般个人信息 | 账号、班级、身份映射 | 最小化采集，手机/邮箱加密，学号哈希 |
| S3 | 敏感个人信息 | 未成年人身份、监护关系、授权、通知触达 | 字段级加密，最小权限，授权/撤回留痕 |
| S4 | 高敏心理与安全数据 | 会话摘要、风险事件、画像、记忆、审计 | 应用层信封加密，严格 RBAC，访问必审计 |
| S5 | 默认禁止落库 | 完整原始对话、原始语音/视频、面部图像/模板、指纹 | **不建表、不持久化**；确需另走专项评估 |

### 7.2 数据最小化与禁止项

| 规则 | 设计要求 |
|------|------|
| 不保存不必要原文 | 默认只存摘要/标签/信号/建议；原文只临时缓存并设 TTL |
| 不保存生物识别 | 不建 face_template 表；声纹仅存不可逆 256 维特征向量 |
| 班主任权限边界 | 只见「需关注/已转介/协同任务」，不见完整聊天/测评解释/个案私密 |
| 心理老师权限边界 | 可见授权范围内摘要/结果/风险/个案；每次访问写审计 |
| 监护人授权优先 | 使用/测评/风险通知/协同需绑定授权范围；撤回后停止处理 |
| 模型日志脱敏 | 只存模型名/Agent/模板版本/Token/延迟/安全结论/脱敏摘要 |

**加密组合：** 应用层信封加密（MyBatis TypeHandler 透明加解密，`_enc` 字段）+ 传输 TLS。S4 字段优先应用层加密，数据库只存密文 bytea + 检索标签。
**哈希：** 租户级盐值 + 不可逆算法处理学号/外部账号/证件号/IP/UA；盐值不存业务库明文。
**删除：** 业务软删除 + 到期硬删除/匿名化两段式；日志/模型/审计表按月分区。

#### 7.2.1 数据最小化落地与 PII 出域阻断（ARCH-007，doing/67，2026-08-06）

- **会话摘要两级策略（D-7，2026-07-28 钱敏健拍板）**：常规消息（riskLevel < L3）`contentSummary` 为**语义提炼 ≤200 字**（`MessageSummarySummarizer` 规则抽取，LLM 提炼登记远期）；风险消息（riskLevel ≥ L3）**原文保真**（儿童安全场景原话为关键证据，安全 > 最小化）；类注释与 design/08 §5.1 准确化，无 schema 变更
- **PII 注入 LLM 置换规则（D-8，2026-07-28 钱敏健拍板）**：对话中提取的 realName → 会话学生 pseudonym 昵称（无昵称 →「同学」）；class →「我们班」泛化（年级+班级可定位个人）；school/address（未来扩展）→「本校」占位；age/grade 保留（年龄适配功能依赖，非身份标识）；原始提取值不落库、不展示、不进上下文；置换失败 → 兜底占位（「小朋友」）+ 审计日志，**不得静默注入明文**
- **验收**：`ConversationContextAgentTest` 断言注入上下文 doesNotContain 明文真名/班级（#realNamePriorityWithFullInfo/#realNameReplacedByPseudonym）；脱敏路径沿用 SAFE-204 26 用例

## 8. PostgreSQL + pgvector 方案

| 设计点 | 建议 |
|------|------|
| 适用场景 | pgvector 仅用于知识库语义检索（RAG）；不对学生原始对话/个案向量化 |
| 索引选择 | <10 万切片用 IVFFlat（已落地 V24）；超 100 万切片评估 HNSW；维度跟随模型（1536） |
| 租户隔离 | 向量表保留 tenant_id/doc_id 元数据，检索先按租户过滤再近邻搜索，避免跨校召回 |
| 性能策略 | knowledge_chunks 用向量索引 + metadata B-tree；业务查询以 tenant_id 为第一列；日志表按月分区（V23 已建性能索引） |
| 运维策略 | 向量模型变更时新建 embedding_model 版本后台重算，不原地覆盖 |

**权限策略：** Schema 级隔离（`tenant_{code}`，每租户独立 schema）+ 应用层 RBAC/ABAC 双保险；所有查询强制校验 tenant_id。

## 9. Java 实现层适配

| 设计要求 | Java 实现方案 |
|------|------|
| 多租户隔离（行级） | 共享表 + 每行 `tenant_id` 强制过滤；所有 Mapper 查询强制 tenant_id 条件 |
| 字段级信封加密（S3/S4 `_enc` 字段） | MyBatis `TypeHandler` 透明加解密（`EncryptedBytesTypeHandler`），密钥经 KMS/信封方案获取 |
| 加盐哈希（`_hash` 字段） | 统一 `HashUtil`（HMAC-SHA256 + 租户级盐），写入前处理 |
| jsonb 字段 | MyBatis-Plus `JacksonTypeHandler` |
| pgvector `vector(1536)` | 自定义 TypeHandler 序列化 `float[]`；检索走原生 SQL（`<=>` cosine） |
| 审计日志追加写 | Service 层 AOP（`@Auditable`）统一落 `audit_logs`，禁止业务用户 update |
| 按月分区 | Flyway 迁移脚本 + 定时任务创建下月分区 |
| 迁移工具 | Flyway（V1-V32 已生效，SQL 优先）；ORM：MyBatis-Plus |

## 11. 实施与验证

| 阶段 | 数据库交付重点 | 验证方式 |
|------|------|------|
| MVP 第 1 阶段 | tenants/schools/users/sessions/message_summaries/risk_events/notifications/audit_logs/model_call_logs | 租户隔离测试、权限矩阵测试、摘要不落原文测试、高风险通知链路测试 |
| 第 2 阶段 | 画像/记忆/知识库 pgvector/家庭码体系/声纹向量 | 授权撤回测试、知识库跨租户隔离测试、RAG 召回安全测试、声纹比对测试 |
| 第 3 阶段 | 量表施测/趋势聚合/归档删除自动化 | 只存结构化结果；TTL、分区清理、脱敏导出测试 |

**验收口径：**
1. 随机抽查表，不应存在 `face_template`/`raw_audio`/`raw_video`/`raw_message_text` 等默认持久化字段（声纹仅特征向量）。
2. 班主任访问学生详情只见风险等级/协同任务/趋势摘要，不见完整聊天与测评解释。
3. 心理老师访问 S4、管理员导出、授权变更、个案关闭必须生成 `audit_logs`。
4. 删除/撤回授权后系统停止新增处理，并按策略清理会话摘要/模型日志/通知载荷。
5. 高风险（4-5 级）风险事件必须触发外发通知（outbox 重试保障，V31）并写审计。

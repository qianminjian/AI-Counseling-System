# 46_学生心理画像自动化迭代闭环设计

> 创建：2026-07-28 | 状态：设计期，待实施 | 不含实现代码
>
> 定位：**画像闭环专题**。design/23 定义了画像模型（6+1 维），design/29 定义了画像→年龄/性格适配注入。本文解决二者之间最大的断链：**画像数据如何自动迭代、如何质量可信、如何真正驱动决策并回收效果**——把画像从"会更新的档案"升级为"自我校准的决策资产"。
>
> 关系：数据模型承接 design/23，注入承接 design/29/44，效果量化对接 design/39，评估信号复用 design/45，情绪数据源接 design/47，长期记忆互哺 design/50。

## 一、现状诊断（对照真实代码）

### 1.1 画像真实实现度：基本实现，闭环缺失

| 环节 | 现状 | 代码位置 |
|------|------|----------|
| 画像存储 | ✅ 7 个 JSONB 维度 | `StudentProfile`（emotionBaseline/communicationPref/resilience/riskTrajectory/socialGraph/growthTrack/personalityTraits + version/totalSessions） |
| 规则聚合 | ✅ 纯 SQL 聚合近 20 次会话情绪/风险 | `StudentProfileService.updateProfile()` |
| LLM 提炼 | ✅ 会话结束异步提炼 4 维增量合并 | `ProfileExtractorService.extractAndMerge()` |
| 注入使用 | ✅ 生成 System 画像片段 | `StudentProfileService.buildProfilePrompt()` |
| 里程碑检测 | ✅ 规则式 | `mergeGrowthTrack()`（first_session/consistent_attendance/first_cbt/first_share） |

### 1.2 三个断链（本文要解决的）

| # | 断链 | 严重度 | 本文章节 |
|---|------|--------|---------|
| B1 | **画像与决策弱联动**：画像片段拼进 System，但不驱动 44 的 StrategyProfile（性格维度未真正参与编排微调） | 🔴 高 | 五 |
| B2 | **无画像质量评估**：LLM 提炼可能漂移/污染，无置信度、无冲突检测、无衰减 | 🟠 中高 | 四 |
| B3 | **闭环不回收**：画像用了没用、准不准、帮没帮到孩子——无反馈证据（design/39 是实验框架，但画像自身的自校准缺失） | 🟠 中高 | 六 |

### 1.3 根因

当前是"**采集→合并→拼接**"的**单向管线**，不是闭环。缺三样：**质量门（B2）**、**决策接线（B1）**、**效果回收与自校准（B3）**。

## 二、设计目标

1. **自动迭代**：画像随会话持续演进，且演进有**质量门控**（置信度/时效/冲突/衰减），不是无脑覆盖。
2. **决策闭环**：画像明确驱动 44 编排（性格微调、兴趣取材、已掌握技巧、风险轨迹），不止拼字符串。
3. **效果回收**：画像增强的会话质量（design/45 四维分）回流，验证"画像到底帮没帮到"，形成自校准。
4. **可信可辩护**：每个画像字段可回溯来源（哪次会话/规则还是 LLM）、置信度、更新时间。
5. **合规安全**：不诊断、不贴标签、不向学生复述画像、画像不外泄、家长/教师可见范围分级（对齐 14/07）。

**明确不做**：不做人格测评式标签固化、不用画像做营销分层、不把画像原文注入可被套取的位置。

## 三、业界最佳实践对标

| 来源 | 可借鉴做法 | 本文落地 |
|------|-----------|---------|
| **用户画像/CDP 范式** | 属性有来源、时效、置信度；events→traits 派生 | 画像字段加 provenance/confidence/updated_at/decay |
| **推荐系统在线学习** | 长期偏好 + 短期意图分离，实时反馈修正 | 稳定画像（长期）× 会话内 entryMood（短期，44） |
| **临床个案概念化 Case Formulation** | 结构化假设 + 证据支撑 + 持续修订 | 画像即"工作假设"，证据不足降置信度 |
| **MBC 测量导向照护** | 量表定期复测校准主观判断 | design/34 量表结果回写画像风险轨迹并校准 |
| **数据质量 DQ 维度** | 完整性/准确性/时效性/一致性 | 画像质量评估四维（4.3） |
| **儿童数据最小化（PIPL/COPPA 精神）** | 只采必要、可解释、可删除 | 画像字段白名单 + 保留期 + 可删除 |

## 四、画像质量门控（补 B2）

### 4.1 字段级元数据（画像可信的前提）

每个画像维度的值不再是裸 JSON，而是带元数据的结构（设计期）：

```
{
  "value": <维度值>,
  "provenance": "rule_agg | llm_extract | scale | teacher_input",
  "confidence": 0.0-1.0,
  "evidence_count": <支撑该结论的会话/信号次数>,
  "updated_at": <时间>,
  "last_seen_at": <该特征最近一次被观察到>
}
```

### 4.2 合并策略升级（在现有 EMA 基础上加门控）

现状 `ProfileExtractorService` 已做：personality 数值 EMA（新值权重 0.4）、interests 累加去重保留 6、coping_skills 累加计次、key_persons 增量。本文补：

| 门控 | 规则 |
|------|------|
| **置信度加权** | 低置信新证据（LLM 单次、模糊）不足以翻转高置信旧结论；置信度随 evidence_count 上升 |
| **冲突检测** | 新提炼与现有值强冲突（如"外向"↔长期"内向"）→ 不直接覆盖，降双方置信度 + 标记待更多证据 |
| **时效衰减 decay** | last_seen_at 超期的特征置信度衰减（孩子会变，旧标签不该永久生效） |
| **污染防护** | 单次异常会话（如被同学乱玩）不应剧烈改写画像；EMA + evidence_count 天然抑制，异常检测辅助 |

### 4.3 画像质量评估四维

| 维度 | 含义 | 用途 |
|------|------|------|
| 完整性 | 有效维度覆盖率 | 低→触发温和的画像补全（非套取隐私） |
| 时效性 | 距最近更新时长 | 过期→下次会话优先重新观察 |
| 置信度 | 各维度置信均值 | 低置信维度不参与强决策 |
| 一致性 | 规则聚合 vs LLM 提炼是否冲突 | 冲突高→人工/教师侧提示核对 |

## 五、画像驱动决策接线（补 B1，最关键）

### 5.1 画像 → StrategyProfile 的明确映射

这是 46 与 44 的接线契约。画像不再只是 buildProfilePrompt 的字符串，而是编排引擎的**结构化输入**：

| 画像维度 | 驱动 44 的什么 | 门控条件 |
|----------|--------------|---------|
| personalityTraits.introversion | opening/pace 微调（内向→更多留白、少追问） | confidence≥阈值才生效 |
| personalityTraits.sensitivity | 追问强度、镜映话术温度 | 高敏→更温柔慢 |
| personalityTraits.curiosity | 是否用探索式引导 | — |
| dominant_interests | emotionMirrorHint/暖场取材（比喻取材） | 仅供取材，不主导 |
| coping_skills（已掌握技巧） | skillPriority（已会的技巧可复用引导） | 已掌握→可主动唤起 |
| riskTrajectory | 合规裁决的辅助信号（近期风险上升→更保守） | 与 04 风险等级取更保守 |
| emotionBaseline | entryMood 的对照基线（偏离基线→值得关注） | 供 47 情绪趋势判断 |
| communicationPref | 语言风格/长度偏好 | 不超越年龄适配上限 |

### 5.2 优先级归位（与 44 铁律一致）

画像个性化在 44 优先级链里位于**性格适配之下、兴趣取材之上**：
```
合规安全 > 情绪稳定 > 年龄适配 > 性格适配 > 画像个性化 > 兴趣取材
```
即：画像置信度再高，也不能突破年龄语言上限、不能压过情绪门控与合规裁决。低置信画像维度**不参与**编排（宁可不用，不可乱用）。

### 5.3 短期 × 长期分离

- **长期画像**（本文，稳定演进）→ 编排的性格/偏好/技巧底座。
- **短期状态**（44 entryMood + 47 本轮情绪）→ 覆盖当轮策略。
- 冲突时短期优先（今天很焦虑的外向孩子，本轮按焦虑策略走）。

## 六、效果回收与自校准闭环（补 B3）

### 6.1 闭环全景

```
① 画像注入会话（5.1 驱动 44 编排）
   └→ ② 会话质量评估（design/45 四维分，带 profile 是否注入/置信度标记）
        └→ ③ 画像效果回收
             ├─ 有画像 vs 无画像/低置信 的会话质量对比（对接 design/39 A/B）
             ├─ 按画像维度下钻：内向孩子用了内向策略，engagement 是否更好
             └─ 里程碑达成率、留存、量表变化（design/34）
   └→ ④ 自校准
        ├─ 某画像维度用了却无正向效果 → 降低其决策权重（该维度可能不准）
        ├─ 量表结果与画像风险轨迹冲突 → 以量表校准画像
        └─ 教师反馈订正 → 高置信人工证据修正画像
   └→ 回到 ①
```

### 6.2 量表回写（design/34 ↔ 画像）

design/34 的 PHQ-A/GAD-7/SDQ 结果是**高置信客观信号**，应回写画像 riskTrajectory 与 emotionBaseline，并作为校准 LLM 提炼漂移的锚点（provenance=scale，confidence 高）。

### 6.3 教师侧闭环（design/05/35）

教师在工作台可见画像**摘要**（非原始敏感原文），可提交订正（如"该生近期家庭变故"），作为高置信 teacher_input 证据进入画像，形成人机协同校准。教师可见范围受 07 权限分级约束。

## 七、画像数据流全景（采集→迭代→使用→回收）

```
采集层：会话文本 + Emotion 信号 + 语音情感(47) + 量表(34) + 教师输入(05/35)
   ↓
迭代层：规则聚合(updateProfile) + LLM 提炼(extractAndMerge) + 质量门控(四) + 量表回写(6.2)
   ↓  [带 provenance/confidence/decay 的画像]
使用层：buildProfilePrompt → StrategyProfile 结构化输入(5.1) → 44 编排 → 提示词
   ↓
回收层：会话质量四维(45) + A/B(39) + 里程碑/量表 → 自校准(6.1) → 回到迭代层
```

## 八、合规与隐私（对齐 14/07/10）

- **不诊断不标签**：画像维度是"沟通/情绪/韧性倾向"描述，非精神障碍标签；对外表述用中性成长语言。
- **不向学生复述**：画像仅在 System 层使用，学生不可见、不可套取（衔接 45 §7.2 注入防护）。
- **可见分级**：学生（不可见）< 教师（脱敏摘要）< 平台（聚合去标识）；家长可见范围按 26 与同意条款（22）。
- **最小化与可删除**：字段白名单、保留期、账号注销/毕业清除；不采集必要外的敏感信息。
- **异常写入防护**：单次异常不剧烈改写（4.2），防他人乱用污染画像。

## 十、EARS 验收标准（摘要）

- WHEN 会话结束触发画像提炼，THE 系统 SHALL 为每个更新维度记录 provenance/confidence/updated_at，且低置信新证据不得直接翻转高置信旧结论。
- WHEN 编排引擎构建 StrategyProfile，THE 系统 SHALL 仅采用置信度达标的画像维度参与性格/偏好微调，且不得突破年龄适配与合规裁决。
- WHEN 收到量表结果，THE 系统 SHALL 以高置信回写画像风险轨迹与情绪基线，并作为 LLM 提炼漂移的校准锚点。
- WHILE 某画像维度被使用但无正向效果证据累积，THE 系统 SHALL 降低其决策权重。
- THE 系统 SHALL NOT 向学生复述画像、SHALL NOT 输出精神障碍诊断标签、SHALL NOT 用画像做营销分层。

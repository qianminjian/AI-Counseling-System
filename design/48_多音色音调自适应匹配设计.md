# 48_多音色音调自适应匹配设计

> 创建：2026-07-28 | 状态：设计期，待实施 | 不含实现代码
>
> 定位：**音色自适应专题**。tts-service 已实现 CosyVoice2 多人设 + 情绪 instruct（design/37 补了情感化 TTS 与三方同步）。本文解决最大断链：**音色由前端显式指定、与画像/情绪脱节，没有自动匹配逻辑、没有效果评估**——把"多音色能力"升级为"与画像×心理状态×情绪专题充分匹配的自适应语音陪伴"。
>
> 关系：能力承接 tts-service + design/37，情绪信号源接 design/47，画像匹配接 design/46，人设品牌接 design/27（波波），情绪策略接 design/44，效果评估接 design/45/39。

## 一、现状诊断（对照真实代码）

### 1.1 多音色真实实现度：部分实现（能力有，智能缺）

| 环节 | 现状 | 位置 |
|------|------|------|
| 多人设音色 | ✅ 4 人设 | tts-service `VOICE_PERSONAS`：xiaoxing(温暖大姐姐/女)、qiqiu(活泼/女)、yueliang(温柔讲故事/女)、xiaotaiyang(阳光大哥哥/男) |
| 情绪化合成 | ✅ 6 情绪 instruct | `EMOTION_INSTRUCTS`：happy/sad/angry/fearful/nervous/neutral |
| 语速控制 | ✅ speed + torchaudio 调整 | synthesize 接口 |
| 降级 | ✅ CosyVoice2→edge-tts | app.py |
| 情感同步 | ✅ 设计层（37） | TTS/表情/微动效三方同步 |

### 1.2 断链（本文要解决的）

| # | 断链 | 严重度 | 本文章节 |
|---|------|--------|---------|
| T1 | **无自动匹配 persona 逻辑**：前端必须显式传 persona，系统不会"为这个孩子选最合适的声音" | 🔴 高 | 四、五 |
| T2 | **音色与画像脱节**：性别/年龄/性格/偏好不影响音色选择 | 🔴 高 | 五 |
| T3 | **音色与情绪状态弱联动**：情绪只改 instruct（同一把声音演不同情绪），不改音色/音调基调 | 🟠 中 | 六 |
| T4 | **无音色效果评估**：哪个孩子适合哪把声音、换声音后参与度是否提升——无数据 | 🟠 中 | 七 |
| T5 | **无预合成话术库**：固定话术（暖场/安全/收束）每次实时合成，延迟与一致性差（37 提了 S1/S0 预合成，需与音色矩阵统一） | 🟠 中 | 八 |

### 1.3 根因

音色是"**能力就绪但决策缺位**"：4 把好声音摆在那，选哪把、怎么随状态变，全靠前端硬编码，没有"画像×情绪→音色"的匹配大脑。

## 二、设计目标

1. **自动匹配**：系统根据画像（性别认同/年龄/性格/偏好）+ 当前情绪状态，自动选出最合适的 persona 与音调基调，前端无需硬指定。
2. **状态自适应**：情绪不仅改 instruct，还调音调/语速/停顿基调（焦虑→更慢更稳，开心→更亮更快）。
3. **画像充分匹配**：音色成为个性化的一部分，与 44/46 的策略一致（不突破合规与年龄）。
4. **可评估可进化**：音色匹配效果回收（参与度/满意度/完成度），A/B 优化匹配规则。
5. **低延迟一致**：高频固定话术预合成，统一音色矩阵管理，首音达标（衔接 37 首音≤1.5s）。
6. **品牌一致**：所有音色统一在"波波"人设伞下（design/27），音色是波波的不同呈现，非多个角色。

**明确不做**：不做真人声纹克隆、不让学生频繁手动切换造成人设割裂、不因音色炫技牺牲合规话术的确定性。

## 三、业界最佳实践对标

| 来源 | 可借鉴做法 | 本文落地 |
|------|-----------|---------|

## 四、音色自适应架构

### 4.1 新增音色决策服务（设计期）

命名 `VoicePersonaResolver`（落 counseling-service voice 包），与 44 编排并列的"输出侧决策"：

```
输入信号
  ├── StudentProfile（性别认同/年级/性格/历史偏好）— 来自 46
  ├── StrategyProfile.emotionState + entryMood — 来自 44
  ├── currentEmotion（语音/文本融合）— 来自 47
  ├── sceneType（暖场/常规/安全/收束/讲故事）
  └── 手动偏好（学生若显式选过，尊重且记忆）
        │
        ▼
  VoicePersonaResolver.resolve()
   1. 冷启动默认：按性别/年龄选默认 persona
   2. 画像匹配：性格/偏好微调
   3. 情绪基调：emotionState → prosody(音高/语速/停顿) + instruct
   4. 场景覆盖：安全/危机场景强制稳定基调（合规优先）
   5. 会话内稳定性：非必要不切 persona（5.3）
        │
        ▼
  VoiceRenderProfile（persona + emotion instruct + prosody + speed）
        │
        ▼
  tts-service synthesize（persona/emotion/speed + prosody 扩展）
```

### 4.2 VoiceRenderProfile 数据结构（设计期）

```
record VoiceRenderProfile(
    String persona,          // xiaoxing/qiqiu/yueliang/xiaotaiyang
    String emotionInstruct,  // happy/sad/angry/fearful/nervous/neutral
    double pitchScale,       // 音高基调（情绪+年龄）
    double speed,            // 语速（情绪+年龄）
    int pauseStyle,          // 停顿风格（稳定态更多停顿）
    boolean locked,          // 安全/危机场景锁定稳定基调
    String source            // default/profile/manual/scene
)
```

## 五、音色 × 画像匹配（补 T1/T2）

### 5.1 冷启动默认规则

无历史偏好时的默认（可解释、可覆盖）：

| 画像信号 | 默认 persona | 依据 |
|----------|-------------|------|
| 低龄（≤2 年级） | yueliang（温柔讲故事，慢） | 低龄需温暖慢速高可懂度 |
| 中年级 + 中性/未知 | xiaoxing（温暖大姐姐） | 通用安全默认 |
| 男生倾向 + 中高年级 | xiaotaiyang（阳光大哥哥） | 同性别陪伴偏好（可被覆盖） |
| 活泼外向画像 | qiqiu（活泼） | 性格匹配 |

> 性别用"认同/偏好"而非强制生理性别；始终允许学生手动更换并记忆偏好（provenance=manual，高优先）。

### 5.2 分龄音调基调

| 年级段 | 语速基调 | 音高/停顿 |
|--------|---------|----------|
| 低（≤2） | 慢 | 停顿多、句短、清晰 |
| 中（3-4） | 中 | 自然 |
| 高（5-6） | 中偏正常 | 更接近平等对话 |

### 5.3 会话内稳定性（依恋原则）

一次会话内**默认不切 persona**（声音是波波的"脸"，频繁换会破坏安全感）。仅在：①学生手动切换 ②进入需强制稳定基调的安全/危机场景（只调 prosody 不换角色）时变化。跨会话可随画像演进缓慢调整。

## 六、音色 × 情绪状态自适应（补 T3）

### 6.1 从"只改 instruct"到"改基调"

现状情绪只选 `EMOTION_INSTRUCTS`。本文补 prosody 基调联动 44 emotionState：

| emotionState（44） | instruct | prosody 基调 |
|-------------------|----------|------------|
| STABLE | neutral/happy | 自然 |
| ACTIVATED（焦虑/激动） | fearful/nervous | **更慢、音高更低、停顿更多**（安抚） |
| CRISIS | 稳定基调锁定 | 极稳、慢、温暖，走安全话术（37 S0/S1 预合成） |

### 6.2 情绪镜映的声音一致性

44 的 emotionMirrorHint（文本镜映）与 TTS 情绪基调、波波表情（37）**三方同源**：同一 emotionState 驱动文本策略 + 语音 prosody + 表情动效，避免"说安慰的话却用欢快的声音"的撕裂。这是 37 三方同步的音色侧落地。

### 6.3 安全/危机锁定（红线）

安全提示、危机干预话术**强制稳定基调 + 预合成**（不受情绪 instruct 影响，locked=true），确保合规话术的确定性与一致性。与 45/37 的"安全类不实验"一致。

## 七、音色效果评估与进化（补 T4）

### 7.1 效果回收

音色作为可评估的干预参数，回收：

| 指标 | 来源 | 用途 |
|------|------|------|
| 语音播放完成率 | 前端埋点 | 声音是否被听完（不适→中断） |
| 会话参与度/时长 | design/39 | 匹配是否提升黏性 |
| 会话质量四维 | design/45 | 音色是否影响 empathy/engagement |
| 手动切换行为 | 本文 | 频繁换=默认不合适（负反馈） |

### 7.2 匹配规则进化

- 手动切换是最强负反馈：某画像类孩子普遍从默认换到某 persona → 修正默认规则。
- A/B（39）：对相近画像随机默认不同 persona，比较参与度，优化匹配表。
- 回写画像偏好（46 communicationPref.voice_preference，provenance=manual/derived）。

## 八、预合成话术库与音色矩阵（补 T5）

### 8.1 统一预合成矩阵

design/37 提了 S0/S1 预合成。本文统一为**话术 × persona × prosody 矩阵**：

| 话术类 | 内容 | persona 覆盖 | 更新 |
|--------|------|------------|------|
| 安全/危机（S0/S1） | 固定合规话术 | 全 persona × 稳定基调 | 话术改版重合成 + 红队校验 |
| 暖场问候 | "哈喽，[昵称]！"（28） | 全 persona | 昵称变量段实时，其余预合成 |
| 收束话术 | 会话结束语 | 全 persona | 预合成 |
| 高频引导 | 接地/呼吸引导（36 工具箱） | 全 persona | 预合成 |

### 8.2 收益

- **延迟**：高频/安全话术零合成延迟，保障首音（37 ≤1.5s）。
- **一致性**：合规话术每次完全一致，不受实时合成波动影响。
- **成本**：减少重复 TTS 调用。

## 九、语音输出数据流全景

```
决策：画像(46)+情绪状态(44)+当前情绪(47)+场景 → VoicePersonaResolver → VoiceRenderProfile
   ↓
合成：命中预合成矩阵？→ 是：直接取（安全/高频，零延迟）
                      → 否：tts-service(persona+instruct+prosody+speed)
   ↓
同步：TTS 情绪基调 ⟷ 波波表情 ⟷ 微动效（37 三方同源，同 emotionState）
   ↓
回收：完成率+参与度+质量四维+手动切换 → 匹配规则进化(7) + 回写画像偏好(46)
```

## 十、合规与安全

- **安全/危机话术锁定稳定基调 + 预合成**，不受情绪 instruct 干扰（红线）。
- **不做真人声纹克隆**，音色为合成人设，统一波波品牌（27）。
- **手动偏好优先**：尊重并记忆学生选择，不强制。
- **无障碍**：提供语速可调、可关闭语音（视觉替代），对齐 19 无障碍。
- **同意**：语音合成播放纳入产品说明（25）与同意（22）。

## 十二、EARS 验收标准（摘要）

- WHEN 未指定 persona，THE 系统 SHALL 依据画像（性别认同/年龄/性格）自动选出默认 persona 并允许学生手动覆盖与记忆。
- WHEN emotionState 为 ACTIVATED/CRISIS，THE 系统 SHALL 调整 prosody 为更慢更稳的安抚基调，危机场景 SHALL 锁定稳定基调并使用预合成安全话术。
- WHILE 一次会话进行中，THE 系统 SHALL 保持 persona 稳定，除非学生手动切换。
- WHEN 播放语音，THE 系统 SHALL 使 TTS 情绪基调、波波表情、微动效同源于同一 emotionState。
- THE 系统 SHALL NOT 让情绪 instruct 影响安全/危机话术的音色基调、SHALL NOT 做真人声纹克隆。

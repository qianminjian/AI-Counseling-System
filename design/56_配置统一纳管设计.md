## 一、问题诊断

### 1.1 当前配置分散现状

| 层级 | 载体 | 典型内容 | 问题 |
|------|------|---------|------|
| 环境变量 | `deploy/.env` | 密钥、服务 URL、引擎选择 | ✅ 合理（12-Factor） |
| Java 配置 | `application.yml` | 业务阈值、SLA、密码策略、声纹模式 | ✅ 结构化，但部分值与前端重复 |
| TTS 服务 | `app.py` 硬编码 | 7 音色矩阵、方言映射、情感 Instruct、模型名 | ❌ 改参数需改代码+重部署 |
| Voice 服务 | `app.py` 硬编码 | ASR 引擎选择（仅 2 个环境变量） | 🟡 尚可，但无配置文件 |
| 前端声纹 | `config/voiceprint.ts` | 阈值 0.55、模型 ID、引导脚本、采集参数 | ❗ 与后端 application.yml 阈值重复 |
| 前端唤醒 | `config/wakeWord.ts` | 模型 ID、唤醒词变体、滑窗参数、静音阈值 | ❌ 运营不可调，改词需发版 |
| Nginx | `default.conf` | 端口、域名、缓存策略 | ✅ 基础设施层，独立管理 |

### 1.2 核心痛点

| # | 痛点 | 影响 | 严重度 |
|---|------|------|--------|
| P1 | 声纹阈值前后端各写一份（0.55） | 改一处忘另一处→验证逻辑不一致 | 🔴 高 |
| P2 | TTS 音色矩阵硬编码在 Python 代码中 | 加音色/改参数需改代码+重新构建镜像+部署 | 🟠 中 |
| P3 | 引导脚本（VP_GUIDE_SCRIPTS）写死前端 | 运营改话术需发版 | 🟠 中 |
| P4 | 模型名分散三处（app.py / .ts / .yml） | 无全局视角，切换模型需逐一排查 | 🟠 中 |
| P5 | Python 服务无独立配置文件 | 与 Java 后端配置风格割裂 | 🟡 低 |
| P6 | 业务参数 vs 密钥引用混杂 | 不清楚哪些能改、哪些是密钥 | 🟡 低 |

## 二、设计原则

| 原则 | 说明 |
|------|------|
| **密钥不落文件** | API Key / 密码 / Token 只通过环境变量注入，配置文件中仅写 `${ENV_VAR_NAME}` 占位引用 |
| **单一事实源** | 每个配置项有且仅有一个权威定义处，其他层通过 API 获取或构建时注入 |
| **分层分治** | 基础设施层（.env）→ 服务层（各服务配置文件）→ 运行时层（API 下发前端） |
| **改配置不改代码** | 业务参数（阈值/音色/话术）变更只需改配置文件或数据库，不触发代码构建 |
| **YAGNI** | 不引入 Consul/etcd/Nacos 等配置中心，当前规模用文件+API 足够 |

### 4.5 前端（运行时配置注入）— 改造

**新增** `frontend/student-h5/src/config/remote.ts`：

```typescript
/**
 * 远程配置加载器
 * 启动时从后端拉取系统配置，覆盖本地默认值
 * 失败时静默降级为本地硬编码值（离线可用）
 */
import { VP_VERIFY_THRESHOLD, VP_MAX_TEMPLATES, ... } from './voiceprint'

export interface SystemConfig {
  voiceprint?: {
    verifyThreshold?: number
    maxTemplates?: number
    enrollSegments?: number
    verifySegments?: number
  }
  wakeWord?: {
    modelId?: string
    windowSeconds?: number
    silenceRmsThreshold?: number
  }
  tts?: {
    defaultPersona?: string
    personas?: string[]
  }
  guideScripts?: {
    verify?: Array<{ prompt: string; hint: string; duration: number }>
    enroll?: Array<{ prompt: string; hint: string; duration: number }>
  }
}

let cachedConfig: SystemConfig = {}

export async function loadRemoteConfig(): Promise<SystemConfig> {
  try {
    const resp = await fetch('/api/v1/system/config', { signal: AbortSignal.timeout(3000) })
    if (resp.ok) cachedConfig = await resp.json()
  } catch { /* 静默降级 */ }
  return cachedConfig
}

export function getRemoteConfig(): SystemConfig {
  return cachedConfig
}
```

**使用方式**：

```typescript
// main.jsx 入口
import { loadRemoteConfig } from './config/remote'
await loadRemoteConfig()  // 3s 超时，失败不阻塞

// useVoiceprint.ts 中
const threshold = getRemoteConfig().voiceprint?.verifyThreshold ?? VP_VERIFY_THRESHOLD
```

**本地 config/*.ts 保留**：作为 fallback 默认值 + 离线 PWA 场景 + 类型定义。

## 五、环境变量引用规范

### 5.1 配置文件中标识环境变量的统一格式

| 服务 | 格式 | 示例 |
|------|------|------|
| Java（Spring） | `${ENV_VAR:default}` | `${DB_PASSWORD:mindsafe_dev}` |
| Python（YAML） | `${ENV_VAR:default}` + 加载时解析 | `${DASHSCOPE_TTS_MODEL:cosyvoice-v3-flash}` |
| Docker Compose | `${ENV_VAR:-default}` | `${HTTP_PORT:-80}` |
| 前端 | 无环境变量（运行时 API 获取） | — |

### 5.2 Python 环境变量解析器

```python
import re, os

def resolve_env_vars(value):
    """递归解析配置中的 ${VAR:default} 占位符"""
    if isinstance(value, str):
        pattern = r'\$\{(\w+)(?::([^}]*))?\}'
        def replacer(m):
            return os.environ.get(m.group(1), m.group(2) or '')
        return re.sub(pattern, replacer, value)
    if isinstance(value, dict):
        return {k: resolve_env_vars(v) for k, v in value.items()}
    if isinstance(value, list):
        return [resolve_env_vars(i) for i in value]
    return value
```

## 七、不应该纳入统一配置的项目

| 项目 | 理由 |
|------|------|
| 唤醒词变体列表（WAKE_PATTERNS） | 纯前端算法逻辑，与模型强绑定，不适合运行时下发 |
| 幻觉检测规则（isHallucination） | 算法逻辑，非配置 |
| ONNX WASM 路径/线程数 | 底层运行时参数，与 Transformers.js 版本强耦合 |
| IndexedDB 库名/版本 | 前端存储结构，变更需配合数据迁移 |
| 音频采样率/段时长 | 与模型输入强绑定，改了模型才能改这些 |
| Nginx 路由规则 | 基础设施层，独立管理 |

## 九、风险与约束

| 风险 | 缓释 |
|------|------|
| 前端拉取配置失败（网络/后端宕机） | 本地 fallback 默认值保底，PWA 离线不受影响 |
| 配置下发暴露内部参数（安全） | 仅下发非敏感业务参数，密钥/内网地址绝不下发 |
| 引导脚本被篡改（合规） | 后端 yml 由运维管控，前端只读消费 |
| Python YAML 解析增加启动依赖 | PyYAML 已在 requirements.txt（dashscope 间接依赖），零新增 |

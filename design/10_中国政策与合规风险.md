# 10 中国政策与合规风险

> 来源：`doc/10_中国政策与合规风险.docx`（原文 309 行）
> 状态：已转换（参考类，含**技术实现约束**——合规要求会硬约束产品与后端设计）
> 核心：面向未成年人 AI 心理服务的**法规红线、行业监管与合规实施路线**，是产品与后端不可协商的边界。

---

## 1. 核心法规

### 1.1 《未成年人保护法》（2021.6.1 实施）

- **要点**：网络保护专章（不得提供诱导沉迷的产品）、强制报告制度（发现疑似侵害应立即报告）、六大保护体系。
- **系统要求**：实名认证、时间限制、内容分级过滤、消费限制。
- **合规措施**：接入实名认证 + 未成年人黑名单、年龄分层差异化服务、强制休息提醒、禁止任何诱导沉迷机制。

### 1.2 《个人信息保护法》

- **敏感信息**：14 岁以下未成年人个人信息属敏感个人信息，需**单独同意**（不接受默认勾选/一揽子授权，同意记录可追溯）。
- **数据最小化**：仅收集与服务直接相关的信息，不收集精确位置/通讯录等无关信息。
- **删除权**：用户可撤回同意并要求删除；处理目的实现后主动删除；注销时删除或匿名化；响应删除请求 ≤ 15 个工作日。

### 1.3 《数据安全法》

- **分类分级**：一般数据 / 重要数据 / 核心数据。
- **出境限制**：重要数据出境须通过网信部门安全评估；向境外提供个人信息需单独同意。
- **安全评估**：定期开展数据安全风险评估并留存报告，含涉未成年人数据特殊考量。

### 1.4 《家庭教育促进法》

- 提供家长查询未成年人使用情况的渠道；经监护人同意推送使用报告；重大事项及时通知监护人；建立家校信息共享机制。

### 1.5 《精神卫生法》

- **服务边界**：心理辅导仅面向心理健康人群的心理困扰，**不得涉及精神疾病诊断和治疗、不得开药**；超出辅导范围需提示转介。
- **危机干预**：识别自杀/自残信号 → 立即提供危机热线（全国心理援助 400-161-9995）→ 启动紧急转介。

## 2. 行业监管要求

- **教育 App 备案**：提交申请 → 省级审核 → 信息核验 → 发放备案号并公示；材料含基本信息、运营者信息、ICP、安全评估/等保证明、隐私政策、未成年人保护方案；周期 30-60 工作日，建议提前 3-6 个月启动。
- **网信办算法备案**：不得屏蔽信息/过度推荐（须提供不针对个人特征的选项）、不得大数据杀熟、须提供关闭算法推荐选项、须有人工干预机制；每年 3.31 前提交算法安全评估报告。
- **等级保护（二级）**：物理环境/通信网络/区域边界/计算环境/管理制度五方面；流程为定级 → 备案 → 建设整改 → 等级测评 → 监督检查。

## 3. 未成年人专项保护

- **时间管理**：参考防沉迷通知（禁用时段、每日累计上限）；实名认证对接、时长监控、强制下线、宵禁机制。
- **内容过滤**：敏感词库实时过滤（涉黄/暴/政/毒）、UGC 先审后展示、举报机制；12 岁以下更严格过滤 + 内容分级标签。
- **家长监护**：账号绑定、使用报告推送、异常提醒；家长可设时长上限/时段/功能限制/远程退出。

## 4. 伦理规范

- **心理辅导伦理**：知情同意（说明性质/范围/局限，未成年人需监护人同意，可随时终止）、保密例外（伤害自己/他人、法律要求披露、事先告知）、避免双重关系。
- **AI 伦理**：透明性（明确告知在与 AI 交互）、可解释性（建议能解释推理、可申诉纠错）、人类监督（人工渠道畅通、AI 无法处理转人工、定期人工审核交互记录）。

## 5. 合规风险清单

| 等级 | 风险项 | 应对 |
|------|------|------|
| 高 | 未成年人信息泄露 | 数据加密、访问控制、定期安全审计 |
| 高 | 未经同意收集敏感信息 | 严守最小化、明确告知目的 |
| 高 | 内容引发心理伤害 | 内容安全审核、危机干预流程 |
| 高 | 违规开展心理治疗 | 明确服务边界、建立转介机制 |
| 中 | 未完成 App/算法备案 | 提前准备材料、预留审核时间 |
| 中 | 等保测评缺失 | 委托有资质机构测评 |
| 中 | 家长监护功能不完善 | 开发完整监护模块 |
| 低 | 隐私政策/用户协议滞后 | 建立法规跟踪机制、定期更新 |
| 低 | 客服响应不及时 | 建立 7×24 客服机制 |

## 6. 合规检查清单（研发对齐用）

- **产品设计**：未成年人身份识别、时间管理防沉迷、家长监护、内容分级、心理服务边界明示、危机干预与转介机制。
- **数据处理**：仅收集必需信息、14 岁以下监护人单独同意、删除渠道、数据分级分类、重要数据出境安全评估。
- **安全措施**：等保备案与测评、安全管理制度、定期漏扫与渗透测试、备份与灾难恢复、第三方服务安全评估。

## 7. 合规实施路线

- **第一阶段（1-3 月）**：隐私政策/服务条款公示、未成年人身份识别、基本时间管理防沉迷、家长监护基础模块、App 备案材料准备。
- **第二阶段（4-6 月）**：完成教育 App 备案、等保二级测评、内容安全审核机制、危机干预转介机制、算法备案材料准备。
- **第三阶段（持续）**：定期更新隐私政策、每年数据安全评估、每年算法安全年度报告、定期安全审计与渗透测试。

## 9. 对技术实现的硬约束（研发落地映射）

> 合规不是文档，是**代码里的强制项**。以下要求需在 Java 后端与前端固化，且属 AGENTS.md 红线（监管责任事项 AI 不做决策，只提供信息）。

| 合规要求 | 落地实现 |
|------|------|
| 14 岁以下单独同意 | 注册/首次使用流程强制监护人授权门槛；同意记录独立存表、可追溯（`consent_records`），不与其他条款捆绑 |
| 数据最小化 | 数据模型评审禁止采集无关字段；对话不索要真实姓名/地址/精确位置（呼应 14 文档 §1.2） |
| 删除权 ≤15 工作日 | 提供账号注销 + 数据删除/匿名化接口；定时任务按保留期（普通 30 天/高风险 1 年，见 14 文档）清理 |
| 不做精神诊断/开药 | `SafetyOutputAdvisor` 拦截诊断/处方类输出，短路到转介模板（呼应 14 文档铁律） |
| 危机干预热线固定输出 | 热线号码固化常量，命中风险由规则引擎强制附加（不交给 LLM，见 04/14） |
| 明确告知在与 AI 交互 | 会话开始展示 AI 身份与能力边界说明（透明性原则） |
| 强制报告 | 命中家暴/性侵/自伤强制场景走 EscalationAgent + 人工通知（见 05/13/14），**AI 只触发流程不做合规判断** |
| 数据加密与等保 | 传输 TLS、敏感字段 AES-256 存储（见 06/14）；部署满足等保二级技术要求（见 12） |
| 时间/防沉迷 | Service 层会话时长与频率限制 + Redis 计数（见 14 §11） |
| 家长监护 | 家长端功能模块 + 数据权限过滤（见 05 权限模型），报告推送需监护人同意 |

> **铁律**：合规判断、监管报告签署、生产发布审批等属监管责任事项，AI 只提供信息与实现，**不代替人做合规决策**（AGENTS.md §5.7）。

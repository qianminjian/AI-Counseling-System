# 一、总览

## 1.1 本卷范围与定位

家长端是 MindSafe "学生-AI-教师-家长"四位一体体系的最后一环：家长在手机端查看孩子的情绪周报、接收 AI 建议、管理数据授权。

**核心原则（定稿）**：

- **低门槛注册为主**：家庭码一次绑定（后续手机号登录）＋教师链接兼容——家庭码解决了教师逐个生成链接的运营成本，且支持多孩绑定；
- **只读为主**：家长只看统计报告，不看对话原文（隐私保护）；
- **合规闭环**：监护人同意确认、同意撤回均可在家长端完成。

## 2.1 P1 → P2 复用分析

| 层 | 复用度 | 迁移工作 |
|---|---|---|
| API 调用层（`src/api/`） | 契约 100% | 迁 Taro 后底层 `fetch` → `Taro.request`，业务签名不变 |
| 业务逻辑（hooks/utils） | 95% | 纯 JS，无平台依赖（`localStorage` → Taro storage） |
| 视图层（页面/组件） | **需重写** | HTML 元素/SCSS → Taro 组件（View/Text/Button）+ WXSS（工作量主体） |
| 认证流程 | **需改造** | H5 用 JWT Token；小程序改 `wx.login` → openid → 绑定 |
| 路由/生命周期 | **需重写** | react-router-dom → 小程序页面路由（app.config 注册 + Taro.navigateTo） |

> ⚠️ 工作量修正：早期"2-3 人天重新编译"的估计过于乐观且基于错误前提（误以为已是 Taro）。实际是一次完整的 React-SPA→Taro 框架迁移（引入 Taro 工程 + 视图/路由重写 + 存储/请求适配 + 微信认证接入 + 提审），只是业务简单（3 页）故总量可控。完整迁移设计以 **design/43** 为准。

# 三、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **Vite 6 + React 19** | 轻量、构建快、与学生端/教师端技术栈统一 |
| 路由 | **react-router-dom 7** | SPA 路由，3 个页面足够（全站唯一用路由的端） |
| 样式 | **SCSS**（单文件 app.scss） | 移动端适配，max-width 480px 居中 |
| 部署 | nginx 静态目录 `/parent/` | 复用现有 nginx，路径 `yun.gxjugu.com/parent/` |
| 状态管理 | React useState/useEffect | KISS，页面少无需 Redux |

> P1 代码结构已部分考虑跨端兼容（API 层纯函数、业务逻辑纯 JS），但**当前为 Vite+React SPA，尚未 Taro 化**；P2 用 Taro CLI 初始化工程重写视图层。

# 四、页面设计（P1 H5）

## 4.1 页面清单

| 路由 | 页面 | 功能 |
|------|------|------|
| `/` | 验证/登录页 | **家庭码注册**（家庭码+手机+密码+关系）＋**手机号+密码登录**双模式；兼容教师链接初始 Token 验证码通道 |
| `/report` | 情绪周报页 | 展示近 7 天情绪分布、对话统计、风险等级、AI 建议 |
| `/consent` | 同意管理页 | 查看授权状态 + 撤回同意（不可逆操作，二次确认） |

## 4.2 验证/登录页（`/`，双模式定稿）

**模式 A：手机号+密码登录**（日常路径）：

```
手机号  [138 1234 5678]
密码    [********]
[登录] → 跳转 /report
```

**模式 B：家庭码注册**（首次绑定，支持多孩）：

```
家庭码  [______]（6 位，学生注册时生成）
手机号  [138 1234 5678]
密码    [********]
关系    [爸爸 / 妈妈 / 其他]
[绑定并注册] → 绑定学生 → 跳转 /report
```

**模式 C：教师链接 + 验证码**（兼容保留）：链接含初始 Token（教师生成，`?token=xxx`）→ 输入手机号 → `POST /parent/send-code` → 输入验证码 → `POST /parent/verify-phone` → 获得正式 7 天 Token → Token 存 localStorage → 跳转 `/report`。

## 5.2 跨端兼容约定（P2 前提）

- **视图层**：P2 用 Taro CLI 初始化工程，将 HTML 元素 / react-router 重写为 Taro 组件与小程序路由。

> 家庭码体系前端实现在**学生端注册流程**（`TrialRegister.jsx` FamilyCodePage），家长端仅消费家庭码完成绑定。

# 八、安全与合规（源：26 §8）

| 项 | 措施 |
|---|---|
| Token 安全 | 初始 Token 仅用于验证流程；正式 Token 7 天过期（与 17 §10.2 口径一致）。JWT `tokenType=parent_report`（SEC-006）独立于学生 access token：家长报告链接 token 不可调用学生接口，防学生自持 token 调家长接口（08 §3.1） |
| 手机号脱敏 | 前端展示 `138****5678`，后端日志同 |
| 只读原则 | 家长端无写入接口（除撤回同意），不暴露对话原文 |
| 撤回不可逆 | 二次确认弹窗 + 明确文案告知后果（冻结学生账号 + 删除心理画像数据，PIPL 47 条删除权联动 10 §2.11） |
| PIPL 告知 | 验证页底部链接到告知同意条款（design/22） |

## 1. 总体架构（分层）

系统采用分层架构，从前端到基础设施共 7 层，层间通过标准化接口通信。

| 层次 | 职责 | 技术方案（现行） |
|------|------|------|
| 前端层 | Web / H5 / 平板多端适配 | React 19 + TypeScript + Vite 8（三应用独立 npm 管理） |
| 负载均衡/网关层 | 流量分发、静态资源、反向代理 | **Nginx**（定稿：单体架构下不引入独立 API 网关） |
| 应用服务层 | 业务逻辑处理 | **Spring Boot 3 模块化单体（Maven 多模块）** |
| AI 编排层 | LLM 对话、RAG、情绪识别、风险管线 | **Spring AI（ChatClient）+ Service 层显式安全管线 + CTX-Agent 4 段式上下文简报** |
| AI 边车层 | 语音能力（ASR/SER/TTS） | **voice-service / tts-service（Python 独立容器，解耦加载）** |
| 端侧 AI 层 | 唤醒词 + 声纹识别（隐私优先） | **Transformers.js + Whisper-tiny/wespeaker ONNX（同源 WASM 自托管）** |
| 数据层 | 关系型/缓存/向量/文件存储 | PostgreSQL 16 + pgvector / Redis 7 / OSS |
| 基础设施层 | 计算、存储、网络 | Docker Compose（试点）/ Kubernetes（规模化） |

**架构实态**：系统是「Java 单体 + 2 个 Python AI 边车服务」（合理漂移：Python AI 生态不可替代，如 FunASR/CosyVoice/emotion2vec）。

> **BA-01 语音类组件最终态（2026-08-08 B-06 修正，his/79 §33）**：风险场景语音降级组件 **VoiceDegradationPolicy 保留在用**——由 TtsController 构造器注入并在 `/tts/voice-decision` 运行时 `decide(riskLevel, emotion)`（S0 静默/S1 预合成/S2 强制安抚，TtsControllerTest 4 用例在测，详见 design/10 §6.9 TTSFX-001 🟩）；仅 **TtsPipelineScheduler（TTSFX-002）与 VoiceEffectivenessTracker（TTSFX-003）两类已删除**（假 API 无生产消费，DOC-074）。

## 3. 后端架构（模块化单体，决策 #8）

### 3.1 技术选型

| 架构要素 | 技术方案 | 说明 |
|------|------|------|
| 语言/运行时 | Java 21（虚拟线程） | 高并发 I/O 场景低成本 |
| 框架 | Spring Boot 3 | 生态成熟，Spring AI 原生集成 |
| 持久层 | MyBatis-Plus | SQL 可控，多租户拦截器友好 |
| API 规范 | OpenAPI 3.0 / SpringDoc | 自动文档 |
| 消息/异步 | Spring Events（进程内）+ @Async | 解耦，试点期不引入 Kafka |
| 构建 | Maven | 多模块管理 |
| JSON 序列化 | **counseling-common 单例 ObjectMapper bean**（ARCH-010 D1） | 全后端统一注入复用，消除手写拼接/每轮 new/三风格并存 |

### 3.2 Maven 多模块结构

```
backend/
├── counseling-common/    通用工具、异常、返回体、常量、TenantContextHolder
├── counseling-domain/    领域模型、MyBatis Mapper、DO/Entity、多租户拦截器（com.mindsafe.tenant）
├── counseling-ai/        AI 编排（Spring AI、Prompt 编排、RAG、风险分类）
├── counseling-service/   业务服务（对话、预警、个案、画像、记忆、通知、报表）
├── counseling-api/       Web 层（Controller、Spring Security + JWT、限流）
└── counseling-app/       启动模块（装配、配置、Main）
```

**CTX-Agent 设计要点**（落地于 `ConversationContextAgent.java`，详见 09 §八·五）：

- Token 绑定租户：解构 Token 时同步校验归属租户；跨校 API 调用返回 403 并记录安 全审计
- RBAC：角色（student/teacher/head_teacher/admin/guardian）+ 数据权限（只能访问 归属自己含下级的学生数据）
- SSO（钉钉/企微 OAuth）为预留能力，商用前随学校采购需求接入

#### 5.3.1 平台管理账号体系（doing/83 后台管理端 M6，DEC-007 议决，2026-08-09 合并）

- **独立 `platform_admin` 表 + 独立登录端点**（`/api/v1/platform/auth/login`），与租户 users 表解耦（平台账号不属于任何租户）
- **独立 token 前缀 `PLATFORM_`**（R-8）：平台登录态与业务登录态隔离；JWT 无 tenantId claim，不绑定租户上下文（平台操作无租户归属）
- **四角色 RBAC**：super_admin（全部）/ ops_admin（监控/降级/告警，**仅看聚合数据，学生级明细仅 super_admin/audit**，R-7）/ finance_admin（计量/报表）/ audit（审计只读）；端点级强制授权 + 前端菜单双保险，deny-by-default
- 过滤器平台分支：`JwtAuthenticationFilter` 识别 `PLATFORM_` 前缀 → 建立 `ROLE_PLATFORM_<角色>` 授权域（不建租户上下文）；已撤销 token 黑名单校验
- 登录防爆破：`PlatformLoginGuard` 内存计数（同 IP 连续失败 ≥5 次锁 15 分钟，XFF 取尾元素防伪造，表项上限 10 万）

### 8.1 服务降级监控链路（doing/83 降级监控专题，OPS-MON-001~008，2026-08-09 合并）

> **实施态核对（2026-08-10，详见 his/14 §四 M2/M3）**：链路实态表 `degradation_events`/`alert_events`（V34）+ `service_health_snapshots`（V35）已落库，OpsController 消费（/services/status、/alerts）；手动切换运行时键按 R-2 决策挂远期。
> **追加同步 2026-08-11（doing/87 M3 运行时档位联动合并 DOC-115）**：覆盖键运行时消费全链落地——tts/voice 请求时读 `mindsafe:degradation:override:{tts|asr|ser}`（redis-py 直连 fail-open；funasr 未加载拒绝切换）+ 后端写侧 TTL 7 天 + /health 档位字段（覆盖值优先）；管理端矩阵 overridden/currentState 与 /health 实际档位一致，见 his/87。

> 触发：BUG-TTS-01 事故复盘——CosyVoice 主引擎因 dashscope SDK API 变更 100% 失败，系统静默降级 edge-tts 长期运行无告警触达。根因：① 监控栈配置存在但生产未部署；② 既有 `tts_engine_available` 只反映配置层可用性，检测不到运行期降级。

**链路**：运行期降级指标埋点（TTS 新增、LLM 复用）→ 告警规则（+3 降级 +4 业务）→ 企微触达（≤5 分钟）→ 事件落库（degradation_events/alert_events，供后台管理端 M2 告警中心/M3 降级矩阵消费）→ 生产部署 + 可重复演练。

**降级告警规则（alert-rules.yml，全部 warning 级——服务仍可用，critical 留给全引擎不可用既有规则）**：

| 规则 | 表达式要点 | 语义 |
|------|-----------|------|
| TtsPrimaryEngineDegraded | `rate(tts_synthesize_requests_total{engine="edge_tts"}[5m]) > 0 and rate(...{engine="cosyvoice"}[5m]) == 0 and 总请求 > 0`，for 5m | 主引擎失效但兜底可用（用成功计数推导，兼容未埋点期） |
| TtsDegradeRatioHigh | `rate(tts_degraded_events_total[5m]) / clamp_min(rate(tts_synthesize_requests_total[5m]), 0.001) > 0.3`，for 10m | 降级率超 30%（防抖动） |
| LlmPrimaryFailing | `rate(mindsafe_llm_model_fallback_total[10m]) > 0`，for 5m | LLM 主供应商连续失败（复用既有计数器） |
| MindsafeRiskOverdueHigh | `mindsafe_risk_events_overdue > 0`，for 5m | 存在逾期未处置预警 |
| MindsafeNotifyDeadPiling | `mindsafe_risk_notify_dead >= 3`，for 10m | 通知 dead 堆积 |
| MindsafeRiskSurge | `(events_24h > 3 * (events_24h offset 1d) + 10) or (events_24h > 20)`，for 30m | 单租户激增（相对 3 倍 or 绝对 20 条兜底新租户首日） |
| MindsafeClaimRateDrop | `events_24h > 3 and claimed/events < 0.3 and 昨日认领率 > 0.5`，for 30m | 认领率骤降（>3 条守卫防无事件误报） |

**降级事件检测器（OPS-MON-007，`com.mindsafe.service.monitoring.DegradationEventDetector`）**：30s 轮询 Prometheus 指标增量（tts_degraded_events_total / mindsafe_llm_model_fallback_total）→ 增量 > 0 写 degradation_events auto 事件；last_value 去重防连续重复；恢复写恢复事件；Redis 覆盖键存在（manual 覆盖中）跳过该点；Redis SETNX 分布式锁防多实例重复。**2026-08-10 修复**：insertEvent 补主键（IdType.INPUT 实体）且落库失败仅 WARN 不中断轮询。

**告警事件采集器（OPS-MON-008，`com.mindsafe.service.monitoring.AlertEventCollector`）**：60s 拉取 AlertManager `/api/v2/alerts`（内网可达）→ upsert alert_events（source=alertmanager，fingerprint 去重）；AlertService 发出时同步写（source=alertservice，WeCom/LoggingAlertService 挂钩）；firing→resolved 流转；保留 30 天每日清理。**2026-08-10 附加通道原则**：先入库（notify_status=PENDING）→ 异步推送 → markNotifyResult 回写 SUCCESS/FAILED；落库失败仅 WARN 不阻断主流程；V40 加 notify_status 列。

**通知链**：企微应用消息（主，alertmanager wechat_configs 注入 WECOM_CORP_ID/AGENT_ID/SECRET/ALERT_TO_USER）+ 业务告警 webhook（辅，群机器人 ALERT_WECOM_WEBHOOK_URL）+ 日志留存（兜底）。GRAFANA_PASSWORD 用 `:?` fail-fast 强制。**实施态（2026-08-10）**：业务告警群机器人 webhook 已配置并验证触达（notify_status=SUCCESS 实证）；AlertManager 企微应用消息未配置（WECOM_* 哨兵值）——OPS-MON-004 剩余部分与 OPS-MON-005 演练归口 **frozen/88** 冻结跟踪，解锁条件 = 企微自建应用凭证。

**部署契约**：monitoring 栈三容器（prom 2.53.1/alertmanager 0.27.0/grafana 11.2.2），3 抓取端点（backend:8080/tts-service:10096/voice-service:10095），Grafana 仅 127.0.0.1:3002 可达（不公网暴露）。**实施态（2026-08-10）**：生产已部署运行，17 条规则 promtool 校验通过；降级演练（AC-6：断 DASHSCOPE key → 指标 +1 → ≤5min 企微 → 恢复）随 frozen/88 冻结，凭证就绪后解冻执行。

## 12. 性能与可靠性

### 12.1 错误处理与降级

| 失败场景 | 降级策略 |
|------|------|
| LLM 瞬时失败（网络抖动/限流/连接重置） | `retryWhen(Retry.backoff(1, 2s))` 自动重试 1 次；超时不重试 |
| 主模型异常 | `ResilientChatModel` 立即切换备用模型（qwen-plus），无等待 |
| 重试耗尽 + 备用失败 | 降级安全话术（"波波现在有点忙不过来…"） |
| TTS 三级降级 | CosyVoice → edge-tts → 浏览器 speechSynthesis |
| 风险检测失败 | 规则引擎（关键词）替代语义检测 |
| 情绪识别失败 | 返回中性情绪 |

### 12.2 超时控制

| 场景 | 超时 |
|------|------|
| 首 token | 12s（prod） |
| 整体流 | 45s |
| 学生端会话 | 单次 ≤20 分钟（对话限制）、每日 ≤30 分钟（未保法） |

### 12.3 缓存策略

| 缓存类型 | 内容 | TTL |
|---------|------|-----|
| 用户画像 | 基本信息、偏好 | 24 小时 |
| 情绪上下文 | 最近情绪分析结果 | 5 分钟 |

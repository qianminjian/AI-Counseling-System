# 20 端到端流程设计

> 状态：新建 | 关联：13 Agent 工作流、16 API 接口设计、18 Prompt 模板库、19 界面详细设计、03 CBT 流程树
> 核心：以**时序图 + 完整对话示例 + 数据流**描述系统核心流程，开发人员可直接按此实现和测试。
> ⚠️ **实现现状（2026-07-28 更新）**：F-01/F-02 主链路已生效，实际管线是 M1 精简版（非本篇 Orchestrator+SkillRouter 时序）；~~F-04 摘要生成零调用~~ → PEVAL-001 已接线（evaluateSessionAsync 已触发）；F-06 测评完全未实现。各流程四态对照与 M1 实际时序见 §10。

## 0. 流程总览

| 流程 ID | 名称 | 触发 | 参与组件 |
|---------|------|------|---------|
| F-01 | 正常对话（低风险） | 学生选择情绪卡片 | 前端→API→Orchestrator→Safety→CBT→OutputGuard→SSE |
| F-02 | 高风险紧急流程 | 学生输入触发 L4/L5 | 前端→API→Safety→Escalation→WebSocket→教师端 |
| F-03 | 教师预警处置 | WebSocket 推送新预警 | WebSocket→教师端→API→预警服务→个案服务 |
| F-04 | 会话收束与摘要 | 对话结束/超轮/转人工 | Orchestrator→ReportAgent→DB→WebSocket |
| F-05 | 放松练习 | 学生进入放松页 | 前端→API→DB（无 AI 调用） |
| F-06 | 测评流程 | 教师发放测评 | 教师端→API→测评服务→学生端→结果→预警 |

### 1.2 完整对话示例：考试焦虑（3-4 年级）

> 场景：四年级学生，数学考砸了，觉得自己笨。风险 L1，走 CBT 微技能。

| 轮次 | 角色 | 内容 | 系统状态 | 后台动作 |
|------|------|------|---------|---------|
| 1 | 系统 | 你好！我是波波 😊 你选了“难过”，能告诉我发生了什么事吗？ | S0→S2 | 创建会话，emotion=sad |
| 2 | 学生 | 我数学又考砸了，觉得自己好笨 | S2 | SafetyInput: L1/academic_stress; SkillRouter: CBT/exam_anxiety |
| 3 | AI | 考砸了确实会很难受。你说"好笨"，是脑袋里的小声音在这样说吗？ | S2→S5 | 捕捉自动想法 |
| 4 | 学生 | 嗯，每次考完我都觉得自己什么都学不会 | S5 | auto_thought="我什么都学不会" |
| 5 | AI | 这个小声音说"什么都学不会"。那有没有哪一次，你觉得自己还做得不错的？ | S5→S6 | 找反例 |
| 6 | 学生 | 上次语文听写我全对了 | S6 | evidence_against="语文听写全对" |
| 7 | AI | 对呀！语文听写全对，说明你不是"什么都学不会"，只是数学这次有点难。我们可以把"我什么都学不会"改成什么更公平的话？ | S6 | balanced_thought 生成中 |
| 8 | 学生 | 我数学这次没考好，但其他科目还可以 | S6→S7 | balanced_thought 确认 |
| 9 | AI | 这句话公平多了！今天你可以做一个小行动：花 5 分钟把错题里最简单的一道重新做一遍，试试？ | S7 | micro_action="重做一道简单错题" |
| 10 | 学生 | 好，我试试 | S7→S8 | 行动确认 |
| 11 | AI | 好的！现在心情温度计变成几分了？还需要老师帮忙吗？ | S8 | 复检 |
| 12 | 学生 | 4 分吧，不用找老师 | S8→END | emotion_after=4, final_risk=L0 |
| 13 | AI | 从 7 分降到 4 分，你做得很好！记得试试那个小行动，也可以和爸爸妈妈聊聊今天的事哦 😊 | END | 会话结束，写入摘要 |

### 2.2 完整对话示例：轻生表达（5-6 年级）

> 场景：六年级学生，对话中突然表达轻生意图。触发 L5 紧急流程。

| 轮次 | 角色 | 内容 | 系统动作 |
|------|------|------|---------|
| 1-6 | - | （正常 CBT 对话，考试焦虑） | L1，CBT 进行中 |
| 7 | 学生 | 老师，我真的不想活了，放学后就去跳楼 | SafetyInput: 硬规则命中"不想活+跳楼"→L5 |
| - | 系统 | **短路**：跳过 CBT/LLM 生成，直接使用 §12 L5 安全模板 | Orchestrator 短路到 EscalationAgent |
| 8 | AI | 我很在意你现在的安全。请你现在就找身边的老师或家人，告诉他们你需要帮助。如果很紧急，可以拨打 120（急救）或 110（报警）。全国心理援助热线：400-161-9995（24 小时）。我已经通知了学校老师，他们会马上来帮你。 | SSE 推送安全模板 |
| - | 前端 | 输入框禁用，显示三个大按钮：[找老师] [打电话] [我安全了] | 前端进入 safety_mode |
| - | 教师端 | WebSocket 收到 S0 紧急预警，桌面弹窗+声音+钉钉+短信 | 并行通知 |
| 9 | 学生 | 点击 [找老师] | POST /escalate → 通知心理老师 |
| 10 | AI | 好的，王老师已经知道了。请你现在去办公室找她，或者在教室里等她来。你不是一个人。 | 安全模板 |
| - | 教师端 | 王老师认领预警，10:35 到达教室 | 处置记录 |

### 3.2 SLA 升级机制

```
预警创建
  │
  ├─ S0 紧急：
  │   ├─ 0 min: 通知值班心理老师（WS+钉钉+短信）
  │   ├─ 5 min 未确认: 通知备份老师 + 管理者
  │   ├─ 15 min 无处置记录: 通知学校危机负责人
  │   └─ 30 min 仍无响应: 触发线下应急预案（电话确认）
  │
  ├─ S1 高：
  │   ├─ 0 min: 通知分派心理老师（WS+钉钉）
  │   ├─ 15 min 未认领: 转备份老师
  │   ├─ 2 h 未初评: 提醒管理者
  │   └─ 24 h 未处置: 进入超时列表
  │
  ├─ S2 中：
  │   ├─ 0 min: 进入待办列表
  │   ├─ 1 工作日未处理: 进入超时列表
  │   └─ 3 工作日: 提醒管理者
  │
  └─ S3 低：
      ├─ 0 min: 进入待办列表
      └─ 3 工作日: 批量处理或自动关闭
```

## 7. 错误处理流程

### 7.1 AI 响应超时

```
学生发送消息
  │
  ├─ 前端显示 TypingIndicator（“小助手正在想...”）
  │
  ├─ 后端调用 LLM，设置 10s 超时
  │   ├─ 正常响应 → SSE 流式返回
  │   ├─ 10s 超时 → 重试一次（5s 超时）
  │   │   ├─ 重试成功 → SSE 流式返回
  │   │   └─ 重试失败 → 返回错误 SSE
  │   └─ 模型降级 → 切换到备用模型（Resilience4j）
  │
  ├─ 前端收到错误 SSE
  │   ├─ 显示“出了点小问题，请再说一次 😊”
  │   └─ 显示 [重试] 按钮
  │
  └─ 连续 3 次失败 → 显示“小助手暂时休息了，请稍后再来” + [返回首页]
```

> ✅ **实现状态（2026-08-01 核对）**：上方为目标设计。M1 实际由 `LlmStreamEnhancer` 统一处理（prod 配置）：
>
> ```
> 学生发送消息
>   │
>   ├─ 前端显示 TypingIndicator
>   │
>   ├─ LlmStreamEnhancer.enhance(Supplier<Flux>, sessionId)
>   │   ├─ 首 token 12s 超时（TimeoutException）
>   │   │   └─ 超时不重试（模型本身慢）→ 直接降级安全话术
>   │   ├─ 瞬时失败（网络/限流/连接重置）
>   │   │   └─ retryWhen(backoff 1次, 2s) → 重试成功则继续流
>   │   ├─ 重试耗尽 → ResilientChatModel 已先尝试备用模型
>   │   │   └─ 备用也失败 → 降级安全话术（“波波现在有点忙不过来...”）
>   │   └─ 整体流 45s 超时 → 降级安全话术
>   │
>   └─ 前端收到降级 token → 正常显示安全话术（无感知）
> ```
>
> 关键差异：无“返回错误 SSE + 重试按钮”路径——所有异常均服务端消化，学生端始终看到友好回复。

### 7.2 SSE 连接断开

```
SSE 连接中
  │
  ├─ 前端 EventSource onerror 触发
  │   ├─ 自动重连（EventSource 内置，最多 3 次）
  │   ├─ 重连成功 → 继续接收流
  │   └─ 重连失败 → 显示"网络不太稳定"横幅
  │       ├─ 消息已发送但未收到回复 → 显示"消息已发送，回复可能丢失"
  │       └─ [重新发送] 按钮
  │
  └─ 后端检测 SSE 断开
      ├─ 消息已生成 → 存入 DB（学生刷新后可见）
      └─ 消息生成中 → 取消生成，不存 DB
```

### 7.3 风险 JSON 解析失败

```
SafetyInputAdvisor 调用 LLM 生成风险 JSON
  │
  ├─ Jackson 反序列化成功 → 正常流程
  │
  ├─ 反序列化失败（LLM 输出非法 JSON）
  │   ├─ 第 1 次：重调 LLM，追加"请严格输出 JSON"指令
  │   │   ├─ 成功 → 正常流程
  │   │   └─ 失败 → 走兜底
  │   └─ 兜底：默认 risk_level=L3, needs_human_review=true
  │       ├─ 走限制性支持（不深聊）
  │       └─ 生成预警给心理老师复核
  │
  └─ 连续 3 次解析失败 → 熔断，所有新会话走兜底模式
      └─ 告警通知运维
```

## 8. WebSocket 消息协议

### 8.1 连接建立

```
教师端登录成功
  │
  ├─ 获取 JWT token
  ├─ 建立 WebSocket: wss://host/ws?token={jwt}
  ├─ 服务端验证 token + 提取 tenantId + userId
  ├─ 注册到 WebSocket session registry（按 tenantId 分组）
  └─ 返回 {type: "connected", userId, serverTime}
```

### 8.2 消息类型

```typescript
// 服务端 → 客户端
type ServerMessage =
  | { type: 'NEW_ALERT'; payload: AlertItem }           // 新预警
  | { type: 'ALERT_SLA_WARNING'; payload: { alertId, remainingMinutes } }  // SLA 预警
  | { type: 'ALERT_ESCALATED'; payload: { alertId, newLevel } }            // 预警升级
  | { type: 'CASE_UPDATED'; payload: { caseId, update } }                  // 个案更新
  | { type: 'APPOINTMENT_REMINDER'; payload: { appointmentId, time } }     // 预约提醒
  | { type: 'SYSTEM_NOTICE'; payload: { message, level } };                // 系统通知

// 客户端 → 服务端
type ClientMessage =
  | { type: 'ACK_ALERT'; payload: { alertId } }         // 确认收到预警
  | { type: 'HEARTBEAT' };                               // 心跳（30s 间隔）
```

### 8.3 断线重连

```
WebSocket 断开
  │
  ├─ 前端自动重连（指数退避：1s, 2s, 4s, 8s, 最大 30s）
  ├─ 重连成功后：
  │   ├─ 发送 HEARTBEAT 确认连接
  │   └─ GET /api/v1/teacher/alerts?since={lastMessageTime} 补拉离线消息
  └─ 超过 5 次重连失败：
      └─ 显示"实时通知已断开，请刷新页面" + 降级为 30s 轮询
```

# 二、后台信息架构与角色权限（源：05 §2/§3）

## 2.1 设计结论（8 大一级模块）

信息架构按「处置优先、管理次之、配置最后」排序：

| 一级模块 | 二级页面 | 核心用途 | 主要角色 |
|------|------|------|------|
| 首页工作台 | 今日待办、风险概览、预约提醒、测评进度 | 心理老师日常工作入口 | 心理老师 |
| 预警中心 | 预警队列、预警详情、分派记录、误报复核 | 识别处置高风险信号，触发人工转介 | 心理老师、管理员 |
| 个案管理 | 个案列表、详情、干预计划、跟进记录、结案复盘 | 沉淀学生长期支持过程 | 心理老师 |
| 测评管理 | 量表库、测评任务、结果解读、班级完成率 | 组织 MHT/SDQ 量表并生成非诊断性摘要 | 心理老师、班主任 |
| 预约与跟进 | 预约日历、时段配置、跟进任务、缺席记录 | 把预警转化为线下/线上辅导安排 | 心理老师、班主任 |
| 协同沟通 | 班主任协同、家校沟通、沟通模板、授权记录 | 最小披露前提下形成支持网络 | 心理老师、班主任 |
| 管理报表 | 学校趋势、年级/班级分布、SLA、服务使用率 | 支持管理层看趋势、资源与合规 | 管理者 |
| 系统设置 | 角色权限、通知渠道、审计日志、数据保留策略 | 保障安全、合规和可追溯 | 系统管理员 |

## 2.2 角色与权限差异（5 类角色）

权限策略：「默认不可见、按职责授权、按事件留痕」。学生身份、聊天摘要、测评结果、风险等级拆分授权。

| 角色 | 可见范围 | 不可见范围 | 关键操作 |
|------|------|------|------|
| 心理老师 | 被分派学生的风险摘要、测评结果、个案记录、预约跟进；必要时看脱敏关键证据片段 | 非分派学生完整资料；默认不开放完整原始聊天全文 | 认领预警、建档、制定干预计划、发起家校沟通、结案 |
| 班主任 | 本班学生风险等级、协同任务、观察表、到场状态、课堂支持建议 | 完整聊天、测评逐题答案、AI 原始分析链路、家庭敏感细节 | 提交观察、确认到场、执行课堂支持、反馈变化 |
| 学校管理者 | 学校/年级/班级聚合趋势、服务量、SLA 达成率、脱敏风险分布 | 任何学生完整聊天、个案详情、测评原始答案、单个学生敏感记录 | 查看趋势、配置试点范围、审核资源制度 |
| 系统管理员 | 账号、角色、组织架构、系统参数、审计日志元数据 | 学生心理内容正文、测评答案、个案笔记正文 | 配置权限、启停通知、导出审计、处理账号异常 |
| 家长/监护人 | 经审核的沟通摘要、预约安排、家庭支持建议、授权请求 | 学生与 AI 完整对话、其他学生信息、未审核风险推断 | 确认授权、查看建议、反馈家庭观察 |

> **最小权限红线**：班主任不查看完整聊天；学校管理者只查看聚合趋势；系统管理员不能借运维权限读取心理内容。任何越权查看、批量导出、非工作时间异常访问必须进入审计告警。
>
> **权限铁律（实现层）**：班主任、管理者、系统管理员对心理内容正文的不可见性由**后端数据权限过滤器强制**（服务端裁剪，响应中根本不含敏感字段），不依赖前端隐藏；越权访问在过滤器层拦截并记审计。

# 三、心理老师工作台（源：05 §4 + 35 三）

## 3.1 工作台目标

把「今天最需要处理的学生和任务」排在第一屏，默认按 S0/S1 优先——教师打开系统 10 秒内知道今天该处理谁、下一步做什么（35 改版核心：从"数据展示页"改造为"行动驱动的工作台"）。

**业界依据**：caseload view + 优先级排序是一线心理老师的核心诉求；警报疲劳是头号失败原因（预警必须分级、可聚合、可标注处理状态）；不同角色必须看到不同的默认首屏（counselor 看个案、principal 看聚合趋势）。

## 3.2 导航结构（左侧栏，按角色裁剪）

```
🏠 工作台        ← 新首页（默认落地页）
🚨 预警中心      ← 预警全量列表 + 处理工作流
📁 我的个案      ← 个案生命周期管理
👥 学生管理      ← 班级/学生列表 → 学生详情页
📋 测评管理      ← 量表任务下发与结果（衔接 34）
📊 数据大屏      ← 现有 BigScreen（管理者角色默认首页）
⚙️ 设置          ← 密码/通知偏好
```

角色裁剪（沿用 2.2 权限矩阵）：
- **心理老师**：全部可见，默认落地"工作台"；
- **班主任**：工作台（仅本班）+ 学生管理（本班，无完整对话）+ 测评（本班任务）；
- **校领导/管理者**：默认落地"数据大屏"，无个案明细入口，只见聚合与脱敏数据；
- **平台运营**：不进此端（走 platform 后台，衔接 38）。

**默认落地页实现**：`defaultLandingFor`（admin→大屏带"返回工作台"，其余→工作台），登录/刷新均生效；`/bigscreen` URL 直达保留（展厅模式无返回按钮）。

## 3.3 工作台首屏（Today View）——三栏布局

```
┌────────────────────────────────────────────────────────────────┐
│  顶栏：今日概况条（在线学生数 · 今日会话数 · 待处理预警数 · 逾期数❗）  │
├──────────────────┬──────────────────────────┬──────────────────┤
│ ① 今日待办        │ ② 预警时间线              │ ③ 快捷操作         │
│  (SLA 倒计时排序)  │  (24h 滚动流)             │  + 发起测评        │
│  🔴 S0 剩 8min    │  09:12 S1 王同学* 情绪…   │  + 新建个案        │
│   张同学* 认领    │  08:40 S3 班级普测摘要     │  + 家校沟通        │
│  🟠 S1 剩 1h20m  │  昨天 S2 李同学* 已处理✓  │  + 查学生          │
│  🟡 复测到期 ×3   │                          │ ─────────────    │
│  🟢 个案随访 ×2   │                          │ 本周关注榜         │
└──────────────────┴──────────────────────────┴──────────────────┘
```

**① 今日待办**（核心，按"逾期 > SLA 剩余时间"排序）聚合四类事项：

| 待办类型 | 来源 | 完成动作 |
|---------|------|---------|
| 预警处理 | S0-S3 未关闭预警 | 走预警处理工作流（第四章） |
| 测评复测到期 | 测评任务复测规则 | 一键下发/顺延 |
| 个案随访到期 | 个案跟踪计划 next_followup_at | 填写随访记录 |
| 家长消息待回复 | 家校沟通未读 | 回复或标记 |

**② 预警时间线**：按时间倒序的 24h 滚动流，每条显示分级色点、脱敏姓名、摘要、处理状态徽标；普测类 S2/S3 聚合为一条摘要。

**③ 快捷操作 + 本周关注榜**：高频动作直达；关注榜只对心理老师显示，来源为画像情绪基线连续下行的学生，**上限 5 人、不显示分数、不叫"排名"**（伦理红线：心理数据不得用于排名）。

## 3.4 学生详情页（统一落地页）

从任何列表点入的统一落地页，按信息密度分四区：

1. **头部**：脱敏姓名（心理老师可点击临时显名，操作留审计日志）、年级班级、风险等级色标、在案状态；
2. **趋势区**：情绪基线折线（30 天）+ 测评趋势卡片 + 会话频次；
3. **画像区**：6 维画像摘要（衔接 10 二章），按角色裁剪——班主任只见沟通建议，不见风险轨迹明细；
4. **动态区**：预警历史、会话摘要（**摘要而非原文**）、个案记录、家校沟通记录（Tab 切换）。

> 反模式清单（明确不做）：首屏放大图表轮播（大屏已独立）、未分级预警平铺列表、聊天记录直接暴露在列表、全校排名/学生红黑榜。

# 四、预警中心与处理工作流（源：05 §5/§20 + 35 四）

> 最新方案口径：状态机以**代码实现为单一事实源**（TeacherService 驱动，§4.2）；转派/静音降噪已由 F-3 补齐（2026-07-28，TDD 全绿）；升级/降级、误报原因结构化回流为 WB-001 余量。

## 4.1 预警分级（S0-S3）

承接 Safety Agent、Emotion Agent、测评结果和人工上报，支持快速分级、认领、转介、误报复核。

| 等级 | 触发示例 | 处置目标 | 默认 SLA |
|:---:|------|------|------|
| S0 紧急 | 明确自伤/伤人意图、计划或即时危险 | 立即人工介入，按危机预案同步线下负责人 | 5 分钟确认，15 分钟形成处置记录 |
| S1 高 | 持续严重焦虑、强烈绝望、疑似欺凌/家庭高压且多次出现 | 当日复核并建立个案 | 15 分钟认领，2 小时完成初评 |
| S2 中 | 连续低落、回避上学、人际冲突、考试压力显著升高 | 安排测评或短谈，跟踪趋势 | 1 个工作日内处理 |
| S3 低 | 短期压力、普通情绪波动、一次性负面表达 | 提供自助资源，纳入趋势观察 | 3 个工作日内复核或批量处理 |

> **等级映射**：S0/S1 对应 R4（红）、S2 对应 R3（橙）、S3 对应 R2（黄）；预警队列以 `risk_events` 为数据源。

## 4.2 预警工作流状态机（已实现基准）

```
open ──认领──▶ claimed ──处置──▶ resolved ──安排回访──▶ follow_up_scheduled ──完成回访──▶ closed(outcome)
  │                │
  └──（SLA 超时→兜底升级告警，非状态迁移）└──标记误报──▶ false_positive
```

- **已实现动作**：认领（claim）、误报（false_positive）、处置（resolve，强制填 TeacherNote 干预记录）、安排回访（scheduleFollowUp）、完成回访（completeFollowUp，强制填 outcome 四值：resolved_improved / resolved_stable / escalated_referral / false_positive）、转派（transfer，F-3 补齐）；
- **转派规则**：body 为 targetTeacherId（必填）+ note；重置为 open + 指派目标教师，**不重置 SLA**（detectedAt 不动）；跨租户/目标不存在拒绝；带备注落 teacher_notes（noteType=transfer）；审计日志 ALERT_TRANSFER；
- **SLA 超时扫描**：SlaEscalationScanner @Scheduled 定时扫描 open/claimed 超时事件（escalate→CRITICAL / remind→WARNING 兜底告警）；「自动转备份老师」的改派动作仍为余量；
- **设计有、实现无（余量）**：升级/降级（老师复核后修正等级，样本回流规则优化）、误报原因结构化枚举（当前 false_positive 无原因字段）、建个案入口（依赖个案域）。

## 4.3 队列字段与安全限制

- **核心字段**：预警编号、脱敏学生 ID、年级/班级、风险等级、触发来源、时间、摘要、证据片段、模型置信度、SLA 倒计时、当前负责人、状态；
- **筛选维度**：等级、年级、班级、来源、状态、负责人、是否超 SLA、是否复发、是否需家校沟通；
- **关键操作**：认领、转派、升级/降级、标记误报、创建个案、关联已有个案、发起预约、生成沟通摘要；
- **安全限制**：证据片段只显示与风险判断直接相关的最小文本；完整聊天默认不进入队列页。

## 4.4 降噪机制（消灭 alert fatigue）

1. **同生 24h 同级重复合并计数**（"李同学* S2 ×3"），点开可见每次明细；
2. **普测批量预警聚合**（衔接 34）；
3. **个案跟踪静音**（AlertTodoMutePolicy，F-3 已落地）：个案跟踪中的学生 S2/S3（level≤1）新预警 `mutedFromTodo=true`——只进时间线不进待办；**S0/S1 永不静音**（安全兜底）；个案跟踪标志存 teacher_notes（type=case_tracking，content=active/inactive，取最新一条，免 schema 变更）；端点 `PUT /teacher/students/{id}/case-tracking`。

## 4.5 关键交互与 SLA 升级链

系统静默生成预警按 SLA 推送值班心理老师 → 老师先确认风险等级再选「建个案/预约短谈/误报/持续观察」→ S0/S1 处置完成前队列顶部悬挂 → 超时自动升级给备份老师和管理者 → 误报必须填原因作为规则/Prompt 优化样本，但不向班主任暴露原始内容。

- **SLA 升级链（补强，归 WB-001）**：虚拟线程定时扫描超时事件，按第十章升级规则通知备份老师/管理者；SLA 达成率进 `/teacher/stats`；
- **优先级依据**：SLA 升级链是 S0「5 分钟必须有人接住」承诺的技术兜底，列最高优先。

# 五、个案管理（源：05 §6 + 35 五）

> 最新方案口径：35 落地记录 M3 已实现阶段推进接口（`POST /teacher/cases/{studentId}/transition` + 周报）；完整 CaseRecord 实体与四阶段生命周期仍为设计期（WB-003 余量）。

## 5.1 生命周期（四阶段）

用于长期跟踪，不应成为聊天全文仓库。记录以人工判断、干预计划、跟进结果和授权记录为主。

| 生命周期 | 入口条件 | 关键字段 | 退出条件 |
|------|------|------|------|
| 待评估 | S1/S2 预警、测评异常、班主任上报、学生主动预约 | 个案编号、脱敏学生、触发原因、初始风险、负责人、授权状态 | 完成初评并选择干预路径 |
| 干预中 | 确认需要持续跟进 | 问题假设、保护性因素、干预目标、计划、会谈记录、协同任务 | 风险下降且连续跟进稳定 |
| 观察期 | 主要风险缓解但仍需观察 | 观察周期、班主任反馈、家庭反馈、测评复测、复发条件 | 达结案标准或复发升级 |
| 已结案 | 目标达成或转外部专业机构 | 结案摘要、转介记录、复盘、后续提醒 | 再次触发风险可重新打开 |

- **会谈记录**：结构化模板「问题 / 观察 / 支持策略 / 学生反馈 / 下一步」，不记录无关隐私；
- **干预计划**：每目标绑定负责人、完成标准、复盘时间；
- **结案复盘**：记录风险变化、有效措施、复发预警信号、后续观察安排；
- **结案规则**：必填结案小结 + 结案原因；结案自动终止复测调度；随访到期进入今日待办。

## 5.2 建案来源与列表视图

- **建案来源**：预警转入 / 测评分档 ≥ 中度建议转入 / 手动创建；
- **列表视图**：我的个案卡片（学生、阶段、下次随访时间、最近量表分变化箭头）；
- **个案详情**：阶段推进条 + 随访记录流水 + 关联预警/测评/画像快照；
- **数据表**：复用 06 已有个案相关表；缺失字段（next_followup_at、stage）按 06 修订流程补充（先改文档再建表）。

## 5.3 与预警的衔接

预警处置页一键"转为个案"（预填学生信息与预警上下文）——当前实现中跟进闭环借 `RiskEvent.followUpAt` + TeacherNote 承载（属预警延伸），完整个案域落地后切至 5.1 生命周期（WB-003）。

# 八、班主任协同与家校沟通（源：05 §9/§10）

## 8.1 班主任协同（支持网络最小披露）

班主任是支持网络的一部分，但不是心理内容的完整接收者。页面重点是「执行观察与支持任务」。

| 页面/组件 | 班主任可见 | 班主任不可见 | 可执行操作 |
|------|------|------|------|
| 班级风险概览 | 本班风险等级分布、需关注人数、班级建议 | 具体聊天、测评答案、个案笔记 | 查看建议、提交班级观察 |
| 协同任务 | 任务对象、说明、截止时间、反馈模板 | 预警证据片段、AI 推断细节 | 完成反馈、申请延期、补充观察 |
| 学生支持卡 | 姓名/脱敏标识、关注等级、课堂支持建议、到场提醒 | 完整聊天、家庭沟通详情、敏感标签 | 确认到场、记录行为变化 |
| 上报入口 | 事件类型、观察描述、发生时间、紧急程度 | 其他个案内容 | 提交上报、追加说明、电话应急提示 |

> **班主任红线**：可以知道「需要关注什么、怎么支持、何时反馈」，但不应知道「学生和 AI 具体聊了什么」。降低标签化、二次伤害和信息扩散风险。

## 8.2 家校沟通（必要、克制、可解释）

对外沟通内容必须经心理老师审核，不能直接把 AI 判断或学生原话推给家长。

| 沟通类型 | 触发条件 | 默认内容 | 审批/留痕 |
|------|------|------|------|
| 授权沟通 | 需监护人同意测评/会谈/持续跟进 | 事项、目的、范围、保存期限、联系人 | 记录授权版本、时间、确认人 |
| 风险沟通 | S0/S1 或学校制度要求通知监护人 | 事实性风险提示、学校支持安排、家庭观察建议 | 心理老师确认，必要时管理者见证 |
| 日常反馈 | 个案观察期或阶段性复盘 | 进展摘要、家庭支持建议、下次安排 | 不含聊天全文和测评逐题答案 |
| 外部转介 | 需医疗或专业机构进一步评估 | 转介原因、可选资源、注意事项 | 保留转介建议和家长反馈 |

- 模板变量只能引用已审核摘要；家长拒绝授权时系统记录拒绝原因并提示按制度选择最小必要处置路径；
- 家长/监护人侧体验详见 12 家长端设计（经审核的沟通摘要、预约安排、家庭支持建议、授权请求）。

# 十、通知机制与 SLA（源：05 §13）

按「静默优先、分级升级、避免扩散」设计。

| 事件 | 通知对象 | 渠道 | 升级规则 |
|------|------|------|------|
| S0 紧急预警 | 值班/备份心理老师、危机联系人 | 站内弹窗、钉钉/企微、短信或电话 | 5 分钟未确认升级；15 分钟无记录升级管理者 |
| S1 高风险预警 | 分派心理老师；必要时班主任收「到场/观察」任务 | 站内、钉钉/企微 | 15 分钟未认领转备份；2 小时未初评提醒管理者 |
| S2 中风险预警 | 心理老师 | 站内、每日待办摘要 | 1 个工作日未处理进超时列表 |
| 预约提醒 | 心理老师、学生；班主任只收到场提醒 | 站内、校园端、钉钉/企微 | 缺席自动生成跟进任务 |
| 家校沟通待审 | 心理老师或指定审核人 | 站内、待办摘要 | 超 24 小时提醒；高风险按预案处理 |
| 权限/导出异常 | 系统管理员、安全负责人 | 站内、邮件/企微 | 立即锁定高危会话或二次验证 |

- 通知只含最小必要信息（对象、风险等级、动作、截止时间），不放学生敏感原文；
- 移动端点击需二次身份校验；通知失败进「通知异常队列」支持补发和电话确认；
- **已生效部分**：教师端 WebSocket 预警推送（useAlertWebSocket）+ 声音/桌面通知；SlaEscalationScanner 兜底告警（escalate→CRITICAL / remind→WARNING）。
- **WS 握手鉴权（P1-FE-4，62bb542 2026-08-05）**：连接地址 `/ws/alerts`，JWT 从 query string 迁移至 `Sec-WebSocket-Protocol` 子协议项 `auth.<jwt>`（不进 nginx access log / 浏览器历史）；`AlertAuthHandshakeInterceptor` 提取 token → `AlertWebSocketHandler` 统一校验（access 类型 + 黑名单 jti + 教师/管理员角色）；协商子协议 `alerts.v1`；前端 useAlertWebSocket 同步对齐（详见 08 §2.9）。

# 十一、异常处理与 MVP 范围（源：05 §14/§15）

## 11.1 异常处理矩阵

| 异常 | 系统处理 | 人工处理 | 风险控制 |
|------|------|------|------|
| 身份无法确认 | 暂停展示个体敏感信息，仅留临时会话摘要 | 核验身份后再归档 | 防止错绑学生档案 |
| 模型误报 | 允许标记误报并收集原因 | 复核后关闭或降级 | 误报不直接通知班主任/家长 |
| 模型漏报后人工上报 | 人工上报优先进预警队列 | 补充风险标签和处置记录 | 用于优化规则但不替代人工判断 |
| 通知失败 | 进异常队列并重试 | 高风险由值班人员电话确认 | S0/S1 不能因系统失败中断处置 |
| 越权访问 | 拦截请求、记录日志、触发告警 | 复核账号和权限 | 必要时冻结账号并通报 |
| 家长拒绝授权 | 记录拒绝状态并提示制度流程 | 学校按预案处理 | 避免未经授权扩大披露 |
| 系统不可用 | 保留应急联系人和离线处置流程 | 按纸面/电话预案先处置高风险 | 恢复后补录关键记录 |

## 11.2 MVP 范围

| 纳入 MVP | 暂不纳入 MVP |
|------|------|
| 工作台：待办、预警、预约、测评进度 | 机器人硬件终端和具身化交互 |
| 预警队列：分级、认领、转派、建个案、误报 | 人脸识别、声纹识别、复杂多模态识别 |
| 个案管理：结构化记录、干预计划、跟进、结案 | 完整聊天全文开放检索与批量导出 |
| 测评管理：MHT/SDQ 任务、完成率、结果复核 | 自定义复杂量表编辑器和跨校题库市场 |
| 预约与跟进：日历、提醒、缺席、后续任务 | 复杂排班优化和跨校共享咨询资源 |
| 班主任协同：最小必要信息、观察反馈、到场确认 | 班主任查看聊天全文或测评逐题答案 |
| 管理者报表：聚合趋势、SLA、负荷、测评概览 | 个体级管理驾驶舱和可下钻敏感明细 |
| 审计日志：查看、导出、权限、通知、关键处置动作 | 高级风控模型和自动化合规报告 |

**MVP 验收指标**：

1. S0/S1 能按 SLA 通知/认领/处置并形成记录；
2. 任一学生具备预警→个案→预约→跟进→结案完整闭环（当前实现为「预警→处置→跟进→关闭」，完整个案闭环待 WB-003 补齐后恢复）；
3. 班主任账号无法查看完整聊天/逐题答案/个案笔记；
4. 管理者账号只能看聚合趋势；
5. 审计日志可追踪关键访问、导出、权限变更、通知失败。

## 11.3 后续演进

MVP 稳定后按数据质量和试点反馈逐步扩展：第二阶段增加语音能力、放松训练管理、趋势分析和更细复测机制；第三阶段再评估多模态、机器人终端、校园心理画像，前提是合规、授权和误报控制成熟。持续把误报、漏报、超 SLA、越权访问作为运营指标驱动迭代。

# 十二、服务层与 Java 实现映射（源：05 §18/§19）

## 12.1 服务层分包指引（目标态）

counseling-service 模块内按业务域分包，每包对外暴露 Service 接口，内部实现可独立演进：

| 包名 | 核心 Service | 职责 | 依赖的 Mapper |
|------|------|------|------|
| `.alert` | AlertService | 预警 CRUD、认领/转派/升级/误报、SLA 扫描 | RiskEventMapper |
| `.case` | CaseService | 个案生命周期、干预记录、结案复盘 | CaseRecordMapper, CaseInterventionMapper |
| `.assessment` | AssessmentService | 量表管理、测评任务、结果复核 | AssessmentScaleMapper, AssessmentResultMapper |
| `.appointment` | AppointmentService | 预约 CRUD、签到/缺席、提醒 | CounselingSessionMapper |
| `.notification` | NotificationService | 多渠道通知、重试队列、升级链 | NotificationMapper |

> **处理原则（YAGNI）**：当前实现为 `TeacherService`/`TeacherController` 单类承担预警+工作台+报表；分包结构保留为目标态（个案/测评/预约域落地时按上表拆分），预警域不强行改名重构，WB-001 增量在 TeacherService 上演进。

## 12.2 Java 实现层映射

| 后台能力 | Java 实现方案 |
|------|------|
| 8 大模块 | 归入 counseling-service（业务服务）+ counseling-api（Web 层 Controller），按模块分包 |
| 5 类角色权限 | Spring Security + JWT；RBAC 角色 + 数据级 ABAC（@PreAuthorize + 数据权限过滤器） |
| 证据片段最小化 | 字段级加密 TypeHandler（MyBatis-Plus），证据片段单独授权字段，默认不随查询返回 |
| 预警队列 | 数据源为 risk_events 表；SLA 倒计时用定时任务（虚拟线程调度）扫描超时升级 |
| 审计日志 | 统一 AOP 切面记录重点动作，落 audit_logs 表；告警规则用规则引擎异步检测 |

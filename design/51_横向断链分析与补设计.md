> 创建：2026-07-28 | 状态：设计期（分析型，不含实现代码） | 版本：v1.0
>
> 定位：对 50 份设计文档（`design/01~50`）做**横向（跨专题）**引用/依赖/支撑关系排查，找出"引用了但没承接、依赖了但没接线、支撑关系声明了但未落地"的**虚化断链**，逐条给出补线契约与责任归属。

> 单一事实源纪律：本文所有"现状"结论均以**代码核实**为准（附文件+行号），与设计文档声明冲突处以代码为事实、并标注需回修的设计文档。

## 〇、方法与分级

### 0.1 证据三层交叉

1. **设计交叉引用图**：各 `design/*.md` 正文中对其他专题的"依赖/接入/回注/联动"声明。
2. **代码接线核实**：声明的连接在 `backend/` 是否真实存在调用链（附文件行号）。
3. **backlog 映射**：断链是否已登记为待实施任务（`TASK-TRACKER.md` §二十三），避免重复造册。

### 0.2 断链类型（三类）

| 类型 | 定义 | 典型表现 |
|------|------|---------|
| **A · 设计间单向声明** | 下游文档声明"接入/回注上游"，但上游文档未定义承接契约，或双方都停在设计层 | 设计自洽、代码皆无 |
| **B · 设计→代码未接线** | 设计定义了连接，代码中承接组件**不存在** | 需新建组件 |
| **C · 代码存在未被触发** | 承接组件**已实现**，但调用触发点缺失（"近在咫尺"型断链） | 补一行调用即通 |

### 0.3 严重度分级

| 级别 | 判据 | 数量 |
|------|------|------|
| 🔴 枢纽级 | 断链点是多条下游依赖的汇聚枢纽，不补则整片能力悬空 | 2 |
| 🟠 中 | 断链阻断某条核心能力闭环，但不影响其他线 | 3 |
| 🟡 轻 | 断链影响增强型能力，主链路可降级运行 | 3 |

## 二、断链清单（分级 + 分类型 + 证据）

### 🔴 L1 枢纽级

#### BL-01 · 编排枢纽缺失（类型 B）

- **断链**：`design/44` 定义的 `PromptOrchestrationService` / `StrategyProfile` / `EntryMoodStrategyResolver` 在代码中**完全不存在**；下游 45/46/47/48/28/29/39 全部声明"接入编排"，但无锚点可接。
- **上游被依赖方**：本枢纽自身。
- **下游悬空方**：45（EMO-001 注入）、46（画像→决策）、47（语音→currentEmotion）、48（emotionState→prosody）、28（冷场入编排）、29（降级入编排）、39（A/B 变体注入）。
- **代码证据**：[AiChatServiceImpl.chat()](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/chat/AiChatServiceImpl.java#L64-L82) 为**静态顺序拼接** `fullSystem = systemPrompt + langRules + genderStyle + profilePrompt`，无"先算策略再拼词"层。全仓无 `PromptOrchestrationService`/`StrategyProfile`。
- **影响**：情绪 `currentEmotion` 无一等载体；个性化四维（年龄×画像×心情×合规）无法从"静态拼接"升级为"策略驱动"；这是整个个性化体系的**单点根断链**。
- **已登记 backlog**：`ORCH-001/002`（P0 近期）。

#### BL-02 · 评估闭环触发点缺失（类型 C · “近在咫尺”）——✅ 已修复（PEVAL-001，2026-07-28）

- **断链（精确修正）**：`ConversationQualityService` **已存在**并封装 `evaluateSessionAsync`（抽样 0.3）/`evaluateSession`（幂等）→ 调用 `AiChatServiceImpl.evaluateConversationQuality()` → 落库 `QualityScore`（V19 表已建）。~~真正断链是：**会话结束钩子 `endSession` 从未触发 `evaluateSessionAsync`**~~ → **已修复**：`MessageSummaryService.generateSummaryAsync` L83 已追加 `conversationQualityService.evaluateSessionAsync(tenantId, sessionId, conversationText)` 调用。
- **代码证据**：
  - 承接组件存在：[ConversationQualityService.evaluateSessionAsync](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/quality/ConversationQualityService.java#L62-L78)。
  - 触发钩子存在但未接：[ConversationServiceImpl.endSession](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/conversation/ConversationServiceImpl.java#L384-L406) 只做 DB 收尾 + `clearMemory` + `generateSummaryAsync` + `updateProfile`，**未调用质量评估**。
  - 关键："近在咫尺"——`generateSummaryAsync`（L410+）已拼好 `conversationText`（正是 `evaluateSessionAsync` 所需入参），只差在其后追加一次调用。
  - 触发路径已具备：`endSession` 由 [SessionController.closeSession](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-api/src/main/java/com/mindsafe/api/controller/SessionController.java#L62-L69) 与 ChatController 两处调用。
- **影响**：质量分永不产生 → `design/45` 自进化闭环空转、`design/39` A/B 无主指标、`design/46` 画像效果回收无质量对比基准。三个下游专题的"效果度量"全断在此。
- **需回修文档**：`design/45` P0 原表述"接线未调用的 evaluateConversationQuality"应精确为"**评估服务已实现，缺会话结束触发点**"。
- **已登记 backlog**：`PEVAL-001`（P0 近期）。

### 🟠 L2 中

#### BL-03 · 画像元数据缺失阻断"画像驱动决策"（类型 B）

- **断链**：`design/46` P0 要求"画像→StrategyProfile 结构化决策（低置信不参与）"，但 [StudentProfile](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-domain/src/main/java/com/mindsafe/domain/entity/StudentProfile.java) 的 7 个 JSONB 维度**无 provenance/confidence/decay 元数据**，无法做置信门控；且画像当前以 `profilePrompt` 字符串直接注入（BL-01 静态拼接的一部分）。

#### BL-04 · 语音情感不回注画像 / 不驱动共情（类型 A+B）

- **代码证据**：SER 分析链完整（[VoiceAnalysisResult](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/voice/VoiceAnalysisResult.java)），但情感信号止于风险辅助。

#### BL-08 · 负面纵向信号→教师关注通道未统一（类型 A）

- **断链**：三条"负面纵向信号→教师关注"路径在不同专题各自独立声明，**无统一汇聚通道**：`design/47` 趋势异常→教师关注、`design/50` 记忆与风险纵向关联、`design/34` 量表关键条目熔断。三者都指向"教师侧非实时关注信号"，但彼此无共享出口。
- **风险**：若各自实现，教师端将出现三套并行"关注信号"来源，加剧告警疲劳（与 `design/35` 降噪目标冲突）。
- **补线建议**：定义统一"非实时关注信号"通道（区别于风险实时预警），三源共用（见 §三 BL-08 补线）。
- **已登记 backlog**：`VCL-003`/`MEM-103`/`SCALE-*` 分散登记，**本文新增横向约束**：三者须汇入同一通道，建议由 `design/35` 教师工作台统筹收口。

## 四、落地顺序建议（拓扑排序）

按依赖拓扑与优先级判据（安全/合规 > 对话产品力 > 教师效率 > 学生体验），补线执行序：

```
第 1 波（无依赖，可并行）：
  BL-01 编排枢纽 (ORCH-001/002)  ← 根任务，解锁最多下游
  BL-02 评估触发 (PEVAL-001)     ← ✅ 已完成（2026-07-28）
  BL-06 知识接主线 (KB-101)      ← ✅ 已完成（2026-07-28）

第 2 波（依赖 BL-01）：
  BL-03 画像元数据 (PROF-022)
  BL-04 语音回注+驱动 (VCL-001/002)

第 3 波（依赖 BL-01+BL-03/04）：
  BL-05 音色匹配 (TMATCH-001/002)
  BL-07 记忆↔画像互哺 (MEM-101/102)

第 4 波（横向收口）：
  BL-08 关注信号统一通道 (design/35 统筹 + VCL-003/MEM-103)
```

**关键路径**：`BL-01` 是根断链，解锁 BL-03/04/05 与 45/46/47/48 全部悬空引用；`BL-02` 独立且最低成本，建议与 BL-01 同期启动以尽早点亮效果度量闭环。

## 六、结论

- **最重要发现**：断链不是设计缺失，而是**缺一个共同落地锚点**——`design/44` 编排枢纽（BL-01）在代码中不存在，导致 45/46/47/48 中 4~5 条**设计层已闭合**的引用在代码层集体悬空。补齐编排枢纽是解锁一大片个性化能力的关键路径。

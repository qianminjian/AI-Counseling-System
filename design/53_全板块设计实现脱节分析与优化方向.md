## 〇、总纲：脱节的根源与判定方法

### 0.1 最大系统性脱节 = 双世界架构（与 design/52 共享）

`backend/` 存在两套并行、互不连通的对话实现（详见 [design/52 〇](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/design/52_核心功能板块心理专业深化设计.md)）：

- **世界 A（线上真实运行）**：[ConversationServiceImpl.sendMessageStream](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/conversation/ConversationServiceImpl.java#L131-L290) → `AiChatServiceImpl.chatWithPrompt`。单次 LLM 调用 + 关键词风控 + 输出过滤。
- **世界 B（孤儿死代码）**：`ConversationOrchestrator` + 全套 Agent + `CbtStateMachine`。实现 design/13 但**从未被任何 Controller/Service 调用**。

这不是本文新增结论，而是**理解下文所有板块脱节的总前提**：许多"设计声明"其实在世界 B 里已实现，但因世界 B 未通电，对线上等同于"未实现"。因此本文的"实现度"一律以**世界 A（线上）能否触达**为口径。

### 0.2 四态判定法（本文核心工具）

对每个板块能力，按"设计—代码—线上"三层落差归入四态：

| 态 | 标记 | 含义 | 脱节性质 |
|----|------|------|---------|
| ① 完全未实现 | ⬜ | 设计文档存在，但无任何代码 | 设计超前，纯待开发 |
| ② 仅骨架 | 🟫 | 有 DB 表/接口/服务类，但无业务闭环或内容为空 | 半成品，易误判为"已做" |
| ③ 已实现但孤儿 | 🟧 | 代码完整且可运行，但**无线上调用点**（死代码/未接线） | **最隐蔽、最浪费**——已投入却零产出 |
| ④ 已实现且生效 | 🟩 | 线上真实运行 | 无脱节 |

> 态③是本文最需要暴露的类型：它让"看起来做了很多"与"线上真正生效"之间产生巨大错觉。快赢机会几乎都藏在态③（接线成本远低于重写）。

## 二、非核心板块逐一体检（三段式 + 四态）

> 核心治疗板块（对话/CBT/风险/安全/共情）已在 `design/52` 深化，本文不重复，仅在总表与优化方向中引用其结论。

### 2.1 学生画像自动化闭环（🟠 态③→②）

- **设计声明**（23/29/46）：多维画像随会话自动迭代，带可信度/时效衰减，回注对话个性化。
- **代码现状**：[StudentProfile](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-domain/src/main/java/com/mindsafe/domain/entity/StudentProfile.java) 7 个 JSONB 维度（emotionBaseline/communicationPref/resilience/riskTrajectory/socialGraph/growthTrack/personalityTraits）+ version/totalSessions。[ProfileExtractorService.extractAndMerge](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/profile/ProfileExtractorService.java) LLM 提炼 + EMA 权重 0.4 合并；[StudentProfileService.buildProfilePrompt](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/profile/StudentProfileService.java) 已线上注入对话。**闭环已生效（态④）**。
- **脱节点**：①无 **provenance/confidence/decay** 元数据——每个维度值无来源、无置信度、无时效衰减，无法区分"一次会话的偶发观察"与"稳定特质"，也无法随时间淡化旧结论（态②骨架）。②`riskTrajectory` 维度存在但未见与风险事件联动填充。③画像更新 SQL 聚合近 20 会话，缺增量一致性保证。

### 2.2 长期记忆增强（🟠 态④→②）

- **设计声明**（50）：跨会话关键事件抽取存储、重要度排序回注、复现主题（recurring_theme）归纳、记忆↔画像双向增强。
- **代码现状**：[LongTermMemoryService.buildMemoryPrompt](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/memory/LongTermMemoryService.java#L110-L143) top5（importance + createdAt 降序）线上注入对话；`evictOldMemories` 保留 50 条。**回注已生效（态④）**。
- **脱节点**：①无 **recurring_theme 归纳**（多次出现的主题不被聚合升权）。②**记忆不回注画像**、画像不指导记忆抽取——设计要求的双向增强未接线（= design/51 记忆↔画像断链）。③记忆仅用于 prompt 拼接，未用于连续性开场（= design/52 ALLY-201）。

### 2.3 知识库 RAG（🔴 态③ 最严重脱节之一）

- **设计声明**（15/49）：心理知识库 + 混合检索（BM25+向量+RRF）+ RAG 上下文注入对话，让 AI 回答有循证依据。
- **代码现状**：[KnowledgeBaseService.buildRagContext](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/knowledge/KnowledgeBaseService.java#L125) 已实现，但**全仓 `buildRagContext` 零调用点**（本次核实：无任何 caller，纯死代码）。[KnowledgeBaseController](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-api/src/main/java/com/mindsafe/api/controller/KnowledgeBaseController.java#L62-L66) 仅暴露原始 `search`/`ingest`/`list`/`delete` 增删查接口，**不调用 RAG 组装**。
- **脱节点**：①**chat 主线（ConversationServiceImpl）从不检索知识库**——对话完全无知识注入，"循证"仅靠底座模型内化知识。②`buildRagContext` 是比"孤儿"更彻底的死代码（连管理接口都不用）。③纯向量检索，无设计要求的 BM25+RRF 混合。④知识库内容为空——即便接线也无料可检。这是"设计闭环、实现断两头（既不进 chat、内容也空）"的典型。

### 2.4 语音情感分析 / 情感化 TTS（🟠 态④→②）

- **设计声明**（16/47/37/48）：ASR+SER 逐轮情感 → 驱动风险/共情/画像；TTS 4 persona 情感化合成；**音色年龄/情绪自适应匹配（48 VoicePersonaResolver）**。
- **代码现状**：[VoiceAnalysisService](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/voice/VoiceAnalysisService.java) / [TtsService](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/voice/TtsService.java) 调用 Python 微服务已实现；voiceEmotion 已进风险融合（态④）。
- **脱节点**：①**无 VoicePersonaResolver**（本次核实：仅测试文件提及 persona，无生产实现）——音色由前端指定或静态 xiaoxing，design/48 的"年龄×情绪自适应"未落地（态①）。②语音情绪仅喂风险，不驱动共情/不回注画像（= design/51 BL-04、design/52 §四）。

### 2.5 Prompt 版本 / 质量评估（🟠 态③）

- **设计声明**（44/45）：Prompt 版本化 A/B + LLM-as-Judge 多维质量评估（empathy/cbt/safety/engagement）驱动迭代闭环。
- **代码现状**：[PromptVersionService](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/prompt/PromptVersionService.java) DB 优先 + classpath 降级 + 5min 缓存 + hash 20% 分组，**线上生效（态④）**。[ConversationQualityService.evaluateSessionAsync](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/quality/ConversationQualityService.java#L62) 四维评估已实现。
- **脱节点**：**`evaluateSessionAsync` 零外部调用**（本次核实：仅内部自调）——[endSession/generateSummaryAsync](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/conversation/ConversationServiceImpl.java#L409-L449) 未触发评估。整个质量评估闭环建成却从不运行（态③），A/B 因此也无效果指标可比——A/B 分了组但没人评分。

### 2.6 教师后台 / 预警（🟠 态④→②）

- **设计声明**（05/35）：预警工作流 + SLA 时效 + 多端实时推送。
- **代码现状**：[TeacherService](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-service/src/main/java/com/mindsafe/service/teacher/TeacherService.java) 状态机完整（open→claimed→resolved/closed/false_positive/follow_up_scheduled，含 claim/falsePositive/resolve/scheduleFollowUp/completeFollowUp），**线上生效（态④）**。
- **脱节点**：①**无 SLA 自动超时/升级**——RED 预警若无人认领无自动升级兜底（儿童安全隐患）。②[AlertWebSocketHandler](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-api/src/main/java/com/mindsafe/api/websocket/AlertWebSocketHandler.java#L93) tenantSessions 为进程内 ConcurrentHashMap，`pushAlert` 仅遍历本进程 → **多实例部署时其他实例的教师收不到预警**（与 §2.10 无状态化同源）。

### 2.7 计费配额 / 运营后台（⬜ 态① 完全未实现）

- **设计声明**（38，219 行）：订阅/配额/用量计量/运营后台。
- **代码现状**：**无任何 billing/quota/subscription/payment 实现代码**（本次核实为空）。
- **脱节点**：设计完整但实现 0%。商业化前置能力全缺。属"设计超前、纯待开发"，非隐蔽脱节——风险在于排期与商用发布时点（关联 design/32 商用清单）。

### 2.8 量表测评数字化（⬜ 态① 完全未实现）

- **设计声明**（34，273 行）：标准心理量表数字化、施测、计分、结果解读。
- **代码现状**：**无任何 scale/assessment/questionnaire 实现代码**（本次核实为空）。
- **脱节点**：实现 0%。注意：量表涉及**专业效度与监管**（未成年人心理测评合规），属 §五须回修/须钱敏健决策事项，AI 不替决策施测范围。

### 2.9 A/B 实验框架（🟫 态② 仅骨架）

- **设计声明**（39）：画像/Prompt 效果量化 + A/B 实验（分流/指标/显著性/停止规则）。
- **代码现状**：仅 `PromptVersionService` hash%10<2 的 20% 分组（态②）；无实验注册、无指标采集、无显著性检验、无实验生命周期。
- **脱节点**：有"分组"无"实验"。且因 §2.5 质量评估从不运行，实验组无客观效果数据——即便补框架也缺评分输入。**A/B 依赖质量评估先接线**。

### 2.10 无状态化 / 水平扩展（🔴 态③）

- **设计声明**（40/42）：会话状态外置 Redis、无状态服务、多实例水平扩展；`ConversationStateManager`（key=session:{id}:state，TTL 2h）。
- **代码现状**：[ConversationStateManager](file:///Users/minjianq/Documents/66-Project/Qoder/AI-Counseling-System-dev/backend/counseling-ai/src/main/java/com/mindsafe/ai/state/ConversationStateManager.java) 已实现 Redis 持久化，但**未接线**——线上 `ConversationServiceImpl.activeSessions` 仍是进程内 Map（`SessionState` 内存态），WebSocket 预警也是单机（§2.6）。
- **脱节点**：**当前架构无法水平扩展**——会话态与 WebSocket 均绑单实例，多副本会导致会话丢失/预警漏送。Redis 状态管理器建成却未接线（态③，快赢接线点）。

## 六、与 51 / 52 的分工与结论

### 6.1 三文档分工

- **design/51 · 横向断链**：专题之间的引用/依赖未接线（如记忆↔画像、语音↔共情、风险↔教师通道）。

- **design/53（本文）· 纵向脱节度**：每个板块"设计 vs 实现"的落差与四态分类，暴露态③"已建未接线"浪费。

### 6.2 结论

1. **最大脱节是结构性的**：双世界架构 + 一批态③"已实现却零调用"资产（世界 B 编排、Redis 状态、质量评估、RAG 组装），造成"看起来做了很多"与"线上真正生效"的巨大错觉。**接线的性价比远高于重写**。
2. **P0 五项接线快赢**（危机短路 / 质量评估触发 / RAG 接主线 / 画像元数据 / 预警 SLA）投入小、覆盖安全与产品力核心，建议立即启动；其中危机短路与预警 SLA 为**儿童安全红线级**。
3. **可扩展性是隐藏地雷**：会话态与 WebSocket 均单机，多副本即失效——`ConversationStateManager` 接线是水平扩展前置。
4. **态①三块（计费/量表/A/B）**为纯待开发，按商用节奏排期；量表已决策（2026-07-28）：PHQ-A/GAD-7 先行开发，施测接线上线前须钱敏健再决策合规范围。

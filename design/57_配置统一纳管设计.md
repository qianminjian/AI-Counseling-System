## 二、设计原则

| 原则 | 说明 |
|------|------|
| **密钥不落文件** | API Key / 密码 / Token 只通过环境变量注入，配置文件中仅写 `${ENV_VAR_NAME}` 占位引用 |
| **单一事实源** | 每个配置项有且仅有一个权威定义处，其他层通过 API 获取或构建时注入 |
| **分层分治** | 基础设施层（.env）→ 服务层（各服务配置文件）→ 运行时层（API 下发前端） |
| **改配置不改代码** | 业务参数（阈值/音色/话术）变更只需改配置文件或数据库，不触发代码构建 |
| **YAGNI** | 不引入 Consul/etcd/Nacos 等配置中心，当前规模用文件+API 足够 |

### 4.5 前端（运行时配置注入）— 改造

```typescript
/**
 * 远程配置加载器
 * 启动时从后端拉取系统配置，覆盖本地默认值
 * 失败时静默降级为本地硬编码值（离线可用）
 */
import { VP_VERIFY_THRESHOLD, VP_MAX_TEMPLATES, ... } from './voiceprint'

export interface SystemConfig {
  voiceprint?: {
    verifyThreshold?: number
    maxTemplates?: number
    enrollSegments?: number
    verifySegments?: number
  }
  wakeWord?: {
    modelId?: string
    windowSeconds?: number
    silenceRmsThreshold?: number
  }
  tts?: {
    defaultPersona?: string
    personas?: string[]
  }
  guideScripts?: {
    verify?: Array<{ prompt: string; hint: string; duration: number }>
    enroll?: Array<{ prompt: string; hint: string; duration: number }>
  }
}

let cachedConfig: SystemConfig = {}

export async function loadRemoteConfig(): Promise<SystemConfig> {
  try {
    const resp = await fetch('/api/v1/system/config', { signal: AbortSignal.timeout(3000) })
    if (resp.ok) cachedConfig = await resp.json()
  } catch { /* 静默降级 */ }
  return cachedConfig
}

export function getRemoteConfig(): SystemConfig {
  return cachedConfig
}
```

**使用方式**：

```typescript
// main.jsx 入口
import { loadRemoteConfig } from './config/remote'
await loadRemoteConfig()  // 3s 超时，失败不阻塞

// useVoiceprint.ts 中
const threshold = getRemoteConfig().voiceprint?.verifyThreshold ?? VP_VERIFY_THRESHOLD
```

**本地 config/*.ts 保留**：作为 fallback 默认值 + 离线 PWA 场景 + 类型定义。

## 五、环境变量引用规范

### 5.1 配置文件中标识环境变量的统一格式

| 服务 | 格式 | 示例 |
|------|------|------|
| Java（Spring） | `${ENV_VAR:default}` | `${DB_PASSWORD:mindsafe_dev}` |
| Python（YAML） | `${ENV_VAR:default}` + 加载时解析 | `${DASHSCOPE_TTS_MODEL:cosyvoice-v3-flash}` |
| Docker Compose | `${ENV_VAR:-default}` | `${HTTP_PORT:-80}` |
| 前端 | 无环境变量（运行时 API 获取） | — |

### 5.2 Python 环境变量解析器

```python
import re, os

def resolve_env_vars(value):
    """递归解析配置中的 ${VAR:default} 占位符"""
    if isinstance(value, str):
        pattern = r'\$\{(\w+)(?::([^}]*))?\}'
        def replacer(m):
            return os.environ.get(m.group(1), m.group(2) or '')
        return re.sub(pattern, replacer, value)
    if isinstance(value, dict):
        return {k: resolve_env_vars(v) for k, v in value.items()}
    if isinstance(value, list):
        return [resolve_env_vars(i) for i in value]
    return value
```

## 十二、环境变量精简分析（实施后补充）

> 实施 CFG-001~008 后，对 .env.example 84 行变量进行二次审视，识别冗余、缺失和归属不当问题。

### 12.1 发现的缺陷

| # | 问题 | 严重度 | 影响 | 修复 |
|---|------|--------|------|------|
| E1 | WECOM_CORP_ID/AGENT_ID/SECRET/REDIRECT_URI 在 .env 定义但 docker-compose **未透传**至 backend 容器 | 🔴 缺陷 | 容器部署时企微 OAuth 永远返回 501 | docker-compose.yml + prod.yml 补充透传 |
| E2 | LLM_BASE_URL/LLM_MODEL 在 .env 和 application.yml 默认值完全重复 | 🟡 冗余 | 删除 .env 中这两行后行为不变，降低认知负担 | .env.example 标注“可选覆盖” |
| E3 | ASR_ENGINE/SER_ENABLED 设计文档§4.4 建议放入 config.yaml，实际不适合 | 🟢 澄清 | 控制启动时模型加载（torch 导入），必须 env 先行 | 设计文档标注“保留 env”原因 |

### 12.2 环境变量归属决策矩阵

| 变量 | 决策 | 理由 |
|------|------|------|
| DB_PASSWORD / REDIS_PASSWORD / JWT_SECRET / ENCRYPTION_* | ✅ 必须 env | 密钥凭证，12-Factor 铁律 |
| LLM_API_KEY / DASHSCOPE_API_KEY | ✅ 必须 env | API 凭证 |
| SMS_ALIYUN_ACCESS_KEY_ID/SECRET | ✅ 必须 env | 阿里云凭证 |
| WECOM_SECRET | ✅ 必须 env | OAuth 密钥 |
| GRAFANA_ADMIN_PASSWORD | ✅ 必须 env | 监控密码 |
| ASR_ENGINE / SER_ENABLED | ✅ 保留 env | 控制容器启动时模型加载（数 GB 内存决策），不能等 config.yaml 读取后再决定 |
| SMS_PROVIDER / CONSENT_TRIAL_AUTO_GRANT | ✅ 保留 env | 跨环境不同（dev=logging / prod=aliyun），运维需免重建切换 |
| VOICE_SERVICE_URL / TTS_SERVICE_URL | ✅ 保留 env | 容器网络拓扑，docker-compose 层管理 |
| HTTP_PORT / HTTPS_PORT / MODEL_CACHE_DIR / VOICE_MEM_LIMIT | ✅ 保留 env | docker-compose ports/volumes/deploy 直接使用 |
| CORS_ORIGINS | ✅ 保留 env | 环境差异大（localhost vs 生产域名） |
| LLM_BASE_URL / LLM_MODEL | 🟡 可选 env | application.yml 已有同默认值，仅切换供应商时才需覆盖 |
| SMS_ALIYUN_SIGN_NAME / TEMPLATE_CODE | 🟡 可选 env | 非密钥（公开信息），但生产必填，保留 env 便于统一填写 |
| WECOM_CORP_ID / AGENT_ID / REDIRECT_URI | 🟡 可选 env | 半公开标识符，保留 env 便于统一填写 |
| ALERT_WECOM_WEBHOOK_URL / MENTIONED | 🟡 可选 env | URL 含 token 但本质是配置端点，保留 env 可接受 |
| DASHSCOPE_TTS_MODEL | 🟡 冗余覆盖 | config.yaml 已有同默认值，env 仅作紧急覆盖用 |

### 12.3 设计原则补充

| 原则 | 说明 |
|------|------|
| **启动决策不可延迟** | 控制“是否加载数 GB 模型”的开关（ASR_ENGINE/SER_ENABLED）必须为 env，不能在读取 config.yaml 后再决定 |
| **env 可覆盖一切，但不应重复定义** | config.yaml/application.yml 已有默认值的参数，.env 中仅标注为“可选覆盖”，避免双源维护 |
| **docker-compose 是 env 到容器的唯一桥梁** | .env 中定义但 compose 未透传的变量 = 死变量（如 E1 缺陷） |

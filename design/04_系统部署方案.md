## 1. 部署架构总览

### 1.1 演进路线

| 阶段 | 编排方案 | 适用场景 | 状态 |
|------|---------|---------|------|

### 1.2 私有化部署模式（多校交付形态）

| 模式 | 规模 | 部署方式 |

## 3. 容器化拓扑

### 3.1 服务清单与关键配置

| 服务 | 镜像/构建 | 关键配置 | 说明 |
|------|----------|---------|------|
| postgres | `pgvector/pgvector:pg16` | 密码 `DB_PASSWORD`；挂载 `init/pg-init.sql`（vector/uuid-ossp/pgcrypto 扩展）；healthcheck `pg_isready` | Flyway V24 依赖 vector 扩展，本地与 prod 镜像必须对齐 |
| redis | `redis:7-alpine` | `--maxmemory 128mb --maxmemory-policy allkeys-lru`；healthcheck `redis-cli ping` | 会话/限流/token 黑名单/验证码 |
| tts-service | 构建自 `backend/tts-service` | `DASHSCOPE_API_KEY`、`DASHSCOPE_TTS_MODEL`（默认 cosyvoice-v3-flash） | 配置文件 `config.yaml`（7 音色 + 8 方言 + 情感 Instruct） |
| voice-service | 构建自 `backend/voice-service`（args `ASR_ENGINE`） | `ASR_ENGINE`（dashscope/funasr）、`SER_ENABLED`、`DASHSCOPE_API_KEY`；挂载 `${MODEL_CACHE_DIR}` → 非 root 用户 HOME | 模型缓存宿主机持久化（emotion2vec ~300MB + SenseVoice ~1GB）；使用前先跑 `prepare-funasr.sh` |
| backend | 构建自 `backend` | 见下方环境变量透传表；`depends_on` 健康检查；**端口仅绑定 `127.0.0.1:8080`** | 公网唯一入口为 nginx，防伪造 XFF 头（P0-3） |
| frontend | 构建自 `frontend`（多阶段） | 产物 volume 共享给 nginx | 静态资源，含 student-h5/teacher-web/parent-h5 |
| nginx | `nginx:alpine` | 挂载 `default.conf`/`default-ssl.conf` + `security-headers.conf` | 双域名反代、安全头、缓存策略 |

- **默认**：GHCR（GitHub Container Registry，免费、与 GitHub Actions 集成最简）。
- **备选**：阿里云 ACR 个人版（GHCR 国内拉取慢时）：创建命名空间 `mindsafe` + 镜像仓库 `mindsafe-backend`/`mindsafe-frontend` → cd.yml 改 push 目标 → 服务器 `docker login registry.cn-hangzhou.aliyuncs.com`。

## 5. CI/CD 流水线

### 5.1 流程

```
开发者 git push feature/*
        │ PR
        ▼
┌─────────────────────────────┐
│ GitHub Actions CI（ci.yml）  │  ← PR 检查：后端编译 + 前端构建
└─────────────────────────────┘
        │ merge to main
        ▼
┌─────────────────────────────┐
│ GitHub Actions CD（cd.yml）  │
│ 1. 测试 + 覆盖率门禁（前端）│
│ 2. 安全扫描（Trivy）        │
│ 3. Build Docker images      │
│ 4. Push to GHCR             │
│ 5. SSH 到阿里云 ECS         │
│ 6. docker compose pull/up   │
│ 7. 冒烟测试（smoke-test.sh）│
│ 8. 前端 dist rsync 直传（deploy-frontend job）│
└─────────────────────────────┘
        ▼
│   阿里云 ECS：postgres/redis/backend/nginx（+voice/tts）│
```

### 5.2 CI（ci.yml）

- 触发：PR（main/develop）
- 内容：后端编译（Maven）、前端三应用构建；前端覆盖率门禁
- 目的：合并前发现编译/构建问题

### 5.3 CD（cd.yml）

- 触发：push main / tag v*；**workflow_dispatch 手动回滚入口**（P1-9：填旧镜像 tag + 回滚范围 backend,voice,tts,frontend）
- **门禁（OPS-003，fix-13 补齐）**：build-and-push 声明 `needs: [backend-build-test, dependency-scan, frontend-build]`——CI 三 job 全绿才允许发版（此前 CD 与 CI 无依赖，测试失败也可发布，已修复）
- 内容：测试 + 覆盖率门禁 → Trivy 安全扫描 → 构建镜像 → 推 GHCR → SSH 登录 ECS → `docker compose pull` + `up -d` → 运行冒烟测试（`tests/e2e/smoke-test.sh`：健康检查、试用注册、学生对话链路、教师端、安全拦截）
- **前端发布（P0-4 修复，独立 job `deploy-frontend`）**：生产 nginx 直接挂载宿主机 `frontend/<app>/dist` 目录（docker-compose.prod.yml），**frontend 镜像虽构建推送但生产从不消费**——前端发布链路此前是断的；现改为 job 内 npm ci + build 三应用（student-h5/teacher-web/parent-h5），rsync 到服务器并保留上一版 `dist.prev` 供回滚，与 deploy.sh 的 rsync 模式对齐
- **回滚**：① 工作流失败自动回滚至上一发布版本；② 前端回滚 = 服务器上 `dist.prev` 目录恢复；③ 后端/服务回滚 = 手动 Run workflow 填旧镜像 tag（workflow_dispatch）

## 7. 域名与 HTTPS

### 7.1 域名规划

| 端 | 域名示例 | 说明 |
|----|---------|------|
| 学生端 | `app.yourschool.cn` 或直接用 IP | Nginx default_server |
| 教师端 | `teacher.yourschool.cn` | 修改 `nginx/default.conf` 中 server_name |

DNS：A 记录 → ECS 公网 IP。⚠️ **ICP 备案**：国内服务器绑定域名必须完成 ICP 备案（约 7-15 个工作日）；测试阶段直接用公网 IP 无需备案。

### 7.2 HTTPS 证书（生产必做）

`docker-compose.prod.yml` 挂载 `nginx/default-ssl.conf`（443 承载全部流量，80 仅证书续期挑战 + 301），首次启动前必须先签发证书，否则 nginx 启动失败：

```bash
# 1. 安装 certbot
apt install -y certbot

# 2. 首次签发（standalone 模式，需 80 端口空闲，compose 启动前执行）
mkdir -p /var/www/certbot
certbot certonly --standalone -d yun.gxjugu.com --agree-tos -m <你的邮箱>

# 3. 启动服务（nginx 容器只读挂载 /etc/letsencrypt 与 /var/www/certbot）
cd /guju/mindsafe && docker compose -f docker-compose.prod.yml up -d

# 4. 自动续期（webroot 挑战不停服；续期后 reload nginx）
echo '0 3 * * 1 certbot renew --webroot -w /var/www/certbot --deploy-hook "docker exec mindsafe-nginx nginx -s reload" >> /var/log/certbot-renew.log 2>&1' | crontab -
```

> 域名变更时同步修改 `default-ssl.conf` 的 server_name 与证书路径、`.env` 的 `CORS_ORIGINS`。

### 7.3 端侧 ONNX 模型投放（语音唤醒/声纹，发布前端前必做）

学生端语音唤醒（whisper-tiny）与声纹登录（wespeaker）均为浏览器内推理，前端配置 `SAME_ORIGIN` 同源加载（`/mindsafe/models/`）。**模型文件不入仓**：

```bash
# 下载到 frontend/student-h5/public/models/（约 60MB），脚本自带投放自检：关键文件缺失时非零退出
bash deploy/scripts/prepare-models.sh
```

> 未执行脚本直接发布 → 模型 404、唤醒/声纹功能加载失败（对话主路径不受影响）。Vite 构建将 `public/models/` 拷入 dist 随 CI 镜像发布。

> O 专题 S5（2026-08-05 定稿）：`prepare-funasr.sh` 删除恒真版本比较（OD-009），保留模型存在性/加载校验（entrypoint fail-fast）；prepare-models-test.sh 8 用例绿。

**WASM/SIMD/SAB 兼容性配置（🟩 nginx 必须配置）**（commit a81dbf4 + a184b4b）：

为启用 SharedArrayBuffer（唤醒/声纹模型推理依赖），nginx 需配置 COOP/COEP 头（`deploy/nginx/default.conf` 与 `default-ssl.conf` 均需包含）：

```nginx
# /mindsafe/models/ 路径添加跨源隔离头
location /mindsafe/models/ {
    add_header Cross-Origin-Opener-Policy "same-origin" always;
    add_header Cross-Origin-Embedder-Policy "require-corp" always;
    add_header Cross-Origin-Resource-Policy "same-origin" always;
    alias /app/student/models/;
    expires 7d;
    add_header Cache-Control "public, max-age=604800, immutable";
}
```

**降级行为**：浏览器不支持 SIMD/SAB 时前端静默降级（不显示错误横幅+隐藏声音按钮），不阻断主路径。

## 11. 环境变量治理（配置纳管纪律）

### 11.1 三层归属

| 层 | 载体 | 职责 |
|----|------|------|
| 密钥层 | `deploy/.env`（不入 Git） | 密钥/凭证，12-Factor 铁律 |
| 服务层 | `application.yml` / `config.yaml` | 业务参数、阈值、音色矩阵 |
| 运行时层 | `GET /api/v1/system/config` | 前端运行时下发（5min 缓存） |

### 11.2 铁律

1. **docker-compose 是 env 到容器的唯一桥梁**：`.env` 中定义但 compose 未透传的变量 = 死变量（历史缺陷 E1：WECOM 四变量未透传导致容器企微 OAuth 永远 501，已修复）。
2. **启动决策不可延迟**：控制是否加载数 GB 模型的开关（`ASR_ENGINE`/`SER_ENABLED`）必须为 env，不能等 config.yaml 读取后再决定。
3. **env 可覆盖一切，但不应重复定义**：`application.yml`/`config.yaml` 已有默认值的参数，`.env` 仅标注「可选覆盖」（`LLM_BASE_URL`/`LLM_MODEL`/`DASHSCOPE_TTS_MODEL`）。
4. **密钥不落文件**：API Key/密码/Token 只经环境变量注入，配置文件只写 `${ENV_VAR}` 占位引用。
5. **变量名必须与占位符完全一致**：`LLM_API_KEY` 写成 `SPRING_AI_DEEPSEEK_*`、`TTS_SERVICE_URL` 写成 `MINDSAFE_TTS_SERVICE_URL` 时 Spring 松散绑定匹配不上，将静默回落默认值。

### 11.3 环境变量归属决策矩阵（摘要）

| 变量 | 决策 | 理由 |
|------|------|------|
| DB/REDIS 密码、JWT_SECRET、ENCRYPTION_*、各 API Key | ✅ 必须 env | 密钥凭证 |
| SMS_PROVIDER / CONSENT_TRIAL_AUTO_GRANT | ✅ 保留 env | 跨环境不同（dev=logging / prod 默认 logging；启用 aliyun 时在 .env 设 SMS_PROVIDER=aliyun + 4 个 MINDSAFE_SMS_ALIYUN_* 凭证；2026-08-06 设计修正：原 prod compose 默认 aliyun fail-closed 改为 logging，因试点期 SMS 未启用、无 aliyun 凭证会卡住部署） |
| ASR_ENGINE / SER_ENABLED | ✅ 保留 env | 控制启动时模型加载（内存决策） |
| VOICE/TTS_SERVICE_URL、HTTP/HTTPS_PORT、MODEL_CACHE_DIR、VOICE_MEMORY_LIMIT | ✅ 保留 env | 容器网络拓扑与 compose 直接使用 |
| CORS_ORIGINS | ✅ 保留 env | 环境差异大 |
| LLM_BASE_URL / LLM_MODEL / DASHSCOPE_TTS_MODEL | 🟡 可选 env | 配置已有同默认值，仅切换时覆盖 |
| WECOM_CORP_ID / AGENT_ID / REDIRECT_URI / ALERT_WECOM_WEBHOOK_URL | 🟡 可选 env | 半公开标识符，统一填写 |

## 12. 运维注意事项

1. **2C2G 内存紧张**：开启 swap（setup-server.sh 已自动配置 2GB）；voice 本地模型（funasr+SER）需 4G，仅 prod 承载
2. **GHCR 私有镜像**：服务器需 `docker login` 才能 pull
3. **x86_64 架构**：CI 构建无需指定 platform
4. **HTTPS 顺序**：测试用 HTTP 即可；生产必须先签发证书再启动 compose，否则 nginx 启动失败
5. **安全组**：SSH 端口建议限制来源 IP
6. **端侧模型**：发布 student-h5 前必须先跑 `prepare-models.sh`（ONNX 模型获取脚本，P0-6），否则语音唤醒/声纹不可用；脚本失败冒烟直接拦截
7. **语音模型宿主机缓存**（9340c6b，2026-07-31）：部署/更新 voice-service 前先跑 `deploy/scripts/prepare-funasr.sh`（FunASR 模型 manifest 版本比对 + 临时容器下载到宿主机 `MODEL_CACHE_DIR`，默认 `~/.cache/msasr`），容器重建不重复拉数 GB 模型；ASR_ENGINE=funasr 时模型缺失 entrypoint **exit 1 fail-fast**（不静默切云端，隐私红线）
8. **密钥 fail-fast**：prod profile 下 `JWT_SECRET`/`ENCRYPTION_KEY`/`LLM_API_KEY` 缺失直接拒绝启动
9. **续费**：经济型 e 实例首购 99 元/年，续费同价（活动期），关注续费提醒
10. **本地 DB 端口统一 5432**（P1-14 修复：开发环境由 5433 对齐为 5432，与 compose 内网端口一致，消除连错实例风险）
11. **TTS/语音服务超时防护**（fix-13）：wait_for 就绪检查、ffmpeg 处理 timeout、executor join 挂死防护已全链路补齐

## 13. voice-service 部署深化（2026-08-02 追加）

### 13.1 内存与模型缓存选型

| `ASR_ENGINE` | `SER_ENABLED` | 内存需求 | 模型体积 | 适用场景 |
|--------------|---------------|----------|----------|----------|
| `dashscope` | `true` | ~1.5GB | emotion2vec_plus_large ~300MB（云端 ASR 零体积） | 低资源主机、公网演示 |
| `funasr` | `true` | ~4GB | + SenseVoiceSmall ~1GB | 私有化部署、信创 |
| `*` | `false` | ~200MB | 仅 dashscope SDK 运行时 | 关闭情感分析，节省 ~1.3GB |

`docker-compose.prod.yml` 默认 `memory: 6G`（为 funasr+SER 留 50% 余量）。

### 13.2 模型宿主机缓存（不打入镜像）

模型文件**不在镜像构建时下载**，而是通过宿主机 volume 挂载：

```yaml
# deploy/docker-compose.prod.yml
voice-service:
  volumes:
    - ${MODEL_CACHE_DIR:-./cache/modelscope}:/home/appuser/.cache/modelscope
```

**首次部署必须执行**：

```bash
# 下载 SenseVoiceSmall (~1GB) + emotion2vec_plus_large (~300MB) 到宿主机缓存
bash deploy/scripts/prepare-funasr.sh
```

> 镜像体积从 ~5GB 降至 ~2GB（P3-31）；模型持久化在宿主机，重建容器不需重新下载。

### 13.3 BuildKit pip/apt 加速

Python 服务 Dockerfile 同时启用 BuildKit cache mount 缓存 **pip 与 apt**，源头走国内镜像：

```dockerfile
# syntax=docker/dockerfile:1

# 系统包：apt cache mount + 阿里云 APT 镜像（避免 ffmpeg/torch 等重包重新下载）
RUN --mount=type=cache,target=/var/cache/apt,sharing=locked \
    --mount=type=cache,target=/var/lib/apt,sharing=locked \
    sed -i 's|http://deb.debian.org|https://mirrors.aliyun.com|g' /etc/apt/sources.list.d/debian.sources \
    && apt-get update \
    && apt-get install -y --no-install-recommends \
        libsndfile1 ffmpeg

# Python 包：pip cache mount + 阿里云 PyPI 镜像
RUN --mount=type=cache,target=/root/.cache/pip \
    pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/ \
    && pip install -r requirements.txt
```

- **APT 阿里云镜像**：`mirrors.aliyun.com/debian`（与镜像版本同源，跟随 Python 镜像的 Debian trixie/bookworm）
- **PyPI 阿里云镜像**：`mirrors.aliyun.com/pypi/simple/`（torch 专用 `-f mirrors.aliyun.com/pytorch-wheels/cpu/`）
- **BuildKit 要求**：本地构建需 `DOCKER_BUILDKIT=1`；CI 默认启用
- **apt cache mount 关键参数 `sharing=locked`**：避免并发 build 锁文件被破坏（dpkg 独占锁）
- **不要 `rm -rf /var/lib/apt/lists/*`**：缓存层必须保留 lists，否则下次重新拉索引
- **tts-service 离线备选**：`./refresh-wheels.sh` 生成 wheels/ 后 `pip --no-index --find-links=wheels/ -r requirements-lite.txt`（P2-24 修真：避免 wheels/ 入仓库；15MB 二进制不占 Git 空间）

> **历史教训**：8月5日 voice-service 构建卡 35+ 分钟，根因是本次仅 pip cache mount + 仅 PyPI 镜像，apt-get install ffmpeg(~200MB) 走默认 snapshot.debian.org 海外源，且 apt cache 未 mount 每次重新拉。修复后两个服务实现对齐。

## 二、同类产品配置体系深度调研（21 项）

> 调研方法：3 路并行检索（开源生态 / 消费级大厂 IoT / 儿童陪伴硬件），以官方文档、公开教程、厂商公开资料为准；**来源标注与不确定性说明见 2.4**。每项输出【配网/配置流程、配置页面形态与页面清单、二维码与绑定信息规范、技术实现、可借鉴点】。

### 2.1 组一：开源 / DIY 生态（7 项）

**① 小智 xiaozhi-esp32（GitHub 78/xiaozhi-esp32，MIT）**——本项目固件基线（NST-HW-02 选型）
- 配网流程：首次上电自动进配网 → 开**无密码热点 `Xiaozhi-XXXXXX`** → 手机连热点 → 浏览器自动弹出（captive portal）或手动访问 `192.168.4.1` → 配网页提供 **WiFi 扫描列表（选择自动填 SSID，仅 2.4G）+ 密码 → 连接** → 成功自动连网、3 秒后自动重启；BOOT 键长按重新配网
- 绑定规范：xiaozhi.me 控制台"设备管理"→ 输入**设备语音播报的 6 位验证码** → 激活（6 位码绑定范式）
- 配置页面：设备内嵌单页配网页（无密码热点 + 扫描选 SSID 免手输）
- 可借鉴点：**无密码热点降门槛、扫描选 SSID、6 位验证码绑定、按键重配网**
- 来源：nologo.tech 配网教程、freenove 文档、xiaozhi.me Q&A

**② ESP-IDF network_provisioning 组件（wifi_provisioning）**——L1 加密配网技术底座（NST-HW-02 §3.6）
- 技术实现：SoftAP 方案 = SoftAP + protocomm_httpd（HTTP 服务器）+ 可选 mDNS（`_esp_wifi_prov._tcp`）；标准端点 `prov-session`（安全会话）/`prov-scan`（scan_start/status/result）/`prov-ctrl`（ctrl_reset/ctrl_reprov）/`prov-config`（get_status/set_config/apply_config）/`proto-ver`（版本+cap）
- 安全：Security 1 = **X25519 密钥交换 + PoP 所有权证明 + AES-CTR 加密**（Security 0 明文）；**事件状态机：WIFI_PROV_START → CRED_RECV → CRED_FAIL（AUTH_ERROR/AP_NOT_FOUND）→ CRED_SUCCESS → END**；凭据存 NVS，`is_provisioned()` 查询；扫描建议 group_channels=4 防 SoftAP 断连
- 可借鉴点：**配网状态机定义、NVS 持久化、扫描分组防断连**
- 来源：ESP-IDF v5.2 官方文档（中文指南）

**③ esp-launchpad（espressif.github.io/esp-launchpad）**——Web 刷机入口（NST-HW-02 §3.2 使用）
- 技术实现：基于 **Web Serial API + esptool-js** 的纯浏览器刷机工具；Quick Start 模式由 **TOML 配置文件渲染**页面（第三方可发布固件镜像 + 支持硬件 + 说明）
- 可借鉴点：**"扫码入口页承载刷机 + 配网引导二合一"的页面范式**；本身无配网能力，配网由刷入固件完成
- 来源：esp-launchpad README

**④ WeXin-BLE-Provision for xiaozhi-esp32（微信 BLE 扫码配网扩展包）**——L1 加密二期选项（NST-HW-02 §3.6）
- 技术实现：微信小程序扫码/发现设备 → BLE GATT 连接 → protocomm Security 1（X25519 + AES-CTR + PoP）传输 WiFi 凭据（scan → set_config → apply_config）；同类参考：安信可 ESP32-C3 微信小程序配网（DH 密钥协商 + AES-128 + CRC16）
- 可借鉴点：toC 家庭版二期可选通道，体验优于 Soft-AP 但依赖小程序与蓝牙权限
- 来源：ESP-IDF 文档 + 安信可 GitHub 示范

**⑤ FoloToy（开源 AI 玩具）**——私有化对接配网页关键参考
- 配网流程：首次开机自动进配网模式（或按键/AT 指令）→ 热点 `FoloToy-xxxx` → `192.168.4.1` → 配置页**同时填 WiFi（仅 2.4G）+ 服务器地址/端口（高级设置 MQTT）**——**私有化部署关键参考**；Android 需处理"信任此网络/保持连接"弹窗
- 绑定规范：三方式——**手动输入 SN+Key（包装盒二维码标签）、扫码、声波配对（Web App 录音 + 玩具发声）**；绑定后 Web App 配置角色（开场白/ASR/LLM/语音）
- 可借鉴点：**配网页同页填 WiFi + 服务器地址（toB 校内服务器预置/可改）、SN+Key 包装标签、扫码绑定**
- 来源：docs.folotoy.com、folotoy.com WebApp 手册

**⑥ captive portal 技术原理**——配网页自动弹出机制
- 技术实现：设备开 AP 后，**DNS 服务器（53 端口）通配解析所有域名 → 192.168.4.1**，Web 服务器 onNotFound 对未知路径返回配网页（或 302），触发系统检测；OS 探测 URL 差异：**Android 探测 connectivitycheck.gstatic.com（generate_204）、iOS 探测 captive.apple.com、Windows 探测 www.msftconnecttest.com**；系统行为差异：Android 弹"信任此网络"、iOS 自动开浏览器
- 已知坑：**HTTPS/DoH 无法劫持（配网页必须 HTTP-only）、DNS 缓存、AP 隔离、deep sleep 后服务未重启、mDNS（esp32.local）不可靠——需 192.168.4.1 手动兜底 + 二维码双入口**
- 可借鉴点：**HTTP-only 配网页、192.168.4.1 兜底、Android 引导文案**
- 来源：espboards.dev troubleshooting、Reddit r/esp32、hirnschall.net

**⑦ ESP32 Web 配网页典型实现（社区范式）**
- 技术实现：单 HTML 内嵌固件（raw string），路由 `/`（表单）+ `/save`（POST）+ onNotFound（captive 重定向）；NVS/Preferences 存凭据（SSID/密码 struct），开机检查 NVS → 无凭据进配网模式 → 保存即重启；BOOT 键清凭据重配网；进阶形态：**fetch + JSON 接口**（异步 WiFi 扫描列表 + 提交配置），与 ESP-IDF prov-scan/prov-config 端点协议同构
- 可借鉴点：**P1 固件定制配网页的 SPEC 依据（§四.2.3）**
- 来源：hirnschall.net 完整示例、DFRobot wiki

- 可借鉴点：**扫码识别设备身份 → 引导配网的双段式流程、配网前置检查清单、超时重试**

### 3.3 配置状态机总览（对齐华为智慧生活回连检查模式）

设备生命周期主状态机（设备侧 + 云端侧一致）：

```
未激活(出厂) ──上电(无凭据)──► 配网中(Soft-AP)
     │                            │ 凭据提交成功
     │                            ▼
     │                       已配网(Station) ──断网重试──► 配网失败(可重试/重配)
     │                            │ 首次上线(回连检查)
     │                            ▼
     │                       待绑定(云端登记) ──绑定验证码+登录态──► 已绑定(运行中)
     │                            ▲                                   │
     │                            └──────── 解绑 ◄──────────────────┘
     └──────────── 恢复出厂(长按/管理台远程) ◄───────────────────────┘
```

配置流程状态机（一次完整配置的页面流转，对齐华为"扫码→连热点→回连检查"）：

```
S0 扫码(①入口页打开, 有网态) ──► S1 自检分流: 设备已绑定? → 跳⑤状态页
                                  │ 未绑定
                                  ▼
S2 连热点引导(①页内, 展示 LED 色对照 + Android 信任弹窗提示)
       │ 手机切到 BoBo_Setup_XXXX 热点
       ▼
S3 配网(②配网页: 扫描选 SSID + 密码 + 服务器地址(预置可改) → 提交)
       │ 设备存 NVS → 关热点 → 连校园/家庭 WiFi
       ▼
S4 回连检查(手机切回原 WiFi, ①页在内存中继续, 轮询云端设备状态 API)
       │ 超时 100s(涂鸦对齐) → 失败分段诊断(§四.2.5)
       ▼
S5 绑定(③绑定页: toB 选班级/咨询室, toC 选家庭/孩子 + 设备验证码确认)
       │ 设备端 LED/语音反馈绑定结果
       ▼
S6 声纹录入(④引导页, 可跳过) ──► 完成 → ⑤状态页确认 → 日常使用
```

**关键设计**：
- **"切换热点断网"矛盾解法**：扫码落地页（①页）在设备未联网时于手机有网态**预加载完成**（SPA 单页，资源内联/已缓存）；用户切到设备热点完成配网后切回原网络，①页在浏览器内存中继续运行，通过**轮询云端设备状态 API**（`GET /api/v1/device/{deviceCode}/status`）感知配网进度——不依赖页面重载
- **回连检查**：设备配网成功后自动连接校园/家庭 WiFi 并上报在线（§六.3 状态上报），云端置 `ONLINE + 待绑定`，①页轮询到该状态即引导进入③绑定页
- **失败分段诊断**（华为模式）：配网页提交失败按阶段提示——WiFi 密码错误（设备返回 AUTH_ERROR）/找不到网络（AP_NOT_FOUND）/设备离线（超时），引导文案区分
- **2.4G 前置**：配网页与落地页均提示"仅支持 2.4G WiFi，双频合一请选择带 -2.4G 后缀的网络"

### 3.4 设备热点与服务器地址规范

| 项 | 规范 | 依据 |

## 四、页面设计（6 类配置页面 SPEC）

> 通用约定：云端 H5 页面（①③④⑤⑥）复用现有前端工程与 doing/83 青屿设计令牌（--ms-primary #2BA8A0 等，见 83 §8.2）；设备内嵌配网页（②）为极简单页（无外网环境，不依赖设计系统资源）；文案采用波波 IP 语气（"请帮我连接网络吧"）；验收标准用 EARS 格式编号 AC-84-xx。

### 4.1 页面①：扫码入口页（H5 落地页）🟩 已实施（parent-h5 `/p/:v/:deviceCode`，4d39665）

**定位**：扫描设备机身/包装二维码后到达的**第一个页面**（无登录态，扫码即达），职责 = 识别设备 + 自检分流 + 引导配置全流程。承载：parent-h5 新增独立路由 `/p/:v/:deviceCode`（或短链 `/p/{deviceCode}`），与二维码 URL 一一对应（§五.2）。

**页面元素清单**：

| 区块 | 元素 | 说明 |
|---|---|---|
| 品牌区 | 波波 IP 形象 + 产品名 | "波波小伙伴"（toC）/ 校园版标识（toB），无屏终端配置向导 |
| 设备识别 | 设备型号/形态图标 + 设备码尾号（脱敏 `****A1B2`） | 从 URL deviceCode 解析，调 `GET /api/v1/device/{deviceCode}/info` 展示 |
| 自检分流卡 | 三态：①设备已绑定 → 显示"设备已绑定" + 入口跳⑤状态页/管理台 ②未绑定未配网 → 显示"开始配置"主按钮 ③未绑定已配网 → 直接进③绑定页 | S1 分流（§三.3） |
| 引导步骤条 | 单页步骤条（涂鸦 UX）：①连接设备热点 ②配置网络 ③绑定设备 ④完成 | 减少页面跳跃（调研⑭） |
| 连热点指引卡 | 步骤：设备长按按键 3 秒进入配网（LED 蓝灯慢闪）→ 手机设置连接 `BoBo_Setup_A1B2` → 返回本页 | 配 Android 弹窗提示："如提示'此网络无法上网/是否保持连接'请选择**保持连接**"（调研⑥） |
| LED 状态对照表 | 蓝=配网中/绿=已连网/红=失败/灭=休眠 | 对齐 NST-HW-02 §3.5 状态色 |

**JSON API（设备内嵌 HTTP 服务，与 ESP-IDF prov-* 协议同构）**：
| 端点 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/api/wifi/scan` | GET | — | `{ssids: [{ssid, rssi, secured}]}`（group_channels=4 分批扫描防断连） |

**状态机**（对齐 ESP-IDF WIFI_PROV 事件）：`PROV_START → CRED_RECV → CRED_FAIL(AUTH_ERROR/AP_NOT_FOUND) → CRED_SUCCESS → RESTART`；失败后 10s 内可重试，超时重新扫描。

| `{domain}` | toB：校内域名或内网 IP（部署矩阵见下）；toC：云端域名 | 私有化适配（调研⑪萤石 API 生成二维码同构） |

**部署矩阵（toB 私有化内网扫码场景）**：

| 部署形态 | 二维码 domain | 说明 |
|---|---|---|
| 校园内网（默认） | 校内域名/内网 IP（如 `http://10.1.2.3`） | 配网页静态托管于校内 Nginx（复用现有部署），内网可达 |
| 教育云/公网（可选） | 公网域名（`https://mindsafe.example.com`） | 学校有公网出口时可用；二维码印刷时确定，不可变（建议出厂印公网域名 + 说明书附内网地址） |

> **决策**：二维码内容**出厂即印**，域名不可变——试点期建议印公网域名或可解析的校内域名（DNS 可改），避免换域名需换码。

#### 5.2.1 deviceCode 编码规则（短码）

- 组成：`SN 派生短码（10 位 base32，大写字母+数字，去 I/O/0/1 易混字符）+ 1 位校验位`，共 11 位（如 `K7M2P9XW4AQ`）
- SN 派生：出厂 SN（如 `BB-2026-000123`）经 HMAC-SHA256（设备私钥派生）取前 10 位 base32 编码，**不可逆推 SN**
- 校验位：Luhn 变体校验，前端/云端可本地校验码合法性，防手输错误
- 与 SN/MAC 的关系：deviceCode ↔ SN 一一映射存 device 表；二维码只印 deviceCode，不印 SN/MAC（防泄露）

**机身铭牌印刷规范**（对齐萤石"序列号+验证码双信息"）：
- 内容：①二维码（300×300 px，白底，纠错级别 M）+ ②deviceCode 文字（兜底手输）+ ③设备型号 + ④`192.168.4.1` 备选入口文字（无网兜底）
- 位置：机身底部/背部（不可遮挡、不易磨损）+ 包装盒侧面

### 5.3 绑定验证码规范（L2，双因子）

- **生成**：用户进入③绑定页 → 云端下发绑定会话 → 设备收到指令后**语音播报 6 位验证码**（TTS 本地/云端播放，仅播放一次，可重播 ≤2 次）
- **校验**：云端比对（哈希存储），3 次错误锁定 5 分钟（AC-84-12）
- **防串绑**：绑定 = 登录态（老师/家长） + 验证码双因子 + 设备在线校验；绑定成功验证码作废、二维码转入"已绑定"态
- **安全**：验证码 5 分钟有效、绑定会话与 deviceCode 绑定、验证码不落日志（对齐 his/16 安全规范）

### 5.4 小程序通道预留设计（P2，不实施）

- 微信小程序码 scene 参数承载短码（**≤32 字符**，调研⑫）：`scene = {v}:{deviceCode}`（如 `1:K7M2P9XW4AQ`，16 字符合规）
- 扫码 → 小程序配网页（Taro 双端产物，43 号 W-1 企业认证为硬前置）→ 配网/绑定逻辑复用同一套 API
- H5 主通道不受影响（决策②）；本设计仅登记预留，触发条件 = 43 号 P2 小程序立项

### 5.5 二维码生命周期

| 状态 | 含义 | 扫码行为 | 转换条件 |
|---|---|---|---|
| 未激活 | 出厂未注册 | 入口页显示"设备未注册，请联系管理员"（toB）/ 注册引导（toC） | 设备首次上线自动注册（§六.3） |
| 待绑定 | 已配网未绑定 | 入口页进入配置流程（S1 分流） | 绑定成功 |

## 八、安全与合规

### 8.1 无密码热点风险与缓解（配网窗口期）

| 风险 | 缓解 |
|---|---|
| 热点无密码被蹭网 | 配网页**零敏感数据**（不展示历史密码/账号）；绑定验证码二次确认才建立业务关系；配网窗口期 10 分钟无操作自动关热点（NST-HW-02 §3.7 provision_task 超时） |
| 热点被伪造（伪热点钓鱼） | 机身二维码是唯一可信入口；配网页页面内展示设备码尾号供用户核对；P1 固件定制后热点名带设备码尾号（`BoBo_Setup_A1B2`）可人工核对 |
| 配网页 HTTP 明文传输 | 配网阶段无外网、无敏感数据（仅 WiFi 凭据本地写入设备，不经过互联网）；**L1 加密（Security 1 / WeXin-BLE-Provision）列为二期**（NST-HW-02 §3.6 已定性），不阻塞 P0 |
| 设备码泄露 | 设备码仅能打开入口页，绑定仍需登录态 + 验证码双因子；SN/设备私钥不出设备（§5.2.1） |

### 8.2 声纹与未成年人数据合规（完全复用现有体系）

- 声纹仅存 256 维向量、不存原始音频、转写即删（74 §5.3 既有红线）——本专题只新增编排 API，不改变存储
- 声纹录入须在**监护人同意**前置下进行（toB 复用现有告知同意流程 / toC 复用家长验证码登录即同意）
- 绑定信息最小化：device_bindings 仅存归属关系，不存学生对话数据
- 设备信息页使用统计**脱敏聚合**（不展示原始对话，74 §1.6 报告替代原始对话红线）

### 8.3 HTTPS 劫持边界说明

- 配网页（192.168.4.1）为 HTTP-only：captive portal 机制依赖 HTTP（HTTPS/DoH 无法劫持，调研⑥）——**页面不含任何表单敏感信息**（WiFi 密码只在设备本地处理）；此边界在①落地页离线兜底卡文案中向用户说明
- 云端 H5 页面（①③④⑤⑥）全部走 HTTPS（现有 nginx 配置），不受影响

**EARS 验收标准**：
| AC | 语句 |
|---|---|
| AC-84-27 | The 配网页 shall 不包含任何账号/历史密码等敏感信息，且 10 分钟无操作自动关闭热点 |
| AC-84-28 | When 声纹录入执行，the 系统 shall 仅存储 256 维向量并校验监护人同意前置（对齐现有体系） |

## 十、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| captive portal 平台差异（Android 信任弹窗/iOS 自动弹窗/DoH 不可劫持） | 配网页打不开 | ①页连热点指引含 Android 弹窗文案；192.168.4.1 手动兜底按钮；二维码同印备选入口（调研⑥） |
| 扫码落地页在设备未联网时不可达 | 扫码白屏 | ①页离线兜底卡（检测无外网即展示步骤说明）；资源内联/缓存保证任何网络态可加载（AC-84-05） |
| "切换热点断网"中断流程 | 配置流程卡死 | ①页预加载（SPA 内存继续）+ 回连检查轮询 + "切回原网络"引导文案（§三.3 关键设计） |
| 二维码泄露/盗绑 | 设备被他人绑定 | 绑定 = 登录态 + 验证码双因子 + 在线校验；一次性绑定；3 次锁定（AC-84-12）；绑定历史可查（audit_logs） |
| 校园网 5G/企业级认证不支持 | 配网失败 | 配网前置检查清单（仅 2.4G/无 802.1X/无 MAC 白名单）在①页与②页前置展示（§四.2.4） |
| 与 doing/83 并行开发（M13 挂载） | 设计空转 | 本专题设计先行、实施挂 83 M13；规范只引用不重复定义（§7.3）。**现状（2026-08-10 二次修正）**：83 已回迁 doing 且实施近完成（ADMIN 26/29 ✅，admin-web 工程/平台登录已就绪），M13 前置已满足，可直接排期实施，剩余风险仅剩与 83 并行改动的协调 |
| 调研素材时效性（厂商迭代快） | 结论偏差 | §2.4 来源标注 + 不确定性说明；实施前以厂商最新文档复核 |
| 热点安全（无密码蹭网） | 配网窗口期风险 | §8.1 缓解表（零敏感数据/超时关热点/伪热点核对） |

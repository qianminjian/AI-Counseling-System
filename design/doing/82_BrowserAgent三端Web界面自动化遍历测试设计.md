## 一、背景与目标

### 1.1 背景

系统现有自动化验证体系（design/05 §8）：

| 层 | 现状 | 缺口 |
|----|------|------|
| 单测/集成 | 后端 1466 + 前端 713 + Python 110 全绿 | 不覆盖真实浏览器渲染/交互 |
| 契约测试 | 三层防线（L1/L2/L3） | 只验证接口契约，不验证页面行为 |
| 冒烟测试 | smoke-test.sh（31 断言，curl 层） | 只验证 API 链路，**零 UI 交互验证** |
| UI 层 | R-4 仅登记 Playwright 预留态 | **无任何真实浏览器端到端遍历** |

结论：**三端 Web 界面从未被真实浏览器自动化遍历过**。本设计落地 R-4，用 Browser Agent 对三端 + 三端联动业务场景做全面遍历测试。

### 1.2 目标

1. 对三端（学生端 / 教师端 / 家长端）全部已实现页面与核心交互做浏览器级遍历，验证 UI 行为与 design/05 §4~§6 测试要点一致
2. 对三端之间按设计的数据联动与业务场景联动（F-01~F-07 + 家长端联动）做端到端验证
3. 每个测试发现的问题按「三端 + 场景」汇总登记问题清单
4. 每个端测试完毕后：自动按问题清单修复 → 自动部署 → 自动复测，直到该端收敛

### 1.3 范围边界

- **范围**：三端已实现功能（design/08 §1.1~§1.5 状态 🟩/🟫 模块）；F-06 测评流程（⬜ 门禁）、frozen/* 冻结专题不在遍历范围
- **不做**：性能压测（k6 已就绪，按需）、多实例高可用、生产环境遍历（本设计只针对本地/测试环境）
- **语音类**：声纹登录 remote 模式、ASR/TTS 真实音频链路在 test compose（不含 voice/tts）不可测，标记 **SKIP-语音**（降级路径断言照常，见 4.3）

## 二、执行架构

### 2.1 工具链与执行方式

| 角色 | 工具 | 用途 |
|------|------|------|
| 执行器 | **Browser Agent**（Agent 子代理，含 browser-use/chrome-devtools MCP 或 agent-browser CLI） | 打开浏览器、导航、点击、输入、截图、断言 |
| 被测环境 | `deploy/docker-compose.test.yml`（postgres+redis+backend+frontend+nginx） | 本地/测试环境，HTTP |
| 数据准备 | `deploy/init-school.sh` + 管理员邀请码 API | 初始化学校与账号矩阵 |
| 修复 | 常规开发链路（TDD：先写失败测试→修复→回归） | 按问题清单逐条修复 |
| 部署 | `deploy.sh`（唯一发布通道，design/04 §5.6）或本地 compose 重建 | 修复后自动部署 |
| 复测 | Browser Agent 重跑失败场景 | 验证修复闭环 |

### 2.3 执行顺序

1. **环境与数据准备**（§三）→ 2. **学生端遍历**（S-01~S-10）→ 修复循环 → 3. **教师端遍历**（T-01~T-08）→ 修复循环 → 4. **家长端遍历**（P-01~P-06）→ 修复循环 → 5. **联动场景**（L-01~L-06，依赖前三端账号与数据）→ 修复循环 → 6. 汇总报告 + 合并归档

> 依赖说明：L 场景依赖 S/T/P 端修复收敛后的环境，故联动排在最后；S 场景产生的对话/预警数据是 T 场景与 L 场景的前置数据源，S 端修复后**不清库**（保留测试数据供后续场景复用）。

## 六、Browser Agent 提示词体系

> 使用方式：每个场景用一个独立 Browser Agent（subagent）执行；提示词含四段（角色/环境/步骤/记录）。所有提示词遵守：**发现问题立即截图**，`take_screenshot` 保存到 `reports/browser-test/screenshots/<场景ID>-<序号>.png`；**不修改被测环境数据**（除场景本身业务操作）；每步记录 console error。

### 6.1 通用执行框架（每个 Agent 的基底提示词）

```
你是 MindSafe 系统的 Web UI 遍历测试执行器。被测环境：学生端 http://localhost/mindsafe/ 、教师端 http://localhost/teacher/ 、家长端 http://localhost/parent/ ，后端 http://localhost:8080/actuator/health 必须 UP。

执行规则：
1. 使用浏览器工具导航与交互（navigate_page/click/fill/press_key/take_snapshot/take_screenshot/list_console_messages/list_network_requests）。
2. 每完成一步关键操作，记录：操作名 → 期望 → 实际 → 通过/失败。
3. 断言失败 = 问题，立即：①截图保存到 reports/browser-test/screenshots/；②按下方「问题登记格式」完整记录，继续执行后续步骤（不中断整个场景）。
4. 禁止：伪造/篡改页面数据、跳过断言、修改被测环境配置。
5. 全部步骤完成后输出：通过数/失败数/问题清单（每条含 场景ID-步骤号-期望-实际-截图路径-疑似根因）。
```

### 7.2 单条问题登记格式（每条固定字段，修复循环机器可解析）

```markdown
### BUG-S-04-01 [P1] TTS 降级提示缺失
- 场景：S-04 对话室核心交互（第 2 步）
- 期望：点击 TTS 朗读后出现「不支持语音播放」降级提示条

- 疑似根因：test compose 未挂 tts 服务但前端未接降级分支（design/10 §6.x 与代码不符）
- 状态：OPEN | 修复提交：- | 复测结果：-
```

字段规则：
- **ID**：`BUG-<端>-<场景>-<序号>`（端= S/T/P/L）
- **严重级**：P0（安全/数据损坏/主链路不可用，如 S-05 失败）/ P1（功能缺失或错误）/ P2（体验/边界问题）/ P3（文案/样式瑕疵）
- **状态机**：`OPEN → FIXED（修复提交） → VERIFIED（复测通过） → REGRESSION（复测仍失败，回滚 FIXED 重新 OPEN）`

## 八、自动修复-部署-复测循环

### 8.1 触发时机与范围

- **触发**：每端（S/T/P/L 四组）场景全部执行完毕，问题清单落盘后立即触发
- **修复范围**：该端 P0/P1 **必须修复**；P2/P3 每轮最多修 3 条（防范围蔓延，其余登记排期）
- **循环轮次上限**：每端 **3 轮**（第 1 轮修 P0/P1 + 顺手 P2/P3；第 2 轮修剩余 + 复测失败项；第 3 轮收尾）

### 8.2 循环步骤（每端执行）

| 步 | 动作 | 细节 | 退出条件 |
|----|------|------|---------|
| 1 | 解析问题清单 | 读 ISSUES-<端>.md 中状态=OPEN 且属本轮的条目 | 无条目 → 直接进入汇总 |
| 2 | 自动修复（TDD） | 每条问题：①先写失败测试（复现该 bug 的最小用例）→ ②修复 → ③全量回归（该模块 `mvn test`/`vitest run` 对应套件，串行 maxThreads=1） | 该端所有目标条目 FIXED 且回归全绿 |
| 3 | 自动部署 | 本地：`docker compose -f deploy/docker-compose.test.yml build frontend backend && up -d`；远程：`./deploy.sh`（唯一发布通道，含 smoke 门禁）；部署后必须 `curl /actuator/health` UP + `smoke-test.sh` 通过 | 部署成功 + smoke 通过 |
| 4 | 自动复测 | 仅重跑该端**失败场景**（复用 §六提示词，Agent 只执行 BUG 对应步骤 + 原场景全步骤） | 原失败断言通过 |
| 5 | 更新状态 | 通过 → `FIXED→VERIFIED`；仍失败 → `REGRESSION`，回滚该修复（`git revert`）重新 OPEN，进入下一轮 | 该端 P0/P1 全 VERIFIED 且 P2/P3 未关闭 ≤ 3 |
| 6 | 轮次控制 | 达 3 轮仍未收敛 → 停止自动循环，升级人工（输出：未收敛问题清单 + 修复尝试记录） | 人工介入 |

### 8.3 修复纪律（对齐项目规则）

- **TDD 强制**：修复必须「先红后绿」（.qoder/rules/tdd-workflow.md）
- **回归纪律**：全量回归每次只跑一次，串行 worker（vitest maxThreads=1 已配置级写死）；查测试详情改读报告文件，不重复跑
- **提交粒度**：每条问题独立 commit（`fix(<scope>): BUG-<ID> <简述>`），check-commit.sh --last 1 门禁
- **不得**：删除文件/改 .env/动 DB schema（红线，需人工确认）

### 8.4 收敛定义（该端完成）

```
该端：P0 = 0 且 P1 = 0 且 P2/P3 未关闭 ≤ 3 且 未关闭条目均已在 ISSUES-闭环记录.md 登记排期
```

三端 + 联动四组全部收敛 → ISSUES-SUMMARY.md 终版（含回归结论）→ 测试报告落 reports/browser-test/ 根目录

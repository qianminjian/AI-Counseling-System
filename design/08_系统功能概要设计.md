### 2.2 F-01 正常对话流程（低风险）🟩

#### 2.2.1 M1 实际时序（当前事实基线，开发对照以此为准）

```
学生端        ChatController    ConversationServiceImpl                    LLM          DB
  │               │                  │                                       │            │
  │─POST messages─▶│──sendStream────▶│                                       │            │
  │               │                  │─1. RiskDetectorService（硬规则+LLM）  │            │
  │               │                  │   ├─ ORANGE/RED → 短路：安全模板 + RiskEvent 入库 + WS 推送
  │               │                  │   └─ GREEN/YELLOW → 继续               │            │
  │               │                  │─2. PiiDesensitizer（脱敏）             │            │
  │               │                  │─3. AiChatService（SYS-001+ChatMemory+长期记忆/画像注入）
  │◀─SSE stream───│◀──────────────│◀──token stream─────────────────────│            │
  │               │                  │─4. OutputContentFilter（Layer1 硬过滤，同步）         │
  │               │                  │─5. OutputReviewService（Layer2 SAF-002，异步留痕）    │
  │               │                  │─6. INSERT message + 记忆写入────────────────────▶│
```

**链路要点**：ORANGE/RED 短路优先（安全模板不交 LLM）；PII 脱敏在模型调用前；输出侧 Layer1 同步硬过滤（pass/rewrite/block/escalate 四决策召回，SAFE-202）+ Layer2 异步语义审查留痕；时序外门控 AUTH-030 每日使用时长超限在 AI 调用前短路引导休息（不拦截 RED 风险）。

> AUD-059 校正：风险等级实际为**四档色级 GREEN(0)/YELLOW(1)/ORANGE(2)/RED(3)** + 整数 riskLevel（`RiskLevel.java`，SSE `metadata.riskLevel` 整数）；下述对话示例中 L1-L5 表述为旧口径历史叙述，不作开发依据。

> 目标态（ORCH-001/002 落地后）：分诊（非流式前置）→ 策略选择（画像/记忆/RAG 并入）→ 回复流式，与 09 对话引擎章节同源。原 §1.1 Orchestrator/SkillRouter 时序为远期目标，不作开发依据。

#### 2.2.2 完整对话示例：考试焦虑（3-4 年级）

> 场景：四年级学生，数学考砸了，觉得自己笨。风险 L1，走 CBT 微技能。

| 轮次 | 角色 | 内容 | 系统状态 | 后台动作 |
|------|------|------|---------|---------|
| 1 | 系统 | 你好！我是波波 😊 你选了“难过”，能告诉我发生了什么事吗？ | S0→S2 | 创建会话，emotion=sad |
| 2 | 学生 | 我数学又考砸了，觉得自己好笨 | S2 | 风险识别: L1/academic_stress; 路由: CBT/exam_anxiety |

| 5 | AI | 这个小声音说"什么都学不会"。那有没有哪一次，你觉得自己还做得不错的？ | S5→S6 | 找反例 |
| 6 | 学生 | 上次语文听写我全对了 | S6 | evidence_against="语文听写全对" |
| 7 | AI | 对呀！语文听写全对，说明你不是"什么都学不会"，只是数学这次有点难。我们可以把"我什么都学不会"改成什么更公平的话？ | S6 | balanced_thought 生成中 |

| 11 | AI | 好的！现在心情温度计变成几分了？还需要老师帮忙吗？ | S8 | 复检 |


### 2.5 F-04 会话收束与摘要 🟩

### 2.8 错误处理与降级 🟩

**LLM 超时/失败（LlmStreamEnhancer + ResilientChatModel 实际链路）**：

```
学生发送消息
  ├─ LlmStreamEnhancer.enhance(Supplier<Flux>, sessionId)
  │   ├─ 首 token 12s 超时（TimeoutException）→ 超时不重试（模型本身慢）→ 降级安全话术
  │   ├─ 瞬时失败（网络/限流/连接重置）→ retryWhen(backoff 1次, 2s) → 重试成功继续流
  │   ├─ 重试耗尽 → ResilientChatModel 已先尝试备用模型 → 备用也失败 → 降级安全话术
  │   └─ 整体流 45s 超时 → 降级安全话术
  └─ 前端收到降级 token → 正常显示安全话术（无感知）
```

> 关键差异：无"返回错误 SSE + 重试按钮"路径——所有异常均服务端消化，学生端始终看到友好回复。

**SSE 连接断开**：前端 EventSource 自动重连（最多 3 次）→ 失败显示"网络不太稳定"横幅；后端消息已生成则存 DB（刷新可见），生成中则取消不存。

**风险 JSON 解析失败**：重调 LLM 追加"请严格输出 JSON"指令 → 兜底 risk_level=L3 + needs_human_review=true（走限制性支持 + 生成预警复核）→ 连续 3 次失败熔断，所有新会话走兜底模式并告警运维。

### 2.9 WebSocket 消息协议 🟩（连接鉴权已生效，P1-FE-4 握手改造 2026-08-05）

**连接**：`WS /ws/alerts`（wss://host/ws/alerts），JWT **不进 query string**（避免落入 nginx access log / 浏览器历史），改由握手头 `Sec-WebSocket-Protocol` 携带 `alerts.v1` 子协议协商 + `auth.<jwt>` 子协议项传输 token。`AlertAuthHandshakeInterceptor` 仅负责提取 token 放入 session attributes；`AlertWebSocketHandler` 统一做**三重校验**（单一认证点）：① `validateToken`（签名+issuer）② `isAccessToken`（防 refresh/家长 token 混入）③ 黑名单检查（`TokenBlacklistService.isBlacklisted(jti)`）+ 角色校验（仅 teacher/psych_teacher/class_teacher/admin，学生 token 接入会泄漏全租户未成年人预警数据）。校验通过 → 提取 tenantId/userId → 按租户注册 session registry；心跳 30s ping/pong。

**消息类型**：

```typescript
// 服务端 → 客户端
type ServerMessage =
  | { type: 'NEW_ALERT'; payload: AlertItem }           // 新预警（🟩 已生效）
  | { type: 'ALERT_SLA_WARNING'; payload: { alertId, remainingMinutes } }  // SLA 预警 ⬜
  | { type: 'ALERT_ESCALATED'; payload: { alertId, newLevel } }            // 升级 ⬜
  | { type: 'CASE_UPDATED'; payload: { caseId, update } }                  // 个案更新 ⬜
  | { type: 'APPOINTMENT_REMINDER'; payload: { appointmentId, time } }     // 预约提醒 ⬜
  | { type: 'SYSTEM_NOTICE'; payload: { message, level } };                // 系统通知 ⬜

// 客户端 → 服务端
type ClientMessage =
  | { type: 'ACK_ALERT'; payload: { alertId } }         // 确认收到预警 ⬜
  | { type: 'HEARTBEAT' };                               // ⬜ 心跳（协议已改裸文本 ping/pong，见下 AUD-040）
```

> AUD-040 校正：心跳协议为**裸文本 ping/pong**（AlertWebSocketHandler 收到 "ping" 回复 "pong"），非 JSON HEARTBEAT 消息；前端当前未启用心跳，重连可靠性依赖 15s 轮询兜底。

**断线重连**：指数退避（1s,2s,4s,8s,最大 30s）→ 重连后 ping 心跳 + 按 `since={lastMessageTime}` 补拉离线消息 → 5 次失败降级 30s 轮询。

> 现状：单实例内 `pushAlert(tenantId, payload)` 按租户组播新预警 + **前端 15s 轮询兜底是可靠性主来源**，广播完善前不得移除；多实例需 Redis pub/sub 广播（STATE 系列，远期）。登出后 jti 进黑名单，已建立的 WS 连接**不即时断开**（下次握手/重连校验），重连周期内敏感推送依赖 15s 轮询兜底。

### 3.1 统一身份契约（JWT）

双 Token 模式：**access 2h + refresh 7d**；另有声纹设备凭证（90d，声纹登录换发正式双 token）与家长报告链接 token（7d，SEC-006，防学生自持 token 调家长接口）。

```
{
  "sub":      "UUID",      // 用户唯一标识
  "userType": "student | teacher | admin | trial_student | parent",
  "tenantId": "UUID",      // 租户（学校 / 试用租户）
  "tokenType": "access | refresh | voice_credential | parent_report",  // P1-13 用途区分，API 只认 access
  "iss":      "mindsafe",  // 签发方（mindsafe.jwt.issuer，可配置）
  "aud":      "mindsafe-api", // 受众，防跨系统 token 复用
  "jti":      "UUID",      // 令牌 ID：撤销黑名单按 jti 粒度（防完整 token 作 Redis key）
  "iat": ..., "exp": ...
}
```

- **密钥管理（P3-28 加固）**：生产强制配置 `mindsafe.jwt.secret`（≥32 字符，缺失/过短直接拒绝启动）；开发密钥由配置项 `mindsafe.jwt.dev-secret` 提供（仅非 prod 生效，**不再硬编码于代码**）；签发校验 `requireIssuer` 严格对齐 `iss`
- **撤销机制（P3-28）**：logout / refresh 轮换时旧 refresh 按 jti 拉黑（Redis `token:blacklist:jti:*`，TTL=剩余有效期自动过期）；`JwtAuthenticationFilter` 与 WebSocket 握手均校验黑名单（详见 §3.5）
- **租户隔离**：JWT 内嵌 tenantId + JwtAuthenticationFilter 注入 TenantContext（**无 X-Tenant-Id Header**）；数据层共享表 + 行级 tenant_id 过滤
- **兼容关键**：`userType` 扩展 `trial_student`/`parent` 枚举，`tenantId` 指向专用试用租户 `tenant_trial`；未来学校正式部署仅换认证策略，JWT 契约不变
- **鉴权收紧**：`/api/v1/chat|sessions|relaxation|diary/**` 均 authenticated；教师/预警/管理端按角色控制；尾部 `permitAll` 兜底对语音/TTS 辅助 API 放行，商用前应改默认 deny + 白名单（P2）

### 3.7 生物识别合规结论（定稿）

**核心判断：不采集、不存储未成年人的指纹/人脸数据。**

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 学生登录（学校共享设备） | PIN 码（4-6 位数字） | 共享设备无法绑定个人生物特征 |
| 学生登录（家中手机） | WebAuthn 设备端指纹/Face ID（可选） | 生物数据不出设备，仅传公钥 credential；合规负担低 |
| 家长登录 | 手机号+密码（实态）/ 微信 OAuth（正式期评估） | 成年人标准流程 |
| 教师登录 | 企微 OAuth / 密码 | 已有实现 |

- WebAuthn 注册/登录流程（可选，阶段三）：学生输入 PIN → `navigator.credentials.create()` → 设备本地验证 → 公钥上传关联 userId；登录时服务器发 challenge → 设备签名 → 验签签发 JWT
- 合规要点：隐私政策声明"不采集、传输或存储生物数据"；WebAuthn 为可选，PIN 始终为备选（满足"不强制"）；无需 PIA
- **55 声纹方案须遵守同一红线**：声纹登录仅存 embedding 向量，不存原始音频（语音转写即删 COMP-009）

**高风险紧急流程（L4/L5）**：学生端禁用输入+安全横幅+三按钮（L5 自动弹出紧急资源）；教师端并行 WS 推送+桌面弹窗+钉钉/短信（按学校配置）+5 分钟未确认自动升级；系统写 risk_events + 生成教师摘要 + 审计日志 + 会话标记 safety_mode（后续消息走安全模板）。

### 4.6 响应式 / 无障碍 / 错误态

## 五、API 接口契约

> 本文档为**前后端并行开发的契约**：定义所有 REST 端点、请求/响应 DTO、错误码与鉴权机制。开发约定：Spring MVC `@RestController` + DTO `record` 类型（Java 16+）+ `jakarta.validation` 校验 + `@ControllerAdvice` 统一异常；接口文档用 SpringDoc OpenAPI 3 自动生成 Swagger UI。
> 契约基线（以实现为准）：统一响应 `{code, message, data}`（**无 traceId/timestamp 响应体字段**，traceId 在日志层）；JWT Payload `{userId, userType, tenantId}`；租户隔离 JWT 内嵌 tenantId（无 X-Tenant-Id Header）。

### 5.1 设计原则

| 原则 | 说明 |
|------|------|
| RESTful | 资源导向，HTTP 动词语义化，状态码标准化 |
| 租户隔离 | 所有请求从 JWT 自动注入 tenantId，后端 fail-fast（行级隔离） |
| 版本控制 | URL 前缀 `/api/v1/`，大版本变更时递增 |
| 统一响应 | `{ code, message, data }` 包装 |
| 分页 | `?page=1&size=20&sort=created_at,desc`，响应含 `total/totalPages` |
| 敏感脱敏 | 学生姓名默认返回脱敏名（`张*明`），完整名需 `scope:student:full_name` 权限 |

### 5.2 通用约定

**统一响应**（code=0 成功，非 0 业务错误）：

```json

```

**分页响应**：`{ items, page, size, total, totalPages }`

**鉴权方式**：

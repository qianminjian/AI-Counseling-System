## 架构结论

本系统应定位为**"校园心理健康陪伴与早期情绪支持系统"**，不是"AI 心理医生"或"AI 治疗师"。

- AI 负责：低风险陪伴、标准化筛查、流程引导和摘要生成
- 心理老师负责：判断、干预、转介与闭环跟进
- 危机事件：必须进入人工处置链路

## 1. 产品定位与架构边界

### 一句话定位

面向小学生与学校心理老师的**"低门槛表达 + 早期筛查 + 标准化辅导流程 + 风险预警 + 人工转介闭环"**系统。

系统的第一责任主体是学校心理服务团队，AI 是工具层能力，不承担诊断、治疗或危机处置职责。

### 核心维度定义

| 维度 | 推荐定义 | 边界说明 |
|------|----------|----------|
| **服务对象** | 学生、心理老师、班主任/任课老师、学校管理员 | 学生是被保护对象，不是被监控对象；老师是干预主体 |
| **核心目标** | 降低表达门槛；提高筛查效率；提供基础情绪支持；形成风险预警和转介闭环 | 不以替代心理咨询室、替代心理老师或替代专业医疗服务为目标 |
| **AI 角色** | 情绪陪伴助手、流程引导助手、风险筛查助手、报告摘要助手、知识检索助手 | 不做医学诊断；不做治疗承诺；不提供药物建议；不单独处理危机事件 |
| **人工在环** | 心理老师对风险分级、干预策略、转介决策和跟进闭环拥有最终判断权 | 红色风险必须转人工；AI 不允许把"继续聊天"作为危机处置方案 |
| **数据原则** | 默认最小化采集、分级授权、摘要优先、原始内容限时保存、敏感内容脱敏展示 | 不默认保存原始语音、面部影像和完整聊天全文 |

### 1.1 产品能力边界

| 允许做 | 必须谨慎做 | 明确不做 |
|--------|------------|----------|
| 情绪表达陪伴；轻度 CBT 流程引导；标准量表测评；压力与情绪趋势记录；老师工作台；风险预警；转介记录 | 语音识别、TTS、面部微表情、机器人终端、家长通知、外部专业机构协同、长周期画像分析 | 诊断抑郁症/焦虑症等疾病；治疗承诺；药物建议；无人工介入的危机处置；对学生进行持续监控；给班主任开放聊天全文 |

**关键约束**：
- 以 5 到 12 轮有限回合对话为主，目标导向、及时收束，减少依赖
- 高风险摘要可保留必要证据片段，但需审批、审计和留痕
- 禁止无限陪聊、鼓励依赖 AI、引导学生远离现实支持系统

## 2. 架构方案取舍与工程原则

### 2.1 两种可行方案比较

| 方案 | 核心形态 | 优点 | 风险与不足 | 建议 |
|------|----------|------|------------|------|
| **方案 A：Web SaaS + 学校私有化数据域 + 文本优先** | 学生通过浏览器/平板进入；教师后台管理；AI 推理通过模型网关；数据按学校隔离存储 | 上线最快；合规风险最低；硬件依赖少；便于迭代；符合 MVP 范围 | 早期体验不如机器人具身交互；语音和多模态能力需要二期补齐 | **推荐作为 MVP 主架构** |
| **方案 B：多模态 + 机器人终端 + 本地大模型同步建设** | 心理咨询室机器人/摄像头/麦克风；本地或混合模型；多模态情绪识别 | 体验更丰富；适合示范校展示；具身化交互更有吸引力 | 成本高；未成年人数据风险高；设备运维复杂；需求不稳定时容易过度建设 | 不建议首期作为主线，可作为三期示范能力 |

**推荐顺序**：先做方案 A，验证"学生愿意表达、老师能高效筛查、风险能闭环处理"三个核心假设；再按二期、三期逐步扩展语音、多模态、机器人和家校协同。

### 2.2 工程原则落地

| 原则 | 在本架构中的落实 | 如果违背会出现的问题 |
|------|------------------|----------------------|
| **KISS 简单至上** | 首期采用 Web、文本对话、规则 + Agent + LLM 混合架构；每层职责清晰 | 交付周期拉长，老师工作台还未验证就陷入设备运维和模型调优 |
| **YAGNI 当前够用** | MVP 不默认做人脸识别、机器人终端、校园全量画像、复杂家校协同 | 过度采集未成年人敏感数据，合规成本和解释成本显著上升 |
| **SOLID 模块化** | 对话、测评、预警、档案、报告、权限、通知、审计拆分为独立服务；Agent 按单一职责编排 | 风险规则、对话逻辑和报告生成耦合，后续很难单独替换模型或升级流程 |
| **DRY 消除重复** | 统一身份、权限、审计、模型网关、知识库、通知服务；不同端复用同一业务服务和风险分级标准 | 各端各自实现规则，导致预警口径不一致、审计链断裂 |

## 4. 分层架构细化

> 注：本节内容较长（原文 4.1-4.8 共 8 小节），完整内容见 `doc/01_心理辅导系统完整产品架构图.docx`

### 4.1 用户接入层

| 角色 | 入口 | 核心任务 | 认证与授权 | 隐私与安全约束 |
|------|------|----------|------------|----------------|
| **学生** | PC 浏览器、机房电脑、平板、后期小程序 | 发起情绪表达；完成测评；接受放松训练 | MVP 建议学号/校园账号 + 一次性授权 | 不默认启用人脸识别；不展示风险标签 |
| **心理老师** | PC 管理台、移动端提醒 | 查看授权摘要、风险列表、测评结果、干预建议 | 钉钉/企微/统一身份认证 + 二次校验 | 优先看摘要和趋势；查看原文片段需理由记录 |
| **班主任** | PC/移动端风险概览 | 了解班级风险态势；接收协助观察任务 | 按班级授权；只访问本班必要信息 | 不能查看完整聊天内容；仅看风险等级和处置状态 |
| **学校管理员** | 系统后台 | 租户配置、角色权限、数据留存策略 | 管理员账号 + 强密码/MFA | 配置权与内容访问权分离 |

### 4.2 应用功能层

| 功能域 | 子能力 | MVP 优先级 |
|--------|--------|------------|
| **心理陪伴对话** | 多轮自然对话、情绪镜像、儿童友好表达、有限回合收束 | P0 |
| **情绪评估** | 文本情绪识别、情绪强度估计、负向情绪趋势 | P0 文本；P1 语音 |
| **标准化测评** | MHT、SDQ 等量表；AI 引导式提问；自动评分 | P0 |
| **轻度 CBT 引导** | 识别情境、想法、情绪、行为；认知重评；行动计划 | P0 |
| **放松训练** | 呼吸练习、正念冥想、情景想象、音乐放松 | P1 |
| **心理成长档案** | 状态趋势、测评历史、干预记录、成长报告 | P1 |
| **预警与干预** | 风险分级、静默通知、任务派发、线下处理记录、升级转介 | P0 |
| **教师工作台** | 学生列表、风险队列、报告查看、干预记录、导出、备注 | P0 |
| **运营与配置** | Prompt版本、风险词库、量表配置、数据留存、角色权限、审计 | P0 |

### 4.3 AI Agent 层

```
学生输入
  ↓
Safety Agent（底线安全：自伤、自杀、暴力、虐待、严重躯体风险）
  ↓ 安全通过/需关注/高危
Emotion Agent（情绪识别：类别、强度、持续时间、触发因素）
  ↓
Triage Agent（风险分诊：绿/黄/橙/红，决定对话、测评、训练或转人工）
  ↓
Conversation Agent（儿童友好表达） ⇄ CBT Agent（结构化轻干预） ⇄ Knowledge Agent（心理知识检索）
  ↓
Output Review Agent（输出审查：不诊断、不治疗承诺、不药物建议、不强化负面）
  ↓
学生回应 + Report Agent 教师摘要 + Memory Agent 长期趋势
  ↓
Escalation Agent（红色风险：静默通知老师/值班人 → 线下处置 → 转介记录 → 闭环复盘）
```

| Agent | 职责 | 安全约束 |
|-------|------|----------|
| **Safety Agent** | 识别自伤/自杀、暴力、欺凌、虐待、严重焦虑抑郁倾向等底线风险 | 高危时优先安全话术和转人工；不继续开放式追问危险细节 |
| **Emotion Agent** | 识别情绪类别、强度、持续时间和触发场景 | 输出仅作为辅助，不直接给学生贴负面标签 |
| **Triage Agent** | 把情绪与风险映射到绿/黄/橙/红分级，并选择流程 | 红色风险无条件转人工；橙色需老师确认或限时跟进 |
| **Conversation Agent** | 用儿童友好语言进行共情、提问、收束和鼓励现实支持 | 避免权威化、治疗化、依赖化表达 |
| **CBT Agent** | 执行轻度 CBT 流程：情境—想法—情绪—证据—替代想法—小行动 | 只处理轻中度压力；危机场景停止干预并转人工 |
| **Escalation Agent** | 生成预警单、通知心理老师、推动线下处置和转介闭环 | 不把高危事件留在 AI 对话内解决 |
| **Report Agent** | 生成教师可读摘要、测评报告、班级聚合报告 | 摘要优先，不默认暴露全文；敏感字段脱敏 |
| **Memory Agent** | 维护长期趋势和上下文摘要，支持连续观察 | 保存"必要摘要"而非完整原文；设置留存期限 |

## 5. 核心业务流程

### 5.1 学生一次对话闭环

```
1. 学生登录/授权
   → 2. 选择"想聊一聊/做测评/放松一下"
   → 3. 输入内容，Safety Agent 先做底线风险检测
   → 4. Emotion Agent 识别情绪与强度
   → 5. Triage Agent 分级：绿/黄/橙/红
   → 6. 绿色：陪伴对话 + 轻度 CBT + 小行动建议 + 收束
   → 7. 黄色：对话继续，但形成老师关注摘要
   → 8. 橙色：限制深聊，生成预警单，老师限时确认
   → 9. 红色：安全话术 + 静默通知心理老师/值班人 + 线下危机流程
   → 10. Report Agent 生成摘要，Memory Agent 更新趋势
   → 11. 老师在工作台处理、记录、关闭或转介
   → 12. 系统沉淀审计、指标与复盘数据
```

### 5.2 风险分级与处置流程

| 等级 | 典型信号 | AI 允许动作 | 老师/学校动作 | SLA 建议 |
|------|----------|-------------|---------------|----------|
| **绿色** | 短期压力、一般情绪低落、考试焦虑、同伴冲突 | 共情、澄清、轻度 CBT、小行动建议、放松训练 | 无需立即介入，可看聚合趋势 | 无强制；日常观察 |
| **黄色** | 持续负面情绪、明显失眠/回避、自责、自卑、反复求助 | 有限对话、建议寻求老师/家长支持、生成关注摘要 | 心理老师在工作台关注，可安排谈话 | 1 到 3 个工作日内关注 |
| **橙色** | 疑似自伤念头、被欺凌、家庭暴力线索、强烈绝望但未明确计划 | 停止深挖危险细节，使用安全稳定话术，触发预警 | 心理老师限时确认，必要时班主任协助观察，联系监护人 | 当日处理，建议 2 小时内确认 |
| **红色** | 明确自杀/自伤计划、正在实施风险、严重暴力威胁、急性危机 | 只提供安全话术和现实求助引导，不继续普通聊天 | 立即通知心理老师/值班负责人，启动学校危机预案，必要时联系监护人/急救/专业机构 | 分钟级响应，直到人工接管 |

## 6. 数据流与权限流

> 注：本节完整内容见 `doc/01_心理辅导系统完整产品架构图.docx`

### 6.1 数据流总图

```
学生输入数据
  ↓
数据分类器：普通表达 / 心理敏感 / 高危敏感 / 语音音频 / 设备数据
  ↓
安全检测与脱敏：敏感词、风险语义、PII识别、Prompt注入检测
  ↓
业务处理：对话服务、测评服务、预警服务、报告服务、档案服务
  ↓
存储策略：
  A. 普通摘要：加密长期保存，用于趋势
  B. 敏感原文：默认不保存或短期保存，需策略与授权
  C. 高危证据片段：限权保存，用于线下危机处置复盘
  D. 原始语音/面部影像：默认不保存，启用需单独授权
  ↓
访问输出：学生端低敏反馈｜心理老师摘要和必要片段｜班主任等级和行动建议｜管理员配置与审计
  ↓
审计闭环：谁访问、为何访问、访问了什么、是否导出、是否处置
```

### 6.2 数据对象与最小化策略

| 数据对象 | 是否必须 | 默认存储 | 访问角色 | 最小化策略 |
|----------|----------|----------|----------|------------|
| **身份与班级关系** | 必须 | 加密保存 | 系统、心理老师、班主任按授权、管理员配置 | 只同步用户ID、姓名/昵称、班级、角色；不导入无关家庭信息 |
| **对话全文** | 非必须 | 默认不长期保存；可即焚或短期保存 | 心理老师经授权查看必要片段 | 摘要优先；全文访问需理由、审批或策略开关 |
| **对话摘要** | 必须 | 加密保存 | 心理老师、系统 Agent | 只保留风险判断和支持建议所需内容 |
| **情绪标签与趋势** | 必须 | 加密保存 | 心理老师、系统；班主任看聚合或等级 | 不向学生展示负面标签；不用于惩戒 |
| **量表答案与分数** | 必须 | 加密保存 | 心理老师；班主任仅等级或建议 | 题目、答案、分数分表存储；报告导出留痕 |
| **预警单** | 必须 | 加密保存 | 心理老师、值班负责人、必要班主任 | 只包含处置必要信息；关闭后限制继续扩散 |
| **原始语音** | 非必须 | 默认不保存 | 原则上不开放；如保存仅限心理老师审批访问 | 二期语音识别后即删，保留文字和低维特征即可 |
| **面部/视频数据** | 非必须 | 默认不采集不保存 | 默认无访问 | 三期如启用需本地处理、单独授权、DPIA评估 |
| **审计日志** | 必须 | 不可篡改保存 | 安全管理员、合规管理员 | 只记录操作必要信息，保护日志本身安全 |

### 7.1 演进路线图

```
MVP：文本化、规则化、可审计
  核心：学生对话 → 风险分级 → 老师工作台 → 预警闭环

  核心：机器人/多模态 → 家校协同 → 专业机构转介 → 数据驾驶舱
  约束：多模态本地处理优先，跨机构共享最小字段
```

## 8. 风险、指标与验证清单

### 8.1 主要风险与控制

| 风险 | 表现 | 控制策略 | 责任人 |
|------|------|----------|--------|
| **AI 越界风险** | 模型把自己表达成治疗师、给出诊断/药物/确定性承诺 | 系统级 Prompt、输出审查、红队测试、敏感话术黑名单、模型变更回归 | 产品负责人 + 心理专家 + 技术负责人 |
| **危机延误风险** | 高危学生被系统继续普通聊天，没有及时通知老师 | Safety Agent 前置；红色风险强制转人工；通知确认回执；逾期升级 | 心理老师 + 学校值班负责人 |
| **数据过度采集** | 为了"更智能"采集人脸、语音、家庭等非必要数据 | MVP 文本优先；DPIA；最小化字段；原始音视频默认不存 | 合规负责人 + 管理员 |
| **权限扩散** | 班主任、管理员或外部方看到过多学生敏感内容 | 权限矩阵、摘要优先、审批访问、审计日志、导出水印 | 学校管理员 + 安全负责人 |
| **标签化伤害** | 学生或老师把风险等级当作人格标签 | 学生端不展示标签；老师端强调"辅助判断"；报告用行为与趋势语言 | 产品负责人 + 心理老师 |
| **模型效果不稳定** | 误判、幻觉、前后输出不一致 | 规则 + 模型混合；置信度；低置信转人工；评测集持续迭代 | AI 负责人 |

### 8.2 核心指标

| 指标域 | 指标 | 解释 |
|--------|------|------|
| **学生体验** | 首次表达完成率、对话完成率、主动结束率、重复使用率 | 验证系统是否降低表达门槛，同时关注是否产生过度依赖 |
| **老师效率** | 预警处理时长、报告生成节省时间、待办关闭率、重复录入减少率 | 验证教师工作台是否真正提升心理老师效率 |
| **风险控制** | 高风险召回率、误报率、红色风险人工接管率、逾期未处理数 | 验证"老师在环"和危机转介是否可靠 |
| **数据合规** | 敏感数据访问次数、全文查看审批率、导出留痕率、数据清理成功率 | 验证数据最小化和权限流是否落地 |
| **系统可靠性** | 服务可用性、通知投递成功率、模型调用失败率、备份恢复演练结果 | 验证基础设施能支撑校园场景稳定运行 |
| **模型安全** | 越界输出命中率、Prompt注入拦截率、红队测试通过率、模型版本回滚次数 | 验证 AI 能力升级不破坏安全底线 |

### 8.3 上线前验证清单

- [ ] 完成"AI 不是心理治疗师"的学生端和教师端提示，并在高危场景显示现实求助路径
- [ ] 完成绿/黄/橙/红风险样例测试，红色风险必须触发人工通知和处置工单
- [ ] 完成权限矩阵验证：班主任不能查看聊天全文，管理员不能默认查看敏感内容
- [ ] 完成数据留存策略验证：对话全文、原始语音、导出报告、审计日志均有独立策略
- [ ] 完成模型输出安全测试：不诊断、不治疗承诺、不药物建议、不强化负面情绪
- [ ] 完成通知可靠性验证：钉钉/企微/短信/邮件至少一种高风险备用通知可用
- [ ] 完成备份恢复演练：能恢复用户、测评、预警、审计等核心数据
- [ ] 完成学校危机干预 SOP 对齐：系统预警单字段与线下处置流程一致

## 9. 深化设计与实现对照（2026-07-28 补充）

> 深化背景：全 55 篇设计文档 triage（TASK-TRACKER §二十四）P2 批次。图例：🟩 已生效 / 🟧 已实现零调用 / 🟫 仅骨架 / ⬜ 未实现。

### 9.1 双世界架构现状（§4.3 愿景图的落地状态）

| 愿景组件（§4.3） | 状态 | 现状说明 |
|-----------------|------|---------|
| Safety Agent（底线安全前置） | 🟩（等价实现） | 线上以规则风险检测 + `fuseRiskSignals`（文本 max 语音情绪 max 趋势）实现，非独立 Agent |
| Emotion Agent | 🟩（等价实现） | 文本情绪标签 + 语音 SER（emotion2vec+，见 `design/54`）随消息上送 |
| Triage / CBT / Conversation Agent 协同 | 🟧 | 世界 B 完整实现零调用；线上为世界 A 单 prompt（SYS-001+语言模板+性别风格+画像+nudge 拼接） |
| Output Review Agent | 🟫 | 输出侧安全依赖 prompt 约束 + 敏感词后置，无独立审查 Agent（RISK/SAFE 系列归口 `design/04` §十八） |
| Report / Memory Agent | 🟩（等价实现） | 会话摘要/教师侧报告 + `LongTermMemoryService`（召回 Top5 回注）已生效 |
| Escalation Agent | 🟩（等价实现） | 预警单+教师通知链路已生效；前台危机交互硬短路归 SAFE-203 |

**结论**：愿景图的能力大多以「服务内等价实现」存在而非独立 Agent；真正的 Agent 化编排（世界 B）待 DEC-CBT 接线。本篇 §4.3 保留为目标态，接线后与 `design/13` §十三 两段式架构（TriageCall）对齐，不另画第三套图。

### 9.2 数据流回注汇聚点补全（§6.1 缺失项）

§6.1 数据流总图为单向「输入→处理→存储→访问」，缺三条**已实现的回注环**，补记如下：

1. **画像回注** 🟩：会话结束 → SQL 聚合 + LLM 增量提炼（7 维 JSONB 含 personality_traits）→ 下次对话 `buildProfilePrompt` 注入 System Prompt（`design/23`/`design/29`）。
2. **长期记忆回注** 🟩：会话摘要 → 向量化存储 → 下次对话按相似度召回 Top5 注入（`design/50`）。
3. **语音情绪回注** 🟩：前端调 voice-service（ASR+SER）→ voiceEmotion 随消息上送 → `fuseRiskSignals` 融合 + 连续消极趋势升级（`design/54`）。

数据最小化对照：三条回注均只落枚举/摘要/向量，不落原始音频，与 §6.2 策略一致。

### 9.3 分期演进对照（§7 倒挂登记）

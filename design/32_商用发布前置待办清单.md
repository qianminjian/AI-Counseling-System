## 一、合规四件套（阻塞级：不做不能进校）

### 1. 等保二级测评（COMP-001）

| 项目 | 内容 |
|------|------|
| 法规依据 | 《网络安全法》§21 + 教育系统采购硬门槛 |
| 负责方 | 钱敏健 + 等保测评机构 |
| 审核周期 | 1-3 个月（含整改） |
| 前置材料 | 系统定级报告、安全管理制度文档、网络拓扑图、应急预案 |
| 当前进度 | 技术差距评估已完成（见 `design/31_等保二级差距评估.md`），识别 4 个 P0 项 |
| 下一步 | ① 选定测评机构 → ② 提交定级备案 → ③ 配合测评 → ④ 整改 → ⑤ 复测出报告 |
| 预估费用 | 3-8 万（测评费） |

| 项目 | 内容 |
|------|------|

| 审核周期 | 1-2 个月 |

| 注意 | 使用 DeepSeek API 也需备案（调用方责任） |

### 3. 教育 App 备案（COMP-003）

| 项目 | 内容 |
|------|------|
| 法规依据 | 《教育移动互联网应用程序备案管理办法》（教技厅〔2019〕3号） |

## 二、第三方配置（阻塞级：功能不可用）

### 5. 企微/钉钉 OAuth 配置（BIZ-002 / AUTH-021）

| 项目 | 内容 |
|------|------|
| 负责方 | 钱敏健 + 学校 IT 管理员 |
| 周期 | 1-3 天（配置即生效） |
| 代码状态 | ✅ 已就绪（企微 OAuth 完整实现，含回调/用户映射/Token 刷新） |
| 所需信息 | corpId、corpSecret、agentId、回调 URL 白名单 |
| 下一步 | ① 学校 IT 在企微管理后台创建自建应用 → ② 获取凭据 → ③ 填入 .env → ④ 验证登录 |

### 6. 阿里云 SMS 签名/模板申请（BIZ-003 / DEPLOY-010）

| 项目 | 内容 |
|------|------|
| 负责方 | 钱敏健 |
| 周期 | 3-7 天（审核） |
| 代码状态 | ✅ 已就绪（AliyunSmsService + @ConditionalOnProperty 切换） |
| 所需材料 | 企业营业执照、短信签名（公司名/产品名）、模板内容（验证码格式） |
| 下一步 | ① 阿里云控制台提交签名 → ② 提交模板（短信验证码）→ ③ 审核通过 → ④ 填入 AccessKey + 签名/模板 ID |
| 降级方案 | 审核期间可用 LoggingSmsService（控制台打印验证码），不阻塞内部测试 |

## 四、推荐执行顺序

```
Week 1-2:  COMP-004（法务审定，最快出结果）+ BIZ-003（SMS 申请）
Week 2-4:  COMP-002（算法备案，材料准备 + 提交）

```

**关键路径：COMP-001（等保）→ COMP-003（教育 App 备案）→ 正式进校**

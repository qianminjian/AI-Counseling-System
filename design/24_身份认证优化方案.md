# 24 身份认证优化方案

> 状态：设计完成 | 关联：21 认证与试用准入设计、10 政策与合规、14 儿童安全对话规范
> 核心：分三阶段加固身份认证体系，解决"任何人都能冒充学生"的安全缺陷，同时满足未成年人数据保护合规要求。
> ⚠️ 合规红线：生物识别信息采集涉及 PIPL §28-31、《人脸识别技术应用安全管理办法》(2025)，最终合规判断需法务审定。

---

## 一、现状问题

| 问题 | 严重度 | 影响 |
|------|--------|------|
| 邀请码共享 = 无身份验证 | 🔴 高 | 任何人拿到码即可注册，无法区分真实学生 |
| 试用学生无密码 | 🟡 中 | 换设备无法找回身份 |
| 家长 Token 无绑定 | 🟡 中 | 链接泄露则任何人可查看报告 |
| 监护人同意无实质验证 | 🔴 高 | 只收集手机号字段，不验证真实性 |
| 密码无复杂度/过期策略 | 🟡 中 | 正式账号 123456 可登录 |

## 二、三阶段优化方案

### 阶段一：M1 试用加固（近期开发）

| 优化项 | 做法 | 工作量 |
|--------|------|--------|
| 邀请码一人一码 | 教师批量生成 → 分发 → 每码绑定一个 userId，用后作废 | 1天 |
| 学生 PIN 码 | 注册后设置 4-6 位数字密码，支持换设备登录 | 1天 |
| 家长 Token 绑定手机 | 生成链接时绑定手机号，打开需短信验证码 | 2天 |
| 密码策略 | 正式账号强制 8 位+复杂度，首次登录改密 | 0.5天 |
| 登录失败锁定 | 连续 5 次失败 → 锁定 15 分钟 | 0.5天 |

### 阶段二：M2 学校正式部署（后续待办）

| 优化项 | 做法 |
|--------|------|
| 学校统一导入 | 管理员 Excel 导入学生名单 → 生成学号+初始密码 → 班主任分发 |
| 企微/钉钉 OAuth | 教师通过企微免密登录（代码已就绪，需配置 corpId/secret） |
| 家长微信小程序 | 家长微信授权 → 绑定孩子 → 查看报告（家长实名） |
| 监护人同意闭环 | 注册发短信给 guardianPhone → 家长点确认链接 → 同意才生效 |
| 微信一键登录（家长） | 家长端接入微信 OAuth → openid 绑定 → 免密进入报告页 |

### 阶段三：合规加固（后续待办）

| 优化项 | 做法 |
|--------|------|
| 使用时长限制 | 每日对话 ≤ 30 分钟，超时引导休息（未保法） |
| 数据最小化审计 | 定期清理超保留期的对话数据 |
| 家长撤回同意 | 家长可随时撤回 → 冻结账号 + 删除画像 |
| 年度合规审计 | 按《未成年人网络保护条例》§37 每年报送 |
| 设备端快速认证（可选） | WebAuthn 设备端指纹/Face ID（见第四章分析） |

## 三、家长端微信一键登录设计

### 3.1 方案

```
家长打开报告链接
  → 微信 OAuth2 授权（snsapi_userinfo）
  → 获取 openid + unionid
  → 匹配 parent_bindings 表（openid ↔ studentUserId）
  → 签发 parent_token（7天）
  → 进入只读报告页
```

### 3.2 数据模型

```sql
CREATE TABLE tenant_template.parent_bindings (
    binding_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL,
    student_user_id UUID NOT NULL,
    parent_openid   VARCHAR(64) NOT NULL,  -- 微信 openid
    parent_name     VARCHAR(50),           -- 家长姓名（可选）
    relation        VARCHAR(20),           -- father/mother/grandparent/other
    bindAt          TIMESTAMPTZ NOT NULL DEFAULT now(),
    status          VARCHAR(20) NOT NULL DEFAULT 'active',
    CONSTRAINT uq_parent_bind UNIQUE (tenant_id, student_user_id, parent_openid)
);
```

### 3.3 合规性

- 微信 OAuth 只返回 openid/昵称/头像，**不采集身份证号、手机号**
- 家长为成年人，标准 OAuth 同意即可
- 绑定关系由教师发起（教师确认"这是 XX 的家长"），非家长自助绑定
- 合规风险：**低**

## 四、生物识别认证合规分析（重点）

### 4.1 法律框架

| 法规 | 条款 | 要求 |
|------|------|------|
| PIPL §28 | 生物识别 = 敏感个人信息 | 需特定目的 + 充分必要性 |
| PIPL §29 | 处理敏感信息 | 需取得个人**单独同意** |
| PIPL §31 | 不满 14 周岁 | 需监护人**单独同意** + 制定专门处理规则 |
| 人脸识别安全管理办法 (2025) §7 | 未成年人人脸 | 监护人同意 + 专门处理规则 + PIA |
| 未保条例 §32 | 非必要信息 | 不得强制未成年人同意非必要处理 |
| TC260 未成年人保护要求 (2025) | 生物识别 | 需符合 GB/T 40660 + 额外保护措施 |

### 4.2 两种路径对比

| 维度 | 路径 A：服务端采集（❌ 不推荐） | 路径 B：设备端 WebAuthn（✅ 可选） |
|------|------|------|
| 原理 | 采集指纹/人脸图像 → 上传服务器 → 比对 | 设备本地验证 → 只传公钥签名 → 服务器不接触生物数据 |
| 我方是否持有生物数据 | **是**（高风险） | **否**（只持有公钥 credential） |
| PIPL 合规负担 | 极高：PIA + 单独同意 + 专门规则 + 年度审计 | 低：生物数据在设备端，我方不处理 |
| 必要性论证 | 难：PIN 码可达到同等目的，不满足"充分必要" | 可：作为便捷选项（非强制），PIN 仍为备选 |
| 适用场景 | 自有设备（手机） | 自有设备（手机/平板），**不适用共享设备** |
| 小学生实际场景 | 学校平板多人共用 → 不可行 | 家中手机/平板 → 可行 |
| 实现复杂度 | 高（需活体检测、加密存储、合规审计） | 中（WebAuthn API，浏览器原生支持） |

### 4.3 结论与建议

**核心判断：不采集、不存储未成年人的指纹/人脸数据。**

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 学生登录（学校设备） | PIN 码（4-6位数字） | 共享设备无法绑定个人生物特征 |
| 学生登录（家中手机） | WebAuthn 设备端指纹/Face ID（可选） | 生物数据不出设备，合规风险低 |
| 家长登录 | 微信 OAuth 一键登录 | 成年人标准流程，零额外合规负担 |
| 教师登录 | 企微 OAuth / 密码 | 已有实现 |

### 4.4 WebAuthn 设备端认证设计（阶段三可选）

```
注册流程（家中手机首次绑定）：
  学生输入 PIN → 验证通过 → 浏览器调用 navigator.credentials.create()
  → 设备弹出指纹/Face ID → 本地验证 → 生成密钥对
  → 公钥 credential 上传服务器 → 关联 userId
  → 完成：服务器只存公钥，不存任何生物数据

登录流程：
  学生点击"指纹登录" → 服务器发送 challenge
  → 浏览器调用 navigator.credentials.get()
  → 设备弹出指纹/Face ID → 本地验证 → 签名 challenge
  → 服务器验签 → 签发 JWT
```

**合规要点：**
- 隐私政策中声明："本服务不采集、传输或存储您的指纹/面部图像数据。生物识别验证完全在您的设备本地完成。"
- WebAuthn 为**可选**，PIN 码始终为备选 → 满足"不强制"要求
- 无需 PIA（因为我方不处理生物识别信息）
- 需确认：学校场景下学生是否有个人设备（若无则此功能无意义）

## 五、阶段一详细设计（近期开发）

### 5.1 邀请码一人一码

**现状**：`trial_invite_codes` 表存通用码（DEMO2026），多人共用。

**改造**：
```sql
-- 扩展 trial_invite_codes 表
ALTER TABLE tenant_template.trial_invite_codes
    ADD COLUMN IF NOT EXISTS bound_user_id UUID,        -- 绑定用户（用后填入）
    ADD COLUMN IF NOT EXISTS used_at TIMESTAMPTZ,       -- 使用时间
    ADD COLUMN IF NOT EXISTS batch_id VARCHAR(50),      -- 批次号（教师批量生成）
    ADD COLUMN IF NOT EXISTS generated_by UUID;         -- 生成者（教师 userId）
```

**规则**：
- 教师端 → 批量生成 N 个码（格式：MS-XXXX-XXXX）→ 导出/打印分发
- 学生注册时验证码有效 → 注册成功 → 码绑定 userId → 标记 used
- 已用码再次使用 → 拒绝（"该邀请码已被使用"）
- DEMO2026 保留为公开体验码（不限绑定，用于产品演示）

### 5.2 学生 PIN 码

**设计**：
- 注册成功后引导设置 4-6 位数字 PIN
- PIN 存储：BCrypt 哈希（复用 passwordHash 字段）
- 登录方式：昵称 + PIN（替代密码）
- 忘记 PIN：需教师重置（管理端操作）
- 连续 5 次错误 → 锁定 15 分钟

### 5.3 家长 Token 绑定手机

**现状**：教师生成链接 → 任何人持有链接即可查看。

**改造**：
- 教师生成链接时输入家长手机号
- 家长打开链接 → 输入手机号 → 短信验证码 → 验证通过 → 签发 7 天 Token
- 短信服务：阿里云 SMS / 腾讯云 SMS（按量付费）

### 5.4 密码策略

- 正式账号（教师/管理员）：≥ 8 位，含字母+数字
- 首次登录强制改密（已有 `mustChangePassword` 字段）
- 密码过期：90 天（管理员可配置）

### 5.5 登录失败锁定

```java
// Redis 计数器
Key: login_fail:{pseudonym}
TTL: 15 分钟
Threshold: 5 次 → 返回"账号已锁定，请15分钟后重试"
```

# 36 - 心理工具箱与离线缓存设计

> 创建：2026-07-28 | 状态：设计完成，待实施 | 对应规划任务：PROD-006 心理工具箱（P1）+ PROD-007 离线对话缓存（P2）（design/30）
>
> 定位：工具箱 = 不依赖 LLM 的**自助调节技能库**（呼吸/正念/情绪温度计/安全岛/接地），离线缓存 = 弱网教室环境下的**可用性兜底**。两者合并设计因为共享同一技术底座：工具箱内容全静态可预缓存，是离线模式的核心承接场景。

---

## 一、业界对标（避免空想的依据）

### 1.1 Wysa / Woebot 的工具箱设计范式

| 实践 | 来源 | 借鉴决策 |
|------|------|---------|
| **SOS 一键模式**：任何界面一键进入 → 危机热线资源 + 接地练习 + 安全计划三合一 | Wysa SOS | 采纳。学生端全局常驻 SOS 入口（波波耳朵下拉/侧边按钮） |
| **安全计划（Safety Plan）对话式创建**：预先和用户一起填好"我难受时可以做什么/找谁"，危机时直接展示 | Wysa（Stanley & Brown 安全计划模板的数字化） | 采纳简化版（儿童版安全岛卡片，§三.5） |
| **单技能教学**：一次只教一个 CBT 微技能，2-5 分钟完成，结束给正反馈 | Woebot | 采纳。每个工具 ≤5 分钟，完成即得成就 |
| **工具独立于对话可达**：不强迫用户先聊天才能用工具 | Wysa 自助库 | 采纳。工具箱是首页一级入口 |
| **练习完成后询问效果**："现在感觉好点了吗？"用于效果记录与推荐 | Wysa/Calm | 采纳（情绪前后对比，喂给画像与 design/39 实验指标） |

### 1.2 循证技术来源（儿童适配）

| 工具 | 循证来源 | 儿童化改造 |
|------|---------|-----------|
| 箱式呼吸/4-7-8 呼吸 | 广泛临床验证的放松训练 | 波波跟着一起呼吸的动画引导（现有 RelaxationExercises 已有基础） |
| 5-4-3-2-1 接地法 | Lifeline / 哈佛医学院推荐的 grounding 技巧 | 改为"和波波玩找一找"：说出 5 个看到的东西… |
| 正念身体扫描 | MBSR 儿童简化版（Sitting Still Like a Frog 范式） | 3 分钟音频引导，青蛙/星星意象 |
| 情绪温度计 | 儿童 CBT 标准工具（情绪外化） | 拖动温度计给心情打分 + 表情脸谱 |
| 安全岛/蝴蝶拍 | 创伤稳定化技术（儿童常用） | "我的安全小岛"卡片：预存让自己安心的画面/人/物 |

### 1.3 离线技术范式（offline-first PWA）

业界验证的关键结论（Google Workbox 文档 / offline-first 社区实践）：

1. **Service Worker 中只能用 IndexedDB**（localStorage 不可用）——离线队列必须落 IndexedDB
2. **Background Sync API 只有 Chromium 系支持，iOS Safari 不支持** → 必须设计前台重试降级路径（`online` 事件 + 页面可见性触发）
3. 静态资源用 Workbox precache（已有），**内容类资源（音频/动画 JSON）用 runtime cache + CacheFirst**，避免首包过大
4. 消息类离线队列的标准模式：本地先写（乐观 UI）→ 队列持久化 → 网络恢复按序重放 → 幂等去重（客户端生成 msgId）

## 三、心理工具箱设计

### 3.1 信息架构

```
首页新增一级入口「百宝箱 🧰」（波波递出宝箱的图标）
├── 🫧 深呼吸（已有，纳入框架）      2-3 分钟
├── 🐸 安静小青蛙（正念身体扫描）     3 分钟
├── 🔍 找一找（54321 接地）          3 分钟
├── 🌡️ 心情温度计                   1 分钟
├── 🏝️ 我的安全小岛（安全计划儿童版）  首次创建 5 分钟，之后即时查看
└── 🆘 SOS（全局常驻，不在宝箱内也可达）
```

### 3.2 统一工具框架（开闭原则，新工具零框架改动）

每个工具 = 一份**声明式配置 + 步骤内容包**：

```json
{
  "toolId": "grounding_54321",
  "title": "找一找",
  "durationSec": 180,
  "minGrade": 1,
  "preMoodCheck": true,
  "steps": [
    {"type": "narration", "text": "…", "audio": "grounding_1.mp3", "boboAnim": "look_around"},
    {"type": "interaction", "prompt": "说出 5 个你看到的东西", "input": "chips_or_voice"}
  ],
  "postMoodCheck": true,
  "rewardBadge": "grounding_master"
}
```

- 内容包（JSON + 音频 + Lottie 动画）静态托管，版本化目录 `/toolbox/v{n}/`，**全部可预缓存 → 天然离线可用**
- 音频用 tts-service 离线生成（构建期产物，非运行时调用），4 音色各出一套，跟随学生音色偏好
- `preMoodCheck/postMoodCheck`：练习前后各一次 1-5 表情打分，差值记录为工具效果（S3 级数据，进画像与 design/39 指标）

### 3.3 工具入口的三条触发路径

| 路径 | 机制 |
|------|------|
| 主动使用 | 首页宝箱入口 |
| 对话内推荐 | AI 检出焦虑/激动情绪 → 回复中附带工具卡片（"要不要和波波一起深呼吸？"），点击直达；safety 包检出 S0/S1 时**不推荐工具**，走危机流程 |
| 冷场引导 | 复用 design/28 冷场决策模型：沉默场景可推荐温度计（低门槛表达） |

### 3.4 SOS 模式（Wysa 范式落地）

全局常驻入口（对话页右上角 🆘，非埋藏在菜单里）。点击后单页三段式：

1. **立即联系**：心理援助热线卡片（12355 / 校配置热线，一键拨号）+ "找老师"（触发教师端 S1 通知，学生可选）
2. **先稳住自己**：直达接地练习 + 深呼吸（预缓存，离线可用）
3. **我的安全小岛**：展示已创建的安全计划卡片

> 设计决策：SOS 页面**纯静态 + 预缓存**，断网也 100% 可打开——这是离线设计最重要的一个场景。学生点击 SOS 的行为本身上报为 S2 事件（网络恢复后补报，不阻塞界面）。

### 3.5 我的安全小岛（儿童版安全计划）

Stanley & Brown 安全计划的儿童简化三栏：

- **让我安心的画面**（选图/上传画作）
- **我可以做的事**（从工具箱勾选 + 自定义，如"抱抱枕头"）
- **我可以找的人**（家人/老师/朋友，最多 3 个；仅存称呼不存联系方式，避免敏感数据）

由波波对话式引导创建（固定脚本，非 LLM）；创建后 SOS 页直达；内容属 S3 级，家长/教师不可见明细（学生的私密空间，仅"已创建"状态对教师可见）。

## 四、离线缓存设计

### 4.1 分场景离线策略（明确边界：什么能离线，什么不能）

| 场景 | 离线能力 | 策略 |
|------|---------|------|
| 工具箱全部工具 | ✅ 完全可用 | 内容包 CacheFirst + 版本化更新 |
| SOS 页 | ✅ 完全可用 | precache，构建产物 |
| AI 对话 | ⚠️ 降级：可输入可排队，不可得到 AI 回复 | 消息队列 + 波波兜底话术 |
| 历史对话回看 | ✅ 最近 2 次会话 | IndexedDB 本地缓存（密文，见 §4.4） |
| TTS 语音 | ⚠️ 工具箱音频可用；对话 TTS 不可用 | 静态音频缓存；对话降级为纯文字 |
| 量表施测（design/34） | ❌ 不支持离线 | critical 熔断依赖实时通道，离线施测有安全风险，明确禁用 |

**核心设计决策：离线时不做"假 AI"**。不用本地小模型模拟回复（质量不可控，儿童场景风险大）；波波用固定陪伴话术 + 引导去工具箱："网络好像睡着了，波波还在！要不要玩找一找？"

### 4.2 网络状态检测与 UI

- 检测：`navigator.onLine` + 心跳探测（对 `/api/v1/health` 的轻量 HEAD，30s 间隔，仅在 onLine 为 true 但请求连续失败时判定"假在线"）
- UI：顶部细条横幅"离线模式 · 波波陪你玩"（暖色调，不用红色报错样式——儿童产品的错误呈现原则）；恢复后横幅变绿 2s 消失
- 波波表情切换为"打盹"状态（复用 BoBoPet 动画状态机）

### 4.3 离线消息队列（业界标准模式落地）

```
发送流程：
用户发送 → 生成客户端 msgId (UUID) → 写 IndexedDB outbox → UI 乐观展示(时钟icon)
  → 在线：立即 POST（带 msgId）→ 成功则删 outbox、icon 变 ✓
  → 离线：留在 outbox

重放流程（三触发器，覆盖 iOS 降级）：
  1. window 'online' 事件
  2. 页面 visibilitychange 变可见
  3. Chromium：SW Background Sync（渐进增强，不依赖）
重放规则：按时间序逐条 POST；服务端按 (userId, msgId) 幂等去重；
  连续失败退避（1s/5s/30s）；超过 24h 的排队消息标记"未送达"由用户选择重发或丢弃
```

- 服务端改动：chat 消息接口增加可选 `clientMsgId` 字段 + 幂等约束（唯一索引 `(user_id, client_msg_id)`）
- 重放的消息进入正常 AI 流程，但**批量重放（≥3 条）时不逐条生成 AI 回复**，AI 收到合并上下文回一条（避免恢复瞬间轰炸式回复与 token 浪费）
- **安全约束**：重放消息同样过 safety 风险检测；若离线排队内容命中 S0/S1 规则，恢复后立即按当前时间触发预警，并在预警中标注"消息产生于离线期间 HH:MM"

### 4.4 本地对话缓存（回看）

- 范围：最近 2 次会话的消息（文本），IndexedDB 存储
- 安全：**密文存储**——用 Web Crypto AES-GCM，密钥由登录会话派生（JWT 派生 key，登出即不可解）；设备共用场景（教室平板）登出时清空缓存库
- 不缓存：音频、画像数据、任何他人数据；缓存总量上限 2MB，LRU 淘汰

### 4.5 Workbox 配置增量（vite.config.js）

| 资源 | 策略 |
|------|------|
| `/toolbox/v*/**`（内容包/音频/Lottie） | CacheFirst，maxEntries 200，30 天过期 |
| SOS 页与其依赖 | 纳入 precache globPatterns |
| API | 保持 NetworkOnly 不变（离线由应用层队列负责，不让 SW 缓存 API 响应——避免缓存到敏感对话数据） |
| Transformers.js chunk | 维持现状排除 precache |

内容包更新：`/toolbox/manifest.json`（NetworkFirst）记录当前版本号，版本变更时后台静默预取新版本，下次进入生效。

## 五、API 与数据模型增量

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/toolbox/sessions` | 上报一次工具使用（toolId、时长、前后心情分、是否完成）；支持离线补报（带 clientEventId 幂等） |
| GET | `/api/v1/toolbox/recommendations` | 对话内推荐候选（服务端按情绪状态返回，客户端渲染卡片） |
| PUT | `/api/v1/students/me/safety-island` | 保存安全小岛内容（S3 加密存储） |
| POST | `/api/v1/sos/events` | SOS 打开事件上报（离线补报），落 S2 事件 |

新表（遵循 design/06 规范，tenant schema 内）：

- `toolbox_usage`：id, student_id, tool_id, pre_mood, post_mood, duration_sec, completed, client_event_id, occurred_at（S3）
- `safety_island`：student_id, content(jsonb, 信封加密 S4), updated_at

教师端消费：学生详情页"自助练习"卡片（次数/偏好工具/前后心情均值差）；班主任不可见安全小岛内容。

## 六、实施里程碑与验收

| 阶段 | 范围 | 验收标准（EARS 摘要） |
|------|------|---------------------|
| M1（P1，随 Sprint E） | 工具箱框架 + 温度计 + 接地 + 正念（呼吸并入框架）+ 前后心情记录 | WHEN 学生完成工具 THEN 系统 SHALL 记录 usage 并发放成就；工具内容包 SHALL 可离线打开 |
| M2（P1） | SOS 模式 + 安全小岛 | WHEN 断网状态点击 SOS THEN 页面 SHALL 正常打开且热线可拨号；WHEN 学生点击 SOS THEN 系统 SHALL 在网络可用时 1min 内产生 S2 事件 |
| M3（P2） | 离线检测 UI + 消息队列 + 重放幂等 + 本地对话缓存 | WHEN 离线发送 3 条消息后恢复网络 THEN 服务端 SHALL 恰好收到 3 条（无重无漏）且 AI 合并回复一条；WHEN 离线消息含风险内容 THEN 恢复后 SHALL 触发预警并标注离线时间 |

**测试要点**：Chrome DevTools offline 模拟 + iOS Safari 真机（无 Background Sync 路径）双端队列重放用例；幂等唯一索引冲突用例；SW 更新时内容包版本切换用例；共用设备登出后 IndexedDB 清空验证；SOS 断网 Lighthouse PWA 审计。

## 1. ⚠️ 自主边界红线（7 条 - 必须先问）

即使在 auto-accept 模式下也**必须停下来问**：

| # | 触发场景 | 必须询问事项 |
|---|---------|------------|
| 1 | 删除文件、目录或 git 历史 | 删除范围、备份方案、是否有依赖 |
| 2 | 修改 .env、密钥、token、CI/CD 配置 | 影响范围、回滚方案、密钥轮换 |
| 3 | 数据库 schema 变更或数据迁移 | 迁移脚本、回滚脚本、备份验证 |
| 4 | git push / rebase / reset --hard / 强制推送 | 影响分支、是否需要 PR review |
| 5 | 安装新的全局依赖或修改系统配置 | 安装必要性、影响范围、是否可项目局部 |
| 6 | 公开发布（npm publish、部署生产、发文章） | 发布版本、审批流程、回滚预案 |
| 7 | 监管责任事项（合规判断、监管报告签署、生产发布审批） | **AI 只提供信息，不做决策** |

**触发协议**：

- 命中红线立即停下，不做任何"先做后问"的尝试
- 列出当前假设（"我准备做 X 因为 Y，因为命中红线 #N"）
- 给出 1-3 个可行方案，等用户明确决策
- 用户拒绝 → 接受并记录，不反复建议

## 2. ⚠️ 启动服务红线（端口冲突防护）

任何 `npm run dev` / `node server.js` / `next dev` / `python app.py` 等服务启动前**必须**：

```bash
# 步骤 1：检查端口占用
lsof -i:<端口>

# 步骤 2：如占用，强制杀掉
kill -9 <PID>

# 步骤 3：再次确认释放
lsof -i:<端口>

# 步骤 4：确认释放后才启动
<启动命令>
```

| 场景 | 处理 |
|------|------|
| 端口被占用 | kill -9 后再启动，不接受"端口冲突就先跑起来" |
| 残留僵尸进程 | `ps aux | grep <进程名>` 找到所有相关进程一并清理 |
| 权限不足 | `sudo` 需先获得授权（命中红线 #5） |
| **例外** | CI 容器内启动可豁免 |

## 2.5 ⚠️ 部署纪律与脚本防呆（2026-08-11 新增）

### 2.5.1 部署执行纪律（用户 2026-08-09 明确要求）

- **禁止后台静默部署**（is_background=true）；`deploy.sh` 必须前台执行并逐个步骤监控输出
- 部署完成后查看 `logs/deploy/deploy-*.log` 的 dm_report 各步骤耗时；步骤耗时异常（prepare-models >10s、总时长 >5min）立即停下分析原因，**不得盲目重跑**
- 命令被取消/超时/失败后必须先诊断（残留进程、部署日志、git 状态）再行动

### 2.5.2 部署脚本防呆纪律（2026-08-11 教训：compose 预检 cwd 漂移）

- 部署/运维脚本内**所有本地路径必须基于 `$PROJECT_ROOT` 绝对锚定**；脚本 `cd` 进子目录后必须恢复 cwd 或用绝对路径，禁止依赖调用者 cwd
- 新增脚本逻辑失败时，**错误输出必须完整可诊断**（禁止只 grep 过滤摘要——关键错误行如 `no such file` 可能被过滤漏报）
- 部署脚本任何修改必须验证：`bash -n` 语法检查 + 在非仓库根目录调用场景下路径可正常解析

### 2.5.3 CI 推送监控与超时判断纪律（2026-08-13 用户明确要求）

- **git push 后必须监控 CI 结果并反馈**：禁止推送后不闻不问；前台轮询 `gh run` 直至 completed，完成后向用户反馈结论与失败 job 明细
- **必须带超时判断机制**：CI 超过约定时限（默认 25 分钟）未完成即停止轮询，立即诊断（进行中 job 列表、卡点定位、日志），**不得无限等待或盲目重推**
- 监控采用轮询+上限循环（如 `DEADLINE=$((SECONDS+1500))` 内每 60s 查一次），超时后输出状态快照供诊断

### 2.5.4 发布链路完整性纪律（2026-08-13 复盘教训：5 轮 push + 部署冒烟失败）

- **CI 门禁步骤合入前必须本地完整验证**（教训：Schema Snapshot Gate 从引入起必失败——01_schema.sql 早已被删/路径双重嵌套/pg_dump 版本/硬编码用户/动态表头 5 个独立 bug 叠加，因前序步骤从未执行到而长期潜伏）；新增/修改 CI 步骤后，先在本地按 CI 等价环境跑通再合入
- **契约变更必须全消费方同步**（教训：ApiResponse 序列化形状变更（F6）同步了 Java IT 却漏了部署冒烟 smoke-test.sh，部署后才发现 6 用例失败）；统一响应形状/字段变更时，消费方清单至少覆盖：Java IT、e2e 冒烟、前端断言
- **依赖升级必须全端回归**（教训：vitest 3→4 引入 stubGlobal 不可构造/覆盖率口径/unhandled errors 三类连锁问题）；升级测试框架后四端 test:coverage 全跑，不得只验单端
- 部署前置已内置 CI 门禁检查（deploy.sh precheck：最近 run conclusion=success 且 headSha=origin/main）；文档类提交不触发 CI 时用 `SKIP_CI_GATE=1` 显式跳过

## 3. ⚠️ 安全编码红线

每次 Edit / Write / Bash 前快速自检：

### 3.1 敏感信息检测

| 类别 | 检测项 | 命中动作 |
|------|--------|---------|
| 密钥/token | API key / access token / private key / Bearer token | 立即停止，拒绝写入 |
| 个人隐私 | 中国手机号（11 位）/ 身份证号（18 位）/ 银行卡号（13-19 位） | 立即停止，脱敏后重写 |
| 数据库 | DSN 连接串 / root 密码 / Redis URL 含密码 | 立即停止，从环境变量读取 |
| 系统凭据 | SSH 私钥 / .env 文件内容 | 立即停止，禁止提交 |

### 3.2 注入防护

| 类别 | 禁止做法 | 正确做法 |
|------|---------|---------|
| SQL 注入 | `query("SELECT * FROM users WHERE id=" + userId)` | 参数化查询 / ORM |
| XSS | `element.innerHTML = userInput` | `textContent` / React JSX 自动转义 |
| CSRF | 裸 POST 无 token | 校验 CSRF token 或 SameSite Cookie |
| 路径穿越 | `fs.readFile(userProvidedPath)` | `path.resolve` + 前缀白名单 |
| 命令注入 | `exec("rm -rf " + userPath)` | 禁止拼接 shell 命令字符串 |

### 3.3 硬编码凭据

- 密码/连接串必须从环境变量读取
- 测试中调用第三方付费 API 必须用 mock 隔离

## 4. 通用工程纪律（4 条）

### 4.1 改完跑验证

- 不要只改不验（具体命令见项目级 AGENTS.md 或各技术栈约定）
- 测试/lint/启动三选一至少做一项

### 4.2 不绕过报错

- 找根本原因，不注释报错或加绕过标记
- 禁止 `try { ... } catch {}` 空吞噬
- 禁止删除/跳过失败测试让 CI 变绿

### 4.3 密钥不进代码

- token / 密码 / API Key 不进代码、commit、日志
- AI 生成测试数据必须用脱敏格式（身份证 `3201**********1234` / 手机 `138****1234` / 银行卡 `6222****1234`）

### 4.4 大改动先出方案

- 涉及多文件 / 跨模块 / 架构级变更 → 先出方案，确认后再动手
- Plan Mode（@design-persistence）下产出方案 → 等用户批准

### 4.5 设计文档与代码一致（项目底线规则）

`design/*.md` 是项目的**单一事实源**，必须与代码保持一致。这是不可妥协的底线：

- **改代码必同步文档**：任何涉及类名/接口/模块职责/安全机制/数据流/Prompt 的代码变更，**同一次提交**内必须同步更新对应 `design/*.md`（尤其是各文档的"Java 实现层适配"章节）。
- **改文档必核对代码**：更新设计文档的实现描述时，必须先读真实代码确认类名/行为，**禁止凭记忆或设计稿臆测**。
- **设计期 vs 已实现要区分**：目标设计（设计期类名）与已实现（真实类名）必须明确标注状态（如"目标设计"/"M1 实际实现"/"尚未实现"），不混淆。
- **交付自检**：commit/PR 前检查"本次代码改动是否已反映到 design/"，未同步视为未完成。
- 发现文档与代码不一致时，**以代码实际行为为准**修正文档（除非代码本身是 bug）。

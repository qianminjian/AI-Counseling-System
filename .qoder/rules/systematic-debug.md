# systematic-debug.md - 系统性调试流程

> 引用方式：`@systematic-debug`
> 触发场景：任何 bug / test failure / 异常行为 / 用户报告"出错/不工作"
> 来源：整合自 Claude Code `rules/work-management.md` §2.3 + Superpowers `systematic-debugging` skill

---

## 1. 调试前自检（接到 bug 报告时）

### 1.1 不假设

- 不要直接看代码猜原因
- 不要"想当然"地开始改
- **先复现 bug** 是第一优先级

### 1.2 写复现测试

```
[1] 写一个能稳定复现 bug 的测试 → 确认 FAIL
[2] 跑测试确认能复现 → 不是偶发
[3] 记录复现步骤（输入、环境、时序）
```

只有能稳定复现的 bug 才能被修复。

---

## 2. 根因分析（5 Why）

### 2.1 问 5 次"为什么"

```
bug 现象：[X 报错 / Y 不工作]
  → 为什么？ [原因 1]
    → 为什么？ [原因 2]
      → 为什么？ [原因 3]
        → 为什么？ [原因 4]
          → 为什么？ [根本原因]
```

通常第 3-5 层才是真正需要修复的地方。

### 2.2 区分症状与原因

| 层次 | 示例 |
|------|------|
| **症状** | 接口返回 500 |
| **直接原因** | 数据库连接超时 |
| **根本原因** | 连接池配置过小 + 高并发场景未压测 |

修症状（重试）→ 缓解；修根本 → 解决。

---

## 3. 调试策略（按优先级）

### 3.1 从最简单假设开始

| 优先级 | 检查项 |
|--------|--------|
| 1 | 数据本身：输入是否正确？fixture 是否生效？ |
| 2 | 环境：环境变量、配置、版本号 |
| 3 | 依赖：依赖版本、lockfile、网络 |
| 4 | 时序：异步/并发/竞态 |
| 5 | 业务逻辑：边界、异常分支 |

### 3.2 排除法

- 注释一半代码 → 跑测试 → 验证是否仍复现
- 缩小输入范围（minimal reproduction）
- 二分定位（哪些文件/模块相关）

### 3.3 工具辅助

- 日志：在关键路径加 print/log，定位执行流
- 调试器：断点 + 单步
- 性能分析：火焰图、慢查询日志

---

## 4. 失败升级（与 work-management §2.3 一致）

| 修复尝试次数 | 动作 |
|-------------|------|
| **第 1 次** | 正常重试 + 确认"修复方向对吗" |
| **第 2 次** | **必须**问"根本原因定位对了吗？目标本身需要调整吗" |
| **第 3 次** | **主动停下来跟用户讨论切换路径**——禁止继续猜 |

---

## 5. 修复协议

### 5.1 修复步骤

```
[1] 写复现测试（FAIL）              ← Red
[2] 修改代码让测试通过               ← Green
[3] 重构代码，保持测试 PASS           ← Refactor
[4] 跑全套测试 + lint + 类型检查
[5] 检查无回归（其他相关测试仍 PASS）
```

### 5.2 修复原则

- **最小修改**：只改 root cause，不"顺手优化"
- **保留风格**：匹配现有代码风格
- **加回归测试**：bug 修复后必须加回归测试
- **记录 commit**：commit message 关联 issue/工单

### 5.3 反例

| 反例 | 后果 |
|------|------|
| 直接改代码不加测试 | 不知道什么时候再回归 |
| 修症状不修根本 | bug 反复出现 |
| 顺手"优化"无关代码 | 引入新 bug |
| `try { ... } catch {}` 空吞噬 | 隐藏问题 |
| 删除/跳过失败测试让 CI 绿 | 红线 #4 |

## 6. 调试输出格式（向用户汇报）

```
## Bug 分析

**现象**：[用户报告的 bug]
**复现步骤**：
1. [步骤 1]
2. [步骤 2]

**根因分析（5 Why）**：
1. 为什么？ [原因 1]
2. 为什么？ [原因 2]
3. 为什么？ [根本原因]

**修复方案**：
- 文件：`path/to/file.js:行号`
- 改动：[具体改动描述]
- 回归测试：`test_xxx.js:用例名`

**验证**：
- [x] 复现测试 FAIL → PASS
- [x] 全套测试通过
- [x] 无 lint 新错误
- [x] 无回归

**Commit**：`fix(module): [Angular 格式] JIRA-XXX`
```

---

## 7. 调试时的安全约束

- 不在调试日志中打印密钥/PII/密码
- 不在 fix 中绕过红线（哪怕只是"临时"）
- 不跳过测试来让 CI 变绿
- 修复前先确认是否涉及数据库迁移（命中红线）

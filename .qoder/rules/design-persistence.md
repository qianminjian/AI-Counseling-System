## 1. BEACON.md —— 项目明灯文件

每个项目的设计北方之星：`design/BEACON.md`。单一摘要文件，贯穿项目全生命周期。

### 1.1 目录结构

```
design/
  BEACON.md          ← 唯一强制文件
  discussion/        ← 可选：多轮设计讨论摘要
  decisions/         ← 可选：详细 ADR（重大架构决策）
  reference/         ← 可选：外部参考材料
```

### 1.2 读取时机

| 触发条件 | 目的 |
|---------|------|
| Plan Mode 激活 | 恢复设计上下文 |
| 启动任何新任务 | 对照 Goals/Scope 确认方向 |
| 用户说"继续"/"接着做" | 恢复上次设计状态 |

读取后在回复中**显式引用**关键内容（如"根据 BEACON.md，当前阶段 X，核心目标 Y"），确认上下文理解正确。

BEACON.md **不存在**时，主动询问："此项目没有 BEACON 明灯文件，是否从当前讨论中创建？"

### 1.3 更新时机

| 触发条件 | 更新章节 |
|---------|---------|
| 设计讨论产生新决策 | ## 设计决策 |
| 需求范围发生变化 | ## 范围边界 |
| 设计阶段推进 | ## 当前状态 |
| 新问题被识别但未解决 | ## 待解决问题 |
| 方案被否定/方向调整 | 追加 ## 设计演进日志 |

## 2. BEACON.md 规范（7 节，≤ 80 行）

文件头：

```
> 创建：[日期] | 更新：[日期] | 阶段：[探索/定义/设计/实现/验证/完成]
```

| 章节 | 上限 | 内容格式 |
|------|------|---------|
| **目标与成功标准** | ≤ 10 行 | 1-3 个核心目标 + 可验证成功标准 |
| **范围边界** | ≤ 10 行 | 两段：**做：** X / **不做：** Y |
| **设计决策** | ≤ 15 行 | `| # | 决策 | 理由 | 日期 |` 表 |
| **当前状态** | ≤ 10 行 | **阶段：** / **最近动作：** / **下一步：** / **阻塞项：** |
| **设计演进日志** | ≤ 15 行 | `| 日期 | 变更 | 原因 |`，倒序保留最近 10 条 |
| **待解决问题** | ≤ 10 行 | `[Q?] 问题 — 谁/何时需要答案` |
| **引用文件** | ≤ 5 行 | `@path — 简述` |

## 4. 更新协议

1. **Read** 当前 BEACON.md
2. **修改** 相关章节（不动的章节保留）
3. **Write** 写回
4. **验证** `wc -l BEACON.md` ≤ 80 行
5. 超出则精简或提取到 `design/discussion/` `design/decisions/`

### 4.1 设计演进日志规则

- 按时间倒序保留最近 10 条
- 旧决策不删除，只标记 `superseded`
- 重大方向变更另起新行，不覆盖历史

## 5. 模式纪律（Plan Mode 期间）

### 5.1 两类操作

| 操作类型 | 行为 | 模式切换要求 |
|---------|------|------------|
| **Materialization**（物化设计产出到 `design/`） | 允许 | 短暂 ExitPlanMode → 写入 → **立即** EnterPlanMode 返回 |
| **Development**（开发/测试/构建/修改源码） | **禁止** | 告知用户："这是开发操作，请手动 `/normal` 切换模式后再进行" |

### 5.2 口头信号

- 物化前："我将暂时退出 Plan Mode 写入文件后立即返回"
- 返回后："已返回 Plan Mode，设计讨论可继续"
- 开发请求拒绝："这是开发操作，不在 Plan Mode 范围内。请手动 `/normal` 切换模式"

### 5.3 后悔保护

用户意外批准 ExitPlanMode 进入开发后，操作完成时主动提醒："开发操作已完成。是否需要返回 Plan Mode？输入 `/plan` 即可。"

## 6. 计划文件位置（硬性红线）

Plan Mode 产出的计划文件（`*.md` 执行计划）**必须**写入项目目录内，**禁止**写入全局目录。

| 项目类型 | 计划文件路径 |
|---------|------------|
| 有 `design/` 的项目 | `<PROJECT_ROOT>/design/<name>-PLAN.md` |
| 有 `.planning/` 的项目（GSD 框架） | `<PROJECT_ROOT>/.planning/phases/<phase-id>/PLAN.md` |
| 新项目（尚无过程目录） | 先创建 `design/`，再写入计划文件 |

**反例**：

- ❌ `~/.qoder/plans/xxx.md` — 全局目录，计划与项目分离
- ❌ `/tmp/some-plan.md` — 临时目录，重启丢失

**正例**：

- ✅ `design/v4.0-EXECUTION-PLAN.md`
- ✅ `.planning/phases/05-v4.0-refactor/PLAN.md`

## 7. 安全约束

**禁止**在 BEACON.md 中包含：

- 密钥、token、密码
- 敏感个人信息
- 数据库连接串

遵守 `core-red-lines.md` §1 + `code-engineering.md` §5。

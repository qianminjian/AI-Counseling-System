# context-management.md - 上下文窗口管理

> 加载方式：模型决策（Model Decision）
> 触发场景：长会话 / 上下文压缩后 / 会话轮数 > 30 / 用户提示"会话太长"
> 来源：整合自 Claude Code `rules/context-management.md`

---

## 1. 会话长度阈值

| 阶段 | 轮数阈值 | 动作 |
|------|---------|------|
| 正常 | < 30 轮 | 无需干预 |
| 预警 | 30-50 轮 | 主动总结当前进展到 `design/session-summary.md` |
| 临界 | > 50 轮 | **强制压缩前保存**：当前任务状态 + 待处理清单 + 关键决策 + BEACON.md 指针 |

---

## 2. 压缩恢复协议

当系统 compact 上下文后：

1. **立即** Read `design/session-summary.md`（如存在）
2. **立即** Read `design/BEACON.md` 恢复设计基线
3. 列出"压缩前正在做什么 + 下一步是什么"
4. 向用户确认："上下文已压缩。我恢复了 [X] 状态，下一步 [Y]，继续？"

---

## 3. 上下文预算

- 单次输出 > 500 字时评估是否可精简
- 长输出（>1KB）用 Subagent 隔离，主上下文只接摘要
- 避免在单轮对话中 Read > 5 个大文件（>200 行/个），优先用 Grep/Glob 定位

---

## 4. 关键信息防丢失

以下信息**必须在压缩前显式写入文件**，不可仅存于对话上下文：

- 未写入的 BEACON.md 决策
- 当前任务的验收标准（EARS 格式，详见 `@ears-spec`）
- 用户明确说"记住这个"的内容
- 跨会话需要的状态（当前阶段 / 阻塞项 / 下一步）

---

## 5. 持久化途径定位

四种持久化机制各司其职，不重叠：

| 机制 | 存什么 | 生命周期 | 加载方式 |
|------|--------|---------|---------|
| Qoder 自动注入的记忆 | 用户偏好、反馈、项目事实 | 永久，自动管理 | 自动 |
| `.qoder/rules/*.md` | 规则约束 | 项目生命周期 | 触发条件命中 |
| `AGENTS.md` | 项目顶层规则入口 | 项目生命周期 | Agent 自动识别 |
| `design/BEACON.md` | 设计决策、架构约束、范围边界 | 项目生命周期 | `@design-persistence` |
| `design/session-summary.md` | 长会话状态快照 | 会话级 | 压缩恢复时 |
| `_scratch/` | 临时产物：报告、调试输出、测试日志 | 会话级，gitignore | 按需 Read |

记忆分工：

- 记忆管"**谁**在做什么"（用户画像、偏好）
- BEACON.md 管"**为什么**这么做"（设计决策、约束）
- `design/` 管"**做到哪了**"（设计状态、计划进度）
- `_scratch/` 管"**当前这次调试/分析**"的中间产物

---

## 6. 深度思考预算

| 命令 | thinking budget | 适用场景 |
|------|----------------|---------|
| `/tp` | ~2K tokens | 新增功能，标准设计 |
| `/tt` | ~4K tokens | Bug 修复，硬思考 |
| `/ttt` | ~8K tokens | 复杂工作，深度审计 |
| `/tttt` | ~16K tokens | 大型重构，极致思考 |

根据任务复杂度选择合适的思考层级，避免小任务过度思考或大任务思考不足。

详见 `@think-deep`。

---

## 7. 压缩前主动检查清单

接近 30 轮时，在系统 compaction 之前主动完成：

- [ ] 当前任务状态已写入 `design/session-summary.md`
- [ ] BEACON.md 中的设计决策已更新至最新
- [ ] 用户明确要求"记住"的内容已写入记忆
- [ ] 待处理清单 + 下一步动作已记录
- [ ] 当前阶段 + 阻塞项已更新

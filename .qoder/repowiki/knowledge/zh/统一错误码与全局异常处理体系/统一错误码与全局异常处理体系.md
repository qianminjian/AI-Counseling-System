## 1. 系统/方案概述
该后端采用 Spring Boot + `@RestControllerAdvice` 的全局异常处理机制，配合自定义业务异常 `BizException` 和集中式错误码枚举 `ErrorCode`，将所有 HTTP 响应统一封装为 `ApiResponse<T>` 记录类型。业务层通过抛出 `BizException` 携带错误码，由全局处理器捕获并转为标准 JSON 响应；参数校验、约束违反等框架级异常也被统一映射到对应错误码。

## 2. 核心文件与包
- `backend/counseling-common/src/main/java/com/mindsafe/common/dto/ApiResponse.java` — 统一响应体（code/message/data/timestamp）
- `backend/counseling-common/src/main/java/com/mindsafe/common/dto/ErrorCode.java` — 按模块分段定义的错误码枚举（10xxx通用、20xxx认证授权、30xxx对话会话、40xxx风险预警、60xxx AI/LLM）
- `backend/counseling-common/src/main/java/com/mindsafe/common/exception/BizException.java` — 业务异常基类，持有 code 与 message
- `backend/counseling-api/src/main/java/com/mindsafe/api/config/GlobalExceptionHandler.java` — 全局异常处理器，统一捕获 BizException、MethodArgumentNotValidException、ConstraintViolationException、Exception

## 3. 架构与约定
- **异常传播路径**：Controller / Service 中直接 `throw new BizException(ErrorCode.XXX, detail)` → Spring MVC 拦截 → `GlobalExceptionHandler` 根据异常类型选择对应 handler → 返回 `ApiResponse.error(...)`。
- **HTTP 状态码约定**：业务异常统一返回 200 OK（由 `@ResponseStatus(HttpStatus.OK)` 指定），具体错误语义由 `code` 字段表达；参数校验类异常返回 400；未预期异常返回 500。
- **错误码分段规则**：`ErrorCode` 枚举以万位区分模块（10xxx 通用、20xxx 认证授权、30xxx 对话会话、40xxx 风险预警、60xxx AI/LLM），新增错误码需遵循该分段命名空间。
- **AI 调用异常**：`ResilientChatModel` 在备用模型也失败时抛出原始异常，交由上层 `GlobalExceptionHandler` 兜底处理，避免在 AI 层自行封装错误码。
- **日志策略**：业务异常使用 `warn` 级别记录 code 与 message；未预期异常使用 `error` 级别记录堆栈。

## 4. 约定与约束
- 所有业务错误必须通过 `BizException` 抛出，禁止在 Controller 中直接构造 `ApiResponse` 作为错误返回。
- 新增错误码必须在 `ErrorCode` 枚举中按模块分段添加，不得随意使用裸数字码。
- 参数校验失败统一走 `MethodArgumentNotValidException` / `ConstraintViolationException` 路径，由全局处理器映射为 `PARAM_INVALID`，不在业务层手动包装。
- 未捕获的任意异常由兜底 `@ExceptionHandler(Exception.class)` 处理，返回 `INTERNAL_ERROR`，确保不会泄露堆栈信息给前端。
- 成功响应使用 `ApiResponse.ok(data)` 或 `ApiResponse.ok()`，失败使用 `ApiResponse.error(code, message)` 或 `ApiResponse.error(ErrorCode)` 静态工厂方法。
